# Side-panel control (A3)

These modules control **display lifetime only**. They neither import a job-control API nor close tabs, jobs, workers or browsers. The receipt is not a caller identity or a job receipt.

## Integration seams for A4 / A5 / A7

- `displayTarget(harness, session, canonicalSource)` builds the source-qualified observation root with `makeSourceId`. `panelSelection` in `src/cli/panel.ts` accepts `--harness`, `--session`, `--source`; `--root` and all-delegations mode remain supported. An omitted source requires corroborated current caller identity, never cwd inference. Display selection never grants execution authority.
- `controlPanel(operation, context, options)` supports `open|close|toggle|status`. The context supplies the main process stamp, verified originating pane/terminal, exact herdr instance, and absolute pinned runtime Node executable / `bin/hud` entry / manifest digest. Production callers obtain these from native evidence and their immutable activation binding, not model arguments. Herdr endpoint binding is likewise explicit (`CliPanelHerdr`).
- `options.native` uses A2's `CallerIdentity` plus native proof of top-level TUI mode. A4/A5 must corroborate that proof. A3 independently checks process stamp, foreground TTY, pane identity, instance and worker launch negatives. No evidence means `panel_eligibility_unknown` and no split. Hook JSON is never deserialized into native proof. The standalone internal CLI therefore cannot auto-open until a harness adapter supplies corroborated native evidence in-process. Delegation identity does not imply panel eligibility.
- A4/A5 must supply `options.isCurrent`, bound to their native epoch, whenever same-process session replacement is possible. A stale epoch after preflight refuses before intent/split. Replacement after split fences and closes only that call's recorded created pane before any run; it cannot touch the replacement generation. Omitting the callback preserves the non-switching caller behaviour.
- Call `open` with `automatic: true` only for native startup events. Repeated automatic starts do not resurrect a manually closed/crashed display. Explicit `open` can reopen a confirmed closed display. `close` and the closing half of `toggle` require the returned generation and matching display root; retain that generation with the native session context so late shutdown events cannot close its replacement.
- `/hud off` is session-local (a generation-specific close). The persistent default is `panelAutoOpen` in `$HUD_HOME/integration-config.json`, default true when absent. Setup/activation must explicitly preview changes to that HUD-owned file; A3 does not mutate it or the R5 settings UI. An unreadable/invalid preference fails closed.
- The split receives only HUD-owned environment fields (home, settings/display paths, token, generation, key). It is a right split with `--no-focus`. Launch uses the existing `commandText({ argv })` quoter and `pane run`, per orchestrator q2; there is no free-form shell input. All argument strings are validated before effects. No secrets go into argv/env overrides. Compatibility gates are unchanged; missing split/env/focus/run support refuses before splitting.
- A7 must dispatch the harness panel entry **in the same process**, before broad CLI imports, set the display context, and install `registerPanel(env, actualPaneIdentity)` (including the herdr-reported workspace ID, never the focused workspace) before entering `runLivePage`. The runtime entry is the pinned `bin/hud`, not the export-only `dist/cli/hud.js`. `registerPanel` corroborates the process argv and initial environment token and returns the receipt with its actual occupant. Pass that receipt to `installPanelLifetime`, with the existing panel's finish callback as `end`, and dispose it in finish. No persistent wrapper/watchdog process is permitted. The current `tree-page.ts` is intentionally untouched; A7 owns that wiring. Until then a launched panel cannot self-register and is not reported open.

## Persistence and ambiguity

All state is private under `getHudDisplayHome(env)/panels` for **every** harness. No Codex home is redirected or written. Files are capped at 16 KiB, reject symlinks and are atomically replaced at mode 0600; directories are created at 0700. Slot identity is a hash of the main process stamp, herdr instance, originating pane and terminal. Receipt and recovery intent precede split. A retained used-slot marker makes total receipt/intent loss refuse another split. Intent recovers ordinary receipt loss. Once a split ID is known, missing run replies only reconcile the original token; they never resubmit split or start. Confirmed absence requires a bounded complete pane inventory explicitly scoped to the recorded workspace on the same pinned instance, plus a valid workspace roster (including confirmation when the workspace itself is gone), not a generic transport error or focus-relative inventory. The split reply or first observation supplies the workspace; unknown scope stays uncertain and cannot authorize close/re-create (q6). Only a failed `pane.get` permits absence fallback: successful get metadata with missing/changed workspace or unavailable occupant evidence always refuses, never becoming absence through a later inventory (q7).

The panel registers independently of the controller lock, closing the lost-start-reply window. A split-only lost reply stays `uncertain` with `split_reply_lost` and guidance about a possible empty orphan pane; automatic retries never split again, while an explicit user `open` may make exactly one fresh-generation attempt without discovering or closing the unknown orphan (q5). An acknowledged split ID is saved before bounded readiness polling; transient startup evidence is retried only for that pane, and the terminal/original shell stay fenced while rc commands finish. Readiness expiry closes only a captured, freshly matching occupant, otherwise leaving the known pane ID uncertain. Missing registration after a known split attempts one bounded close only when the original terminal AND occupant still match; the outcome stays uncertain until confirmed absence. Reused panes are refused. Lock files are not stolen on an age/heartbeat guess; a crashed controller can require explicit reconciliation rather than risking duplicate allocation. State loss is not evidence of successful cleanup.

## Bounds

Control operations cap at 4 seconds, below the 5-second hook envelope; stdin caps at 64 KiB with a 500 ms deadline. Normal close caps at 900 ms (plus at most 500 ms input). Each subprocess caps at 500 ms within the remaining total budget, uses ignored stdin/private pipes and destroys inherited stdout/stderr pipes on deadline. Calls are serialized; no transport daemon is started.

Lifetime uses one single-flight approximately 1-second cadence. One herdr ownership sample (instance plus exact pane/foreground identity) is allowed every 3 seconds, sharing a 500 ms deadline. Main death, replaced generation, HUP, terminal loss or changed pane identity ends only the display. Prolonged unavailable proof ends the display after 9 seconds; it never remotely kills an unverified pane and never restarts. Dispose removes timers and signal subscriptions.

## Validation

`node --test dist-test/tests/unit/panel-control.test.js` uses a subprocess fake herdr and synthetic process/TTY evidence, with separate real synthetic-process registration and shell-quoting checks. No real pane or CLI session is used. `node tests/panel-control-mutants.mjs` copies emitted modules into isolated temporary homes and requires all seven negative controls to fail assertions. Real right-split/focus/cleanup and ordinary-client checks remain NOT_RUN; fixtures are not live acceptance.
