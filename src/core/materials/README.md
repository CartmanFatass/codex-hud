# Model material boundary (B17)

`buildMaterials` reuses the core envelope, provenance and policy types. It identifies public fields, checks local/model scope, matches each source's positive purpose/recipient grant, and only then reads text and computes fingerprints. Independent fragments may produce a partial envelope. An inseparable derived fragment needs every original contributor. `materialRequest` carries empty system/prompt fields and an authorized formatter; the formatter must use its approved envelope, never a separate unfiltered input.

`SmallModel` remains the queue, budget, cancellation, priority and retry authority. It resolves the actual transport before formatting, revalidates before consuming a cache, after coordination waits, immediately before dispatch, inside the cache publication lock, and before delivering a reusable result. Callers check `handle.isAuthorized()` again before notes land. Repair/translation use the prior envelope as inherited material. Backend off never reads material or dispatches a request. Explicit probes are a fixed synthetic operation with purpose `probe`; the callback cannot change its text.

Source-aware composition supplies a `MaterialAuthority`: a positive local/model scope for each exact ref/origin/field/purpose, plus its source policy reader (`fileAuthority` reads `HUD_HOME/sources/<sourceId>/outbound.json`). Missing or invalid scope/policy denies. Scope revisions must advance when effective scopes change; outbound policy writers retain their contract's monotonic revisions. An API needs a concrete nonsecret account identity, or an explicit accountless identity. A CLI needs an explicitly trusted profile or a resolver; both paths also pin the concrete executable/stat, PATH and observable profile context, and invalidate known credential changes in-process. A supplied resolver is additionally bound to the selected transport. Keys never create grants or become recipient identity. Static API account labels pin the effective authorization privately in-process and deny credential drift before reads or cache lookup. A trusted fresh resolver may verify a rotation still reaches the same actual account; merely echoing an account label is not a resolver. Null/throwing resolution never falls back to legacy identity. Queued/late jobs compare the current selected authorization with their captured connection and must be rebuilt after credential changes.

New cache domains include approved source/ref/origin/record provenance, purpose, recipient, actual model, language, coverage and authorization scope. Output-bound private sidecars are published within the existing cache commit lock. General replies use `materials-v1/replies/cache.json`; the optional cache directory in `ModelRuntimeStore` shares the original coordination, claim and call files. General retention cannot prune the original Codex cache. Unknown/mismatched sidecars refuse a general hit without deleting the artifact.

`DerivedMaterialStore` is B10's persistence handoff for generic/delegated notes. Save only with a currently authorized minted envelope; load rechecks every original contributor under the new consumer's purpose/recipient. Never write general output into the provenance-free `AgentLog`/`RecapStore` formats. Same-source delegated origin still needs its own positive scope. A parent's ref cannot replace a child's provenance.

The legacy bridge reads the raw original Codex configuration, never migrates it. Explicit backend opt-in covers the fixed historical feature defaults; booleans, credentials and display controls alone grant nothing. Original-home canonical paths, matching bounded headers and native topology are verified. Both historical parent encodings work; conflicting parent IDs, explicit delegated origin, missing universal origin and mismatched refs deny. A pre-create charge remains parent-owned before the child file exists, with the child ref/origin guards retained. Progress omits charges whose parent cannot be proved. Async extraction captures its exact contributors before reading and rechecks them after the read; removing a child never substitutes root authority. The bridge has no implicit generic-source grant. An observed explicit policy becomes authoritative; its absence cannot resurrect the bridge. Policy authority markers contain no baseline account identity.

Local display of old labels is a separate off-tick path: it first proves original home, original cache file and native local scope, including with backend off. Universal ref/origin metadata cannot enter this historical display lookup. Pending local hydration is deduplicated, including reentrant apply-onChange callbacks. Display state never populates model cache or dedup identity; reuse for a model request needs fresh outbound authorization. Label scans retain progress past unusable/sealed sources and revisit fresh source records. Collector scheduling observes metadata only; text reads and hashes occur inside the granted formatter.

Legacy outputs remain tainted and cannot be promoted into general material. Old recap fingerprints do not prove transitive scope. Main-only reuse requires an output-bound narrow influence proof (`legacy-scopes.ts`); otherwise prior recap, prior coverage and agent overall are omitted. New main recaps omit unexpected agent fields and retain private scope evidence for safe translation/restart reuse. Old files are preserved until ordinary authorized feature updates replace their current record.

B10 must preserve actual source/ref/origin when combining trees and use the general plan/store for delegated material. It must not cast universal nodes into the legacy tree adapter or copy generic notes into legacy stores. B14 should rerun the synthetic failure suite and real profile/source routing cases. Hidden provider/account changes across restarts remain unproved: the MVP has no persisted nonsecret account/profile baseline (owner decision), while endpoint/executable/PATH and private credential continuity are pinned within a process.

Source-aware callers invoke material building outside collection and paint turns; B10 must preserve that scheduling. Generic source-aware submission does not add a scheduler. Legacy filesystem checks run during configuration setup and deferred material work, outside the collection/paint turn. Steady tick scheduling adds zero filesystem operations and zero policy-index lookups. The material tests print per-call timing and the legacy test instruments synchronous filesystem calls on a collector tick.
