# MCP-NEXT: High-throughput orchestration, zero-copy context and managed worktrees

Elaborates `docs/spec.md` §2.1 (owner, 2026-11-18).

## Scope

1. **Fine-grained concurrency, pre-flight CLI trust and parsed quota cooldowns (`01`).** Replace global mutation serialization in `thin-main.ts` with per-`request_key` / per-`job` locks so slow CLI launches never block unrelated `hud_create`, `hud_respond`, `hud_send` or `hud_close`. Verify CLI directory trust locally before opening a herdr tab (`grok`, `agy`, `claude`), failing immediately with `untrusted_cwd` and naming `hud trust <cwd>`. Parse reset durations from 429/quota messages (`try again in 18m`, `retry-after`, `resets in 2h 15m`, ISO/epoch timestamps, clamped between 1 minute and 24 hours) instead of always using a fixed 1-hour TTL.
2. **Per-job preset selection (`02`).** Add optional `preset` to `hud_create` (`thin-main.ts` and `PI_ROLE_TOOLS`). Resolves the named preset from the role's merged `presets` list, picks its first available non-exhausted place, and applies optional `model`/`thinking` overrides on top without mutating `$HUD_HOME/roles/*.json`.
3. **Multi-job event wait (`03`).** Add `hud_wait({ jobs?: string[], mode?: 'any' | 'all', wait_ms?: number })` (up to 120000 ms). Event-driven over `fs.watch` on `$HUD_HOME/jobs`; wakes immediately when any watched job (or all watched jobs in `all` mode; open questions or failures always wake early even in `all` mode) settles, fails, blocks, enters `waiting_orchestrator`, or opens a question.
4. **Native silent event wake for pi & watcher liveness (`04`).** Add `watcher_alive: boolean` to MCP metadata/responses when `HERDR_PANE_ID` is present. In the pi package (`package-entry.ts`), run an in-process lightweight watcher for the session's `HERDR_PANE_ID` (recording `$HUD_HOME/watchers/<pane>.pid` so `hud-notify` skips typing) and deliver actionable question/settlement lines via `pi.sendMessage` (`deliverAs: 'followUp'`, `triggerTurn: true`), matching Codex's silent queue UX without touching user editor drafts.
5. **Zero-copy context assembly (`05`).** Add `context_files?: string[]` and `from_jobs?: string[]` to `hud_create`. For `pi` and `cli` places, prepend a clean `## Context References` section to `brief.md` listing resolved file paths and upstream job `report.md` paths. For `bro` places, read and inline the bounded contents (up to 64 KiB per file, 256 KiB total, rejecting symlinks outside cwd/HUD_HOME or binary files) into `brief.md` with fenced headers so material bypasses the main session's LLM output window.
6. **Worker progress heartbeats & live pane peek (`06`).** Add `bin/hud-progress.mjs` (`node <hud>/bin/hud-progress.mjs --dir <job-dir> "step text"`) appending bounded JSONL lines (`{ at, text }`, max 50 retained) to `<job-dir>/progress.jsonl` and mention it in local worker briefs. Expose `latest_progress` and `progress` in `hud_read` and `thin-jobs`. Add read-only `hud_peek({ job, lines?: number })` returning the worker's recent herdr pane lines (default 40, max 120), STATUS summary and progress log without stamping `read_at` or altering job state.
7. **Managed worktree isolation (`07`).** Add `isolation?: 'none' | 'worktree'` to `hud_create`. When `'worktree'`, create a clean git worktree under `<repo-parent>/<repo>-wt/<job-or-slug>` on branch `wt/<slug>-<shortid>` from HEAD, symlink `node_modules` if present in the main repo, trust the directory if the main repo is already trusted for that CLI agent, and record `worktree: { root, branch, base_head, main_root }` in `job.json` (recognized by Project's `WorktreeCollector` so it is not flagged as unlisted). Enrich `hud_read` with `git_summary` (`base`, `head`, `commits`, `changed_files`, `dirty`). In `hud-watch.mjs`, automatically remove managed worktrees after job closure only when the working tree is clean and `HEAD === base_head` or already ancestor of the main branch; dirty or unmerged worktrees are preserved.
