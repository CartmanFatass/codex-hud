All in src/roles/job-usage.ts plus tests/unit/job-usage-stats.test.mjs. No archive format change; numeric token accounting stays as it is. (1) Pi error/abort turns. piTotals (~:158-162) adds piModel(m, u) for every assistant row that has `usage`, and piModel falls back to `m.model` when `responseModel` is absent. Pi's OpenAI Responses emitter initialises `model: model.id` and zero usage before the request, then persists that message with `stopReason: "error"` or `"aborted"` on failure. A quota rejection after a successful turn therefore records a requested alias that served nothing as the latest served_model. Do not add a model observation for an assistant row whose stopReason is error/aborted unless it shows evidence of a response (a valid responseModel, or non-zero input/output usage). Keep the row's numeric usage handling unchanged. (2) AGY terminal result masking a cut native log. In recordJobUsage (~:314-339), an intact stdout result marks stream model evidence complete even when transcriptUsage returned early because the planner transcript was cut or malformed. Fixture: planner A then B with A in the discarded prefix of a >1 MiB transcript_full.jsonl, result B: settlement must keep the stream token totals but omit served_model/served_models (unknown), not publish B alone. Carry native model coverage (read, intact / cut-or-malformed / absent) out of transcriptUsage and through the merge; a terminal result establishes only the final model, not the full history, when the native view exists but is incomplete. (3) Continuation order. The merge replays prior-turn stream observations (prefix.usage models) after the new native observations, so for an intact first AGY turn with result A, a contiguous second turn whose result has no model, and a complete native transcript A then B, the output is [B,A] with served_model A. Keep the prior-turn prefix separate from current-terminal evidence: prior-turn observations go before the native history (or are superseded by it), and only the current turn's terminal evidence may follow the native observations. Add this two-settlement test next to the existing one-settlement A/B test.
