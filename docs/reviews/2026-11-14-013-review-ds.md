## Spec

### 1. `2`/Tab reopens the last Project page instead of the hub — minor

`src/render/workboard-input.ts:121-126`

The `project-tab` branch calls `home()` (which clears `projectList`/`projectBack` but **not**
`projectPage`) and then sets `mainTab = 'project'`, so the page left open before going Home is
restored. Feature spec item 1 says "`2` (or Tab) opens the hub"; item 7 says "`2` opens the hub of the
project shown last"; ticket 04's checkbox says "`2` behave[s] as specified".

Failure scenario (verified through the real input path with the fixture): open Project → Progress →
`1` (Home) → `2`. State is `mainTab: 'project', projectPage: 'progress'` and the first row is
`‹ demo-project › Progress`, not the hub. `Tab` behaves the same. The reference doc and
`docs/releases/0.1.3.md` were changed to describe this ("at the page it had open, else its hub"), so
it is deliberate — but the feature spec and the ticket were not amended, and
`tests/unit/project-list.test.mjs:114-118` asserts only `mainTab`/`projectList`/`projectRoot`, so the
test cannot catch it.

Fix: clear `next.projectPage = undefined` (and `projectSaved`) in that branch, or amend feature spec
items 1 and 7 to say "the page it had open, else the hub" and keep the test as is. Owner's call.

### 2. The Projects list's last-activity column is not translated — minor (§8)

`src/render/project-view.ts:191-194`

`sinceText` builds `12m` / `3h` / `4d` directly instead of going through `t()`. `ARCHITECTURE.md` §8:
"Panel words go through `t()` with EN/ZH entries." Every other age in the panel is translated
(`ageText` → `{n}分钟`, `{h}小时{m}分`).

Failure scenario: a ZH panel opens the Projects list and reads `0m`, `5h`, `2d`, `40d` in the
right-hand column while the Docs row on the same screen says `评审 30分钟`. Captured in
`tests/fixtures/project-list-frames.json` (`list-40-zh`), so the snapshot now locks the English units
in.

Fix: add `'{n}h'`/`'{n}d'` (and reuse `'{n}m'`) to `WORKBOARD_ZH`, or reuse `ageText` for the
sub-hour case and add the two hour/day keys.

### 3. Blank Project tab until the first collection of a newly shown project — minor

`src/tree-page.ts:732`

`render()` reads `visits.snapshot(shownRoot())`, which is `undefined` for a root the panel has not
collected yet, and `projectRows` returns `[]` for an undefined snapshot — so the body is empty.
`withInputRefresh` (`src/utils/workboard-input` caller, `src/tree-page.ts:1358-1365`) renders the
input *before* `collect(true)`, and `collectNow` only renders again at its end.

Failure scenario: on the hub of project A press `]` for the first time in this session. The frame
painted immediately after the keypress is `[" Home 1  Project ...", "", "", …]` (verified by
rendering with `snapshot: null`); the hub appears only when the collection finishes (tens to hundreds
of ms). Switching back to an already-visited root does not blank (its snapshot is kept), and a reload
does not blank (`render` is gated on `collected`).

Fix: keep the previous root's snapshot until the new root has one (e.g. fall back to the last
snapshot while `visits.snapshot(shownRoot())` is undefined), or trigger the collect before the paint.
