## Findings

### 1. Major — unfinished collection can be reported as complete between source turns

**`src/collectors/task-observations.ts:598–600, 617–619`** — pending membership/file work is not included in snapshot-wide completion accounting, so an already-created lane can make an unfinished source disappear from the coverage warning when its next turn falls outside the current probe slice.

**Failure scenario:** Create 80 empty task directories, `T000`–`T079`, and one `ZZZ` directory containing 100 valid QA pairs, all default A/answer A. These populations are within the specified lane and per-task limits. Through the production `PanelJobPipeline`, refresh ticks **10 and 13** (zero-based) contain all **81 lanes**, **zero of the 100 calls**, and `coverage.incomplete:false` with **no diagnostics**. Each slice has exhausted its **64 probes**, with zero reads, enumerations or reparses. Rendering that snapshot at 56 columns displays **`✓ nothing needs you`**, without an incomplete warning. The final 400-refresh run contains all 100 calls, demonstrating that the omitted files are valid and eventually collected, not absent or malformed.

`refresh()` resets `incomplete` at line 483. The unread-file check at line 598 only examines sources visited in that slice; the global check at line 600 only requires a lane to exist. A lane can already exist while its directory/QA membership or initial reads remain unfinished. `snapshot()` persists issues, invalid status and pending pair validation, but not those other unfinished states. A slice spent on other sources can consequently clear the warning without completing the outstanding work. This violates plan §3's pending/partial accounting and the brief's explicit “Partial coverage never shows ‘nothing needs you’” requirement; it also presents an incomplete call feed without its partial qualifier.

The new 50/100-pair tests validate eventual completion and warm behavior for one populated task, but do not assert truthful coverage on every catch-up slice across multiple sources.

**Suggested fix:** Persist or derive outstanding membership/initial-file work across **all** retained sources when forming coverage, independently of which sources were visited; distinguish it from ordinary warm signature rotation. Add a real-pipeline multi-source regression that rejects complete coverage while these admitted QA files remain uncollected, while preserving zero-reparse warm snapshots.
