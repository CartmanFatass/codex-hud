Simplicity and quality

Blocking. A failed "write your report" prompt does not stay with the main session. In `packages/hud-mcp/bin/hud-cli.mjs` (about lines 242–251), `finished-no-report` sets `reportPromptSent`, writes `turn.json`, then sends the fixed prompt. If that `herdr agent prompt` fails, the shell marks the decision `needs-human` / `prompt-failed` and judges it against the turn from before the write, so `STATUS.json` can show `waiting_orchestrator`. The write has already bumped `turn.json`'s seq. The directory watch, or the 30 s tick (`diskDirty = true`), reads the new seq. `judge` treats a new seq as a fresh `working` turn and clears the handoff (`packages/hud-mcp/src/cli-judge.ts` lines 97–102; the table tests "only explicit turn reopens" and "a new turn can ask again"). The one prompt is already consumed, so the next quiet period will not send it again. The worker sits another idle grace (default 10 minutes) before a later `needs-human` can stick. Ticket 10 and spec §2 say any error goes to the main session. Publish the turn only after the prompt is accepted, or apply `needs-human` to the new seq so the next wake cannot clear it.

Nothing else should be deleted. The nested `herdr agent wait` loops are already gone. The judge's `prompt-report` arm is the decision's meaning; the bug is the shell publishing a turn that erases the failure.
