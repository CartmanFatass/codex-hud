## 应优先处理的实际问题

### 1. Inspector 显示字面的 ANSI 控制码

在 terminal、mocha、latte 主题中，模型标记先被着色，然后送入 `wrapped → monitorText`。后者为外部文本设计，会把 ESC 转义成可见的 `\x1b`。45 列实测：

```text
│ \x1b[96m☀\x1b[0m\x1b[96m◕\x1b[0m \x1b[2mA │
│ stra\x1b[0m                               │
```

位置：`src/render/monitor.ts` 的 agent Inspector 分支和 `wrapped`。这是显示 bug，不是风格偏好。应先清理外部原始字段，再进行布局与内部着色，保持外部控制字符防护。

### 2. 点击 Agents 框中的空白行会切换会话

30×40 的样本中，点击视觉上完全空白的第 10 行，handler 返回 `{type:'switch', id:'a2'}`。`monitorItemAt` 对没有 item 的行回溯到最近的 agent，连摘要行也会落到某个 agent。

建议让空白和摘要不触发会话操作，点击热区只对应可见条目。保留或调整“单击 agent 立即切换”的策略可以独立决定：若保留，需要明确目标行；若改成先选中，再按 `o` 切换，鼠标和键盘语义会更一致。

右键正向对照：当前 decoder 忽略右键 press/release，未产生选择动作。此前右键粘贴/抢焦点问题的修复不应回退。

### 3. 重要信息的隐藏顺序需要调整

40 列、缓存到 25 分钟的样本实际为：

```text
!2 | ▸ | ☀ | main* | 1▸1✗ | ◷~25m
```

上下文消失，而分支和代理统计保留。当前 context 优先级 66，agents 70，project 88；缓存告警优先保留是正确的，但 context 应排在分支和代理汇总之前。建议最小形态保留状态、模型、上下文、缓存/异常提醒，再让项目、代理详情、会话时长依次退出。普通宽度继续保持一行。

### 4. 窄屏帮助和设置控件被裁剪

16 列设置页头部为 `[Back] [Save] […`，Reset 没有完整名字；标签变成 `HUD…`、`The…`、`Bar next …`。30 列帮助页的模型和 effort 图例仍在右边被裁断，帮助状态也没有滚动处理，12 行高度时后半段完全不可见。

建议 16–20 列采用缩短后的明确标签与紧凑操作行，保留“保存/返回”；Reset 放进次级操作。帮助应自动换行并可滚动。设置区分“立即生效”和“下次启动”，未保存项带小标记，避免所有反馈依赖底部一条消息。

## Tree 的展示建议

### 名字、模型、状态分配固定空间

30 列样本的长名字占满行，`☀◕` 被完全截掉；同页短名字 reviewer 却能显示 `★◐`。建议先保留状态和两字符模型/推理标记，再裁剪名字。模型名 Astra/Sol 留给 Inspector；仅在有额外空间时显示文字。不要同时在每行重复 `✓` 和 `done`、`!` 和 `error`，将省出的列留给角色名。

16 列下实际内容只剩 12 列，层级前缀还会压成 `…`，已经无法可靠区分深层父子关系。因此把 16 列定位为简要监控：状态、短名、数量；完整层级在 30–45 列显示。根据主窗口空间选择宽度，避免为了侧栏把 Codex 主区挤窄。

### 减少边框和无效空白

当前每个盒子占两条边框行，左右边框及 padding 共占 4 列；在 16 列中是四分之一。Agents 和只有两个条目的 Worktrees 还会分摊剩余高度，产生大量空框。

建议只强调当前焦点区域，其他区域使用轻分隔线；标题可以同时带计数，例如 `Agents 1▸ 2✓ !1`。给 Agents 优先高度，Worktrees 按内容收缩。没有代理或只有一个干净 worktree 时用紧凑摘要，仍保留明确的展开入口。完成的历史代理可折叠为带数量的组，错误和正在工作者优先可见；排序变化应保留当前选中节点，避免列表跳动。

### 区分“选中”“正在工作”“已切入的会话”

现在主要通过整框 accent 和一个 `›` 表达焦点/选中，整行状态色又很强。建议选中行使用轻背景或反白，并保留 `›` 供无色模式辨认；工作状态只着色状态符号；模型保持专属颜色，名字使用普通前景色。当前真正切入的会话若没有可靠来源，不应把列表选中项当作该状态。

### Inspector 提供用户要判断的信息

当前最先看到的是 ISO 时间、Last evidence、UUID。建议主视图改为角色/模型、当前状态、持续时长、最近一次活动；UUID、完整时间和绝对路径移到展开区。若补充当前任务或最近工具，应从已有可靠日志字段提取简短摘要，显示缺失/过期状态，避免根据静默推断已完成，也不要重新引入完整对话流。

### Worktrees 与 Changes 保持“能判断、能找到”

- Worktree 主行显示分支和 `7Δ` / `!1`；路径缩成尾部目录，完整路径进 Inspector。45 列当前拼接完整路径，往往恰好把分支/路径后半部截掉。
- 默认 20–30 列下 Changes 只有文件数量、staged/unstaged 汇总，没有文件条目。这是现有设计取舍，但用户无法在这里选择想看的文件。建议至少提供短文件名列表，摘要移到标题；窄屏预览提供明确的宽度或放大提示。
- 45×24、四区同时打开时，diff 预览只露出路径和 `---` / `+++`，真正修改行在下面。进入 diff 时优先给 Inspector 高度，或自动使用现有 zoom 模式，并保持 Esc 返回。
- diff 当前没有区分增加、删除、hunk 的颜色。建议 `+` 淡绿、`-` 淡红、`@@` 淡青，保留符号供无色模式使用；长行可横向滚动或按需换行。

## 配色建议

现有语义配色和模型图形值得保留，不需要增加更多图标。优先降低边框、分支、模型、整行状态同时竞争注意力的程度：一个焦点 accent，普通名字采用前景色，告警色仅用于确有需要的项目。

Mocha muted `#6C7086` 在示例背景 `#1E1E2E` 上的对比度约 3.36:1；Latte muted `#9CA0B0` 在示例背景 `#EFF1F5` 上约 2.30:1。这是指定背景下的计算，不是用户终端实测。尤其应加深 Latte 的说明文字、空状态和快捷键；Mocha 可适当提亮次要文字。终端主题保留用户的背景和默认前景，不硬编码整屏底色。

## 建议实施次序

1. 修 Inspector 控制码、空白误切换；提高 context 保留优先级。
2. 固定 Tree 的状态/模型列，减轻边框，完善选中反馈与窄屏 Settings/Help。
3. 调整面板高度、Inspector 内容顺序、文件列表和 diff 配色。
4. 再补可配置的历史代理折叠和更细的主题色调整。

这批修改的验收重点应是 20/30/45 列仍能读懂状态、名字和上下文，空白不触发导航，diff 首屏可见实际修改，且不破坏一行状态栏、键鼠透传及用户自定义配色。
