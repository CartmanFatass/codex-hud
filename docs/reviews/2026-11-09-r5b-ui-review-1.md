## Major findings

### 1. Stale jobs still acquire a running glyph and live clock in the Timeline

**`src/render/monitor-timeline.ts:274–279,309–331` — Major.** The effective-status handling added to `monitor-labels.ts` does not cover timeline entries: an `agent-started` event unconditionally becomes a running entry, with a running glyph, clock face and `live: true`, irrespective of the job's current freshness/status.

**Failing scenario:** Feed a stale job with `node.status: 'unknown'`, a recorded `createdAt`, and no finish event through the real `observedEntries(node)` → `WorkbenchHistory.timeline(...)` → `renderMonitor(...)` path. At 56 columns the Timeline displays:

```text
│  5m ├─▸ Fix parser recovery                          ◷
```

The Agents row correctly displays unknown, but switching panes makes the same uncorroborated job look live again. The current freshness tests supply neither timeline events nor agent logs, so their “anywhere” assertions miss this path.

**Suggested fix:** Make unresolved job timeline entries respect effective status/freshness; retain historical start evidence without claiming ongoing execution or drawing a live clock. Add an integration-style render test using the real history producer for stale, unavailable and unknown jobs. `monitor-timeline.ts` is unchanged and outside the implementer's listed files, so coordinate the required file ownership rather than silently extending it.

### 2. Native model labels override the required job task name

**`src/render/job-details.ts:104–106` — Major.** `shownNode` changes `name` but leaves `label` intact, after which `shownName(..., labelAsName)` / `agentTitle(..., labelAsName)` selects the native/model label instead of `job.name`.

**Failing scenario:** An enriched native node carries `job.name: 'Fix parser recovery'` and `label: 'OLD MODEL LABEL'`, with `labelAsName: true`. Real compact rendering displays `▸ OLD MODEL LABEL`; rich rendering with original-name display disabled does the same. The job's task label disappears despite ample width. The Inspector heading has the same precedence problem. Existing fixtures never give the job-bearing node a model label.

**Suggested fix:** Give `job.name` explicit display precedence over native/model labels at job-aware title call sites, while preserving native label/name facts separately in the Inspector. Test enriched nodes with labels-as-names enabled in both layouts and the Inspector.

### 3. Native timestamps can immediately expire a newly completed job

**`src/render/panel-state.ts:87–90`; `src/render/monitor-labels.ts:289–290` — Major.** The status comes from the job, but expiry and displayed completion age still prefer the native node's timestamps over the job's evidence time.

**Failing scenario:** Compose an exact-ref enrichment with native `statusAt`/`lastEventAt` one hour old and a completed job whose `freshness.evidenceAt` is ten seconds old. With a three-minute linger window, the real `composeJobTree` result returns `isExpired(...) === true`; `renderMonitor` shows `⊕ 1 finished` and no job row. With history shown, its completion age is also taken from the old native event. This can occur when native evidence lags a facade invocation/continuation. The new expiry test covers facade-only nodes, not enriched ones.

**Suggested fix:** Choose timestamps consistent with the effective job status when a node carries `job`; retain the existing timestamp precedence unchanged for nodes without it. Apply the same policy to expiry and card/Inspector completion ages, and add an exact-ref enriched-node regression test.

## Minor findings

### 4. Missing backend values silently fall back to observed native model/effort

**`src/render/job-details.ts:110–113` — Minor.** `badgeOf` falls back field-by-field to `node.model`/`node.effort` even for a job whose binding explicitly has null model/effort, contrary to the rule that row badges show backend binding and observed values appear only in the Inspector.

**Failing scenario:** An enriched node has `job.backend.model: null`, `job.backend.effort: null`, and native/observed `gpt-6.1-sol` / `max`. Both real compact and rich renderers show `imp 6.1sol·max` in the row, silently presenting observed settings in the binding slot. The current observed-model test checks only the Inspector and uses a fully populated binding.

**Suggested fix:** Use native badge fallback only when there is no `job`; for job-bearing nodes, leave missing binding fields absent and show observed differences in the existing Inspector section. Test null and partially populated bindings on enriched nodes.
