# Milestone review: workflow engine with batch, prewalk, council and land templates (2026-11-25)

Reviewer job j5178ecd2a6689c49 (astra high). Brief: tmp/tasks/review-engine/brief.md. Commits: 4dbb54ab (workflow/01), 850f26ac (workflow/03), 825b98b5 (workflow/02), f9237e4d (workflow/04).

Verdict: changes-required

Four fixes are needed. The detached council addresses the original orphaned-parent problem. No reachable null council pane at the flagged call and no permanently held main-checkout lease after host SIGKILL.

## Spec

1. **Major — an orderly MCP restart cancels an accepted prewalk.** Closing the MCP transport calls `stop` (`packages/hud-mcp/bin/hud-mcp.mjs:78–82`). That reaches `shutdownInline`, which aborts the same controller used for an explicit job stop (`src/mcp/mcp/server.ts:282`; `src/workflows/inline.ts:20–22`). Prewalk treats that signal as cancellation, writes the reserved target as stopped, and never launches it (`src/mcp/prewalk-flow.ts:83–88`; `src/mcp/dispatch/orchestrator.ts:309–312`). The watcher adopts only *working* runs. Killing the MCP with SIGKILL works, as tested, but disconnecting and restarting it normally while scouts run loses the dispatch. Separate host retirement from user stop: leave the cursor, scout jobs and reserved target adoptable on disconnect. Verify with stdin close during a live scout, not just SIGKILL.

2. **Major — prewalk can silently change a fixed-batch member's confirmed preset.** Batch submission freezes a preset per item and chooses a pilot per preset (`src/mcp/batch.ts:120–138`; contract: `docs/reference.md:193–195`). Ordinary member launch deliberately disables the even-pool planner (`src/mcp/dispatch/orchestrator.ts:610–618`). But an imp batch with shared `scouts` launches its targets through `launchReservedJob`, which reconstructs that planner for an even route without checking `base.batch_flow` (`src/mcp/dispatch/orchestrator.ts:303–305,1118–1120`). A pre-input quota refusal can then replace the candidate list with a different preset at `:1207–1208`. A pilot can succeed on B while the index credits A; retry-failed can likewise run somewhere other than the snapshotted placement. Preserve the pinned-member restriction in the reserved launch path. A two-preset imp batch with a refused scouted pilot should report that failure, not rotate presets.

**Scope and the four migrations.** All four use the common elected driver, DAG advance and commit-before-effect boundary (`src/workflows/driver.ts:27–56`). Execution adapters are added per template; no model coordinator or new resident scheduler. Batch retains one-call submission, whole-batch controls, indexed item results and folded notices. Admission runs under the shared concurrency lock, refuses queued-work bypass and counts members across batches against cap minus two (`src/mcp/dispatch/orchestrator.ts:132–140,677–685,827–834`). Direct and queued prewalks use the reserved target; keyed scouts and the persisted target place prevent a second launch on adoption (`src/mcp/dispatch/orchestrator.ts:269–283,960,1096–1102`; `src/mcp/job-step.ts:11–20`).

Council keeps the parent `j…` result, quorum, per-seat receipts and main synthesis by default (`packages/hud-mcp/roles/council.json:6`; `src/mcp/dispatch/council.ts:103–128`). It reserves the fresh one-time grant before publication; an ambiguous recovered launch is not refunded (`src/mcp/dispatch/orchestrator.ts:576–593`; `src/mcp/council-step.ts:36–54`). Land wraps the existing transaction whole, preserves `f…[-n]`, gate sidecars and terminal notice transport, and bounds worker repairs at two independently of base moves (`src/mcp/land-workflow.ts:23–29`; `src/mcp/land-runner.ts:167–187,510–519`; `src/workflows/engine.ts:30`). Recovery binds repair evidence rather than dispatching a repair or replaying Git (`src/mcp/land-state.ts:88–115`).

No deferred public feature found. Graph-shape validation and cost recording are workflow/01 requirements, not a main-composed graph API. The council grant is not a graph grant. The ticket queue still calls `startLand` from its own runner; no lead session or `Assumed:` policy was introduced.

## Simplicity and quality

3. **Major — even a known pre-update Git refusal can make a job permanently unlandable.** `src/mcp/land-runner.ts:341–350` writes `publish_pending` before `git merge --ff-only` and clears it only on success. If Git returns an error without updating the checkout (for example it cannot acquire the main index lock), `fail` persists the marker (`:401–407`). Even after the obstruction is removed, `retryableLand` rejects that receipt and `hud_land` returns it forever (`src/mcp/land-state.ts:40`; `src/mcp/land.ts:33–37`). That is broader than the documented exception for an *unknown* fast-forward (`docs/reference.md:422–424`). On a witnessed refusal, distinguish a provably unchanged checkout from an ambiguous result. Keep the interlock on host death, timeout or uncertainty; do not clear it on every Git error. Test both the refused-merge/new-attempt case and the unknown-result/no-new-attempt case.

4. **Major — the compatibility land bootstrap says "ready" to an old caller but cannot execute its receipt.** `packages/hud-mcp/bin/land-runner.mjs:1–2` imports the new bootstrap, which sends `ready` after loading `runLandWorkflow` (`packages/hud-mcp/bin/workflow-runner.mjs:3–7`). A still-running pre-upgrade ticket queue has the previous `startLand` in memory (`packages/hud-mcp/bin/ticket-queue-runner.mjs:3–4`; `src/mcp/ticket-queue-runner.ts:15,147`). That caller forks this compatibility path, publishes a legacy queued receipt without `workflow`, and sends permission (`f9237e4d^:src/mcp/land.ts:43–61`). The new listener returns without doing anything (`src/mcp/land-workflow.ts:13–16`). The queue sees an exited land helper instead of its result. Honor that freshly launched legacy IPC protocol, fenced to the designated live helper, or explicitly negotiate an incompatible generation before reporting ready. Do not make general recovery of legacy Git effects replayable.

**Requested risk checks.** `pane!` at `src/mcp/dispatch/orchestrator.ts:601` is the calling main's pane, not the member's tab. The `herdrId` type guard at `:560` rejects a missing ID before reservation. A closed tab can leave a stale string, not null; the detached council collects member status/report files, not pane handles (`src/mcp/dispatch/child-report.ts:14–25`). The assertion can be deleted without adding another runtime guard.

Land obtains the checkout lease before boarding. Compatible queued candidates are sorted by creation time then flow ID, rechecked while boarding, and cherry-picked in that order (`src/mcp/land-runner.ts:200–215,410–437,453–470,501–505`). A boarded passenger does not start another Git transaction. This is ordering within a train, not a FIFO guarantee for all lease contenders or singles after a red train. The lease records the detached helper's PID and start stamp; the next acquirer checks liveness and replaces a dead holder's record (`src/roles/lease.ts:66–84`; `src/collectors/thin-jobs.ts:405–409`; `src/roles/worker-tree.ts:28–35`). SIGKILL does not need a `finally` to make the lease available again.

## Optional — not part of the verdict

- **Lease expiry is not child-process cleanup.** Gate/after commands are spawned in separate process groups, with the timeout enforced by a timer in the helper (`src/mcp/land-runner.ts:31–52,154–159`). Killing the helper can leave the command running after the lease becomes reclaimable. Predates the migration. The kill test releases the gate's sentinel before retrying (`tests/unit/workflow-land-recovery.test.mjs:32–46`); it is not evidence that the orphan command was terminated. Track separately, particularly for `after` commands operating in main.
- **Narrow pre-publication crash window.** Council and prewalk publish a working public job before its adoptable workflow header (`src/mcp/dispatch/orchestrator.ts:590–602,944–960`; `src/mcp/prewalk-flow.ts:37–44`). A kill between those writes can leave a working job with no flow to adopt. A reconciliation test at this boundary would be useful.
- **Delete duplicated launch logic, not the sealed land transaction.** The direct and reserved launch loops independently assemble attempts, handle quota/fallback, persist the job and finish dispatch (`src/mcp/dispatch/orchestrator.ts:843–934,1125–1214`); finding 2 is a concrete example of policy drift between them. Share the attempt/fallback decision while leaving admission, task creation and caller-specific hooks outside it.
