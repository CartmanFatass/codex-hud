## spec

1. PANEL-V2 07 silently drops pending acceptance work. `src/render/html-board.ts:167` truncates the To-try section to the newest 12 slices even though `.scratch/panel-v2/spec.md` §7 asks for all To-try slices. Once the ledger has 13 pending items, the progress count includes 13 but the oldest has no card or acceptance steps in the export. `src/collectors/project-board.ts:378–385` likewise populates diff bars only for those first 12. Smallest fix: render every To-try row in the export and collect its commit diff with bounded concurrency in the one-shot exporter. Keep the terminal refresh budget and the 12-files-per-diff cap.

2. PANEL-V2 07 can export another project's job details and questions. `src/cli/board.ts:109` passes the selected project to `readThinJobs`, but `src/collectors/thin-jobs.ts:383–390` filters receipts only by pane. The panel also passes its full Home workboard even when exporting a different Project (`src/tree-page.ts:1195`). `src/render/html-board.ts:157–175` then exports every live worker and open question from that workboard without checking project membership. An owner who runs jobs for projects A and B from one pane can export B's question into A's HTML. Smallest fix: in the common export path, intersect workboard entries with the collected project's active job IDs, using the existing project membership check at `src/collectors/project-board.ts:403–412`, which already includes managed worktrees. Keep caller-pane scoping. Add a two-project, one-pane test.

3. PANEL-V2 03's Progress filter can report a matching slice by role and then show no match in Split. `src/render/filter.ts:53–57` keeps the matching worktree metadata but removes the corresponding ledger row if the role is not also in the ledger text. Split builds selectable slice rows only from the ledger (`src/render/split-project.ts:85–99`). For example, a working slice `build-feature` whose attached job is `frontend-imp` but whose ledger text just says “add the feature” gives `1 match` and no selectable row for `/frontend-imp`. Smallest fix: match a ledger row against its joined slice/job role before filtering, and count each joined slice once. Cover a joined role match, not just an unsliced-job role match.

Documented non-blocking deviation: PANEL-V2 01 uses `r` then `1`–`4`/`d` (`src/render/job-actions.ts:49–75`), not the literal single key on an expanded question in `docs/spec.md` §2.2. This avoids accidental irreversible answers from tab keys and is pending the owner's decision, as directed by the brief. No other blocking scope creep identified.

## simplicity and quality

1. MCP-NEXT 07 can delete a nested Git repository, including commits not in the parent, while reporting successful cleanup. `packages/hud-mcp/src/managed-worktree.ts:93–105` trusts an empty parent `git status` and unforced `git worktree remove`. Neither protects a nested `.git` inside a directory whose ordinary files are already tracked by the parent. In a temporary fixture I initialized such a repository in `vendor/`, made a nested-only commit, and restored the parent-visible file to its base content. The parent porcelain output was empty. The real `reapWorktree` returned `null` and the nested `.git` disappeared. On this result the watcher records `worktree_removed_at`, not `worktree_kept_reason` (`packages/hud-mcp/bin/hud-watch.mjs:184–189`). Smallest fix: before unlinking or removing anything, refuse a checkout containing any extra `.git` file or directory, via a bounded walk that doesn't follow symlinks and preserves the tree if the check cannot finish. Skip only the checkout's own top-level Git marker. Add this preservation case to the watcher tests and assert that the nested commit and temporary branch survive.

2. PANEL-V2 06 counts normal worker questions as quiet escalations. `src/collectors/control-radar.ts:127` counts every `waiting_orchestrator` state, but `packages/hud-mcp/src/cli-judge.ts:245–256` also sets that state for ordinary open questions, blocked input and supervisor problems. The radar tells an owner that a role is repeatedly going quiet when its workers are just asking normal questions; the count can then disappear when the question is answered. Smallest fix: count recorded quiet-decision evidence, not the general wait state. Test that an ordinary question does not increment the tally.

What can be deleted: `src/render/html-board.ts:174` need not check `workboard` a second time before mapping `workers`; line 157 already defaults the worker list to empty. Apply project scoping once to that list for both questions and In flight.
