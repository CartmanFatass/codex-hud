## Spec

### 1. Major — Project cycling is not wired into Codex's prefix commands

**`src/utils/workbench-input.ts:138–139`** — The new `[` / `]` shortcuts only name ordinary key input; there is no corresponding Codex panel command or tmux prefix binding.

**Failure scenario:** Open Project in the embedded Codex panel with several registered projects. Ordinary bracket input is forwarded to Codex while panel keyboard focus is off (`src/tree-page.ts:1254–1262`), and `Ctrl+\ [` / `Ctrl+\ ]` have no bindings in `bin/codex-hud-keys`. Consequently the advertised project-cycling shortcuts do not work on the normal Codex control path, although standalone tests pass. The Projects list remains an alternative, but does not implement the specified shortcuts.

**Suggested fix:** Add previous/next-project panel commands, monitor mappings, prefix bindings and appropriate closed-panel handling. Exercise the prefix-command path, not just the raw-key decoder.

Probe B returned:
```json
{"prev":false,"next":false,"plain":[{"type":"key","key":"project-next"}],"prefix":[]}
```

### 2. Major — Jobs from other sessions lose their task description

**`src/collectors/project-board.ts:364–367`** — An active job's title depends on the current panel's workboard or `job.json.title/task`, without reading the brief that actually carries a normal HUD job's task.

**Failure scenario:** Switch to another registered project whose running job was started by another main pane, with no explicit package label. `readThinJobs` restricts the panel's workboard to its caller pane, so that job has no `worker`; normal MCP-created `job.json` does not contain `title` or `task`. The collector correctly includes the job in `active`, but Progress displays only `◉ imp 20m`, despite a readable `brief.md` identifying the work. Multiple such jobs become indistinguishable. This misses feature-spec item 2's role plus sentence/detail requirement on an ordinary multi-project path.

**Suggested fix:** For included active jobs lacking a workboard description, obtain a short factual title from a bounded, signature-cached brief read. Keep this confined to full collection; no model request is needed.

Probe A used a normal-shaped job from another pane and returned:
```text
brief: # Build the Project tab
active: [{"jobId":"j0000000000000001","role":"imp","state":"working","at":1794485700000,"asking":false}]
rendered: [ '  ◉ imp                              20m' ]
```

Otherwise the hub/pages, lightweight project list and collector pool are in scope. Per orchestrator clarification q1, preserving the previously open page on `2` is approved and is **not** a finding.

### Optional — Minor, follow-up: jobs-only Progress cannot be paged with the keyboard

**`src/render/project-view.ts:311–314`** — Active-job rows have no `item`, while Project navigation moves only between rows with an item (`src/render/workboard-input.ts:137–138,171–174`).

**Failure scenario:** A project without STATE has enough active jobs to exceed a short panel. Down, PgDn and End cannot move its viewport at all, leaving later jobs accessible only by mouse wheel. Probe C rendered 12 jobs in a 40×12 panel; after all three keys it returned:
```json
{"rows":16,"viewport":10,"scroll":0,"unchanged":true}
```

**Suggested fix:** Give each active job a stable selectable row identity, or allow keyboard scrolling when there are no selectable rows. This crowded/short-panel display case is a non-blocking follow-up.
