## New work since 3280cc02

**JOB-RETENTION.** `packages/hud-mcp/bin/hud-watch.mjs:113-155` deletes a job directory only when its STATUS is
`closed`/`failed`/`stopped` and `reaped_at ?? settled_at ?? ended_at ?? STATUS mtime` is more than 24 h old. Open
states (`working`, `waiting*`, `idle_grace`, no STATUS with a live dispatch) return before the check, so an open job is
never deleted. The id regex plus `lstat` (not `stat`) keep the deletion inside `$HUD_HOME/jobs` and refuse a symlinked
job directory. `fs.rmSync(recursive)` does not follow symlinks, which is what makes SESSION-LINK safe: my probe deleted
a job dir containing `sessions/<link>.jsonl` and `sessions/<dirlink>` and the linked history and its directory survived.
A second probe ran the real watcher over an expired job with a linked session: the directory went, the history stayed,
`watch.log` recorded `delete … state=closed`, exit 0, no stderr. No new timer is added (the existing failed-retention
timer is unchanged), and the watcher still exits when nothing is open.

**SESSION-LINK.** `packages/hud-mcp/src/thin-main.ts:267` no longer passes `--session-dir` and no longer creates
`<job>/sessions`; `src/collectors/thin-jobs.ts:119-125` and `src/collectors/job-sentences.ts:53-58` realpath each
entry, stat the target and ignore dangling/non-regular targets, while still refusing a `sessions` directory that is
itself a symlink. The fresh `job-sentences` test links two real files, asserts the newest *target* mtime wins, that
`jobActivity` and the sentence input read the linked content, and that deleting the job dir leaves both files intact.
pi-roles (outside this repo, read only) creates the links in `dispatch.ts` from `sessionManager.getSessionFile()`, and
`27e2006` skips the link when an older launcher already put the file under `<task>/sessions`, so no self-link. The HUD
still reads a job's real in-dir session files from an old launcher (same code path), so the migration window is safe.

**PANEL-SCOPE.** `src/collectors/thin-jobs.ts:163-175` decides from STATUS alone (state + `settled_at`/`ended_at`/
mtime) before `job.json`, and `:214` repeats the check on the computed `settledAt` before any brief/report/qa/session
read; active/unknown states bypass both. `src/tree-page.ts:127,205,506,527` threads the panel's `openedAt` into the
pipeline, and `:878` carries it through every restart; `src/utils/panel-reload.ts:13` gives a legacy handoff the
consumption time. The fresh `panel-scope` tests exercise the real pipeline and renderer: five terminal states settled
before open stay out even with `show-all`, legacy fallbacks (receipt-only dispatch failure, missing STATUS) obey the
boundary, and a patched-`fs` test shows zero artifact reads and zero sentence/title/label/ranking/brief requests for an
excluded job with a positive control on the admitted one. `panel-reload` asserts `openedAt` is identical across two
real replacements. The bar's own `settledBefore` cutoff is unchanged (its test still passes).

**M4-FIX2 / M4-PRUNE2.** The reload place/width and brief-continuity behaviour are fixed with real tests (above). The
