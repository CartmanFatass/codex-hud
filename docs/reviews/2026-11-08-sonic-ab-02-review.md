## Findings

### 1. D — major: the headings expression cannot execute

**`<arm D>/src/jev/runtime/executor.ts:865`** — `HEADINGS_EXPRESSION` ends with `}))))()`, with one extra closing parenthesis.

**Failure scenario:** a real page contains a visible `h1` such as “Example Domain” → `Browser.evaluate` encounters a syntax exception → `evaluatedHeadings` catches it and returns `[]` → the judge never receives any heading facts. This fails the central heading-collection requirement on every page, not just an edge case.

The authorized read-only probe compiled the exact exported, built expression with `new vm.Script(expression)` and got **`SyntaxError: Unexpected token ')'`**. Running the actual observer with an evaluator that executes that string produced `facts.headings: []`.

**Suggested fix:** remove the extra `)`; the ending should be `})))()`. Add a test that compiles and executes the exact supplied expression against a synthetic DOM stub. The current expression-text assertions at `tests/unit/jev-judge-structure.test.ts:146–156` do not establish that it is valid JavaScript.

**Report discrepancy:** `report-D.md` shows a balanced expression, but that is not the string generated by the submitted code. Its green test counts are reproducible; successful real heading collection is not.

### 2. B — minor: heading text is unbounded across the evaluate/CDP boundary

**`<arm B>/src/jev/runtime/executor.ts:878–880`** — the expression pushes the full normalized heading text; the 200-character cap is applied only after evaluate returns, at line 899.

**Failure scenario:** a visible heading contains a very large text node → the browser serializes and sends the entire string over CDP, and Node parses it, before retaining only 200 characters. The synthetic probe returned a **5,000-character** heading from B's actual expression, versus **200** from A and C. The final judge request is correctly bounded, so this is not a claim that oversized text reaches the model.

**Suggested fix:** apply `.slice(0, MAX_HEADING_CHARS)` inside the expression before pushing the text, retaining the defensive host-side cap. Test the expression-side bound as well as the normalizer.

**Report discrepancy:** the source comment says the expression “stops at the bounds” and repeats them below. Only the entry-count bound is present in the expression.

### 3. A — minor: the required existing browser/CDP fake is not reused

**Suggested fix:** wrap the existing `fakeBrowser`, overriding `observe` and adding/removing `evaluate` for these cases, as C does. Keep the runtime-job integration assertions.

### 4. B — minor: the required existing browser/CDP fake is not reused

**`<arm B>/tests/unit/jev-judge-structure.test.ts:78`** — `structureBrowser` duplicates the browser stand-in instead of using an existing fake helper.

**Failure scenario:** the tests use their own browser implementation, and its evaluator at line 100 ignores the supplied expression entirely. The suite can remain green when the expression or its invocation changes incorrectly; it also does not enforce the requested single headings-evaluate call.

**Suggested fix:** wrap the existing fake, capture the expression/call count, and assert one headings evaluation per observation. Preserve the current action and provider-forwarding assertions.

### 5. C — minor: the provider-forwarding test has a load-sensitive 50 ms deadline

**`<arm C>/tests/unit/jev-judge-structure.test.ts:137`** — this functional test uses `awaitStates`' real clock with `maxMs: 50`.

**Failure scenario:** the test process is descheduled for at least 50 ms during its first observation or stabilization poll → `awaitStates` exhausts the stable-page budget before calling the fake provider → a correct implementation reports `timeout` and the test fails. This did **not** occur in my prescribed runs.

**Suggested fix:** inject deterministic `now`/`sleep` functions through the existing `AwaitStateOptions`, or use a substantially less aggressive deadline. This is nonblocking for the implementation recommendation.

### 6. D — minor: the required existing browser/CDP fake is not reused

**`<arm D>/tests/unit/jev-judge-structure.test.ts:45`** — the file declares its own `fakeBrowser` rather than reusing an existing fake helper.

**Failure scenario:** its evaluator returns the configured headings without executing the expression, so the focused tests exercise an invented successful evaluate response even though the submitted expression always fails. The actual syntax defect is finding 1; this finding records the separate brief requirement to reuse the existing fake infrastructure.

**Suggested fix:** wrap the existing fake and add an evaluator that executes the exact expression against synthetic heading nodes for the collection test. No real browser or network is necessary.
