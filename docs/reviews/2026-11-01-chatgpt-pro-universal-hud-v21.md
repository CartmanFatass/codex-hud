2. 会导致返工的问题

身份协议未闭环。
问题： linkId 共现被当作确定身份。为什么： 工具结果与历史可被复制或继承；resume 的注入消息也不是会话首条消息；环境失效后，whoami 未定义可用的调用者上下文。建议改法： 明确调用者注册与绑定握手，用 linkId、runId、角色、调用 ID 关联，经启动回执或受验证的会话证据确认 SessionRef；无法确认保持 pending。transcript 只承担约定范围内的核验。影响章节： §6.6–6.7、7、16.5。

原子文件不足以支持控制账本。
问题： 多个 MCP 无锁修改同一 JSON，request_key 又可选。为什么： rename 防半文件，不防父追加 run 与子 report 相互覆盖；“启动成功、写回前崩溃”还会导致重复启动。建议改法： 用事务存储、带调用者范围的唯一幂等键及参数摘要；spawn/resume 先提交启动意图，再执行、对账。结果不明标 uncertain，禁止盲重试；SQLite 也不能自动保证外部动作恰好一次。影响章节： §6.6、6.11、13、16.2。

resume 缺少运行隔离。
问题： 关系进入 reported 后如何重跑未定义，report/wait 只指 linkId，“打开”直接 resume。为什么： 旧报告可能满足新等待；活跃 headless 被打开可能产生第二个执行者。建议改法： 关系、run、报告分别建模；报告与等待带 runId/事件序号。每 SessionRef 只允许一个受管写入 run；活跃时看日志，确认结束后才 resume；未知存活不能视为结束。影响章节： §4、6.6、6.8、10、13。

没有明确的运行托管者。
问题： stdio MCP 退出后谁保存退出码、取消任务未定义，控制操作仍依赖 pane。为什么： 进程消失不能还原退出结果，关闭 tab 也不能作为通用取消协议。建议改法： 用独立的每-run 包装进程管理日志、退出回执与取消，定义父断连策略；控制接口操作 RunHandle。最小 status/cancel 前移至 B；ask 尚未实现时保留明确旧通道。影响章节： §6.2、6.6、6.12、8、13。

Jev 锁与资源范围不一致。
问题： §5.3 要求共享浏览器串行，§6.6 却按账号锁，§8 还保留直接 CLI。为什么： 不同账号及 CLI 可绕过同一浏览器的互斥。建议改法： 按实际浏览器实例锁定，所有入口共用协调；做不到就禁止混用。发送前持久化 key，发送结果未知及人工介入都须先核对再释放资源。影响章节： §5.3、6.6、7.4、8、13C。

3. §16 八项抉择
项	明确建议与理由
1 等待	有界长轮询，推送只作提示。 wait 按 runId＋事件游标读取持久结果；超时不改变任务状态。120 秒按客户端实测设上限，不依赖向父 pane 注入文本。
2 存储	SQLite。 多写者、幂等索引与历史更新需要事务；JSON 保留为导出。坚持 JSON 就必须接受锁、版本校验与恢复协议。
3 resume	同一任务、同一所有者复用 linkId，新增 runId。 换任务或所有者新建关系；复用会话不等于复用委派。
4 headless	只在 HUD 呈现。 隐藏 tab 增加宿主依赖；活跃时查看，结束后续跑，不能无条件“打开即 resume”。
5 身份	现有路径不足。 daemon/env 及多会话隔离探针前移至 A 定型之前；绑定握手无法成立的路径暂不支持。
6 路由外发	共用检查实现，单独授权目的与接收方。 摘要授权不自动覆盖路由；未授权关闭远程建议。auto 执行权限、预算另算。
7 切换	两者都要。 功能与基准达标后 opt-in 试用，再可回滚地切默认；两周只是观察窗口，不能代替故障标准。
8 Herdr 边界	保留注册表、宿主、运行控制三职责。 输入/取消归运行控制，聚焦/按键归宿主；用 RunHandle 隔离 pane。降级仅限确定尚未执行的启动，超时后先对账，避免重复任务。
4. 建议删掉或推迟的内容

取消“所有会话均能任意模式 resume”的保证，改为已验证能力矩阵。B先覆盖 Herdr、tmux 各一种可见布局，加 headless 及结束后的 resume；其余 tab/split 组合后补。通用 ask/send 可推迟；最小取消、退出回执、多消费者所需采集租约，以及验收场景所需的面板入口必须在 B，不能等 D/E。

5. Astra 评审有误或采纳不当之处

没有依据判定其本机核实结论错误；有两处采纳失真。

Astra §2.2 的原子 JSON 建议被扩成多 MCP“无锁”账本，而其 §2.6 已指出 rename 不能防丢更新。
Astra §3.3 的“无需全局 daemon”针对采集/statusline，不能推导出委派任务无需托管和恢复。每-run 包装进程即可满足，两者不矛盾。
