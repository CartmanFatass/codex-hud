## Findings

### 1. Major — a recovered task directory never restores its cached worker or fresh calls

**`src/collectors/task-observations.ts:573–586`**, together with the projection fast path at **`:373`** — directory-read failure directly removes workers and marks the published calls stale, but neither that transition nor successful directory revalidation marks the source dirty.

**Failure scenario:** Warm a safe task containing a valid working primary STATUS and `review-1.md` with `Verdict: accept`. Make the task directory unreadable, refresh, restore its permissions, then refresh forty times without changing the files. Through the production `PanelJobPipeline`, the results are:

| State | Workers | Review stale | Coverage incomplete | Diagnostics |
|---|---:|---|---|---|
| Before outage | 1 | false | false | none |
| Directory unreadable | 0 | true | true | unreadable/pending/source-unavailable |
| Permissions restored | **0** | **true** | **false** | **none** |

The body-cache hits never set `source.dirty`, so `project()` keeps returning early. The worker stays absent and its calls stay stale indefinitely until an unrelated artifact changes, despite complete coverage. This violates the source-outage/recovery contract and is not covered by the existing individual-file and nested-QA recovery tests.

**Suggested fix:** Track directory availability as a projection dependency and invalidate/revalidate the retained reduction on outage and recovery. Restore worker/call facts only after safe validation, and add a real-pipeline whole-task-directory permission-outage/recovery regression with unchanged file bodies.

## Non-blocking

### 2. Minor — clicking the Home activation hint expands the decision instead of opening Work

**`src/render/home-view.ts:86`; `src/render/workboard-input.ts:129–132`** — the `Enter: open in Work` hint has an ordinary target row but no activation hitbox, so mouse input treats it as another click on the already-selected decision.

**Failure scenario:** Select a Home QA decision, render its activation hint, and click that hint. The panel remains on `mainTab: "home"` and adds the decision to `boardExpanded`; there are no `board-activate` controls. The plan §4.2 explicitly requires hint clicks to activate. Keyboard Enter still works, so this does not independently block acceptance.

**Suggested fix:** Give the hint a `board-activate` control and route it through the same Home-to-Work activation function as Enter. Test the visible hint's actual coordinates and resulting Work target.
