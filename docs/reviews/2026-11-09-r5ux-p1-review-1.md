## Findings

### 1. Major — completed-job probes bypass ancestor safety checks

**`src/collectors/job-observations.ts:1053–1062`** — The new completed-observation fast path checks dependency leaves with `lstat`, but never revalidates their pinned ancestors before continuing to publish the cached job as current.

**Failure scenario:** Warm a completed Pi dispatch with a written report, rename the synthetic HUD home's `jobs` directory, and replace `jobs` with a symlink to the renamed directory. Thirty subsequent refreshes still return `freshness.state: "current"`, `status: "completed"`, complete coverage and no diagnostics. Leaf signatures do not change because `lstat` follows intermediate symlinks. Replacing an ancestor with a different real directory containing the same leaf inodes has the same underlying problem. This bypasses the plan §3 requirement to refuse symlink/replaced ancestors; the ordinary read path's `pinAncestors` protection no longer runs for these cached observations.

**Suggested fix:** Revalidate ancestor identities and no-symlink constraints within the bounded dependency-probe path, invalidating current eligibility on failure. Add a warm completed-job ancestor-replacement regression, not only a cold/read-path unsafe-file test.

### 2. Major — over-cap discovery permanently starves admitted lanes

**`src/collectors/task-observations.ts:419–429`** — Discovery repeatedly probes every unadmitted child before scheduling source work, even after the 200-source admission cap has been reached.

**Failure scenario:** With 270 immediate empty task directories, 300 refreshes admit 200 sources but project **zero lanes**. Each warm slice spends all 64 metadata probes retrying children that `admit()` will reject, so execution never reaches the round-robin source loop. The final slice has zero reads, enumerations and parses, with `lane_capacity` and `observation_pending`. A workspace exceeding the advertised resident bound therefore loses all task visibility rather than showing bounded, partial results.

**Suggested fix:** Give discovery its own persistent bounded cursor/reservation and stop probing nonadmissible children at capacity, preserving a source-processing share. Add an over-capacity fixture; the existing 45-directory fairness test does not exercise this case.

### 3. Major — partial QA refresh publishes a mixed-revision decision

**`src/collectors/task-observations.ts:320–325, 495–504`** — Each successful file read mutates the published file cache and immediately reprojects a question/answer pair, without requiring a coherent pair revision or marking an unfinished update pending.

**Failure scenario:** Begin with options `A) Keep`, `B) Remove`, default A and answer A. Rewrite both files to options `A) Remove`, `B) Keep`, default B and answer B. With a one-file slice, the first refresh combines the new answer with the old question and publishes `departure: true` with `coverage.incomplete: false`; the next refresh corrects it to false. The owner temporarily sees a fabricated `≠` call even though both actual revisions chose their respective default. The same boundary can occur when the normal slice is exhausted by other files. This directly violates plan §3's coherent-source/partial-QA-pair rule.

**Suggested fix:** Stage changed pair members and commit their reduction only after validating both dependencies together; retain the previous coherent reduction as pending/stale during deferral. Test snapshots between individual reads, not just the eventual warmed result.

### 4. Major — missing end time suppresses a terminal human-required job

**`src/collectors/job-observations.ts:620–630`** — Both runtime termination and Home needs-human eligibility incorrectly require a valid `run.endedAt`, conflating termination evidence with its optional display clock.

**Failure scenario:** A validated Jev record with `state: "completed"`, result `{status: "needs_human"}` and no end timestamp produces a completed worker with `homeNeedsHuman: false`. Through the real pipeline, coverage is complete and Home displays **“nothing needs you.”** The binding source/degradation table explicitly says a missing end time omits the waited age; it does not authorize dropping the human-required item.

**Suggested fix:** Derive termination from the validated terminal runtime state/result and retain a nullable end time independently. Cover completed ask and ended judge needs-human records without an end clock while continuing to exclude running records.

### 5. Major — the older-today fold traps keyboard navigation

**`src/render/workboard-input.ts:178–195`** — Navigation encounters `fold:older`, expands it, and returns without advancing the selected target, so the next Down operation encounters the same fold again.

**Failure scenario:** Home contains a recent q1 call followed by an older-today q2 call. Repeated Down presses expand `fold:older` but keep q1 selected indefinitely; neither the older call nor the subsequent lane/worker rows are reachable by normal Down navigation. This breaks the approved fold navigation and Home-to-Work hand-off for those calls.

**Suggested fix:** Represent fold rows as selectable navigation anchors, or explicitly advance past an already-open fold while retaining a usable collapse action. Add sequential keyboard tests covering recent → fold → old call → lane and the reverse path.

### 6. Major — a failed QA-directory read leaves retained calls fresh

**`src/collectors/task-observations.ts:474–479`** — A null QA membership result becomes an empty question list without marking previously cached QA files or their reductions stale.

**Failure scenario:** Warm two QA decisions, then make their `qa` directory unreadable. After thirty refreshes, coverage correctly reports `unreadable_directory`, but both retained decisions still have `stale: false`. A replaced/unsafe QA ancestor takes this same branch. The last-good calls therefore remain individually certified as current even though their source cannot be verified, contrary to the stated last-good-as-stale contract. Only failure of the task directory itself gets the explicit stale treatment above this code.

**Suggested fix:** On QA membership failure, mark affected cached evidence/reductions stale and retain the failure until successful revalidation. Add nested-directory outage/replacement and recovery tests alongside the existing individual-answer chmod test.

### 7. Minor — wide Home can lose the selected progress-row cursor

**`src/render/home-view.ts:83–87`; `src/render/work-view.ts:322–324`** — Wide rows preserve the right-column target only as a mouse control when the left column has an item, but selection painting tests only `row.item`.

**Failure scenario:** At 110 columns with a recent decision in lane SYN and another lane ZZZ, selecting ZZZ leaves the correct `homeTarget` but renders **no cursor anywhere**. With one lane and a blank left-column item, the cursor instead appears on the unrelated left-side “recorded calls” heading. Mouse hit-testing and reveal can find the right-column control, but visible selection does not follow it.

**Suggested fix:** Preserve per-column target/selection geometry and paint the selected right-column lane itself, rather than treating the merged physical row as one left-anchored item. Test right-column selection while both columns contain content.
