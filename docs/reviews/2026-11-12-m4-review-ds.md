## Axis 2 — simplicity, quality and cost

### 1. A malformed `hud-settings.json` or `config.json` now stops the panel from opening, and kills an open panel when `,` is pressed

**Severity: major** — `src/cli/panel-pane.ts:76`; `src/tree-page.ts:1301–1302`; `src/settings.ts:207–209,214`.

`loadSettings()` now also reads and validates `$HUD_HOME/config.json` (`resolveDecisions(readHudConfig(...))`) and throws on a JSON error or an invalid `decisions.primary`/`decisions.fallback`; it already threw on a malformed `hud-settings.json`. Two new callers do not catch:

- `openPanelPane` defaults `width = loadSettings(env).treeWidth`. With `HERDR_PANE_ID` set (every Claude/pi pane), `hud panel` and pi's `/hud` throw before creating the split. `src/cli/hud.ts` maps that to `internal_or_output_failure` and exit 1: the panel simply does not open. Before this milestone `openPanelPane` used `width = 56` and never read settings.
- The Settings-open path calls `loadSettings()` and `decisionKeys(readHudCredentials())` inside `processInput`. `readHudCredentials` throws `jev_env_perms` for a `credentials.env` that is not exactly 0600 (a hand-created file is 0644 by default), and `loadSettings` throws as above. The exception escapes the input handler (`withInputRefresh` only has a `finally`), so the panel process dies and leaves the terminal in the alternate screen/raw mode.

The owner is told to hand-edit both files: the Settings help says "edit model in hud-settings.json for another ID", and `config.json` is required for the Jev locations. A typo is a normal editing mistake, and the failure is total (no panel, or a dead panel). `saveSettings` also calls `loadSettings()` (`:214`), so every Settings save fails while either file is malformed.

**Smallest fix:** wrap the width read in `openPanelPane` and the two reads at `tree-page.ts:1301–1302` in `try/catch` (fall back to `DEFAULT_WIDTH` / the already-loaded `settings` / `undefined` keys), and make `loadSettings` degrade `decisionApi` to the default when `config.json` is unreadable or its `decisions` values are invalid.

### 2. The Recommended-mode progress brief is silently rejected when the model ends its reply with a newline

**Severity: major** — `src/collectors/home-recommendation.ts:99`.

`validateResponse: (text) => !!text.trim() && text.length <= 600 && !/[\n\r{}]/.test(text)` runs on the raw completion: `SmallModel.request` calls `validFormat` on `completionText(json)` before `cleanOutput` trims it (`src/collectors/small-model.ts:763`). A reply `"The build finished. A layout question waits on the owner.\n"` therefore fails as `Invalid response`, and `summarize` never sets `row.brief`. The owner sees Recommended ordering but no brief, with no error (by design), so the second half of HOME-RECOMMEND silently does not work for any model that adds a trailing newline.

**Smallest fix:** test the trimmed text in `validateResponse` (`const t = text.trim(); return !!t && t.length <= 600 && !/[\n\r{}]/.test(t)`), or let `cleanOutput` run before validation.

### 3. The mjs suite is red on any host that is not in UTC (release gate)

**Severity: minor** — `tests/fixtures/kept-pages.mjs:12` and `tests/fixtures/project-page.mjs:12` (`NOW = Date.parse('2026-11-12T12:35:00Z')`, reused by `home-progress.mjs`); rendered with local dates (`src/render/work-view.ts:203` "done today", `src/render/project-view.ts:112–118` "updated HH:MM").

On this host (TZ=PST) `npm run test:mjs` fails 8 tests in `kept-pages.test.mjs` (home/older/job/asking/decision frames: "2 done today" vs the fixture's "3"), `project-page.test.mjs` (frames + drift: "updated 04:35" vs "12:35") and `project-tickets.test.mjs` (frames). All pass with `TZ=UTC`. The product is right (the panel should show local time); the fixtures assume UTC. Ticket 05 requires "full test suite green", so the release check must pin `TZ=UTC` (or the fixtures must build their timestamps in local time).

**Smallest fix:** run the mjs tests with `TZ=UTC` in `package.json` (`test:mjs`) or set `process.env.TZ = 'UTC'` at the top of the fixture modules before any date is formatted.

### 5. `docs/reference.md` still describes the pre-CARD-HEIGHT card

### 6. `saveSettings` rewrites `config.json` on every save, even when the Decision API did not change

**Severity: minor** — `src/settings.ts:214–219`.

The Settings draft always carries `decisionApi`, so `patch.decisionApi !== undefined` on every save; the whole `config.json` is re-serialized (reformatted) even for a theme change, and a malformed `config.json` makes every save fail. **Smallest fix:** read the current primary first and write `config.json` only when `settings.decisionApi` differs.
