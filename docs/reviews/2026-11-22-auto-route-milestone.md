## Spec — blocking

1. **The owner cannot pin a job to a tab.** `src/roles/tool-definitions.ts:60` advertises only `mode: "headless"`; `src/mcp/thin-main.ts:1409–1415` rejects `"tab"`. `pickImpRoute` takes a boolean `explicitHeadless`, so even a direct call with `mode: "tab"` asks the API about mode before being rejected (`thin-main.ts:1784`, `src/mcp/imp-routing.ts:22–30`). Ticket 03's final decision, confirmed in review, covers **both** modes. Accept either explicit choice, ask only for the tier, and apply the continuability check only to headless.

2. **Non-general placement is still caller-controllable.** The four named fields are correctly rejected, but `placeOptions` accepts caller-supplied Pi model/effort flags in `pi_args`; `dispatchPi` appends them *after* the configured flags (`src/mcp/thin-main.ts:431–434,1439–1450,1519–1523`). The launcher preserves this order and Pi takes the last value. The receipt and quota attribution can therefore say the role-file model while another model runs. There is also a normal retry path to the same problem: retry a failed `general` job that had a one-job `model`, specifying `role: "reviewer"`. Validation inspects only the new input, then merges the old model into the new role (`thin-main.ts:1460–1469,1519–1536,1630–1634`). Reserve placement flags in **caller** Pi args for general, and don't transfer general's overrides when the caller changes roles. Neither fix requires changing owner role-file args or same-role retries.

3. **A selected `standard/headless` route can fail without trying the active preset in a tab.** `launchPlan` appends the standard/tab fallback only if `route.tier !== 'standard'` (`src/mcp/thin-main.ts:1658–1667`). For example, an active Pi place with a tab-valid `--session-dir` option is rejected for automatic headless at line 1448; admission returns that error at lines 1824–1831. The owner's active chain is available in a tab, but nothing launches. The same omission applies to a confirmed headless-only pre-input launch failure. Treat a change of **mode** on standard as a real fallback when mode wasn't explicit; never replay after input might have reached a worker.

4. **`g` opens the Inspector, but it discards Antigravity output.** The shipped light preset selects `agy`. Its stream uses `event` records (HUD itself reads `event === 'init'` in `src/mcp/sonic-process.ts:81–85`). `src/collectors/headless-output.ts:43–76` dispatches only on `event.type`; valid unrecognized JSON never takes the plain-text path. `src/render/work-inspector.ts:49–54` then says “No output yet” for a growing, nonempty log. This affects the shipped light/headless combination, not a hypothetical future harness. Handle Antigravity's activity records and distinguish zero bytes from a nonempty tail with no displayable lines.

5. **A headless CLI question requests a turn end but does not cause one.** For Claude and Antigravity, `hud_ask` snapshots the tree and returns an ordinary text tool result saying to end the turn (`src/worker/tools.ts:380–383`). The runner waits for the CLI to exit before reading the session ID and marking the question resumable (`src/mcp/sonic-process.ts:133–146,176–181`). The CLI can continue taking actions; an owner who answers while it is still running gets `worker_not_waiting` after 30 seconds (`src/mcp/thin-main.ts:2997–3007`). The fake CLI exits of its own accord after the ask, so it does not establish this contract. Arrange a harness/runner end-of-turn handoff that retains the native session, rather than relying on the model's next response. Pi already has an explicit end-of-turn hook.

**What matches / scope:** The tier-to-preset mappings, purposes and mode texts come from the winning role file. As clarified, `light`, `standard` and `hard` are fixed protocol keys, **not** configurable preset names. Standard resolves the active chain; missing tier keys are not offered; the decision reason uses the configured text without a second call. Initial and queued overflow borrow the general slot rather than general's chain. The `g` action and periodic recollection really are wired through the panel controller. Codex/Grok staying on tabs is intentional. No unrelated product expansion found.

## Simplicity and quality — blocking

1. **Unrouted headless workers stop at the first clean launch rejection.** Both launch loops break on `job.headless && !job.route` (`src/mcp/thin-main.ts:2048,2299`). A continuable general chain with Claude first and Pi second fails outright if Claude hasn't trusted the cwd, even though `dispatchCli` explicitly identifies that as pre-input (`thin-main.ts:718–722`) and Pi could run headless. Likewise the first candidate's mode-validation error ends unrouted admission instead of considering a later compatible place. Keep the one-shot exception for Sonic, not all headless jobs; share the compatible-place/pre-input fall-through rule between direct and queued creates.

2. **An expired follow-up to an overflow job loses its imp provenance.** Within `resume_s`, reopening uses `current.overflow_from ?? current.role` (`src/mcp/thin-main.ts:2477`). Outside it, `hud_send` calls `dispatchJob` with `jobOptions(current)` and a repair ID; those options contain `role: 'general'` but no imp origin (`thin-main.ts:1460–1469,2601–2603`). The imp-chain exception at lines 1724–1729 only recognizes a `retrySource`. A follow-up just after expiry can thus get general's instructions and model, not merely a new session. Carry the source launch role into the replacement, as the land-repair path already does.

3. **A symlinked `cwd` makes a valid headless Pi session unresumable.** `jobCwd` retains the caller's lexical path (`src/mcp/thin-main.ts:99–105`); the native header records the child process's physical cwd. `piSessionIdentity` compares the two strings literally (`src/mcp/worker-resume.ts:37–41`). On a question the watcher declares the job failed for a missing session (`src/runtime/watch-runtime.ts:352–355`); after a report a send can unnecessarily fork a repair. Compare canonical directory identities, keeping the session-ID and file checks.

**What can be deleted:** Remove the blanket headless break above instead of adding per-harness retry exceptions. The local `retrySource` shadow in `dispatchJob` just copies the already loaded `source`. The collector retains 40 parsed output lines for a sole consumer that takes 12; one shared display limit suffices. Keep the native identity checks and the prohibition on replay after uncertain input.
