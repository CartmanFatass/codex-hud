## Simplicity and quality

No blocker or major. Nothing to delete: the `dirty`/`attach` machinery in `watch.ts` is the minimum for an
event-driven watch with a rescan, the `turn.json` flag is the minimum for once-per-job across supervisors, and
`showQuiet` is two conditions.

### 1. Inspector still shows a settled job's last quiet decision — minor, follow-up

`src/render/work-inspector.ts:99` — `['quiet', quietDecisionSummary(worker.quietDecision)]` is unconditional, so a
job that got `still-working 92% → wait` and later settled still shows that row in the Inspector while its card
(`work-card.ts:150-152`) and the Home lane drop it. Failure: the Inspector says "still-working 92% → wait" for a job
whose state row says `closed · done`. Fix: reuse the same guard (`worker.settledAt === null || (failed &&
action === 'fail')`), or label the row as history.

### 2. Two docs the brief did not name still describe the pre-SUPERVISOR-08 supervisor — minor, follow-up

`docs/ARCHITECTURE.md:341` ("a dead supervisor fails the job") and `packages/hud-mcp/README.md:106-126` ("A
missing, empty or unchanged report fails the job"; "Herdr `idle` or `unknown` counts as an exit only when the agent
is gone"; "A mid-turn `blocked` status … sends one `[tag] BLOCKED: …` line"; "A dead supervisor fails the job
(`supervisor exited`) on the next check"). These contradict the new reference paragraph and `docs/spec.md` §2.
Failure: a developer or agent reading the architecture doc or the MCP README (which the reference links to) expects
a dead supervisor to fail the job and re-dispatches instead of `hud_send`. Pre-existing since 0.1.1 and outside the
brief's named files, so not counted against this round; fix with the same rewrite as `reference.md:149-163`.

## Optional (does not change the verdict)

- `hud_read`'s `observation()` (`thin-main.ts:731-765`) does not include `quiet_decision`, so after a failed report
  prompt the session's `reason` is the generic "quiet without a report; hud_send to continue or hud_close to stop";
  only the panel shows "prompt failed". Adding `quiet_decision`, or setting the judge's reason from
  `decision.reason`, would carry the cause to the session.
- `reference.md:95`, `reference.zh.md:108` and `releases/0.1.4.md:49` say the panel/statusline/pi footer/MCP/`hud
  watch` "read jobs through one reader". The panel, statusline and pi footer use `readThinJobs`; MCP and `hud
  watch` use `readThinJobRows`; they share `jobRow`, so the agreement claim holds, but it is two readers. "share one
  job-row reader" would be exact.
- `watch.ts:105-114` attaches the watch after the baseline scan, so a change between the baseline and the attach
  waits for the 30 s rescan; and when `$HUD_HOME/jobs` does not exist at start, the first job's line can wait up to
  30 s (the attach retries on the rescan). Attaching before the baseline scan (or treating a missing `jobs/` as
  `dirty`) closes both.
