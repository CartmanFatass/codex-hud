## Spec / plan — blocking

1. **perf-ts/06: MyHUD does not reuse its own tested TypeScript build.** `canPublishTestedBuild()` rejects any compiler input outside `src` or the recognized dependency roots (`src/mcp/land-build.ts:74–84`). MyHUD imports `scripts/dist-lock.d.mts` and `packages/hud-mcp/bin/agy-events.d.mts`; both appear in the actual main build info. Even for a clean, identical landed tree, the first such file makes the check false, so `after` invokes `npm run build` again. The land fixture uses a program without those imports. Compare the corresponding declaration inputs in the two checkouts and cover the real program shape; do not simply exclude declarations from verification.
2. **native-statusline/02: a Claude session with no pane displays other panes’ workers.** Previously `collectJobLanes()` returned no workers without a valid `HERDR_PANE_ID` (`src/collectors/job-snapshot.ts:76–84`). Now the compact TS path passes `null`, which selects `snapshot.global`; Rust makes the same choice (`src/cli/statusline.ts:166–174`, `src/collectors/work-summary-snapshot.ts:146`, `native/src/state.rs:372`). Open Claude outside herdr while another pane has a pending question: the line shows that pane’s `!1` while the snapshot is fresh and drops it when stale. Both renderers agreeing does not satisfy the **this pane** contract in `docs/reference.md:1150–1157`. Keep global counts for explicit global consumers; no pane should mean no worker zone here.
3. **perf-ts/05 regresses at the native-statusline/01 publication sites.** A normal `hud_respond({answers: [...]})` calls `respondJob(item, true)` without the shared receipts for every item. Each successful ordinary answer calls `publishWorkSummary(undefined)`, which walks all job IDs and reads their facts *before* deciding whether a write is necessary (`src/mcp/thin-main.ts:2866–2878, 3020–3023`; `src/collectors/work-summary-snapshot.ts:87–96, 199`). Four answers can therefore cause four extra full census passes in one call. Coalesce the display publication or reuse the updated call scan. A fresh check for dispatch admission is a separate correctness requirement and should stay.
4. **native-statusline/02: byte parity already differs for a recognized model.** For a Claude payload with a GLM model ID and a coloured `line` or `p10k` look, Rust assigns the `ℤ` mark ANSI colour 69 (`native/src/render.rs:399–400`); the shipped TS catalogue deliberately has no colour for `zai` (`src/models/models-catalog.json:59`, `src/render/layout/bar-fields.ts:1074–1081`). The same stdin changes bytes when the binary falls back. Match the optional mark colour or decline this case, and add it to the differential fixtures.

**Other rows and scope:** No blocking plan finding for perf-ts/01–04 or /07: the foreground handoff, harness-specific finder, caps, reload/drain, unchanged-tick paths and guarded worktree reap are present. /08 implements the ordinary-file EXP cache, with the invalidation defect below. DF-23 verifies source and binary hashes on the native handoff and has a successful no-Cargo path with a land note; that does not fix the separate TS reuse issue. No Rust panel, watcher or MCP, test-concurrency change, or Antigravity migration was introduced.

## Simplicity and quality — blocking

1. **Snapshot freshness changes what pi’s passive `Work:` status means.** The lane renderer distinguishes `stalled`, `failed` and `report ready`. The fresh-snapshot renderer can say only `needs you` and `running` (`src/render/work-summary.ts:7–19, 35–44, 55–61`; `src/harness/pi/segment.ts:54–79`). In a pane with one running job and one failed job, the fresh path drops the failure; losing the producer makes it reappear without any job change. This affects the passive status, distinct from the deliberately live-only icon census. Preserve the richer status facts or use the lane read for that text when needed.
2. **perf-ts/08: a symlinked settings file can leave EXP off until restart.** The settings reader follows links, but the subscription watches only `dirname(preferences)` and filters by the link’s basename. Editing the target in a dotfiles directory produces no event there. After the first off observation, even subsequent draws return without reading it (`src/settings.ts:197–204`, `src/collectors/exp-proxy-refresh.ts:29–35`, `src/harness/pi/subscription.ts:108–129`). Watch the resolved target as well as link replacement, or decline permanent caching when the watch does not cover the file read.

**What can be deleted:** Remove the per-answer census rebuilds rather than adding another cache. In `src/collectors/thin-jobs.ts`, `seenFacts` mirrors the keys of `seenStamps` on every add/delete; give `exportFacts` the map’s keys on a cache miss instead of maintaining both collections on every tick.

## Optional — not part of the verdict

- Report fast-path **hit rate** separately from native render time. The installed Claude refresh interval is 5 seconds (`install.d/claude.sh:28`); the Git cache is valid for less than 2 seconds (`native/src/state.rs:179–191`). With default Git collection and no intervening refresh in that repo, each ordinary tick takes TS. That is correct stale-data handling, not a reason to relax freshness.
- Pi expands a validated count into one object per worker (`src/render/work-summary.ts:46–52`) without the 4,096-worker guard already used by the Claude consumers. Passing counts through directly, or applying the same bound, would keep a corrupt small snapshot from exhausting the pi host.
- On Linux ARM64 the launcher correctly bypasses native, but the unguarded failed-renderer test still expects its fake executable to have written `CAPTURE` (`tests/unit/native-statusline.test.mjs:149–172`). Split the portable TS-bypass assertion from the Linux-x64 replay assertion.
