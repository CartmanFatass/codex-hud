## Axis 1 — spec compliance

### 1. Major — Reload loses the saved place whenever the panel is bound to a native session

**Location:** `src/tree-page.ts:576`, `:965–967`.

The replacement initially restores `place.state`, but starts with an empty `tree.rootId`. Its first collection of a bound Claude or Codex session therefore executes `state = configuredState()`, discarding the restored tab, Help/Inspector, selection, scroll, card choices and show-all state.

**Owner-visible scenario:** Open Project, Help or an Inspector in a normally bound Claude panel, then build. The replacement returns to default Home instead of keeping its place. This violates PANEL-RELOAD, independently of whether replacement uses execve or the older-Node supervisor.

**Verification:** A fresh isolated probe launched the real compiled `dist/tree-page.js` with a serialized reload handoff containing `mainTab: 'project'`, `help: true` and show-all. Without a native root, the first collected frame retained Help. With a synthetic Claude source/session selected through the production environment variables, it rendered default Home and no Help. Both processes exited cleanly with no stderr. The existing live reload tests pass because their job-only fixtures leave the native root empty.

**Smallest fix:** Preserve the handoff through the first binding/reconciliation, while still resetting for an actual subsequent root change. Carry/check the saved root if needed; do not unconditionally replace restored state on initial collection.

### 2. Major — Reload restores the opening width rather than a width saved during the panel's lifetime

**Location:** `src/utils/panel-reload.ts:21`, `:46`; `src/tree-page.ts:610–612`, `:1126`.

`PanelReload` captures the startup environment, including `HUD_PANEL_WIDTH`. Saving Width clears the current process's `widthOverride`, but replacement reintroduces that original environment value and treats it as authoritative again.

**Owner-visible scenario:** A Claude/pi panel opens at 56 columns; the owner saves Width = 64. It correctly grows to 64, but the next build reload shrinks it back to 56 even though Settings still says 64. This breaks the saved-width behaviour and PANEL-RELOAD's continuity.

**Verification:** An isolated probe exercised real panel Settings input, the real restart/execve path, and a synthetic herdr command that updates its geometry from the received resize arguments. Saving produced width 64 and one left resize of `0.05` in a 160-column split. After replacement, the same panel issued a right resize of `0.05` and returned to approximately 56. Only the reload-detection poll was replaced with a deterministic trigger; save, handoff, replacement and width application were real.

**Smallest fix:** Include the current width override—including the fact that it was cleared—in the handoff, or replace the stale opening-width environment value with the current effective policy before restarting.

## Axis 2 — simplicity, quality and cost

### 3. Major — M4-PRUNE still ships the retired native-host startup and owned Jev bridge/runtime

**Location:** `src/managed/jev-host.ts:42`, `:179`; `src/managed/host-ipc.ts:15`, `:106–186`; `src/managed/relations.ts:43`; `src/managed/jev-bridge.py:12`.

The large deletion removes the SQL ledger, supervision and pi-owned runtime, but leaves `PythonJevBridge`, `createJevHost`, the Python Agent bridge, detached-host spawning/startup locks, and the relation writer. These are executable runtime bodies, not the allowed DTO remnants or read-only readers.

**Concrete remaining path/evidence:** The panel imports `readJevRelations` from `jev-host.ts`, which keeps that module in the shipping import graph; it never calls `createJevHost` or constructs `PythonJevBridge`. The sole `NativeHostClient` construction is `new NativeHostClient(home, false)` in `src/collectors/native-calls.ts:78`, so its launch/spawn/lock branch cannot run on a shipping path. A caller sweep found no caller of the Jev creation/bridge exports or `RelationStore`; the Python bridge is referenced only by that unused bridge implementation. The startup helper even names the removed `host-entry.js`.

This is the unfixed remainder of Sol finding 3: the checkout/build still carries its own prohibited host/bridge execution implementation, contrary to spec §3 and M2/M4-PRUNE. It is not a claim that current jobs execute it. The orchestrator confirmed that only DTOs and actually executed shipping code were approved for retention, not these dormant branches.

**Smallest fix:** Delete the unused creation/bridge/writer exports, Python asset and disabled client-startup branch. Retain the used relation readers, display types and read-only client exchange; no replacement framework is needed.
