### 1. Major — M4-PRUNE left the retired execution/native-host/owned-Jev runtime behind, and the reference still tells the owner to configure it

**Where:** `src/core/execution.ts:23-579`; `src/core/checkpoint.ts:1-984`; `src/core/observation.ts` (all but
`:121,265,334`); `src/core/identity.ts:43-388`; `src/core/capacity.ts`; `src/core/collect-lease.ts`;
`src/core/launch/message.ts`; `src/managed/jev-host.ts:9-26,42-112,179-270`; `src/managed/host-ipc.ts:10,15,36`;
`src/managed/relations.ts:27,43`; `src/jev/ask/config.ts:91,134,266-300`; `src/cli/import.ts` (Jev/`aistudio` TOML
merge). Owner-facing: `docs/reference.md:737` and `docs/reference.zh.md:526` ("Jev locations" required, "fails closed
before any browser contact … run `hud import`").

**What the owner would see:** the reference still says `jev.cdpUrl`, `chrome`, `profile` and `stateDir` are required in
`$HUD_HOME/config.json` for browser jobs and that a missing one fails before browser contact. After M4-PRUNE the HUD
never contacts a browser: `packages/hud-mcp/bin/hud-jev.mjs` runs the external `jev-*` CLIs with their own setup, and
nothing reads the `jev` locations or `aistudio` sections any more (`loadJevConfig` has no caller; only the legacy
`jev.decisions` fallback in `resolveDecisions` remains). The owner configures keys that do nothing, and
`hud import --from <jev-ask.toml>` writes the same dead section. At the same time ~3,000 lines of the retired platform
still ship as production source, which §3 ("no ledger database, process supervisor, native host or bridge") and the
M4-PRUNE intent ("the retired ledger/supervision/owned runtimes … are gone; type-only DTO remnants stay where shipping
code reads them") rule out. The dead parts are not type-only: `reconcileRun`/`makeRunSlot`/`lookupIdempotency`
(execution engine), the checkpoint preparation/decoding, the identity claim/redemption machinery,
`spawnDetachedHost`/`RelationStore` (native-host writer) and `createJevHost`/`PythonJevBridge` (owned Jev host) have
no caller anywhere in `src bin packages tests` (verified by per-symbol reference scan; only `isRunTerminal`,
`RecoveryIndexOverlay`, `displayNodeKey`, `runExecutionProjection`, `initialParserState`, `validateSessionRef`,
`makeSourceId`, `sessionRefKey`, `sameSessionRef`, `readRelations`, `readJevRelations`, `ownerKey`, `nativeKey` and
`NativeHostClient` are still read). `NativeHostClient` is only ever constructed with `launch=false`
(`src/collectors/native-calls.ts:78`), so the host is never started.

**Smallest fix:** delete the unreferenced exports/modules above (keep the live helpers and the `JevRelation`/
`DirectRelation` types), drop the `jev`/`aistudio` TOML merge from `hud import`, and update the "Jev locations"
paragraphs in `docs/reference.md`/`docs/reference.zh.md` to say the external Jev CLIs own that setup.

### 2. Minor — the Recommended brief disappears whenever a card's sentence changes before the next Summary interval

**Where:** `src/collectors/home-recommendation.ts:96-117` (`briefKey`, `summarize`, `apply`).

**Failure scenario:** the brief is cached under a digest that includes each card's current sentence. When a sentence
changes (a job moves from implementation to checks, or a settlement arrives), `briefKey` changes, `summaries` has no
entry for the new key, and `apply()` returns `homeBrief: undefined`. The brief vanishes from Home until the next
Summary interval elapses and a new brief arrives (up to 5 minutes by default). Probe against the compiled service:
first `homeBrief` `"Brief text."` (1 brief); after a sentence change within the interval `homeBrief` is `undefined`
(still 1 brief); after `now += 5 min` it is `"Brief text."` (2 briefs). This is display-only and does not affect
ranking, but the owner loses the brief for minutes at a time on the normal path.

**Smallest fix:** keep the last successful brief text and use it as the fallback in `apply()` when the current digest
has no entry, replacing it when the new brief arrives.
