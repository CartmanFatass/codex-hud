# 本地活动、证据与采集优化验收

本轮基于 `6617ded`，在 `codex/hud-observability` 隔离工作树中实现。测试完成日期为 2026-10-25（America/Los_Angeles；部分原始文件名采用 2026-10-26 UTC）。原运行目录未切换到新版本。

## 交付范围

| 功能 | 入口与行为 |
| --- | --- |
| 状态来源与 TPS 解释 | `Ctrl+] c` 的来源页，或点击状态带 TPS；说明来源、采样时间、估算口径及原生读回冲突。缺失证据显示 unknown。 |
| 待处理收件箱 | `Ctrl+] u`：已观测的审批、故障、健康异常可标已读或稍后处理。已读不等于问题恢复。 |
| 离开后的变化 | 活动中心的变化页：完成、失败、已观测 Git 状态及已有模型摘要的变化；明确操作才确认已显示的事件。 |
| 搜索与关注 | `Ctrl+] p`：按名称、角色或路径过滤，支持中文和粘贴；Ctrl+P 固定关注，按根会话持久化。 |
| 诊断预览与导出 | 来源页切换到导出：先看固定 JSON，再点击保存或按 `s` 写入精确预览字节。白名单排除身份、路径、端点、凭据及文本内容。 |
| 模型调用统计 | 调用页按功能统计本地请求、缓存、成功、失败、取消、限额与平均耗时；连接探针单独计数。 |
| 自适应采集与分段扫描 | 确认空闲且稳定才降低采集频率；输入、活跃、失败及不确定状态恢复正常频率。大文件扫描在分段之间让出事件循环。 |
| 有界历史 | 活动中心的历史页保存观测到的状态快照及保留事件，明确标记历史；不恢复终端或重新执行任务。 |

这几个入口只观察已有数据，不引入额外模型请求。原有模型功能仍受已有配置、暂停及调用上限控制。

活动存储按根会话隔离，采用原子写入和跨面板合并，上限为 500 个事件、48 个快照、200 个代理/关注项、30 天和 4 MiB。只保留必要状态、有限路径和已有模型摘要，不保存原始任务、对话、命令或推理。无 HUD 运行期间的数据不会被重建。

模型统计保留最近 24 小时、最多 1000 条记录。请求数包含缓存消费者及拒绝，不能当作供应商调用次数；耗时为实际派发到结算，不含排队。其他面板未完成的请求、启用前记录、token 与金额缺少证据时保持未知。

导出文件为新建的 0600 文件，保存在 `$CODEX_HOME/hud/diagnostics/`。运行身份只包括启动时观察到的入口文件哈希、应用版本和平台，不能证明整个构建或当前 Git 状态。

## 验证

测试环境：Node 24.22.1、tmux 3.4、WSL Linux；所有构建在隔离工作树中完成。

| 检查 | 最终结果 |
| --- | --- |
| `NO_COLOR=1 npm test` | 构建及测试编译通过；TypeScript 1009/1009，MJS 47/47 |
| `env -u NO_COLOR npm run test:unit` | 同一最终构建，1009/1009 |
| 完整 shell/tmux 集成 | runner：26 通过、0 失败、1 跳过；其中 Windows 脚本自行报告跳过但返回 0，因此实际为 25 项通过、2 项未执行 |
| 独立源码审查 | 三项实质发现均修复并完成复核；审查者未代替父级执行运行验收 |

新增真实 tmux 测试使用独立 socket、临时 CODEX_HOME、合成会话和接收输入的主窗格。覆盖中文查找与关注持久化、事件已读/稍后处理、只确认可见变化、历史标记、来源/调用/导出切换、滚动和返回。诊断预览不创建文件；显式保存后核对权限、敏感哨兵缺失及启动入口文件哈希。32×12、48×12 的中英文、彩色/无色组合补充验证受限视口，并检查关闭后恢复主窗格输入。

本轮修复两处既有集成测试的环境/时序问题：设置安全测试明确选择其点击断言要求的彩色配置；Herdr wrapper 测试在健康 sidecar 落盘后才比对 PID。没有通过削弱断言隐藏产品失败。

## 审查修复

- 根会话切换先取消旧任务并切换摘要日志归属。活动观察同时校验 data/tree/log 的根会话及新鲜度，扫描失败不能把旧摘要写入新会话。
- 扫描期间文件发生截断后增长时，提交前验证已消费字节摘要、头部和续读边界。验证期间再次变化则拒绝提交，防止混合不同文件代际。普通追加仍可继续。
- 健康恢复使用对应收集器的成功水位。成功时间跨过失败时间会处理恢复；后续静默水位变化不重复写盘。stale 数据的显式树和嵌套缓存树均不更新代理生命周期。
- 连续 Escape 后紧接面板 APC 命令时，解码器正确拆分，避免返回/切换被吞掉；原始输入转发及分片情况有回归测试。

## 性能证据与边界

最终数据见 [results-adaptive-post-integrity-20261026.json](../tests/performance/results-adaptive-post-integrity-20261026.json)，包含源码与编译文件哈希。此前的 [首轮记录](../tests/performance/results-adaptive-20261026.json) 保留原字节，不以最终结果覆盖。

| 合成文件（各三轮） | 同步扫描的排队回调延迟 | 分段扫描的排队回调延迟 | 分段扫描最大定时器间隔 |
| --- | --- | --- | --- |
| 44.12 MB，多记录 | 72.74–120.73 ms | 4.09–4.40 ms | 8.18–8.46 ms |
| 27.66 MB，含大记录 | 51.33–65.56 ms | 4.06–4.15 ms | 8.33–9.95 ms |

六次树结果逐项相同。这是缓存文件系统上的合成事件循环测试，不是原生终端按键延迟，也不代表普遍吞吐提升。单条 JSON 解析、文件列举、首行读取及缓存写入仍有同步步骤；完整性校验增加 CPU 工作。持久扫描缓存沿用既有 4 KiB 续读边界检查，不提供文件系统快照隔离。
