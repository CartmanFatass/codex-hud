Short panel and many projects

All 17 registrations stay visible: when the full layout needs more rows than the panel has, every project drops to one row (mark, name, roll-up bar and count of its open Objectives' tickets, load, age). The full layout for these 17 projects would need 59 rows at 40 columns.

Text layout rules the build follows

  1. A row is a grammar, not flowing prose. Mark, token, graphic or fact, then right-hand facts. The left part is cut, the right part is whole or absent. Only sentence rows wrap.
  2. A token is cut by cell, never wrapped. Project name 14 / 18 / 24 cells at 40 / 50 / 80 columns, Objective id 11 / 14 / 14, feature slug 16; the last cell is ….
  3. A sentence starts its own row. Request, Objective title, next step, result, STATE note never follow a label or a token of varying width. Row limits: Home request 2, result 1, note 1; Project request 4, title 3, next 3, result 2; the last row ends in ….
  4. Fixed hang. A continuation line starts where the first line's text started: 2 cells after a mark. A label shares a row with a value only in the fixed label column of the Details block (9 cells below 56 columns, 10 above), and the value is a short fact.
  5. Cut at a word, or between CJK characters (cutWords); a Latin token longer than the row is cut by cell. English owner text in the zh panel is fine.
  6. Facts leave whole, in a fixed order: priority arrow, idle word, age, load. Unknown is absent, never 未知 or Partial; a bound is named when it limits a count.
  7. A count names its unit once: in the section heading below 56 columns, on every row at 56 and above. The only denominator on Home is tickets of linked features (dropped excluded); a feature that was not read gives no bar, never 0/0.
  8. Time is an age (20分 4时 9天 5周), not a clock time or an ISO date, except on a dated receipt.
