Reconstructed from the renderer's own grammar (work-card.ts, project-view.ts) on the same invented data, so the options compare like for like. Not a screenshot of the real panel.

1 · Inbox recommended

One list, ranked by how much each thing needs you. Package lanes dissolve into the job's own title; a job is one row, and a second row only when it runs or went wrong. Decisions fold to a count unless one is worth a look; the progress block shrinks to a bar.

Project opens on what you owe (tries, the choice, asks), acts on it in place with y / n, then shows what is moving, then five page rows that lead with a mark. The pages keep their drill-in and read in the same order: owe, moving, next, past.

2 · Split

A list on top, a preview below that follows the cursor. Home lists one row per package and per block (waiting, decided, progress); the cards, unchanged, show for the row under the cursor only. The list never changes height, so nothing moves while jobs write; what needs you is always a row.

Project is the same machine. The hub is a page list with the page under the cursor previewed below it, so Progress answers the common question without Enter. The pages keep their full form behind Enter, built the same way: a list of rows, the cursor row explained underneath.

3 · Timeline

Live things above, history below it, history sorted by time. Home shows what runs now as one row per job, then one feed for everything that finished, was decided for you or landed. A sentence only appears where something went wrong.

Project is one page that scrolls: a map of the milestones (a cell per slice), then now, next and the last seven days; the four small pages (tickets, working tree, docs, control plane) are folds at the foot that open in place. Progress as a page is the long feed behind Enter.
