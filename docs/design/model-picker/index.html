Model picker: one sample to settle

11 frames, drawn cell by cell as the terminal paints them (CJK counts two cells; every row is checked to be exactly as wide as its frame when the page is built), in the owner’s setup (Split layout, mocha theme), in Chinese and again in English. The panel frames are 40 columns; the zoomed picker is 120 by 36. One invented project, harbor-api, and invented models; nothing here is real data and nothing is built. Baseline: CONTROL-TAB-03 (frames 6a–6c of docs/design/control-tab/index.html); this sample keeps its rules and everything stays inside the terminal panel, no web console. The generator is gen/, copied from the Control tab sample and made width-parameterized.

1 Entry: a model field on every place

CONTROL-TAB-03 opens its picker with m on a place of the Control role chain. The sample changes only how a person finds it: every place row ends in a visible [model ▾] field that is also a mouse target, and m model is the first hint in the footer. Setting a model behaves as it does today.

2 The picker at 40 columns

The CONTROL-TAB-03 rules stay: one list grouped by provider with counts, a typed case-insensitive filter over the whole provider/model, query and match count pinned, current ◉ apart from the cursor ›, middle ellipsis, discovery only when Control opens or on refresh. New here: a pinned section above the list, groups that start folded, a two-to-four-row strip that gives the whole ID and the columns pi --list-models prints, a state on the row itself, and the mouse (grey notes beside a frame are annotations, not terminal cells).

3 The zoomed picker

Opening the picker zooms the panel pane (herdr pane zoom) and closing restores it, so the panel gets about 120 by 36 cells: the grouped list on the left with pi's columns and the HUD's facts, the cursor model's detail on the right. It is still one list with one cursor; the right pane is text, not a second list.

? To settle

The frames draw the best reading of each choice. These are the readings the owner may want to change.

  1. Zoom on open, or on a key. Drawn: m zooms the panel's own pane at once (herdr pane zoom --on, the pane looked up at call time, nothing stored) and Esc or a set restores it, only if the picker did the zoom: a pane that was already zoomed stays zoomed. Below about 100 columns, outside herdr or when the zoom is refused, the 40-column picker (2a–2d) is used. The alternative is to open at 40 columns and zoom on a key; letters are filter text, so that key would have to be a non-printable one (F2, say).
  2. Which pinned sections. Drawn: Current, This role (the pi models of the role's presets, tagged with the preset) and Recent. Current and This role need nothing new. Recent needs a small local record of what the picker set (for example $HUD_HOME/display/recent-models.json, written when a model is set, never on a tick); drop it if one more file is not worth it. Pinned rows also stay in their provider group so the counts stay true; the alternative takes them out of the group.
  3. Groups start folded. Drawn: every group folded with its count (six rows for 88 models), typing opens the groups that match, a click folds or unfolds. No key folds, because headers are not on the cursor path (design.md §4). The alternative is open by default, which at 40 columns is a long scroll, or selectable headers so that a key can fold.
  4. Providers that are off. Drawn: their models are not offered (spec: models of the providers that are on); one muted line names the off providers, and a current model whose provider is off stays pinned with ⊘ (frame 3e). The alternative is no line at all.
  5. The columns need a cache field. Context, max-out, thinking and images come from the same pi --list-models call, but today the parser drops them and the cache (display/model-lists.json) keeps only provider/model strings (src/roles/model-discovery.ts). Showing them means the cache also keeps each model's four columns: one field added to the same file, · in the columns until the next discovery after an upgrade, no new command. If the owner would rather not touch the cache, the columns go and the strip keeps only the ID and the state.
  6. Price is not drawn. pi --list-models prints no price column. The only per-model rates the HUD sees (USD per million tokens, src/harness/pi/exp-usage.ts) come from inside a running pi, for the model it is using, to price EXP usage: observed for models in use, not for the 88 listed, and the picker's discovery cannot read them. The pi spend on the Usage fold is observed spend, not a price. So no local source covers a price column for the whole list, and nothing is guessed; if the owner wants one, name where it should come from (a bounded read of pi's own model definitions, say) as a separate decision.
  7. Ctrl+R and Esc. Letters are filter text inside the picker, so refresh is ^R there (outside it, r keeps its meaning). Esc always closes without setting. Say if Esc should first clear a typed filter.
  8. The strip at 40 columns. Drawn: always shown, two to four rows (the whole ID, the columns, a state line). It costs those rows of a narrow panel; the alternative shows it only after the cursor has rested or been clicked.
  9. What the stop rule left out. The design needed no second list. Not drawn, because the spec rules them out: a provider rail or column beside the list (a second list, and design.md drops provider-to-model drill-down), and a picker that edits a whole preset at once.
