# EXP · 用量与赠额：Codex 原生状态栏、pi 订阅代理、API 赠额账本

状态：实施草案，2026-11-20。只记录方案，不表示功能已实现或已启用。适用基线：MyHUD `1234b2a0`，本机 Codex CLI 0.171.0、pi 1.5.2、Claude Code 2.1.329。下面的时间和 UI 文案是建议默认值，不是厂商承诺。


## 0. Owner 决定（2026-11-20，优先于下文）

- **位置：** EXP 是独立的**实验性顶层 tab**，不在 Project 下，也不放进 Control tab。设置 → 面板 → 实验功能 打开后才显示（默认关；关闭即无 tab、不采集、不刷新）。下文“Project → EXP”“不是第三个顶层 tab”作废。
- **刷新：** 不用 systemd timer、不加任何常驻进程。pi 会话绘制 footer 时若读数超过间隔，异步发起一次加锁刷新；多个 worker 不重复请求；没人用 pi 时不刷新。下文 §3“周期刷新”的调度部分按此改。
- **账本存储：** 追加式 JSONL（每个费用事件/校准一行，带去重键），余额读取时计算并缓存小快照；不用 SQLite。
- **分片：** `.scratch/exp/issues/01–05`；下文 EXP-05 联验由 owner 试用完成，不单独开工单。

## 1. 交付给使用者的体验

- 在 **`hud panel → Project → EXP · 用量与赠额`** 管理所有新增的 HUD 设置。EXP 是临时页面，不是第三个顶层 tab。设置是**本机用户全局**的，不因切换 Project 复制或改变；页面标题标明“本机 · 所有项目”。以后迁走页面不迁账本。
- Codex 用 **Custom status line**，不是 tmux 里画一条外置栏。原生底栏显示当前 Codex 账号自己的订阅窗口和 MyHUD 摘要。pi 用 ChatGPT 订阅时显示直接读数，拿不到就显示用户绑定的 Codex 账号的**近似值**，后者自动周期刷新。不会因为 panel 关闭而失去刷新能力。
- pi 走 `oapi` 或 Anthropic API 时显示**对应赠额账的估算剩余美元**。Claude Code 的订阅仍显示 Claude 提供的窗口。状态栏只展示：不配置、不校准、不轮询厂商、不写账。未启用 EXP 时原有行为不变。
- 不做厂商账单同步、余额抓取、自动充值、请求拦截或管理员密钥管理。即使估算余额为零，也不妨碍 CLI 继续运行。

## 2. 先做 EXP 页：一个入口，三组操作

| 分区 | 可见信息 | 可修改项 |
|---|---|---|
| Codex 原生栏 | 各本机 profile 的稳定别名、最近一次观察到 MyHUD 原生栏的时间、接入状态（未观察到不等于没安装） | 本次实验的展示开关、接入说明、恢复旧栏说明 |
| pi 订阅代理 | 当前绑定、主/次窗口剩余和重置时间、读数来源、最近成功、最近错误、下次尝试 | 选择/解绑一个已知本机 Codex profile；启停自动刷新；设间隔。平时不需要按“刷新” |
| API 赠额 | Anthropic API 和 OpenAI API 各一行：估算剩余、周期、已计费用、未计价请求数；展开见最近校准 | 每本账独立启用、设置每期赠额和续期日、校准“此刻剩余”、查看近期记录 |

**首次设置示例：** 绑定 `codexH1` → 启用每 15 分钟刷新 → 为 `oapi` 填「每月 $20、每月 18 日续期、当前剩 $13.40」→ 保存。若在周期中途启用但不知道当前剩余，可先只记录后续消耗，余额显示 `未校准`；除非用户明确选择“本期从全额起算”，否则不能假设赠额全在。

交互沿用现有 panel：上下选择、Enter 编辑、显示保存结果、Esc 取消且不落盘。保存校准前显示“旧估算 → 新基准；不改变下期赠额”。Classic/Split 与各 Project 布局共享同一页面模型；40 列可用，详细来源放展开行。暂不在 Control plane、`/hud footer` 或各状态栏重复提供编辑器。

**宿主边界：** 所有 **HUD 自有**配置都在 EXP。Codex 自己的实验许可和 provider 选择仍由用户在所选 Codex profile 的 `/experimental`、重启、`/statusline` 中完成一次；EXP 给准确步骤，不偷偷改 `~/.codex*`。本项目规格当前明确保留 `codexH` tmux 栏；替换默认入口、删除旧栏或同时显示两条栏都不属于试验。先用普通 Codex 启动相同 profile 验收原生栏，`codexH` 留作回退；若以后改默认，另请 owner 决定并修订规格。

## 3. Codex 原生栏和 pi 代理：同一份配额，两种可信度

### 原生栏

在现有 `hud-mcp` 增加 Codex 能发现的 statusline 入口，保留原有工具协议：`tools/list` 声明 `_meta["openai/ui"].entrypoints`，`resources/read` 从请求 `_meta["com.openai/codex-statusline-state"]` 读取当前线程快照，返回 `application/json` UI tree。复用 MyHUD 字段选择和宽度优先级，不把现有 ANSI 文本直接塞进去。模型、上下文、配额优先来自该请求；工作提醒读本地缓存；没有可靠数据的字段省略，不编造 TPS。原生 surface 是短摘要，侧栏仍用 `/hud`。资源读取不启动 CLI、不扫描全部会话、不等网络；验证低于 Codex 的 1 秒超时。失败时旧入口仍可用。

### 绑定和显示

- 用户绑定的是**明确的本机 Codex profile**，不是模型名、当前目录或“最近用过的账号”。本机 `codexH1` 指向 `.codex-account2`，`codexH2` 指向 `.codex`。面板显示别名并允许核对目标，只接受本机已知 profile，不执行用户填入的 shell 命令。profile 不是永久账户 ID；有可用的账号/工作区变化信号就作废旧值要求确认，无法验证身份时仍标代理。
- pi 先按当前请求的 provider 和鉴权种类判路由：`openai + OAuth` 才能读绑定代理；若当前请求有可归属的订阅窗口，直报优先；`oapi` 不借用订阅值。不要靠 GPT 模型名区分。换模型、换绑定、解绑应立即丢弃不适用读数。
- `5h 剩 72%` = 当前来源直报；`5h ≈72%` = 绑定账号代理。窗口看上游的时长、分桶和重置时间，不凭空造 5h/7d，不用本机 token 再从代理百分比上扣。超过两次刷新间隔未成功，标旧；某一窗口过了重置点但没拿到新值，该窗口显示 `待刷新` 或隐藏，不跳回 100%；缺其它窗口不影响有效窗口。

### 周期刷新

建议默认 **15 分钟，可在 EXP 改为 5–60 分钟或关闭**。保存绑定并明确启用时，在面板说明“将周期性使用此 profile 的现有登录查询额度”，随后异步首刷，不发推理请求、不传提示词。刷新端只对选定 profile 调用官方 Codex app-server `account/rateLimits/read`；HUD 不读取或复制 OAuth token，不使用私有网页登录接口。

采用**每用户一个调度入口**，本机优先复用已有定时设施；如没有合适宿主，试验采用由 EXP 显式启停的 `systemd --user` timer + 一次性刷新任务。启动前检测支持、从面板可见启停结果；不可用时显示“后台刷新不可用”，不伪称自动刷新成功。面板、各 CLI、每个 worker 和每次状态栏绘制均不得自建定时器。关闭 panel 后定时器仍工作；机器休眠不承诺准点，恢复后只补一次，不追打漏掉的次数。

一次刷新：检查启用与到期 → 非阻塞单实例锁 → 指定 profile/`CODEX_HOME`，有总超时地读 RPC → 按绑定版本和 profile 校验 → 原子替换快照。切换/关闭绑定时在途旧结果不得写回。遵守 `retry-after`，临时故障指数退避；未登录/授权失效暂停并在 EXP 提示，用户修复后从 EXP 恢复。只存允许的窗口字段、观测时间和分类错误；不存原始 RPC 包或响应头，不拉起交互登录。解绑后停止此目标的网络访问并移除当前代理展示。

## 4. API 赠额：校准的是剩余，不是历史

首版两本 USD 账：`anthropic-api`、`openai-api`。**剩余估算 = 本期最近基准金额 − 基准之后归入这本账的已计费用。** 基准可以是本期赠额或手动校准。月赠额和当前剩余分别编辑。比如校准 `$13.40` 后计入 `$0.65`，状态栏显示 `API ≈$12.75`；校准不回写历史请求，也不改变下期的 `$20`。

- **计费范围：** 首版覆盖本机能可靠取得单请求 usage 且能证明是对应 API 路线的 pi 会话（包括有同样采集能力的 worker）。`oapi` 是本机独立 API provider；`anthropic` 要确认 API key 路线；内置 `openai` 只有确认走同一核准 API 账时才并入。ChatGPT/Claude 订阅、第三方网关、无法归属的调用都不扣。EXP 明示覆盖范围；其它机器、未装采集的 worker、Claude/Codex API 客户端等未验证来源，不宣称已覆盖。后续只需增加有证据的适配器，不改账本算法。
- **费用：** 优先使用语义明确、非占位的请求费用；否则按请求发生时的模型价格和实际 input/output/cache 分项估算，不把缓存 token 重复算成普通输入。来源标为已报告/按价估算/未计价；不认识的模型或占位 `$0` 不静默当免费。金额用定点整数（如微美元），只在显示时四舍五入。
- **只扣一次：** 采集独立于 footer 渲染。成功获取最终 usage 后，以稳定的请求/响应 ID 去重；若无厂商 ID，用可重放的会话 + 消息/条目标识，不用时间戳单独去重。并发 worker、重复事件、重载和会话恢复不得重复扣。没有可靠计费证据的失败或重试不猜扣。首版默认不回填启用前的历史。
- **校准与迟到事件：** 基准有生效时间。先发生、后导入且在校准前完成的请求只记历史，不再减少新基准；跨期按请求完成时间归属。无法确定时间的记录列为待核对。支持多次校准，以最近一次为准；详情保留校准前后值和时间。
- **周期：** 每账独立设置月续期日，记录时区，默认建账时本地时区、当日 00:00；29–31 日在短月取月末，下一月恢复原定日。默认不结转，跨多个周期也不叠加赠额。修改未来赠额/续期日先展示生效日期，默认下一期生效。超额时栏显示 `≈$0`，详情保留超估金额；零不是停用 API 的依据。

## 5. 存储与责任分工

放在 `$HUD_HOME` 的版本化 EXP 专区，**不要**把新 JSON 随手放进当前会把其它快照当 Codex 水位读的旧雷达目录。配置、订阅快照、API 账务分开：配置仅由 panel 保存；订阅快照由刷新端写；请求费用由采集器写；手动校准由 panel 形成账务事件。状态栏只读已算好的小快照，不全量扫描 JSONL。

建议先验证一个本机事务存储实现（如 Node 24 的 SQLite）：费用事件唯一键、校准与周期基准、按账本和时间的索引，在同一事务中幂等写入并更新投影；读者看到旧完整值或新完整值。别把“追加账目”和“改余额”拆成两个无恢复机制的文件写。目录和文件仅当前用户可读写；只存最少计费字段，不存对话、密钥、完整账号标识、全量请求头。实验关闭后不再采集或轮询，保留账本供以后核对；删除历史需另行明确确认。

**代码落点（实施时重查，不是指定必须改的文件）：** Project 子页和各布局从 `src/render/project-view.ts`、`src/render/board-project.ts` 进入；pi 接入从 `src/harness/pi/package-entry.ts`、`p10k-footer.ts` 分离采集与显示；Codex 从 `packages/hud-mcp/src/thin-main.ts` 接 provider，不把后台刷新塞进 MCP 热路径；Claude 保持 `src/statusline-parity/` 的现有输入契约。`src/collectors/control-radar.ts` 的 pi 今日费用是摘要样本，不可当作赠额账务流水。

## 6. 分片、验收与退出条件

| 顺序 | 可独立试用的交付 | 验收重点 |
|---|---|---|
| **EXP-01 页面与设置** | 先上独立 EXP 页、绑定选择、两本账表单和保存/取消；未接通数据明确写 `未接入` | 40 列、键盘/鼠标、Classic/Split、Project 布局切换、重启持久、跨项目同一份；不发请求、不改 CLI 配置 |
| **EXP-02 Codex 原生栏** | 一个 profile 可选择 MyHUD，旧入口原样保留 | 合成 `tools/list`/`resources/read` 验约、缺字段和窄宽、切线程/两个 profile 不串、资源响应不等 RPC；本机人工选 provider 验证，退出试验可恢复 |
| **EXP-03 周期代理与 pi 显示** | panel 保存绑定并启用后，pi 订阅显示有来源的近似值 | 可控时钟 + 假 RPC 测首刷、退避、超时、过重置点、换绑竞态、关闭；本机经同意用一个绑定账号验两次自动刷新，期间 panel 关闭，多个 worker 不增加请求数 |
| **EXP-04 API 赠额端到端** | 先打通 `oapi` 从 usage 到余额，再用同套账务接 Anthropic；EXP 可校准 | 合成请求校验分项定价、未知价、重复请求、并发、校准后的迟到事件、月末跨期；有无 footer 的采集覆盖分别核实。订阅请求零扣款，两本账互不影响 |
| **EXP-05 一次本机联验** | 两个 Codex profile、pi 在订阅/两家 API 间切换、Claude 保持原样 | 状态栏只显示当前路线；panel 之外不能配置；关闭实验后零后台请求、旧栏可用、账不丢。只在用户本来就要进行的 API 调用上核对费用，不专为验收制造消费 |

从 EXP-01 开始，不等原生集成或账本算准了才做页面。每片分别标记「合成已验」「本机 CLI 已验」「真实账号已验/未验」，不把代理值验成厂商余额。自动刷新无法证明只走绑定账号就不上线该刷新器；无法可靠归属/去重的消费不入账。更改产品默认入口、把 EXP 移出实验区、全局启用后台任务都留到 owner 试用之后。
