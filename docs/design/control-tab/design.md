CONTROL-TAB — design recommendation (checkout fee5f739)

Give Control its own tab. Make three things visibly different: a preset is the owner's saved order for one role; “Next” is the first place in that order that can run now; a harness switch is a machine-wide preference. Switching presets should take one keystroke. Turning off a subscription should take one toggle and change zero role files. Neither action launches anything.

Example for the sample: `imp [daily] → pi/xai` changes to `imp [daily] → agy` when the owner turns off `pi:xai`. The first place still reads `off`; the preset is still `daily`. Restore xai and it is first again, unless it is also at quota. Turning off `cli:grok` instead would not affect this pi place. Show this same example in the panel, roster and next-create acceptance test.

1. What persists (proposed)

• Harness switches: add one property to the owner's existing `$HUD_HOME/harnesses.json`, e.g. `{"disabled":["cli:grok","pi:xai","bro:jev-flow"],"grok":{"state_trust":"advisory"}}`. No project version, Settings copy or shipped list of enabled subscriptions. Missing file/property or absent ID = on, including later discoveries. Remove inserts an ID; Add removes it. Write just this property on a fresh read of the object, atomically, privately; preserve defaults, catalog, unknown keys and disabled IDs absent from discovery. Invalid/unreadable switch data is an explicit configuration error, not permission to overwrite the file or dispatch as though everything were on. Existing per-name harness defaults keep their shallow shipped → owner merge (`src/roles/roster.ts:310–339`). A separate switch file would also work but buy nothing here; the array cannot be mistaken for a harness definition.
• Canonical switch IDs, independent of display labels, model, thinking or `on` alias: `pi` (whole runner); `pi:<exact provider id>`; `cli:<agent>`; `bro:<tool>` (`jev-ask`, `jev-aistudio`, `jev-flow`). A pi place needs both runner and provider on. Turning the runner back on does not turn its children on. Browser granularity is the executable: `chatgpt` and `gemini` share `bro:jev-ask`; `argon` maps to `bro:jev-aistudio`. Show the affected sites on that tool row. No second set of site switches is required by “browser tools”. Actual adapters/defaults: `packages/hud-mcp/harnesses.json:2–53`, `src/roles/cli-kinds.ts:1–20`, `src/roles/roster.ts:116–127`. Alias decisions use the resolved target, not its spelling.
• Role definitions stay in the role files. Raw example in `$HUD_HOME/roles/imp.json` (simplified, complete):
  {"role":"imp","instructions":"implementer","can_continue":true,
   "run":[{"harness":"pi","pi_role":"implementer"}],
   "presets":[{"name":"daily","run":[{"harness":"pi","model":"xai/grok-4.7"},{"harness":"cli","agent":"agy","model":"gemini-4-hydrogen-high"}]}],
   "active_preset":"daily","hidden_presets":["hydrogen"]}
  `run` remains the file's own runnable chain. `presets[].run` is the full chain for that name, not a patch. New optional `active_preset` selects a name, without copying its places over `run`; null explicitly selects the file chain (UI: Custom). Absent = today's semantics: use `run` and infer its displayed preset by first exact normalized match. A named selection, even between two equal chains, is unambiguous. This matters as soon as someone saves a copy under a new name: today's `find(isDeepStrictEqual)` can never select the second copy (`src/roles/roster.ts:32–39`).
• Load valid layers by role name: shipped → owner → registered project, then the project's enabled-role filter. The winning definition supplies `run`, instructions and selector; never inherit a lower layer's selector onto a project role. Merge preset names in existing order at each layer: first subtract that layer's `hidden_presets`, then overlay its named definitions (replacement keeps position, new names append). Thus a deleted inherited preset stays deleted locally, but an explicit project definition can reintroduce its name. Omission without a hide still inherits. Validate tokens/uniqueness and nonempty chains as today. A missing explicitly selected name (e.g. after a shipped update) uses the intact file chain with a visible “preset <name> missing; using file chain” diagnostic, not an arbitrary other preset. Registry returns the EFFECTIVE `run`, `preset`, `presets` and consequent launch fields; compute them after the merge, not from the first place of raw `run`. Keep provenance of the chosen chain for file/model details. Existing loader/tests: `src/roles/roster.ts:167–244,413–448,462–531`; `tests/unit/role-presets.test.mjs:25–88`.
• Create/copy/edit → only the changed preset is materialized in the owner layer. Rename/delete an inherited name by suppressing that name, not by writing a shipped file; remove a local entry too if present. A local-only name needs no hide. Rename keeps selection on the new name. Delete of the selected name explicitly previews “use file chain next”; on confirmation set selector null, preserve raw `run` and all other presets. Deleting the last preset is fine; deleting the last runnable place of a saved chain is not. Edits to Custom change only raw `run`; edits to an active named chain change only that preset and select it explicitly. Never store both a mirrored active chain and an authoritative pointer.
• Only the effective owner file is updated, or create the conventional `$HUD_HOME/roles/<role>.json` from the shipped role's raw fields if none exists (inherit preset definitions rather than eagerly copying them all). Use the actual winning owner path when filename and role ID differ. Preserve legacy single-place conversion, unknown fields/launch options on retained places, and the current atomic 0600 writer's non-file/symlink checks. Save a whole edit with one rename. Refuse stale drafts if the role source or edited definition changed; do not flatten normalized places over owner-authored options. Existing writer and guard: `src/roles/roster.ts:738–808`; `src/roles/role-control.ts:178–207,222–271`.
• Project-pinned role: show the project, role path, effective chain and presets, and offer file open; no panel select/rename/write pretending to override it. Machine switches still apply, as does clearing a quota mark. An unregistered repo supplies no `.hud/` inputs. A non-pinned role viewed through a project writes the GLOBAL role, visibly labelled as such. No writes to `.hud/`, client config, auth, or job files. This preserves `docs/spec.md:13,94`, `docs/reference.md:487–491,525–533` and the tested pin in `tests/unit/role-presets.test.mjs:43–63`.

2. Fallback rule (one paragraph)

For each new job, use exactly one ordered chain: the effective role chain, the requested one-job `preset` chain, or one explicit `on` target (never both overrides). In order, resolve the actual target/model, skip an owner-off runner/agent/tool/provider, skip a live quota mark on that place key, skip missing runtime prerequisites; take the first remaining place. Off lasts until the owner restores it; quota lasts until its parsed reset (one hour only if unspecified); missing means the existing executable check failed, not “not in a model list” or “not logged in”. If none qualifies, roster `available:false, runs_on:null`; create returns `ok:false, code:"no_available_place"` with reasons, before creating a job, worktree or tab. No trying a different preset, guessing a provider, retrying a rejected launch, or changing jobs already created. Re-enabling or clearing quota makes the place eligible in its original position on the next resolution. No auto-retry; the main session still decides what to do after failure (`docs/spec.md:13,24–30`; `src/roles/exhausted.ts:47–87,162–195`; `src/roles/roster.ts:365–375,478–531,549–586`).

Implementation contract:
• Replace the panel's second test of availability with one shared evaluation per ordered chain: e.g. `places:[{index,place,state,off_by?,until?,provider?,provider_source?}]`, states `active|standby|off|exhausted|missing`. Include this diagnostic on roster and on no-place failures. Keep raw configured places in effective order, `runs_on` the chosen place or null, and existing `exhausted:[{place,key,reason,until}]` for actual unexpired quota marks ONLY. Simultaneously off and at quota → row says off, detail may show the real mark; it stays in `exhausted` until expired/cleared. Never manufacture a deadline or persist off in `exhausted.json`. No mark for “missing”. `x` clears only a real mark. An intentionally off fallback alone is not an attention alert. A role with no next place always is.
• `hud_roster` already calls assignment, but `hud_create(on:…)` builds its own place and `model` is applied AFTER selection today (`packages/hud-mcp/src/thin-main.ts:1107–1136,1164–1191,1209–1230,1352–1356`). Bring run/preset/singleton-on through that same evaluator. For eligibility use the actual one-job model on pi/CLI candidates, overriding the place model, and the resulting quota key; don't reject an enabled override because the former model's provider was off, or launch an off override because the former model was on. Explicit `on` must not fall through to a different harness. Preserve per-harness option validation, CLI trust checks, idempotent existing-job return, and effective selected-place launch options. Catalog membership is not launch validation. Panel shows the un-overridden next job. Failure messages naming the next job also use assignment, not a second algorithm.
• Provider attribution (orchestrator ruling, job `qa/q1.answer.md:1`): use the applicable job override/explicit place `provider/model`; otherwise the pi-role frontmatter `model`; with no model passed, read `defaultProvider` (+ `defaultModel`) from `${PI_CODING_AGENT_DIR:-~/.pi/agent}/settings.json`. For an effective bare model ID use an exact match across the UNFILTERED cached pi list only when exactly one provider owns it; ambiguous/absent = unknown, not whichever enabled provider remains. Do not substitute a lower-priority default for an explicit ambiguous ID. Read pi settings locally, bounded and signature-cached; never write them, never spawn pi at create time. Return/display “provider unknown” when unknown; it does NOT block launch (runner off still does). `pi_args` are passed verbatim, not parsed. This is selection policy over attributable HUD places, not a guarantee about what an external CLI ultimately chooses. Current model source resolution: `src/roles/roster.ts:340–364,462–477`.

3. Interaction contract for the HTML sample

• Final main tabs: Home | Project | Control | EXP (首页 | 项目 | 控制 | EXP). EXP is a separate experimental tab owned by a separate effort; this design delivers Control, not a placeholder EXP page. Arrows, Tab/Shift-Tab and click switch tabs; no digit shortcuts. Control uses the project currently selected in Project (initially the panel's own); name it at top. `[`/`]` change that same root, never Home's root. Switches say “This machine · all projects”. Remove the Project hub page row in Timeline/Board/Inbox; a Project Inbox role alert may link directly to that role on Control. No second Control inside Board. Preserve separate cursors/scroll, and remap saved Project/control to Control on reload. Collect Control facts for the displayed root, not the previous snapshot while a new root loads. Don't collect Git/tickets just to open Control or start discovery behind Home. See `docs/reference.md:533–548,594–614,632–655`, `docs/ARCHITECTURE.md:184–210`.
• Control has sibling Roles (landing view) and Harnesses, not a hub of menus. `h` or the labelled heading switches between them. Roles opens with Needs attention: invalid files, no next place, live quota affecting enabled places, then Healthy folded. Enter/click Healthy reveals one selectable row per role. The row identifies role, active preset or Custom, and next target/none; e.g. `imp [daily] → agy`. Selected detail supplies full next model, thinking, source and numbered chain, including skipped places and reasons. Usage and Files remain foldable sections on Roles: quota windows, pi spend, dispatch health; convention and source, instructions, pi definitions, native agents, invalid/ignored files, keys/browser presence. Enter on a file (also `o`) opens in the existing editor action. A role is an action row, not a file row; `o` on it opens its source. Keep error rows actionable (`src/render/control-view.ts:72–90,115–165,169–237`; `docs/spec.md:51–56,78–83,93`).
• On a role row, `c` immediately selects next named preset, `C` previous; wrap in effective order (from Custom: first/last). No confirmation, no detour into places; stay on the role even if its attention group changes. With zero names show “No presets · N copy / I empty”; with one already active, no write. For many names, `p` opens a single list of names plus Custom (file chain); type to filter, ↑↓, Enter to apply directly, Esc cancel. Do not skip a deliberately selected all-off preset: display “Next: none”, not another preset's name. Project-pinned rows show the lock/source instead of edit shortcuts.
• On the role row: `N` = new from current chain, `I` = new from empty; enter unique name (existing `[A-Za-z0-9._-]{1,32}`), Enter to continue, Esc cancels. Both open an inline draft labelled “Not saved”; `s` saves and selects it in one write. Empty is a START, never dispatchable/saved until it has a valid place. `R` renames selected named preset (Enter commits); `D` deletes it (show affected role/name and resultant next chain, Enter confirms, Esc cancels). Select a different name with `p` to manage it; renaming/deleting Custom is not offered. Names and action words are distinct UI fields; don't translate identifiers.
• Enter on a role focuses its ordered chain in place: in Split this is the preview; in Classic expand under the role. Read-only until a change makes a draft. `i` inserts a chosen place at the end (no guessed fallback), Enter on a place edits its fields, `K`/`J` move that place up/down, `Del` removes it from draft, `s` validates and commits the draft and returns focus to the role. `x` on an existing marked place clears that mark immediately, outside a structural draft; not offered on draft indices. `o` opens the role file outside a dirty draft. Esc exits clean chain focus. Dirty leave (Esc/tab/project/quit) asks inline “Discard edits?”; Enter discards, Esc resumes; a save error keeps the draft. Delay self-reload while dirty as with Settings. The saved “Next” stays distinguishable from a draft preview.
• Add/edit place uses ONE temporary sheet over that inline chain. Fields are Target, Model (or Flow kind), Thinking where applicable; a final Done row. Up/down selects a field; Enter edits it INLINE, without another window. While choosing a value, type to filter, arrows/PgUp/PgDn to select, Enter fills the field and returns to the form; Esc leaves the field unchanged. Done/Enter puts this place in the draft; Esc from the form cancels this place. Target offers enabled compatible pi/CLI targets for a model role with the required instructions, or the compatible browser sites/tools for a browser role; missing executables marked, not called installed. A pi target is simply `pi`: its model field spans providers. Disable selection of off targets but keep existing off places visible/movable/removable in a chain. If switching target would discard advanced launch options, refuse that replacement and offer file open (do not strip `skills`, `pi_args`, `args`, true `split`, etc.). Existing place options/restrictions: `src/roles/role-control.ts:178–220,268–306`. CLI thinking/model values from its catalog; unset is labelled Default. Browser fields reflect the actual adapter: ask uses site/effort, AI Studio model/thinking as supported, Flow image/video, no invented universal thinking (`packages/hud-mcp/bin/hud-jev.mjs:79–100`).
• Harnesses: sections Runner, CLI agents, Browser tools, Pi providers. Each row distinguishes owner on/off from installed/missing (provider: listed/not seen, not an auth claim); a provider under an off runner shows “pi off”, retaining its own switch. Default list = enabled items plus a folded “Off (N)” group. Space/Enter on a target toggles its own switch immediately; `Del` on an enabled item is Remove (= off). `i` = Add back: one filterable list of off IDs; Enter restores, Esc returns unchanged. No destructive delete or install flow. Candidates = compiled CLI adapters, supported browser tools and pi; pi provider prefixes from discovery; also retain referenced explicit providers and stored off IDs so a lapsed subscription can be restored before it reappears. Show missing binaries/sources honestly. A newly supported CLI appears from the adapter table, a newly logged-in pi provider appears on refresh already enabled. No executable names typed by the user; no PATH scan for arbitrary programs. This default is settled in `qa/q2.answer.md:1`.
• Keys across both views outside text entry: ↑↓ or j/k, PgUp/PgDn, Home/End as today; clickable action labels and second click = Enter; wheel scrolls. Split keeps `=`/`+`/`-` sizing and Esc back from preview. `r` refreshes the local model lists; `?` Help, `,` Settings, `q` close, Esc at tab root as on other main tabs. Existing global controls not acting on a Control row keep their normal scope (e.g. no job reply/reap on a role). In a name/filter input printable keys including q, j, k and digits are text, Backspace edits, Enter chooses/submits, Esc or Ctrl+C cancels input; navigation doesn't leak into tab changes. Invalid/colliding name or no matching entry: explain, stay put. Context footer shows only applicable whole hints, full list in Help. Action labels are mouse targets, not just a legend. No `n` shortcut, which is reserved for flagging a try (`docs/reference.md:618–629,645–676`).
• Drop: Project→Control navigation, flat place rows as the main way to find a role, p/P blind harness cycling, e/E blind effort cycling, automatically invented fallback, provider→model drill-down, include/family curation and Tab “show all”. Keep `c/C`, `i`, `Del`, `K/J`, `x`, `r` where their actions still make sense. Tab should never be required to expose more models.

4. Model list and narrow frames

• A successful `pi --list-models` is authoritative for the discovered picker list: parse provider and model into an exact qualified ID; deduplicate ONLY identical IDs. Never collapse families, versions, dates, or different providers selling the same model. Group alphabetically by provider with non-selectable headers/counts, models sorted within each; one list, one selection cursor. Type any case-insensitive substring of the full `provider/model` across all on groups. No need to choose a provider first. Default/unset row for pi resolves and displays its effective source; do not present a known-off default as an on-model choice. An existing unlisted/off model remains visible as the current assignment, not smuggled into search results. No-match text doesn't silently become a different model. Manual file IDs and single-job overrides remain valid even when not discovered. CLI/browser lists retain their separate catalog/default behavior.
• On entering Control use the existing day cache; if absent/stale run one bounded asynchronous discovery batch. `r` explicitly refreshes; coalesce while one is running. No subprocess per key, paint, tick, provider toggle or MCP call. Render current snapshot first. Keep last successful per-source results on command/parse failure, with age/stale notice; if no successful pi result, offer a clearly labelled limited offline catalog (still filter off IDs), not “all models”. Distinguish a successful empty list from failure. A failed pi probe must not inherit a fresh agy timestamp and mask retry on next open. Existing limits/cache/parser: `src/roles/model-discovery.ts:10–69,126–152,196–287`, open/force gating `src/tree-page.ts:517–531,556–560,1328`; today discovery failure can write a cache without pi. Use a keyed index from the same snapshot for grouping/attribution; never filter the disk cache itself.
• At 40 columns, render provider once as group header; one model suffix per result row, highlight current vs cursor distinctly, and pin query + match count. Clip by terminal cells, not bytes; for a long highlighted ID let the selected detail wrap/show the whole ID before accepting. Preserve distinguishing suffixes in list rows (middle ellipsis rather than identical prefixes); hide counts/decorative columns before state/identity. Short role rows show preset and next harness before model/effort; selected detail gives full values. Same actions/words in both layouts; translated controls/statuses (e.g. 已停用 vs 未安装 vs 配额用尽), unchanged IDs, non-colour marks. Current measurement/escaping contract: `docs/ARCHITECTURE.md:399–414`. Test the picker against the full synthetic command output, not the brief's approximate count; align parser and setter acceptance (parser allows up to 128 chars; current edit cap 120: `src/roles/model-discovery.ts:33–48`, `src/roles/role-control.ts:151–154,275–282`).

5. Migration and ownership boundaries

• First open does not rewrite role, preset, harness, quota or pi files, create a subscription list, or prompt for setup. Reuse legacy run/single place, `jev` alias, same-name preset overrides/omission inheritance, and normalized equality display while no selector exists. First intentional edit writes only its owner file; preexisting `catalog.pi.include` has no effect on the picker and need not be removed from user JSON. A before/after read with no disabled IDs must yield the same default chain/next executable on the same machine and clock. `imp` ships default/grok/hydrogen, not neon (`packages/hud-mcp/roles/imp.json:6–25`); local neon needs no special case. Oracle's fable/architect presets illustrate cross-harness vs single-place chains (`packages/hud-mcp/roles/oracle.json:6–23`).
• EXP boundary (owner's latest instruction supersedes `qa/q2.answer.md:3` and the placement in `docs/design/exp-usage-plan.md:3–24`): EXP is its own experimental main tab. It may read Control's machine-wide inventory by stable ID: known pi provider IDs, their effective on/off state, and whether the `cli:codex` adapter is enabled/installed. An adapter ID is not a Codex account/profile or proof of authentication: EXP may join to known profile references from their owning source; Control need not discover or manage profiles. EXP does not own the routing switches. Control retains its existing read-only quota/spend/dispatch radar and hosts NO EXP editors; it does not read EXP balances into fallback policy.
• Scope flags, not implicit spec changes: adding an arbitrary executable/adapter or tuning official harnesses inside a project would exceed §2.1/2.3; “add” here means enable a supported target. If all project-pinned roles must become panel-writable, stop and obtain a separate decision; do not mask the project file with a user override. With a registered project overriding a shipped role, today's loader validates the project's own presets as pi-only BEFORE merging inherited presets (`src/roles/roster.ts:205–220,432–448`); do not turn global preset management into a new project `hud setup` policy. No additional spec exception is needed for Control beyond the owner-authorized tab arrangement.
