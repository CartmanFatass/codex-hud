# Brief B10B-s3: delegation panel, segment 3 (selection, navigation, control bar)

Tier M, rendering. Frontend implementer: Sonnet xhigh. Oracle: Opus max.

Branch `cloud/b10b-s3`, created from `universal-hud` (segment 2 and its rulings were merged on 2026-11-03). You implement; you do not design.

## Why

Segment 2 draws the delegation view, but nothing in it can be selected in production. `renderMonitor` runs `reconcileMonitor` → `reconcileSelection` every frame against the legacy `SubagentTree`. That tree is empty whenever `data.delegation` is non-null, so `state.tree.selectedId` is reset each frame (ruling B10B-s2 Q6, "fact 2").

This segment makes the delegation rows selectable and navigable, and draws the §3.7 control bar for them. Out of scope: the Inspector (§4.11) and the actual execution of side effects. Both are later packages; see "Not yours".

## Goal

1. **Selection over delegation rows.**
   - When `data.delegation` is non-null, `reconcileMonitor` keeps `state.tree.selectedId` if it equals a planned row key: a node key, or a `put:` key.
   - A key that disappeared follows `tree.selectionMap` when it maps to a planned row. This covers an intent binding to its session.
   - A removed `put:` key moves to the nearest planned row at the same position.
   - Otherwise the selection falls back to the first row.
   - When `data.delegation` is null, today's legacy behaviour must stay byte-identical.

2. **Navigation over `plan.rows`.**
   - The existing key and mouse paths — `↑/↓`, `n/N`, `h/l` (fold or unfold through `state.tree.collapsed` by row key), `a` (`showHistory`), `s` (`sortByCreation`), and click — work over the delegation rows.
   - The summary row and the parent row are never selectable.
   - `h/l` on a card in rich draws the collapsed card's `+N (…)` on its head (segment 2 review F6).

3. **Control bar for the selected delegation row (§3.7).**
   - The ⇢ button reads `Open`, `Switch` or `Log`, with the word following the selected row. It is greyed when the §3.7 gate fails: `host.currentState = null`, or a `stateKey` starting with `uncertain:`.
   - The ↻ button appears only when it applies:
     - `Reconcile` when the node's `reconcile` descriptor is non-null;
     - `Resume` on a reported, resumable row, which in the MVP always shows the diagnostic `resume not verified on this machine · ask the parent to delegate_resume`.
   - The `older` button reads `plan.putAway`.
   - Words through `t()`, with EN and ZH entries.

4. **Typed actions, not effects.**
   - `handleMonitorInput` returns new typed `MonitorOutcome.action` values for delegation rows:
     - `delegation-open` (row key);
     - `delegation-log` (row key);
     - `delegation-copy` (carrying the node's `ActionDescriptor` as given, its `displayCommand` included);
     - `delegation-diagnostic` (text).
   - Keys: `o`/Enter for open, `L` for log, `R` for reconcile or resume, exactly as §3.7 separates them.
   - The panel never builds a command string itself. The only command source is the descriptor's `displayCommand` (§3.7, §7 #10).
   - Nothing is executed in this package. Painting, notifications, reconnects or timers never produce an action.

5. **Cleanups carried from segment 2.**
   - `src/render/delegation/facts.ts`:
     - widen the comparator key guard to `/^[A-Za-z_$][\w$]*$/`;
     - drop the stray `eslint-disable` comment;
     - add a test that a fact name containing a digit compares correctly.
   - Segment-1 width order (review F7): at ≤ 39 columns, a row without a state word drops `⊟` before it cuts the name (§3.4, §4.13 32-column sample).
