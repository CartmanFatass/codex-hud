# Brief B12M: metered recovery reads in the observation store (core)

Tier M. Implementer Opus; Oracle Fable max. Branch `cloud/b12m` from `universal-hud`.

## Why

B12's observation store fetches recovery data before checking its size and returns no read statistics, so the HUD
collector cannot charge recovery work to its shared 8 MiB / deadline allowance exactly. B10C now charges a known
inline size as a conservative estimate. The Oracle ruling `docs/reviews/2026-11-02-astra-b10c-worker.md` §4 assigns
the fix to this package.

## Goal

1. Admission before fetch: `readRecovery` size-probes before selecting `projection_body`, the checkpoint body or the
   identity, and refuses to fetch what does not fit the remaining budget. It returns a continuation or a typed refusal,
   not a partial read.
2. Read statistics on every outcome, including continuations and failures that did work:
   `{ bytesRead, recordsRead, elapsedMs }`. State in the type's doc comment whether bytes are logical decoded payload
   or storage I/O. Do not claim physical SQLite I/O from JSON lengths.
3. Metered lazy lookups: `RecoveryIndexLookup.get/page` take the active grant (remaining `ReaderBudget` / deadline) and
   return their value plus statistics. They respect the deadline and size limits.
4. Pinned identity: a lookup obtained at recovery or commit ACK keeps reading the commit it was created for. If that
   commit was replaced, it returns a typed stale result, never another commit's data.
5. Charged once: give callers a per-slice accumulator or an explicit drain, so the lazy use after ACK is charged to the
   currently active collection grant exactly once, with no double counting between reader and collector.
6. **Additive and backward-compatible.**
   - The existing signatures and behaviour stay: the new metered API sits alongside, or takes optional parameters.
   - Every current caller, B10C's included, compiles and behaves the same without changes.
   - B10D adopts the new API later. List the exact call-site changes B10D will need in the report.

## Failure-mode acceptance

Each item is a real test on real SQLite in a temporary `HUD_HOME`.

- An oversized projection, checkpoint body or identity against a small remaining budget: no fetch above the budget,
  and the result is a typed refusal or continuation with statistics.
- A deadline hit inside `page()`: it stops at the deadline and reports statistics, with no partial value presented
  as complete.
- A lookup used after a newer commit replaced its commit: a typed stale result, no data from the new commit.
- Lazy use after ACK under an active grant: charged once (an accumulator test with reader and collector both
  draining).
- A thrown read after partial work: the statistics still report the work done.
- A compatibility caller with no budget arguments: byte-identical results to before (a test against fixtures
  recorded from the pre-change behaviour).
- Performance: the B12 focused suites' timings do not regress; report the size-probe overhead per recovery (p50/p99,
  n ≥ 1000).
