**Additive.** Every existing signature and its no-grant behaviour are unchanged. The compat fixture deep-equals values recorded on the base tree. No current caller changes; B10C compiles and passes unchanged.

**Bytes definition.** `bytesRead` is the logical decoded payload: the UTF-8 length of TEXT values loaded into JS. It is not SQLite storage I/O. Size probes count 0. `recordsRead` counts 1 per checkpoint, per fetched value and per page entry. `elapsedMs` is the grant clock's time, including the read COMMIT.

## Failure-mode tests

- B12M oversized checkpoint body/identity: admission refuses before any fetch, with stats; projection never selected
- B12M deadline inside page(): stops at the deadline with stats and no partial page
- B12M lookup after a replacing commit: typed stale result, no data from the new commit
- B12M lazy use after ACK under an active grant is charged once (reader and collector both drain)
- B12M grant activation is scoped: no interleaved activation, stale deactivators never clear a live grant, close
- B12M metered reads inside an open write transaction run in it instead of nesting BEGIN
- B12M a thrown read after partial work still reports and charges the work done
- B12M compatibility callers without grants match the pre-change recorded fixture

Both Oracles mutated the compiled store, and every observable mutation was caught.

## B10D adoption list (`src/collectors/delegation.ts` at 6fcf08a)

**Invariant.** Collects never interleave on one store, so one grant is active per store; `activateRecoveryGrant` enforces this with `recovery_grant_active`. Grants and lookups never cross threads.

1. **:646 / :702–705: one grant per slice, created before its first use.**
   - Build it as `new RecoveryGrant({ maxBytes, maxRecords, budgetMs } from the remaining shared allowance, { deadline: Math.min(collectionDeadline, this.deadline) })`.
   - Create it just before :674 when `reading.recoveryPending` is set, otherwise right after :705.
   - Use the same grant for the recovery and the read.
2. **:674: `const r = source.store!.readRecoveryMetered(prior, grant)`.** Map each result:
   - `stale` → the `!recovery` path
   - `continuation` → the `'kind' in recovery` path (at :676–677, read `r.continuation.kind` and `.minimumBytes`)
   - `recovered` → `r.recovery`
3. **:678:** replace the conservative charge with `grant.drain()`.
4. **:682–690:** delete the `canonicalJson(inline)` estimate. Take the charge from `grant.drain()` and the next budget from `grant.remaining()`.
5. **:707–710:** wrap the read in `const end = source.store?.activateRecoveryGrant(grant); try { … await reading.reader.read(budget) … } finally { end?.(); }`.
   - The deactivator must always run. A leaked activation is cleared only by `close()`.
   - Slice loss: a lazy read that straddles the deadline, or doesn't fit the remaining bytes, throws `RecoveryReadError` and fails the whole slice.
   - Allowance split: the reader's own file I/O is not charged to the grant during `read()`.
6. **:763–769:** `charged` = `result.stats` + `grant.drain()`.
7. **:772–778 (catch):**
   - Charge `grant.drain()`, plus the reader's budget for the native-read part only.
   - Don't add `RecoveryReadError.stats` again; they are already in the grant.
   - `if (error instanceof RecoveryReadError && error.minimumBytes !== undefined) this.minimumBytes.set(displayNodeKey({ kind: 'session', ref }), error.minimumBytes);`
8. **:785:** `takeUnattributedIO()` is unchanged. Drain once per slice.
