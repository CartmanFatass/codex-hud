## 4. The Node 22 warning: exact mechanism and limits

**Finding G1/F3, P1 acceptance blocker; underlying test-output compatibility defect P2.**

**tests/unit/run-process.test.ts:67–75,92–114 — the fixture routes child stdout and stderr to the same file, then parses the entire file as JSON — Node 22 enabled-envproxy startup diagnostics make the required one-shot case throw — retain failure and resolve through the owning compatibility/integration route.**

There are three distinct levels of output:

1. The outer command's **.stderr** retains the top-level Node runner's UNDICI-EHPA warning.
2. Its **.stdout** is TAP and includes worker warnings as “#” diagnostic lines. Those lines do not themselves fail a test; other tests and the entire serial 44/44 command pass while warnings are present.
3. Inside the failing test, setup passes **stdoutFd: fd and stderrFd: fd** to the group launcher. native-group.ts:21–28 maps those two descriptors to the helper, and group-helper.ts passes inherited stdout/stderr to its workload. The test later executes **JSON.parse(readFileSync(fixture.output, 'utf8'))** at source line 113.

The retained stdout records the failure at lines **132–148**: SyntaxError, **Unexpected token '(', "(node:8298"... is not valid JSON**, at compiled run-process.test.js:98. The raw failure prefix, surrounding UNDICI warning records, source descriptor wiring and report agree with stderr diagnostic bytes being mixed into the supposedly JSON-only file.

The complete internal fixture output file was not published separately and is removed by fixture cleanup. Therefore this review does not claim independent byte-for-byte reconstruction of that file, the exact child PID that emitted its first diagnostic, or an observed full JSON payload. The supported diagnosis is the fixture's stream-merging mechanism, not an invented complete raw trace.

Before that parse, the test had already checked command/scope existence, helper and command PGID binding, exit code 7, null exit signal and dead helper. Those assertions did not fail. The JSON equality for argv/stdin bytes and the following proveGroupGone assertion were not reached successfully in this case. They must not be credited as passing here, nor called proven incorrect.

In the same Node 22 three-file execution, all other **53 tests** pass, including all 20 run-control cases, all 24 RUNZ1 cases and the other nine run-process cases. The independent serial command adds passing controlled-Q and evidence-oracle coverage. Node 24 passes the failing case as part of 54/54.

**Conclusion:** this is not evidence of unsafe KILL behavior, missing stdin EOF, incorrect native status or broken process-group semantics. It is a real required-check failure because the test cannot complete its output assertion under the retained supported profile. The proper remedy preserves stdout/stderr separation and strict payload assertions; it is not to suppress warnings, strip proxy configuration, trim a JSON-looking line or ignore exit 1.

This candidate does not contain the separate NODE22-PROXY fixture change. A pass on that package's different tree cannot be transferred to this candidate.
