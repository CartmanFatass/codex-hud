# Claude print stream child transport: synthetic slice

This is a one-shot, unmanaged direct-child transport and bounded JSONL observer, distinct from Claude transcripts, hooks and managed delegation. It does not establish session ownership, execute a tool on the user's behalf by itself, install configuration, grant capabilities, or wire a panel. Caller must supply an explicitly selected executable, cwd, environment and mode and independently authorize/trust the action. No real Claude client, account, provider or network is required by the tests or demo.

Sources are rolling official documentation read 2026-11-05, **not an executable version pin**: [programmatic Claude Code](https://code.claude.com/docs/en/headless), [CLI reference](https://code.claude.com/docs/en/cli-reference), [SDK result type](https://code.claude.com/docs/en/agent-sdk/typescript#sdkresultmessage) and [hooks](https://code.claude.com/docs/en/hooks). CLI documentation describes `-p`, `--output-format stream-json`, `--verbose`, partial messages, stdin, and resume by session ID; the SDK result documents `subtype`, `is_error` and `session_id`. This reader validates a deliberately small subset, not the full SDK schema. Synthetic records are not captured from a real client.

The caller must choose `default` or `bare`. Default requires an additional explicit `allowDefaultDiscovery: true`: the official docs warn that `-p` may run project hooks and connect project MCP servers without a workspace trust dialog. This flag is a caller assertion, not a trust or authorization verifier. Bare adds `--bare`; it suppresses ordinary auto-discovery and hooks, but is **not a sandbox**. Authentication differs: current official docs say bare does not use subscription OAuth/keychain, while supported provider credentials have their own rules. No authentication behavior is simulated or inferred.

The argv is fixed: `claude [--bare] -p --output-format stream-json --verbose --include-partial-messages [--resume UUID]`. A bounded text prompt goes via stdin; no shell is used. The current headless docs confirm piped stdin with an additional CLI instruction; [historical official SDK documentation](https://docs.anthropic.com/fr/docs/claude-code/sdk) included a stdin-only `-p` example but now redirects. This is documentation evidence, not a live executable verification. Resume accepts only a lowercase canonical UUID and compares `system/init` and `result` session IDs, if present, to it. This comparison is observation, not proof of ownership or of successful resume. Names, paths, option-like IDs and implicit latest are excluded.

The parser retains only session ID, result classification, bounded counts and transport state. It never retains prompt, assistant/tool bodies, hook data, costs or stderr text. Only a single final success result with `is_error: false`, matching session ID, no malformed records or unrecognized top-level event types and clean direct-child close yields `observed_complete`: this is not proof of model execution, task success, MCP work, authorization or external side effects: a result can arise from a zero-turn hook block or local command. Any later frame and multiple-result flow are conservatively unsupported. Unrecognized top-level event types, malformed or incomplete records, and the prior fixture's incomplete `result` stay uncertain. Nested fields and non-init system subtypes are not exhaustively validated. Caller-fed/output data can never promote a capability.

One instance attempts at most one spawn, including failures and aborts. It never auto-retries or falls back. This is not cross-instance or crash-durable idempotency; uncertain effects require caller reconciliation. Input is capped at 1 MiB, stdout is bounded to 64 KiB/record and 4 MiB total, stderr is drained and capped at 1 MiB (count only). Node stream buffering handles the bounded stdin write; a finished write is required for completion but does not prove that the child consumed it. Timeout, abort, IO error or output limit requests SIGTERM and then SIGKILL for the direct child only; a bounded close wait may return without close proof. Even a direct-child close does not prove that descendants or external work stopped. Nothing here is a performance guarantee.

Run under Node 22 >= 22.13 or Node 24 with temporary HOME/HUD_HOME:

```sh
npm run build && npm run build:test
node --test dist-test/tests/unit/claude-print-transport.test.js
node scripts/demo-claude-print-transport.mjs
```

Tests start only a synthetic executable, including the prior documented-contract fixture, and cover exact argv/stdin, both discovery modes, resume match/mismatch, result errors/missing/unknown, UTF-8 framing, child exit/abort/timeout, output bounds and one-instance no-retry. They do not establish live Claude compatibility, full M2 completion or managed capability readiness.
