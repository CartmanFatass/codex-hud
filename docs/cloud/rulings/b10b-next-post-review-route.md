## 4. Alternative causes and the existing-artifact discriminator

There are several plausible contributors, which the current evidence does not collapse into one explanation:

1. **Residual changed-view work.** Fresh cloned identities still require topology/maps/PNode/subtree construction, complete fact extraction/comparison, aggregate computation, plans and row layout. Fewer fact records do not remove those costs. Relation-group copy/sort, shortRefOf value construction and session-cost preparation are concrete source sites, but a hot enclosing function alone does not choose one as the next remedy.
2. **Allocation/GC timing across workload phases.** structuredClone preparation is outside each measured sample but inside the same allocating process. Required new snapshot containers and caller-held older frames remain legitimate. Their allocation can affect later collections. It is not valid to move work across the frozen boundary, force GC, or infer a leak from sampled old-space/RSS.
3. **Runtime/JIT/object-shape effects.** Node 22/24 differ, and the fixed initializer adds writes on allocation/all-miss paths. This is a hypothesis, not a demonstrated deoptimization, regression or reason to drop a runtime or tune flags.
4. **Scheduling/resource effects.** Host differences, quotas, descheduling or external load could contribute to the long excursions. Before/after load snapshots and separately namespaced process views do not establish continuous isolation or identify the cause. A quiet snapshot, a passing workstation run or a multi-second outlier is not proof of host contention.
5. **Artifact/environment attribution.** NEXT-E1 prevents offering the dispatcher run as complete independent verification. It does not invalidate the separately well-identified implementer Node 24 failures. NODE_USE_ENV_PROXY was cleared in the NEXT strict protocol; old-target proxy-output failures do not explain those timing failures.
