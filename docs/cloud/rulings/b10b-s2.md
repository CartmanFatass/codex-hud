Two facts in the code shape several answers:

1. With a HUD home that holds `ledger.sqlite`, `HudDelegationCollector.open` returns a collector (`existingHudHome` requires the file) and `tree-page.ts` **does not build the legacy `SubagentTree` at all** (`tree = rootId && !delegation ? build… : { rootId, nodes: [] }`, ≈ lines 988–1005, B10A commit ca45a21): the native children travel in the view model as `edge = 'native'` nodes. On such a machine "today's agents view" is already an empty pane; the only tree data is `data.delegation`.

With `delegation` non-null that tree is empty, so `state.tree.selectedId` is null in production until segment 3 changes that path.

"Touches" names what a ruling reaches outside `src/render/**` + `tests/unit/b10b-s2-*`: *none*; *design doc* (a text or sample amendment for the owner — the implementation follows the ruling now, the amendment does not block); *data layer* (an open item for B9/B16 with no contract change; goes in the handoff). No ruling below changes a contract.

## Q1 — when the delegation view is drawn

**Decision.** The agents view (rich and compact) is the delegation view whenever `data.delegation` is non-null; the legacy view only when it is `undefined`/`null`. No content heuristic (not "has a delegated edge", not "has an intent", not "has a job").

**Reason.** Fact 1: on a ledger machine the legacy tree is empty, so (B) would draw `No agents started in this session yet` for a session whose native agents sit in the VM. The byte-identity acceptance (#4) is exactly the null case, which is the no-HUD-home / no-ledger case. A heuristic would relayout the whole pane at the first intent and is a guess (§0.1 #2; §5.4: the accordion is the only automatic layout change). §4.3/§4.4 "as today" means the same structure — the foot status card untouched (it is `planFoot`, not part of `agentsView`), cards, `!` first, `◷` clocks — not byte identity.

Sub-question: the legacy view keeps today's `✓1 ▸1 · 2 subtasks, 1 failed · ~42 tok/s` untouched; the delegation view's summary row is §4.2's (`1▸ 1✓ …`, see Q4), in (b) too.

**Hook.** None in `tree-page.ts`. `renderMonitor` already receives `hud = hudStatus.current()`, which `tree-page.ts` extends with `delegation` (`Object.assign(built, { delegation })`, ≈ lines 1037 and 1058, both before `render()`). Read `input.hud?.delegation`; widen `MonitorData.hud` to `HudData & HudDelegationData` in `src/render/monitor.ts` (type only; `HudData` is assignable to it). Report the hook as "none". B10D changes the collector wiring in `tree-page.ts`; the panel's rule ("non-null VM") must not depend on how the VM gets there.

No viewpoint root in the VM (`proj.roots` empty: session id unresolved, or the ledger degraded with no prior snapshot): draw the summary row (empty counts, chips per Q4 v); add today's `emptyAgentsRows` lines only when `tree.ledger.state === 'available'` and the legacy `tree.rootId` is known — an unreadable ledger is not "no agents".

**Acceptance.** #4 unchanged. (a) and (b) are scenarios of the delegation view: new baselines, not today's frames. Unit test: a VM with a root and natives only → delegation view; `delegation: null` and `undefined` → output byte-identical to the legacy call.

**Touches.** None.

- `⚑` rows: the pending word alone (`⚑ approval` / `question` / `needs human` / `blocked`). `stop in pane` rows: the contract sentence as §3.4/§3.5 already define (card: full sentence, word-wrapped ≤ 3 lines at 48 / 2 at 80; micro card `⚑ Still running — stop this run in its pane`, under 40 columns `⚑ running · stop in pane`).
- `?` rows: `? <state word>` plus `: <cause words>` when the cause is not the state word's own (`? uncertain: scope unknown`; `? supervisor lost` — `supervisor_dead` is the word itself), then any `reconciliation.missing` entry that is not the cause, humanised (underscores → spaces, through `t()`). Cause words: `supervisor_dead` → `supervisor lost` (`W`); the other `ReconciliationCause` values underscores → spaces, ZH entries added to `i18n.ts` (scope unknown 范围未知 · resume ref mismatch 恢复引用不符 · clock anomaly 时钟异常 · supervisor stale 托管过期 · submission unknown 提交未知 · cancel unconfirmed 取消未确认 · identity conflict 身份冲突 · scope conflict 范围冲突 · provisional conflict 占位冲突 · launch timeout 启动超时 · unknown 未知). Every producer today sets `missing = [cause]` (`src/core/link/execution.ts`, `src/ledger/delegation-read.ts`), so the sample's `no receipt` cannot be derived: no invented `no …` prefix. `slot held` is a delegation-line element (Q3) and is not repeated on line 2.
- Report line: `✓ <summary>` / `! <summary>` (flattened as the rows do); `· exit 1` / `· signal TERM` only with `exitSource` and a non-zero code or a signal (§3.3 row 4); terminal without a report: `ended · no report [· <cause word>] · exit unknown`, plus `cancel timing unknown` / `retire timing unknown` from `execution.terminal.note` (§3.3 row 9a). All of these are in the VM.
- Micro card: line 1 = the delegation line (Q3), delegated and intent nodes only; line 2 by §3.4's priority: stop-in-pane sentence > pending/fault reason > report summary or terminal facts. Conflict rows: line 2 only, `⚠ conflict: N records · since ~6m` (§1). Root and natives: line 2 only; nothing available → no micro card lines at all (no empty line).

**Reason.** `ObservationView` carries status, run, report, link, host, spend, workspace, model/effort/context and nothing model-written; `pendingReason` is an enum. §0.1 #2: leave empty, draw no placeholder.

**Acceptance.** The (a)–(h) comparisons exclude the brief/action/rate lines and the native sub-rows' digests (`Verified boundary fix.`); the pending line is the word alone. New baselines are drawn from the fixtures accordingly. Facts added to `facts.ts` (cost quality, workspace, run seq, heartbeat, bound time…) each get a row in the `b10b-cache` table, as the groundwork did.

**Touches.** Data layer (open item, no contract change): `ObservationView` lacks `action`, `brief`, `outputRate` and the natives' digest (§1 rows "brief", "当前动作 / 工具", "速率"; §4.5 sub-row); `reconciliation.missing` has no vocabulary of its own. Design doc: the samples carry these lines; no text change needed.

## Q3 — the delegation line

**Decision.** Grammar, every element only when known, `·` between elements (`-` in ASCII):

`role · host · time [· run N] [· heartbeat <age>] [· $cost] [· in <dir>] [· slot held] [· close pane]`

- `role`: `link.role` through `monitorText`; empty → element absent.
- `host`: `pane <label>` from `host.currentState.label` only (a visible run without a verified pane writes nothing, §1); `⊟ headless` when `run.mode = headless`; absent once `isRunTerminal` (samples: `writer · reported 2m`).
- `time`, exactly one: `reported <age>` when this run has a report (`latestReportForRun.createdAt`); else `handshake` (link `pending`) / `handshake claimed` (link `claimed`); else `bound <age>` from `link.boundAt` (null → the word `bound` alone, never an invented age). Intent node: `handshake` / `handshake claimed`. An extra intent root (parent unresolved): line 1 is `parent unconfirmed` (§3.1) and nothing else.
- `run N`: `run.runSeq` when > 1, at every width (§0.2; the 80-column sample's `run 1` is not followed).
- `heartbeat <age>`: from 80 columns, run alive (`starting/running/cancelling/uncertain`) and `heartbeatAt` known.
- `$cost`: `spent.costUsd` — `$0.12` reported, `~$0.12` estimated, nothing when unknown.
- `in <dir>`: managed nodes only, when the node's normalised `workspace.worktreeRoot` differs from the viewpoint root's; name = `workspace.worktree`, else the basename of `worktreeRoot`; a root unknown → compare normalised `cwd` (name = its basename); both unknown → `in ?` (§1: unknown is not equal). Never on natives or intents.
- `slot held`: `run.state = uncertain` (supervisor lost included); warning ink.
- `close pane`: `marker.closePane`; text ink (§5.2).
- Other ink: role text; host, time, run, heartbeat, cost, dir muted.

Shedding, right to left, the line never wraps: `in <dir>` → `$cost` → `heartbeat` → the time's word (`bound 14m` → `14m`, `reported 8m` → `8m`, `handshake claimed` → `claimed`) → the time altogether → `run N` → host → then the role is cut (`…`, ≥ 4 cells). `slot held` and `close pane` are never shed; when `role · slot held` does not fit, the role is cut. This reproduces `implementer · pane 4 · 14m` at 32 and `implementer · ⊟ headless · run 2 · slot held` at 48 (time shed before `run N`, as §4.8 shows).

**Reason.** §3.5's grammar is the rule; the samples disagree among themselves (the (c) card drops the time, its micro card shows `· 2m`). One grammar, one shedding order; the age is on the row clock or card foot anyway, so the time is cheap to shed.

**Acceptance.** Element and shedding tests at 32/40/48/56/80. Sample deviations accepted in the new baselines: (c) `reviewer · ⊟ headless · bound 2m · $0.12` (card and micro card alike); (d)/(e) `… · bound 14m · slot held` where it fits. Extend `tests/fixtures/b10b-delegation.ts` additively (`workspace`, `runSeq`, `boundAt`) so `in ?` does not appear on every synthetic node; existing `b10b-*` tests stay green.

**Touches.** Design doc: sample strings in §4.5, §4.7, §4.8 (amendment for the owner, non-blocking).

## Q4 — summary row

**Decision.**

(i) `workers` = nodes on the list that are delegated sessions, intents or conflict children (one per `childKey`), not the root, not natives, not inside a put-away subtree; `jobs` = job nodes likewise. Written `3 workers, 1 job` with `t()` singular/plural (`{n} worker` / `{n} workers`, `{n} job` / `{n} jobs`; ZH `委派` / `作业`), absent when both are zero. Conflict children without a row (`omittedConflicts`) are not workers — they are "not loaded".

(ii) `N put away` from `plan.putAway` when > 0 (ZH `已收起`).

(iii) No rate.

(iv) `N not loaded`: N = `tree.counts.knownUnloaded + tree.counts.omitted + proj.omittedConflictRows`, when > 0. `tree partial` only when N = 0 and the tree's coverage is not complete (`tree.coverage.state` partial, or `tree.counts.unknownDescendants`); the two are exclusive by construction, so §4.2's precedence applies only between them and the ledger chips.

(v) `tree.ledger.state = 'degraded'`: reason `ledger_busy` → `ledger busy`, muted, always; any other reason (`ledger_unavailable`, `ledger_identity_changed`, `ledger_closed`, …) → `ledger unavailable`, muted for the first 30 s of continuous degradation and warning after (§7 #14), timed by one render-local first-seen stamp in the summary module (set on the first tick with a non-busy degraded reason, cleared when the ledger is `available` or the reason is `ledger_busy`; `nowMs` is the clock, so tests drive it). A presentation debounce like the fades, not a dwell time.

Order: `counts · [slots N/N] · [one coverage chip] · [workers, jobs] · [put away] · [spend]`. Counts and chips never shed (chip precedence: `slots` first — only when full, segment 1's `slotsAlert`; then `ledger unavailable` > `ledger busy` > `tree partial` > `N not loaded`); shed, in order, `put away` → `workers, jobs` → spend (`spendText`). Counts are segment 1's `proj.counts` through `countParts` — the bar's rule: every node but the root, natives and put-away history included, `■` with `✓` — so (b) reads `2▸ 1✗ 1✓`, not `1▸ 1✓ · 2 subtasks, 1 failed`: the "subtasks" figure is not used in the delegation view, natives are in the counts (§0.5 #1, one notation with the bar, §0.2). The pane title (tabs layout) uses the same text; today's worded form (`▸1 run`) is not used.

**Reason.** (g) and (c) fix (i)/(ii); the bar already counts every node (segment 1, accepted) and §0.2 wants one notation; §7 #14 fixes (v), and a render-side stamp is the only way to honour its 30 s without a data change.

**Acceptance.** Tests per chip, precedence, (i)/(ii) counting (put-away subtree excluded, a conflict child once), the 30 s flip, shedding at 32–56; the summary strings of (c)(d)(e)(g)(h) as sampled except no rate; (b) `2▸ 1✗ 1✓`; (e) `5 workers, 1 job` includes the conflict child.

**Touches.** Design doc: §4.2 gains `put away` in the drop order and the `tree partial` / `N not loaded` exclusivity; §4.4's summary string (amendments for the owner, non-blocking).

## Q7 — ASCII kind icons

**Decision.** (A): under `icons=text` the kind slot is blank, and the icon column exists only when the tree is cross-harness (harness letters for sessions, a blank for natives) or when some row has a kind icon *in the glyph set in use* — so a single-harness tree draws no slot column at all in ASCII (`kindIcons` says what the data has; `slotText` decides the column from the glyph set). The `◈N` chip in ASCII is `rN`.

**Reason.** §5.3: `icons=text` switches the whole table, and the table has no ASCII column for kinds; "缺席时留空" is defined behaviour and needs no design change. Letters would add six symbols to §5.3 and share the column with the harness letters. Today's `agent-title.ts` drawing `KIND_GLYPHS` regardless of the icon set is a legacy inconsistency, untouched here (delegation null stays byte-identical).

**Acceptance.** ASCII tests: no slot column for a natives-only tree; blank native slot and `C X P J` session slots in a cross-harness tree; `r2` chip.

**Touches.** Design doc only if an ASCII kind column (`R E F V W S`) is wanted later; not needed now.

## Q9 — the top parent row

**Decision.** Drawn only when the viewpoint root has an as-child relation (an entry of `tree.relations` whose `childKey` is the root's key: prefer `confirmed`, else `intent`, else the newest by `link.createdAt`) or `root.parent !== null`. One row above the summary row, pinned with it (the agents pane's `pinned` becomes 2). Forms:

- confirmed (`link.parentRef` non-null): `↑ parent <mark> <name> [· pane N] [· <state>] [· bound <age>]` — mark = the parent's harness; name = `root.parent.name` when B9 gives it, else the parent's session short form (`claude:a7f3`, `shortRefOf`: a last-resort name, not a guess); `pane N` = `root.parent.paneLabel` only (never the relation's `host`, which is the root's own); state = `offline <age> · <policy>` from the relation's `parentOffline` (or `details[root].parentOffline`), else `exited` when `root.parent.liveness = 'gone'`, else no word (alive/unknown: no activity word, never `working`); `bound <age>` from `link.boundAt`.
- the root's own run visible and `cancelling`: `↑ parent <mark> <name> · asked to cancel <age> · stop here` (age from `cancelRequestedAt`; replaces the state word; `asked to cancel` alert, `stop here` text).
- unconfirmed (`link.parentRef` null): `↑ parent ? unconfirmed · caller <head>`, head = the first 8 characters of `link.parentCaller` (hud-mcp mints it with `randomUUID()`, `packages/hud-mcp/src/registry.ts`: no pid or path inside; the same head rule as the intent key), no harness mark.

Shedding (§4.6): `bound <age>` → `stop here` → `pane N` → state word → name cut (≥ 8). Ink: `↑ parent` and the mark muted; name text; `offline` / `exited` warning; `unconfirmed` muted.

**Reason.** `LinkTreeNode.parent` is filled only when the parent is a node of the tree (`src/core/link/index.ts` ≈ 412–424), so in the delegatee's view the root has no parent name, liveness or pane; the as-child link in `relations[]` has the parent's ref, bound time and offline event. §0.1 #2: no activity word without an activity fact.

**Acceptance.** Tests for the four forms, the pinned position and the shedding at 32/48. Fixture: add an as-child relation for the root (additive).

**Touches.** Data layer (open item, §7 #20): B9 to fill `node.parent` for the viewpoint root from its as-child link (name, liveness, verified pane); until then the row shows the parent's short form and no pane/activity.

## Q10 — natives inside rich cards; the root card

**Decision.**

- Rich always draws the viewpoint root as a card when the VM has a root, at indent 0; depth-1 cards indent 2, depth-2 indent 4, up to depth 4; deeper nodes are `↳` rows at the depth-4 indent, as compact. The root card's body has no line unless Q2 gives one, so it is header + foot. Compact keeps segment 1's root row.
- A native whose parent is the viewpoint root is a card (today's L1 card); every other native is a sub-row of the nearest ancestor that has a card (its delegated session's card, or its L1-native card): descendants at any depth inside the card, as today.
- Sub-row: `<marker> [<kind icon>] <name> [· <state word>, trouble rows] … <clock>`, no tree prefix; a badge only when the native's model differs from the card's (≥ 40 columns); no meter; clock and ink as the compact row's. Order: `compareSiblings`, depth-first.
- At most 5 sub-rows per card at every width; the rest fold into one line `+N (1⚑ 2▸)` (segment 1's `foldTexts`, long form; `+N? (…)` when `childrenUnknown`); nothing folded but `childrenUnknown` → one muted line `children unknown`. No `2 working · 1 done` line and no role line: natives carry `kind`, not `role`, and the fold line carries the counts.
- Accordion (§3.5): cards = the root, delegated/intent/job/conflict cards and root-native cards; the folded form is the card's `renderRow` output with `─` in the frame column; sub-rows fold with their card; fold order `✓ ■` → unselected `▸ ·` → the root; `⚑ ? ⚠ !` and the selected card never fold automatically.

**Reason.** (c)/(d)/(h) draw the root card and the accordion names it ("最后根"); a root card only once delegations exist would relayout the pane at the first intent. The foot status card (untouched) keeps the root's brief and alerts; the duplicated clock and meter are what (c)/(h) show. (b) is "as today" and `docs/reference.md` says one card per L1; §4.5's cc sub-row example is read as a native under a delegated cc session's card (cc native topology is deferred this period, §7 #33).

**Acceptance.** (b) baseline: root card, two native cards with their sub-rows (`! failed_子` first, then `▸ running_子`), summary `2▸ 1✗ 1✓`; (c): the impl-parser card with two native sub-rows; a card with 7 natives → 5 sub-rows + `+2 (…)`; a `childrenUnknown` card; the accordion order.

**Touches.** Design doc: §3.5 count line not drawn, root card always, root natives as cards (amendments for the owner, non-blocking).
