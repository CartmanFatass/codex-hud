Record actual parameters and successful protocol responses. Do not silently fall back to surviving-object-only sampling, which cannot answer the disposable-record question. 6. **Memory and GC completion.** Use heap-space statistics and process memory/RSS readings, not heap snapshots or forced collection. Take readings at population boundaries and after every 50 measured samples, identically on both arms and outside timed bodies; record their actual times. Subscribe to GC entries before the workload. After recorded workload completion, perform a one-shot delayed drain of at least 100 ms, consume remaining takeRecords entries before disconnecting, and record drain completion and collection errors. Keep workload-end and drain/export intervals distinct. Node delivers observer callbacks asynchronously, and takeRecords returns and clears queued entries. [Node performance observers](https://nodejs.org/docs/latest-v24.x/api/perf_hooks.html#class-performanceobserver). A delay is not proof of perfect coverage. Empty or undrained GC output is an unavailable/inconclusive GC observation, not evidence of no GC; no artificial allocation storm or forced collection may manufacture a positive control.

Clear and record NO_COLOR, FORCE_COLOR, NODE_USE_ENV_PROXY and NODE_OPTIONS; select the same exact Node/npm paths and versions. Record UTC start/end, exits, actual paths, OS/kernel/CPU/host and observable load limits. Reserve a serialized window with no other agent-controlled builds/tests/benchmarks; quiet snapshots are not continuous host isolation. No unrelated process termination, permission bypass or assistant-run local testing is released.

Short-reference and other value-producing work still exists. Disclose inlining, sampling, unassigned frames and attribution uncertainty.

Scope changed rows-only allocation stacks separately from clone preparation and whole-renderMonitor work where the recorded stacks support that separation. Sample labels alone do not give heap samples timestamps. If every-row and 60-row calls or warm-ups remain inseparable in allocation stacks, report their combined scope explicitly, as the earlier brief did; do not claim gated-only or per-timed-sample byte totals. The protocol's heap sample ordinal is an ordering identifier, not a sample timestamp. [Sampling profile schema](https://raw.githubusercontent.com/ChromeDevTools/devtools-protocol/master/json/js_protocol.json).

For changed-path CPU, report scoped sampled observations and the mapping used. For GC, calculate time overlap against sample intervals, merging overlapping GC intervals before summing; report the denominator and selection rule, including the slowest ten measured samples per changed population if used. Overlap is temporal correlation, not causal decomposition or CPU time. Never subtract it from strict durations. Memory readings establish sampled heap-space/RSS levels and sampled maxima, not exact peaks, retained-byte bounds, heap-root reachability or a leak.

The mechanism claim must combine source/lifetime reasoning, §7 correctness guards and the paired observations. The code must still extract and compare every fact, transfer a scratch record permanently on a miss, and retain at most one extra temporary record within a build pass. For a fully compared equal pass, the intended bound is at most one disposable full record; with M misses, at most M retained records plus one temporary record. These are algorithmic ownership bounds, not conclusions obtainable by dividing sampled bytes. The single pair may support reduced record-materialization pressure; it cannot prove an exact allocation count, universal CPU/GC improvement or reliable strict tail compliance. No numerical allocation-reduction acceptance threshold is added.

## Fixed-shape initializer clarification

Permit one private, narrowly scoped in-file allocator returning an ordinary, freshly allocated, fully typed 66-field literal of inert primitive defaults, immediately filled by the single authoritative extraction-assignment path. It fits §5's permitted facts-materialization helper. Duplicating schema/key names in this initializer is not duplicating the input-extraction expressions.

Conditions:

- Allocate only when no opt-in buffer is supplied. A refill must allocate no second full record, temporary literal or Object.assign source. No module-level reusable record, pool, class, shared mutable template or extra cache is introduced.
- Preserve the existing normal object prototype, exact own enumerable key set and key order. The initializer must be checked as a complete NodeFacts literal, not an incomplete object made acceptable with a type assertion or any.
- Every successful extraction writes all 66 fields unconditionally through the one authoritative path, including null/false/absent transitions, before comparison, return or cache publication. No consumer may observe inert defaults as extracted values. Schema, fact values, shortRefOf, metric behavior, factsEqual, comparatorFor and FACT_NAME stay unchanged.
- Default nodeFacts calls remain independent fresh records. Equal hits retain old cache facts untouched; misses transfer ownership and clear the local scratch reference before further refill. The allocator is private; disclose only the permitted optional final buffer parameter as the API change.
- Compile-time completeness of the initializer proves key presence, not complete refill assignment. Keep the existing field/value and comparator coverage, add incompatible-shape refill coverage and lifetime/alias guards in the already-owned test files, and do not rely solely on fresh-vs-refill equality when both use the same possibly incomplete extraction path. Verify expectations against existing independent field-value coverage and the frozen baseline semantics.

This selects the typed initializer rather than the empty-object assertion alternative. It does **not** establish that property-by-property growth necessarily produces dictionary storage on the selected V8, nor guarantee that literal initialization is faster. Extra default writes on allocation and all-cold/all-miss cost remain real and must be included in the unchanged measurements. An unfavorable result does not authorize a shape experiment or another mechanism.
