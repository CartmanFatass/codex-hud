# 示例代码审核清单（通用版）

用于 PR / 代码变更前的示例化审核清单，可按项目裁剪。

## 一、变更背景与风险

- [ ] 是否明确了本次变更的目标、影响范围和验收标准？
- [ ] 是否存在跨模块、跨服务的兼容性影响（接口、Schema、配置、数据库）？
- [ ] 是否确认本次变更不会违反现有行为约定（向后兼容）？

## 二、功能正确性

- [ ] 新逻辑是否有明确的边界条件处理（空值、非法输入、边界值）？
- [ ] 分支条件是否完整且互斥，是否存在缺失返回路径？
- [ ] 异常处理是否完整、信息是否可追踪（含上下文）？
- [ ] 是否避免了错误地吞掉异常或静默失败？
- [ ] 是否有与既有特性一致的行为（幂等性、默认值、单位、时间格式）？

## 三、可维护性与可读性

- [ ] 命名是否清晰反映业务意图，是否避免缩写/歧义变量？
- [ ] 复杂逻辑是否有必要的注释、类型注解或分解为小函数？
- [ ] 控制流是否可读，是否有重复代码可抽象？
- [ ] 是否遵循项目既定代码风格和 lint/format 规则？
- [ ] 是否减少了“魔法值”，用常量/配置替代硬编码？

## 四、性能与资源

- [ ] 是否避免了明显的重复计算、全量扫描、N+1、重复 I/O？
- [ ] 是否存在潜在阻塞点（同步等待、长事务、大对象遍历）？
- [ ] 缓存失效策略是否明确，是否有必要时引入缓存/异步化？
- [ ] 是否会引入明显的内存泄漏风险（未释放定时器、事件监听、连接）？

## 五、安全与合规

- [ ] 输入是否经过校验与清洗，是否防止注入类问题？
- [ ] 权限与鉴权路径是否保持最小权限原则？
- [ ] 敏感数据（token、密码、个人信息）是否被遮蔽/不落盘/不明文输出？
- [ ] 日志是否避免输出高敏感信息（PII、密钥、内部路径）？
- [ ] 是否遵守项目的安全与合规检查清单（如有）？

## 六、测试与验证

- [ ] 是否新增或更新了单元测试覆盖关键分支路径？
- [ ] 是否有边界值/错误路径/回归场景测试？
- [ ] 是否有集成或端到端测试覆盖跨系统交互？
- [ ] 本地/CI 是否有可复现的验证步骤？
- [ ] 新增/变更功能是否有回归用例并通过？

## 七、文档与可观测性

- [ ] 是否同步更新相关文档、接口说明、API 示例？
- [ ] 是否在关键路径新增日志、指标或追踪点，便于线上排障？
- [ ] 是否更新配置说明与运维手册中的注意事项？
- [ ] 是否明确说明回滚条件与回滚步骤（需要时）？

## 八、上线与运维准备

- [ ] 是否配置了必要的环境变量、特性开关或迁移步骤？
- [ ] 是否评估了灰度/回滚风险和监控告警阈值？
- [ ] 是否确认未遗漏数据库/依赖/脚本变更的发布顺序？
- [ ] 是否获得代码评审人、测试负责人和需求方的确认？

## 九、最终确认（审核通过前）

- [ ] 变更是否有清晰的“为什么这样写”说明（非个人偏好）？
- [ ] 是否有至少一个反对意见处理记录（风险、替代方案、取舍）？
- [ ] 是否符合本项目“不得新增未修复的关键 TODO”原则？
- [ ] Reviewer 是否在 `approve` 前再次检查了关键风险项并打勾？
