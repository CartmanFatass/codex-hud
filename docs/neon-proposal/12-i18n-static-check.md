## 1. 背景与现状证据

### 1.1 词典结构
- `src/render/i18n.ts:1-12`：英文原文就是键；中文缺失时回退英文，不会报错。
- `src/render/i18n.ts:40-42`：`const ZH = { ...WORKBOARD_ZH, ...SPLIT_ZH, <自有词条> }`。对象字面量里**后写的键覆盖先写的**，所以 `i18n.ts` 的自有词条会悄悄覆盖两个子词典里的同名键。
- 同一个对象字面量里写重复键，`tsc` 已经会报错（TS1117）；但跨文件经 spread 的重复，**编译器发现不了**。
- `src/render/i18n.ts:616` 的 `EN_OVERRIDES`（2 条）与 `:622-627` 的 `t()`。

### 1.3 为什么不做死键检查
150 处非字面量调用意味着许多键只在运行时拼出来，静态判定「未使用」会大量误报。为此维护一张白名单，代价高于收益。

## 2. 目标与非目标

### 目标
1. 新增一个单测：任何键出现在多于一个中文词典（`ZH` 自有、`WORKBOARD_ZH`、`SPLIT_ZH`）时失败，并打印文件和行号。
2. 同一个单测：`src/**/*.ts` 中，从 `i18n.js` 导入的 `t` 以字符串字面量调用时，键必须在三个中文词典的并集中，或者在测试内的小白名单里；否则失败，并打印调用位置。
3. 一次性清掉现有 19 处重复，让测试第一次运行就是绿的。

### 非目标
- 不合并三个词典文件，不改 `t()` 的运行时行为和回退策略。
- 不做死键（未使用词条）检查。
- 不检查非字面量调用。
- 不改英文文案，不新增语言。

## 3. 核心设计方案

### 3.1 测试文件 `tests/unit/i18n-dictionaries.test.mjs`
- 读取**源文件**（`src/render/*.ts`），不读编译产物：`ZH` 没有导出，而且 spread 在运行时已经把重复抹平了。用 `typescript` 的 `createSourceFile` 解析 AST，取三个变量初始化器里的 `PropertyAssignment` 键和行号。
- 重复检查：建 `Map<key, location[]>`，长度大于 1 即失败；报错信息列出全部位置，便于一次修完。
- 覆盖检查：遍历 `src/**/*.ts`，只看 import 了 `./i18n.js` 或 `../render/i18n.js` 等路径中 `t` 的文件（共 40 个），收集 `t('…')` 与无替换的模板字面量 `` t(`…`) ``。
- 白名单：测试里一个常量数组，初始为空，只放刻意不译的键（例如品牌名，见 §6 Q2）。
- 运行开销：解析约 256 个源文件，预计 < 1 秒；不读写任何 HOME、HUD_HOME，不需要临时目录。

### 3.2 重复词条的清理规则
- **值相同的 12 处**：删掉子词典（`workboard-i18n.ts`、`split-i18n.ts`）里的那条，保留 `i18n.ts`。显示零变化。
- **值不同的 7 处**：推荐默认**保留当前实际显示的值**（`i18n.ts` 那条），删掉子词典里被覆盖的那条，显示零变化。如果 Owner 想改用子词典的措辞（例如 `parent` → 父代理），在 §6 Q1 里逐条点名，改 `i18n.ts` 的值即可。
