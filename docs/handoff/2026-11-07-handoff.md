## 1. What the product is now

Scope converged on 2026-11-07 (concept §15, "Scope convergence: fixed roles, herdr execution, owned Jev"). Pro's rulings are in
`docs/reviews/2026-11-07-pro-scope-1-observer.md` (superseded) and `docs/reviews/2026-11-07-pro-scope-2-fixed-roles.md` (final).

- **Five fixed roles:**
  - `oracle`, with two slots: `oracle.propose` and `oracle.converge`;
  - `imp`;
  - `reviewer`;
  - `sonic` (fast, light work: small patches, exploration, tests, search);
  - `jev` (our browser automation: web oracles, browse, page judgments).
- **Bindings:** `$HUD_HOME/routing.toml` holds backend profiles, presets and Jev decision profiles. A preset is selected per main session, and a switch affects future jobs only. Example: `docs/examples/routing.toml`.
- **MCP surface:** six static tools, `hud_roster`, `hud_create`, `hud_read`, `hud_send`, `hud_respond` and `hud_close`. They are served only when `HUD_MCP_SURFACE=roles` is set; default sessions keep the old `managed_*` and `jev_*` tools until R6.
- **Executors:**
  - herdr runs CLI agents through four launch adapters chosen by the profile's `recipe`: `pi-role`, `codex-zsh` (with `wrapper` `codex` or `codex2`), `grok` and `claude`.
  - A lazy Jev-only runtime (one per HUD home, private socket, idle exit) runs browser jobs.
- **Chaining:** the main session and the `hud-delegate` skill chain every step. HUD never advances a step.
- **Deferred:** WF1 (the workflow engine) is deferred in full. The general native agent host in `native-hud-v2` is superseded.

- **Reviews:** an Opus subagent at high effort, with a fresh one-shot brief per review or re-check. Never stop a running agent.
- **Implementation:**
  - Grok 4.7 high is the default, but its weekly limit is used up;
  - the owner chose to wait for Codex for R4;
  - pi imp handles tests and ordinary, short, well-specified segments.
- **Autonomy:** the orchestrator adopts Pro's and the reviewer's recommendations and commits and pushes at sensible boundaries without asking. The owner is asked only about real conflicts or irreversible, outward-facing steps.
- **jev-ask:**
  - one send per key;
  - after a send, read `jev-ask status` before claiming anything;
  - an `uncertain` key gets only `wait` or `reconcile`;
  - to continue a conversation, pass its URL to `--conversation`; the URL is read from the local record and never printed.
- **Public repo:** synthetic data only. No home paths, account names, conversation URLs or keys in committed files. Never commit `node_modules/.package-lock.json`. `node_modules` is tracked, so a worktree with a symlinked `node_modules` shows deletions; never commit those.
