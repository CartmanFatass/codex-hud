# 0.1.2

`hud setup` writes a project's worker config under `.hud/` (meant to be committed)
and registers that root in `$HUD_HOME/projects.json`. `--detect` prints the current
roles and skills; `--apply PLAN` writes the plan; `--remove` drops the registration
and leaves `.hud/` in place. An unregistered `.hud/` is ignored.

Customisation is pi only: model, thinking, pi role, worker skills (symlinks under
`.hud/skills/`, passed as `--skill`) and an optional `.hud/agents/<role>.md`
worker prompt. Other harnesses' roles can only be shown or hidden. A skill whose
frontmatter sets `disable-model-invocation: true` is reported as not model-invocable:
pi loads it, but a worker will not pick it by itself.

The `hud-setup` skill, installed with `hud-delegate` for Claude, Codex and pi,
asks those questions and runs the commands. It does not run `hud trust`.
