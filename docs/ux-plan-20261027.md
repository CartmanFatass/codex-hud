# UX 改进计划（2026-10-27）

来源：对功能、UI、UX 的整体审查。依据 `docs/ARCHITECTURE.md`、`docs/reference.md`、README、`docs/reviews/2026-09-21-ui-review.md`、`docs/fig/*.png`，以及用 `renderMonitor` 和视觉基线渲染出的帧（空会话、32/48 列面板、设置页）。

总体判断：功能已经足够多。用户难以发现这些功能，认知负荷也已超过 48 列侧栏能承载的程度。本轮的重点是做减法、提供引导，并让状态看得见，不再增加字段。

每项改动都遵守 ARCHITECTURE §8 的规则：宽度用 `visualLength` 计算；所有文字经过 `t()`，同时补 ZH；颜色只用 `theme.*`；渲染保持纯函数；只用合成数据。如需修改 §8 本身，要写进本文件和 ARCHITECTURE。

### 追加：模型回复语言校验（完成）

起因：用户看到详情区域显示日文。经核实，那是 `README.ja.md` 的 git diff，不是模型输出。但排查时发现一个真实问题：模型回复存下来时标记的是请求时要求的语言，内容实际是什么语言没有检查；`entryLanguage` 的兜底规则又是「含汉字就算中文」，分不出中文和日文。所以如果模型交回日文，会被当作中文照常显示。

- 新增 `src/collectors/reply-language.ts`：
  - `replyWords` 取出人会读到的文字：JSON 的字符串值，跳过回显的 `agent`/`id`/`path` 字段，并去掉代码、路径和 URL。
  - `wrongLanguage` 按占比判断。要求中文时：假名或韩文占中日韩字符的五分之一及以上判为错，或者有一句话长度的拉丁字母却完全没有汉字也判为错。要求英文时：中日韩字符占全部字母的十分之三及以上判为错。
  - 夹带名字或简短引文可以通过。
- `ModelRequest.language`（可选）：不发送给模型，也不参与缓存标识。
  - 新回复语言不对时，按 `invalid-response` 记为失败，提示「回复不是面板语言」，不写入缓存。
  - 命中缓存但语言不对时，从内存缓存和磁盘缓存中删除（`ModelRuntimeStore.reserve` 新增 `accept` 参数），然后重新调用。
- 调用方都传了 `language`：model-jobs 的 8 处（摘要、名称、标题、原因、审批、改动）、progress、brief/recap 及其格式修复重试。连接测试（probe）发送固定的合成消息，没有传。
- 测试：新增 `tests/unit/reply-language.test.ts`（2 项），覆盖各语言组合的判定、回显名字和引文能通过、代码/路径/URL 被去掉、新回复失败且不缓存、改用中文回复后成功并缓存、不带 language 时保持原行为，以及已缓存的错误语言回复被删除并重新调用。
