## 安装

在检出目录运行 `./install --with claude,pi,codex,browser,herdr`（Node **22.x ≥22.13 或 24.x**）。
可任选五个扩展：**claude**、**pi**、**codex**、**browser**、**herdr**；核心始终安装。
外部工具只检查并报告，不会静默安装；提供方密钥另行配置。
herdr 扩展检查 PATH 中的 herdr 与 pi-roles 命令，仅缺少 herdr 时失败；卸载不做修改。
browser 扩展检查 PATH 中的 `google-chrome`、`jev-ask`、`jev-aistudio` 和 `jev-flow`；缺少 Chrome
或 `jev-ask` 时，在任何修改前失败。只检查，不写浏览器配置、目录或备份，不启动 Chrome、不登录；卸载不做修改。
Chrome 与外部 Jev CLI 使用各自的配置，需另行设置。项目页也以 Chrome + `jev-ask` 的 PATH 检查显示可用性。
不用 browser 扩展，决策 API 和面板也能工作。
Claude 的状态栏与 pi 的页脚始终开启；Codex 使用安装器输出的 `codexH() { hud codex "$@"; }`。
只有面板按需打开：Claude、pi 用 `/hud`，Codex 用 F12。用 `hud uninstall` 或 `./install --uninstall` 卸载。
扩展修改内容、备份及多个 Codex home 的用法见[安装器扩展](../install.d/README.md)。

## 替你决定：标题与内容语言

「替你决定」的标题及展开行、详情中的问题、答案、替代选项和原因都跟随设置中的语言。每个决定仍只调用一次
`title` 功能（lite 档 DeepSeek flash，推理强度 `none`，最多 400 输出 token），只发送该任务的问题与回答文件，
每份最多 4096 字节。JSON 返回 `title`、`question`、`answer`、`instead`、`why`，没有的字段省略。
标题最多八个词，可带两个关键词；其余内容忠实、简短地适配，标识符、路径、代码与旗标原样保留，已是目标语言也不改写。
展开与详情逐字段优先显示适配文字，缺失就用原文；纯文本回复仍只作为标题。Enter 的展开／收起行为不变。
关闭模型或没有匹配 key 时不调用，只显示原文。全部仅用于显示，不改问题、回答文件或任何工作流事实。
标题与适配文字一起保存在私有 `display/model-cache/decision-titles.json`（200 条），按版本、决定 ID、回答修订和语言缓存；
旧版只有标题的记录会再调用一次，此后重绘、重开不重复调用，回答修订或语言改变才重新请求。沿用共享队列与调用上限。

## 决策标签（Decision labels）

这是当前首页、详情和项目页的附加显示；下方较早版本的面板说明不改变这些标签的行为。
「模型文字」主开关开启且有 `GEMINI_API_KEY`、`OPENAI_API_KEY` 或 `TYPESAFE_API_KEY` 时启用，没有新设置。
未保存主开关时，Mistral、OpenAI 或 Gemini 任一 key 存在即默认开启；已保存的布尔值优先。
聊天文字仍需要其聊天端点对应的 key，决策标签单独检查 Gemini/OpenAI/TypeSafe key。

- **结果：** 已结束任务的首页卡片及项目进度块显示完成／部分完成／失败／受阻标记，详情另显示置信度。
  每次结算只请求一次，只发送最终状态和报告前 12 行（最多读取头部 4096 字节）。同次结算的后续报告编辑
  不重新标注；任务继续运行并再次结束后可生成新标签。
- **类型：** 详情显示界面、修复缺陷、功能、重构、评审、研究、文档、杂务，可多选。
  每个任务一次，只发送 brief 的标题与目标（头部 1500 字节内前两段）；仅运行中或结束一天以内可请求，不再回填更早已结束任务。
- **反复失败：** HUD 任务或原生子代理安静三分钟后，可显示 `⚠ 反复失败`，详情显示置信度。
  只发送生成该卡片句子时同一份 32 KiB 会话尾部中的最后 12 个公开工具调用及对应结果摘要，
  调用和摘要各最多 600 字符。每卡最多五分钟一次，输入不变不重问；出现不同活动立即清除旧标记。
- **问题类别：** 待答问题及「替你决定」行显示设计权衡／澄清／需要授权／受阻标签，需要授权的优先列出。
  每个问题文件修订一次，只发送头部 4096 字节，每个已观察任务最多 100 个问题。
- **评审发现：** 详情和项目进度块显示必须修复／应该修复／可选的数量。每个最新评审修订一次，从
  32 KiB 头部提取最多 24 个 Markdown 列表项，每项最多 400 字符；也支持评审任务本身的 report.md。
  不要求固定标题，检查结果、摘要等非发现项不计数，没有发现就不画数量。

全部仅用于显示：不改任务状态，不给工作者发送任何内容，不回答问题，也不延迟问题处理。
标签与 Jev 一起跟随设置 → 模型 →「决策 API」的选择（默认 OpenAI），复用同一自动回退规则和 Gemini 限流冷却。
更改适用于下次未缓存的标签请求；失败标签不显示任何内容，绝不显示提供方原始 HTTP 错误，保留原有修订重试与缓存规则。
每次实际 HTTP 尝试（含回退）与首页排序共享单独的决策小时上限及账本，不占聊天文字的额度；同一 HUD_HOME 的面板合计。
成功和失败尝试均缓存在私有 `display/model-cache/decision-labels/` 修订记录中，重开不为不变输入调用。
关闭主开关或没有决策 key 时既不显示也不请求；切换语言在本地翻译枚举，不重新调用。
不新增进程或 watcher，支持中英及 80／120 列。

## 面板

### 构建后自动重载

面板每次刷新只检查自身安装目录的 `dist/tree-page.js`。变更稳定两秒后，先在子进程验证新入口及其依赖能加载，再以相同参数和环境在原窗格重启（Codex、Claude、pi 共用此路径）。通过私有重启状态保留 Home/Project、选中项、滚动位置、卡片展开/折叠、显示全部及 Inspector/设置/帮助。未保存的设置不会传递；有未保存修改时等到保存或放弃后才重启。坏构建不会关闭旧面板，只显示暗色的“新构建加载失败”，直到下一个可用构建。独立状态栏进程不变。

### 区域

面板有四个区域：**1 卡片**（卡片布局中是卡片，紧凑布局中是树）、**2 时间线**、**3 改动**（工作树列在改动的文件上方）和 **4 详情**；默认只打开卡片，其余从控制栏或用 `Ctrl+\` `2`–`4` 打开。各区域纵向排列。每个区域有一行**标题**，按面板的外观来画（见下），写着它的名字；右端在需要滚动时写当前显示的行（`7–14/46`），否则写有多少项（`4 个文件`、`9 条`）；下面是内容，只在左边有一条竖线 `│`（聚焦的区域用强调色，其它为暗色），没有右边框，也没有底线。面板在 30 行及以上时，各部分之间空一行：控制栏下、两个区域之间、状态卡上方；空行从不挤占区域的行，圆角框外观也不空行，它的边框已经把各部分隔开。区域只有**打开和关闭**两种状态，关闭的区域不占任何行。点击区域的标题把它放大到控制栏和状态卡之间的全部空间，再点一次还原，和 `Ctrl+\` `z` 一样。区域只占它要显示的行数；剩余空间给卡片，详情区域有焦点时给详情。卡片区域也一样：它的标题行写着各状态的数量，点击它放大卡片；它也可以从控制栏关闭，其它区域随即分掉它的空间。
每个区域保留自己的滚动位置。选中代理按 ID 保持，选中文件按路径保持。

### 模型设置与调用预算（2026-11-12）

设置 → 模型保留模型文字主开关、模型与决策 API，新增／调整以下行，全部保存在 `hud-settings.json`：

| 设置 | 字段 / 默认值 | 选择 |
|---|---|---|
| 调用上限（仅 LLM：句子、标题、简报） | `modelCallsPerHour` / 60 | 30、60、120、240、无上限 |
| 决策调用上限（标签、首页排序） | `decisionCallsPerHour` / 0 | 600、2000、无上限 |
| 总结间隔（运行中任务句子、首页简报） | `summaryIntervalMinutes` / 5 分钟 | 2、5、10、15、30 分钟（验证 1–120） |

两个调用上限均以 0 保存「无上限」，计数显示 `n/∞`，没有进度条或达到上限警告；仍继续计数。LLM 使用 `display/model-cache/calls.json`，决策使用单独的 `display/model-cache/decision-api/calls.json`，各自显示本小时计数，不相互占用额度。每个计数下方用一行按次数从多到少列出本小时各功能调用，跟随中／英文并按宽度截断；零调用不显示明细。LLM 包括任务句子、原生句子、决定标题、首页简报和测试；决策包括结果、类型、反复失败、问题类别、评审严重度和首页排序。旧的纯时间戳仍计入总数，列为「早期格式」。总结间隔保存后立即生效，无需重启；运行中材料还必须有变化。不变材料不重问，已结束的句子每次结算成功后冻结。最终结算句子与首页排序仍使用固定两分钟下限。

| 模型功能 | 档位 / 默认推理强度 |
|---|---|
| 任务／原生代理句子与名称 | low / low |
| 决定标题 | lite / none |
| 首页进度简报 | medium / high，4096 输出 token 额度另加推理额度，90 秒超时 |
| 决策标签、首页排序 | 决策 API 结构化判断，不使用聊天档位 |

### 首页模式：默认 / 模型推荐（2026-11-12）

设置 → 面板 →「首页模式」选择默认或模型推荐，`homeMode`（`default` / `recommended`）保存在 `hud-settings.json`，默认保持原样。模型推荐把最多 200 张当前卡片的 id、泳道、状态、角色（80 字符）、标题（160）、年龄、当前句子／原因（240）、问题标志及结果标签批量交给所选决策 API（默认 OpenAI），不读文件正文。0–4 分决定泳道和卡片顺序；低于 2 分的已结束卡片进入现有旧项折叠，`a` 可显示。问题、失败和结束后需要人工的卡片始终靠前且不隐藏；原生代理按子树最高分排序兄弟组，子项仍按原顺序跟随父项。相同摘要再经任务句子的聊天模型通道生成一两句中／英文进度简报，在需要你提示下按宽度换行。卡片集合／状态指纹缓存在内存，不变不重问，最多两分钟一次，绝不阻塞绘帧；变化等待期间恢复默认排序。无决策 key、错误或无效排序时保留默认顺序，不显示错误文字。简报有独立的状态／当前句子摘要和缓存：材料变化时才调用，每个总结间隔最多一次，不受排序成功或可用性影响。聊天简报失败或不可用时仅省略简报，保留有效排序；关闭模型同时隐藏两者。不改变状态、计数或卡片原话。

### 首页卡片：折叠与隐藏（2026-11-12）

首页卡片是标题行加固定两行句子；文字尚未到达时显示 `┃ …` 占位，句子过长时第二行末尾显示 `…`。回车展开完整句子及事实。只有最新且仍属当前的已结束卡片自动展开，其余默认收起。
已结束的 HUD 任务和原生代理卡片从结束时刻起分两段（运行中的卡片、需要你的卡片和决定不受影响）：

- **折叠**（设置 → 面板 →「折叠时间」，`cardFoldMinutes`，默认 5 分钟，可选 1、2、5、10、15、30）：卡片收成一行，同「替你决定」的行：状态符号、角色、标题、结果标签、状态词和时长。回车展开全部内容，再按回车收起；已折叠的卡片不会自己展开（最新结果只在折叠时间之前自动展开）。
- **隐藏**（「隐藏时间」，`cardHideMinutes`，默认 15 分钟，可选 5、10、15、30、60、120）：卡片离开首页，进入 `a`（显示全部／「另有 N 项较早」）部分；失败或已停止的卡片至少保留 30 分钟。隐藏时间小于折叠时间时按折叠时间算。

两项保存在 `hud-settings.json`（整数 1–1440），改动无需重启，下一帧生效。「替你决定」的时限不变（30 分钟，◆ 离场 2 小时）。

已结束的任务目录会在关闭一天后删除，包括隐藏卡片、详情、旧决定、`hud_read` 访问和 `report.md`。清理在下一次 watcher 扫描时进行（若已退出，则等下次 `hud_create`），不设专用到期定时器。

### 首页的空余行：项目进度与工单（2026-11-12）

当前主标签是**首页**与**项目**（取代下文旧版的「首页与工作」）。首页先显示问题、作业与原生代理卡片、决定；
只在余下的空行显示一个进度块：与上方决定之间隔一个空行，样式同首页的其它分节（标题、横线、右侧一个事实）。
`进度 ──── 里程碑 M3b` 一行之下依次是 STATE 的 `## Now` 单行摘要（按宽度截断）、堆叠条和图例，
然后是 `工单 · <功能> ──── 完成数/总数` 与未完成工单的编号、短标题、状态。堆叠条与图例等宽，而不是占满窗格；
图例只列计数不为零的状态，按列对齐，用最少的行排下（最宽 60 格）。每个功能的工单是短列表，最多六行：
工作中在前，其次就绪，再次受阻，其余以「另 N 个」计。不重复进行中切片或已完成、已放弃工单。
窗格变矮时先减少工单，再隐藏图例，再隐藏堆叠条，再隐藏摘要，最后整个进度块消失，绝不挤掉卡片。↑/↓ 可选中进度块，Enter 或点击会打开
项目页的进度板或对应功能，并展开目的节。首页只经现有签名缓存读取 STATE.md 和 `.scratch/*/issues/`，
文件未变就不重读正文；git、控制面、自定义代理及工单关联作业扫描仍只在项目页运行，Help、设置和详情等覆盖页不触发这些读取。

### 首页与工作（R5UX-P2）

面板的两个主标签是**首页**和**工作**，两者都只显示工作流已经写到磁盘的内容，不驱动任何执行。

- **工作：** 每条观察到的包、调用或原生会话一条泳道，泳道内是共享的紧凑工作卡片，旁边是该泳道的决定记录。导航是逻辑的：泳道 → 代理 → 决定；← 折叠所选泳道并收起所选卡片，→ 展开泳道并展开所选卡片，工作页的 Enter 不动作。首页的 Enter 把所选泳道、卡片或决定交给工作页并展开对应泳道。110 列时首页的「工作速览」用同一个泳道/卡片渲染器，不是另一套解释。泳道只是观察导航，不是执行归属；未知阶段或顺序显示为未知。宽工作页保留书面标题列及共享的序数阶段轴；浏览器卡片使用已记录的阶段，不按角色推断实现或设计。
- **紧凑工作卡片：** 收起时固定三行：标题行写角色、短任务、状态词与分钟数，其后固定两行句子；未有文字时显示 `┃ …`，过长时第二行末尾显示 `…`。只有最新的当前已结束卡片自动展开；设置 → 面板默认在结束 5 分钟后折叠成一行、15 分钟后隐藏。四个活动状态是「需要你」「工作中」「待验收」「停滞」，另有已完成的「完成」。没有任务/汇报/助手文字、模型徽标、关系或底栏；完整模型与推理强度、证据和时间依据在详情里。评审只在首行恰好是 `Verdict: accept` 或 `Verdict: changes-required`、且助手状态已结算并写出输出时才算数，助手退出本身不是结论。当前助手的进展或失败还要求主代理与助手的开始时间已知且相容，文件时间一致；旧槽位或未证实的助手只显示未知状态，不会使新主代理成为「需要你」。可读的当前问答在本地显示问题和默认答复，展开及详情保留选项与证据；不可用时才用通用的查看任务提示。原生及门面详情保留原有信息和操作边界，同时显示完整工作状态、阶段历史和证据。需修改的一轮只有在主会话恢复后才显示「修复中」。直接任务不能推断验收或合并，pi 的 STATUS 自动关闭不等于门面关闭。
- **状态优先级：** 当前请求或失败 > 结果待验收 > 停滞（证据过期、未知或无活动，或超过停滞阈值仍无实质进展；默认 10 分钟，可存 1–120）> 工作中。这只是显示，不改变执行状态、等待语义、验收或来源。模型调用、计数、心跳或内容相同的触碰都不推进活动。代理的问答结果或普通失败永远不会进入首页的「需要你」。门面结果在门面关闭前一直固定在「待验收」。首页（含概览和代理栏）与工作页共用原有已完成代理收起时限，计数只含可见代理；零表示保留全部，`a` 在两个标签上显示或收起已完成历史。到期不会隐藏已结束且需人工处理的代理、当天固定的不可逆决定、覆盖不完整提示或未关闭的门面结果。
- **保留的次要渲染器：** 生产路径始终提供 workboard sidecar；无 sidecar 的堆叠渲染器只为夹具和旧调用保留，实时面板不会走到，计划在 P2 之后移除（q4）。它使用同一张紧凑工作卡片，不是旧的富卡片，也不增加新功能。

### 布局

**两种布局**（设置 → 面板 →「布局」）。这是保留的次要渲染器：只有夹具和旧调用会用到，实时面板不会走到，实时面板见上面的[首页与工作](#首页与工作r5ux-p2)。它保留自己的次要边框、底栏和按键；卡片就是实时页面用的同一张紧凑工作卡片，没有第二套卡片渲染器，也没有开关能恢复旧的富卡片正文。计划在 P2 之后移除。

- **卡片**（rich，默认）：主会话启动的每个可见 agent（**L1**）都用同一张紧凑工作卡片，不论活跃还是空闲，按同样的排序、筛选和已完成收起时限排在固定的统计行下。没有卡片展开/收起状态，也没有展开箭头。各层级后代保留在所属 L1 的聚合统计与详情里，不另起卡片或子任务行。统计行按状态计数 L1（`!1 失败  ✓3 完成  ▸3 运行`），子任务仍在运行的 L1 也算运行中，并列出守护评审（`◈N`，有失败时为错误色）；放得下时还写子任务数及其失败数（`· 17 子任务，1 失败`）以及所有运行线程的合计输出速度（`· ~186 tok/s`）。卡片本身即[首页与工作](#首页与工作r5ux-p2)所述的三行工作卡片：标题行的角色、任务、状态与分钟数，加固定两行句子，未有文字时用 `┃ …` 占位。
  - **选中（仅夹具）：** 点击卡片只选中它；400 毫秒内再次点击名字才切换 Codex 对话，Codex 窗格至少 63 列或宽度尚未确定时名字带下划线。`Ctrl+\` 后按 Enter、空格或 `v` 打开选中项的详情，不会展开卡片；选中的卡片落在较亮色带上。实时首页和工作页有自己的选中方式，没有原生切换。

- **紧凑**（compact）：Agents 区域（树，每个 agent 和子任务一行，用 Codex 的原名，标题行与卡片布局相同），下面是简报、回顾和 agent 日志，与之前相同。

所有视图的计数口径一致：**agent** 指主会话启动的 agent，**子任务**指它们之下任意层级的 agent，**评审**指守护批准评审（不论挂在哪一层）。Agents 区域的标题行和卡片、状态卡的警报和通知（各种失败合成一句：`! 1 个 agent · 1 个子任务 · 1 个评审 失败`）、状态栏的 Agents 字段和警报、Agent 简报以及 `codex-hud --json` 都把三者分开计数；子任务还在运行的 agent 也算运行中。这些聚合统计不变；紧凑工作卡片不重复子任务或评审计数。

### 控制栏

**控制栏**是面板的第一行（圆角框外观是两行），面板所有的控件都在上面；卡片、状态卡和各区域的标题上都不画按钮。每个控件都是一个**按钮**：图标，放得下时加上文字。栏上不写任何按键；按键只在帮助里。

```
120 列   ⌂ 主会话   ▦ 卡片   ≣ 时间线  ± 改动  ◫ 详情  ⚙ 设置                                  ǁ 暂停模型  ⊕ 1 个已完成  ? 帮助
 56 列   ⌂  ▦ 卡片   ≣ 时间线  ± 改动  ◫ 详情  ⚙ 设置    ǁ ⊕1 ?
 40 列   ⌂  ▦ 卡片   ≣  ±  ◫  设置       ǁ ⊕1 ?
 32 列   ⌂  ▦ 卡片  ≣ ± ◫ 设置   ǁ ⊕1 ?
```

- `⌂` 把 Codex 切回主会话。所有按钮都放得下文字时它才带上文字（主会话）；圆角框外观的标题里只要放得下就带着。
- 标签就是各个区域，按区域的顺序：`▦` 卡片、`≣` 时间线、`±` 改动、`◫` 详情，图标和区域标题上的一致。聚焦的标签按外观来画（标签行外观里是一块填色的标签），打开的用正文色，关闭的为暗色。叠放时，点一下打开关闭的区域并聚焦它，再点一下关闭打开的区域，卡片也一样；标签页排布下，点一下就切换到那个区域，区域标题不再重复标签上的名字，只写计数和行范围（`✓38 完成  · 101 子任务    23–44/103`），框线外观里没有可写的就只剩框线。
- `⌨`（按键在侧栏）在面板保留按键时出现（点击空白行或左侧空白之后）：在 Esc 或点击它之前，输入都不会交给 Codex。它用强调色显示，有空间时带文字；腾出空间时不会先于帮助按钮被去掉。
- `⇢`（切换）在卡片区域有选中的 agent，或 Inspector 正在显示某个 agent 时出现。点击它会把实际的 Codex 对话切换到这个 agent，与 `o` 相同。空间不够时，它和模型按钮一起让出位置。
- `ǁ` / `▶`（暂停模型 / 继续模型）暂停或继续所有模型生成，配置了模型后端时显示；`⊕N` 显示被收起的已完成 agent，`⊖` 再把它们收起，只在有这样的 agent 时显示（卡片布局只计 agent，即列表的行：后代属于各自的卡片，不另计入这个按钮的数量；紧凑布局计树收起的每一行）。这一行放得下文字时写作 `⊕ N 个已完成`，已经展开时写作 `⊖ 收起`；放不下时仍是 `⊕N` / `⊖N`。图标设为 text 时仍是 `+N 已收起`。主导航里的 **设置 Tab** 打开设置；`?` 打开帮助。设置标签在导航行，圆角框外观下也位于第二行的标签区，不再是右侧单独的齿轮操作。24 列及以上保留「设置」文字，更窄时保留短文字，而非只剩齿轮。
- 控制栏随宽度变化。已完成按钮先试着带上文字，这一行放不下就只留图标，然后才去掉别的文字或按钮。其它操作按钮的文字只有在所有按钮都放得下文字时才有，然后是关闭区域的标签的，再是打开区域的标签的（聚焦的除外），最后是聚焦标签的，其间标签之间的间距从三列逐步收窄到一列。然后去掉按钮：关闭区域的标签、“已完成”按钮、模型暂停按钮、其它标签、聚焦的标签。主会话、设置和帮助始终保留。按钮两侧间隙的中点之间，任何位置都算点这个按钮。没有颜色时（`theme: none`），聚焦的标签加方括号，关闭的区域没有标签。

### 外观与图标

**外观**（设置 → 显示 →「外观」，或 `CODEX_HUD_LOOK`）有五种画控制栏和区域标题的方式。在设置里选一种外观会换上它配套的图标（只设 `CODEX_HUD_LOOK` 不会换图标）；之后仍可在「图标」里改。

```
tab     ⌂  ▦ 卡片   ≣ 时间线  ± 改动  ◫ 详情  ⚙ 设置    ǁ ⊕1 ?
band    ⌂ ▦ 卡片  ≣ 时间线  ± 改动  ◫ 详情  ⚙ 设置 ──── ǁ ⊕1 ?
tile    ⌂  🤖 卡片     🕘     📝     🔍     设置        ǁ ⊕1 ?
frame  ╭─ ⌂ 主会话 ──────────────────────── ǁ ⊕ 1 个已完成 ? ─╮
       │  ▦ 卡片    ≣ 时间线   ± 改动   ◫ 详情   ⚙ 设置       │
pill    ⌂ ▦ 卡片  ≣ 时间线  ± 改动  ◫ 详情  ⚙ 设置    ǁ ⊕1 ?
```

- **tab**（标签行，默认；Unicode 图标）：聚焦的标签填色，两边各留一列底色。区域标题是图标和名字，聚焦时用强调色，没有自己的底色。
- **band**（状态带；Unicode 图标）：控制栏是一条有底色的色带，和状态卡的色带一样，标签和操作按钮之间的空白是一条强调色的线；聚焦的标签用强调色。区域标题也是色带，放大的区域的标题像聚焦的标签一样填色。
- **tile**（Emoji 色块；Emoji 图标）：每个打开的标签各有一块底色，聚焦的填色；区域标题后面接一条横线，聚焦时为强调色。
- **frame**（圆角框；Unicode 图标）：整个面板外围一个圆角框。主会话是顶边上的标题，操作按钮在顶边右端；标签在它下面一行；每个区域的标题是横穿框的一条边（`├─ ± 改动 ────────── 4 个文件 ─┤`），内容在框的两边之间（聚焦区域旁的左边框为强调色），底部由状态卡的转角收口（`╰─ … ─╯`）。不足 20 列时按 tab 画。
- **pill**（胶囊；Nerd Font 图标）：聚焦的标签是两端圆角的胶囊；区域标题也是胶囊，聚焦区域的用标签色，其它的落在底色块上。

**图标**（设置 → 显示 →「图标」，或 `CODEX_HUD_ICONS`）选择图标集：`unicode`（上面的字符）、`nerd`（[Nerd Font](https://www.nerdfonts.com/) 图标：主页 `U+F015`、机器人 `U+F06A9`、历史 `U+F1DA`、差异 `U+F440`、信息 `U+F05A`、暂停 / 播放 `U+F04C` / `U+F04B`、眼睛 / 划掉的眼睛 `U+F06E` / `U+F070`、齿轮 `U+F013`、问号 `U+F059`）、`emoji`（各区域为 🤖 🕘 📝 🔍，各占两列，操作按钮仍用 Unicode 字符）或 `text`：按钮只有文字（`← 主会话`、`卡片 时间线 改动 详情`、`暂停模型`、`+1 已收起`、`设置 帮助`），窄时缩短（`← 主`、`暂停`）。设为 text 时，面板其它的符号也换成文字（状态卡的需要你、目标、现在、已完成，`12d 前`，底部状态栏的 `Working`、`Idle`）。「模型标签」（`glyphs`）只管面板的模型徽标：设为 text 时把模型和推理强度写成文字，不影响图标。底部状态栏总是用文字写出模型名称。Unicode 和 Nerd Font 图标以及胶囊的圆角都由 MesloLGS NF 绘制（见[字体](../README.zh.md#字体)）。

### 状态卡

**状态卡**位于底部，由一条色带和一个转角组成，就像 omp 画它的状态行；用量条是细线，读数写在填充的末端：

```
 ✓ 空闲 ★◆ 5d ──────────────────────56%──────────────────272K ~3m
│ ◎ 把分词器提速一倍，同时不破坏中日韩文本
│ ▸ 等待中日韩修复和缓存审查
│ ✓ 流式接口已合并
│   基准测试已在 50 MB 语料上搭好
│   依赖审计无问题
│   新增流式分词接口
╰─ parser-kit · main * ↑2 7d ───────────────────────────99% ↺4d18h
```

- **色带**有自己的底色，横跨整个宽度：会话状态（工作中时是正在运行的工具和目标、本轮时长和 `~N tok/s`；空闲时，从一轮结束满一分钟起写出已等你多久：`✓ 空闲 12m`；底部状态栏在通知区写出这一轮何时结束：`✓ turn done in 12:48 · 12m ago`）、模型徽标和会话时长；上下文用量条，百分比在填充末端，结尾是窗口大小（`config.toml` 设了 `model_auto_compact_token_limit` 时用 `┃` 标出自动压缩点）；配置了简报时，再加简报的状态（`~3m` 为回顾的时间，其余用文字：生成中…、失败、已暂停）。点击色带任意位置切换档位，同 `r`。
- **正文**挂在左侧一条竖线（`│`）下，竖线的颜色就是主会话的状态：空闲为暗色、工作中为信息色、失败为错误色、同步延迟或需要你（待批准、工具、agent、子任务或评审失败、回顾说需要你）为警告色。
- **转角**（`╰─`）：会话所在位置（项目名加粗，仓库不同时为 `› 仓库`，`· 分支`）；最紧的额度窗口的用量条，标为 `7d`、读数 `99%`（窗口已满但还有积分时，读数换成余额 `积分 31.8K`，不标 `!`：Codex 会接着用积分）；重置倒计时。
- 用量条以信息色填充，超过 70 % 为警告色，超过 85 % 为错误色，底轨为暗色。
- 空间不够时，色带依次去掉输出速率、任务数、会话时长、窗口大小、模型和简报状态，然后用量条缩成百分比；转角依次去掉其它窗口、分支、窗口名、仓库和预计，然后是用量条和重置时间。状态和百分比最后才去掉。不足 24 列时不画状态卡。32 列及更窄时状态卡画成一行，加宽后回到保存的档位。较矮窗口也保留保存的「完整」档位，在高度允许的范围内显示；修改 agent 卡片内容不会改变状态卡档位。

它有三档（设置 → 面板 →「状态卡」，与其它面板偏好一样保存）；按 `Ctrl+\` `r` 或点击它的色带依次切换：

- **一行**（min）：只有色带，右端是简报状态和额度读数；上下文用量条前写 `上下文`（英文为 `Ctx`），就像额度读数用窗口名标注（`5h 61%`），两个百分比不会混淆；空间不足时它比用量条的线段、窗口大小和简报状态保留得更久。有工具、agent、子任务或评审失败，或回顾说需要你时带 `!` 标记。
- **状态**（status）：色带、有警示时的警示行，以及转角。
- **完整**（full，默认）：上述内容，再加主会话的简报：先是模型对待批准请求的说明（`⚑ ~ …`），然后是回顾，标签在同一列行内：需要你（`!`，警告色）在前，然后是目标（`◎`）、现在（`▸`）和最近两条已完成（`✓`，其余以暗色 `+N` 计数），每项最多两行；只有没有回顾时，全局一句话才放在「现在」的位置；最后是调用失败或格式不符的回复。暂停时简报变暗。图标设为 text 时标签是文字（需要你、目标、现在、已完成），按显示宽度对齐成一列。状态卡最多占面板的三分之一，面板够高时至少给 agent 留 10 行；卡片布局中，它的高度独立于 agent 卡片内容设置预留，较长的 agent 卡片在自己的区域滚动，不挤掉主会话回顾。简报放不下时保留需要你、现在和目标，其余滚动可见（在状态卡上滚动鼠标滚轮），并有一行说明还有多少不在视野里。

紧凑布局不变：简报和回顾仍在树下方的区域里，用同样的行内标签，所以它的状态卡只有「一行」和「状态」两档（「完整」即「状态」），`Ctrl+\` `r` 在两者之间切换。

### 滚动与选中

卡片区域标题行以下的视图放不下时可以滚动：鼠标滚轮、`PgUp`/`PgDn`，以及移动选中项（视图会跟着把选中的 agent 滚进来）。标题行右端写着当前显示的是哪几行（`6–17/40`）。滚动位置在重绘和新内容到来时保持不变，内容变少时自动收回。视图不足 12 行时先去掉空行，而不是藏起内容。底部状态卡和打开的 2–4 号区域位置不动。

### 本地活动与证据

`Ctrl+\ u` 打开独立的活动中心。Tab／左右键切换五页，方向键和滚轮选择条目，Enter 查看当前代理；Escape 返回。历史中已不存在于当前树的代理不会被当作当前目标切换。

- **收件箱**聚合已观测到的批准请求、失败和读取/状态冲突。选中后可标记已读（`r`）、稍后处理十分钟（`s`）、关注/取消关注（`p`），也可点击文字按钮。已读不等于故障已恢复，恢复需要对应来源的成功证据。它不另发一套桌面通知。
- **离开后的变化**列出尚未确认查看的完成、失败、Git 状态和已存模型摘要变化。`v` 或“标记已查看”仅确认本屏可见事件；打开页面或退出不会清空未查看内容。Git 文件信息在这一页或改动页打开时采集，缺失/过时会明确标注。这里的变化不是两个时刻之间的完整 Git diff。
- **查找**按名称、角色或任务路径过滤，中文与粘贴均可用。输入框里普通字母都是查询文字；用 `Ctrl+P` 或点击“关注”固定选中代理，`Ctrl+F` 返回查询。关注状态按主会话保存。窗口关闭后普通输入继续透传给 Codex。
- **历史**回看有界观测快照中的状态和相关事件，不是对话录像。快照明确标为历史；恢复现场、重新执行任务或自动重试不属于回放功能。
- **会话**列出近 7 天在当前会话目录下启动的主会话，最多 8 个，最近写入的排在前面。每行显示时间、距今多久、之前由模型写下的标题（没有标题时显示 id 开头），当前会话标「当前会话」。列表下方完整显示选中会话的恢复命令 `$ codex resume <id>`；一行放不下时，id 单独换行。HUD 不会执行这条命令，这一页也不调用模型。列表只在这一页打开时，从 rollout 的第一行读取，最多每 10 秒读一次。

活动记录位于 `$HUD_HOME/display/activity/`，每个主会话独立，私有原子写入：最多 500 个事件、48 个快照、200 个代理/关注项、30 天，序列化上限 4 MiB。只保存所需状态、有限路径和已生成模型摘要，不保存原始任务、对话、工具命令或推理。紧凑栏和面板都记录观测，跨面板合并；锁竞争或无法保存时显示等待保存，下一次刷新/退出再次尝试。未运行 HUD 的时段不补造历史。

`Ctrl+\ c` 的“来源”页解释主会话和选中代理的状态、采样时间、TPS 的估算口径、Herdr 读回与冲突。点击状态带的 TPS 也可进入；`Ctrl+\ d` 的诊断详情保留，并提供来源/调用/导出入口。缺失证据保持 unknown，完成状态不代表工作质量通过验证。

“调用”页按功能显示本地已观测的请求、缓存命中、成功、失败、取消、限额和平均执行耗时。记录上限为最近 24 小时、1000 条；连接测试独立归为 probe。请求数包含缓存消费者及拒绝，不能等同供应商调用次数；耗时不包含排队，其他进程尚未完成的请求与启用前记录不可知，token 和金额未知时不估算账单。

“导出”先显示固定的完整 JSON 预览，点击“保存报告”或按 `s` 才写入 `$HUD_HOME/display/diagnostics/` 的新文件（0600）。保存的字节与预览相同；默认排除凭证、服务端点、标识符、文件路径及对话/摘要正文。报告含应用/Node 版本、平台和启动时入口文件哈希；它只是入口文件的启动凭据，不是整个构建或当前 Git 状态的证明。

正常采集在明确空闲、来源不变后逐步放缓至最多五秒（原本配置更慢时保留配置），活动、未知、故障、输入或来源变化恢复正常节拍。时钟重绘与输入独立。大日志扫描分批让出事件循环；单条 JSON 解析仍是同步操作，五秒也不是模型响应或通知投递的时限。

### 会话切换

会话切换借助 Codex 自带的 `/subagents` 选择器（已对照 Codex 0.154 和 0.157 验证），选中显示该代理完整 UUID 的那一行，不会提交猜测的 `/agent <id>` 命令。需要空输入框（包括查看子代理时的只读输入框）或已识别的选择器；有草稿、处于复制模式或无法识别界面时，会提示原因。键盘移动选中项只预览，按 `o` 才切换。目标已在可见范围内时合并移动操作，长列表按页翻找，Enter 前再次核对该行。切换后不再重复打开选择器，避免二次弹窗和对话重绘；请求已发送不等于独立确认了最终显示的会话。

Codex 窗格窄于约 63 列时，选择器不再显示 UUID。此时按选择器显示的名字（任务路径，或 `Main [default]`）匹配，且仅当本会话没有其他代理显示同一名字时才切换；否则拒绝切换并提示加宽 Codex 窗格。有代理正在运行时，Codex 每次打开选择器都会在对话里插入一条 “Sub-agents running” 提示，这是 Codex 自身的行为。

### 时间线

第 2 个区域默认关闭，以主会话为主轴按时间倒序排列整个会话，每条写距今时间（连续几条时间相同时只在第一条写出）。

| 层级 | 哪些内容占一行 |
|------|----------------|
| 主会话（最左边） | 完成的一轮及其回复的开头（`⏎`）、请求批准与答复、上下文压缩、额度窗口越过 80 % 和 95 %、一轮中断或失败、工具调用失败（写出它运行的命令，`exec` 脚本写它的第一条命令，如 `✗ rg -n …`，没有命令时写工具名）；连续相同的合并为一行并标 `×N`。 |
| 主会话启动的 agent（缩进一级） | 每个阶段一行：结束的阶段放在结束的时刻，写用了多久、这段时间里结束的各层级子任务（`✓2 ✗1`），它最新的阶段还写返回内容的前几行；仍在进行的阶段放在开始的时刻，写它的时钟和它说要做的事。为别人工作的 agent，其阶段写出是为哪个负责人做的（`性能顾问 → 分词器提速`）。 |
| 子任务（再缩进一级） | 只有要紧的（失败或被标记留意，与卡片的子 agent 范围开关无关），放在它结束的时刻 |

- 每个 agent 用它所在方向的颜色，与卡片上的名字一致：一个 L1 和它下面的 agent 同色，为别人工作的 agent 用负责人的颜色，同时进行的方向颜色互相错开。
- 「失败原因」写过的原因显示在失败下方，以 `~` 标出。
- 只写 rollout 记录下的事实：一段安静不算一条。守护评审的开始和完成不显示，失败仍保留。
- 待批准的请求还会显示已经等了多久，在状态栏警示（最宽形式）和侧栏的状态卡片里都有。

```
                  核对查表是否一直留在 L1 缓存里
          40m     ✗ b03_review_harness             15m
          50m   ▸ 中日韩正确性                       ◴

分道      28m ⏎ │ │ 中日韩第一阶段已合入；竖排标点作…
          30m │ ▸ │ 性能顾问 → 分词器提速            ◵
              │ │ │   核对查表是否一直留在 L1 缓存里
          40m │ ✗ │   b03_review_harness           15m
          50m │ │ ▸ 中日韩正确性                     ◴
```

- **主轴**（rail，默认）：主会话的条目在左边一条竖线上，agent 的条目从竖线分出，子任务再往里一级。
- **缩进**（indent）：同样的层级，只用缩进表示。
- **分道**（lanes）：主会话一道，每个有子任务或仍在工作的方向各一道，最多三道，48 列起四道；方向的条目落在它那一道上，方向仍在工作时它那一道从顶部画起。

设置 → 面板 →「时间线范围」是时间窗口：最近 1、3（默认）、6、12 或 24 小时，并且无论多久都至少显示最新的 8 条；仍在进行的阶段不论从何时开始都会显示。更早的条目在最后一行计数（`▸ 更早 40 条`）：点击它，或在时间线有焦点时按 Enter，每次再加载 20 条。点击 agent 条目的任意一行，或用 ↑/↓ 把光标移到该条目后按 Enter，会在 Inspector 中打开这个 agent。光标只停在 agent 条目和「更早」行上；按 ↓ 从视图顶部开始。在这个 Inspector 中按 Esc 会回到时间线，光标保持原位。PgUp/PgDn、`g`/`G` 和滚轮仍然滚动视图，同时取消光标。

### Agent 日志

每个 subagent 都有一份日志，按时间倒序：观察到的开始、完成、失败和最新说明（与刷新 tree 的同一次读取写入），以及模型写的简报/进度说明、结果摘要和失败原因（紧凑布局和详情中以 `~` 标出，表示由模型撰写）。卡片布局不在卡片上列出这份日志（见上文卡片部分）；详情里显示。

- **语言：**模型写的条目按写下时的语言显示：切换语言后，另一种语言的说明先不显示，等相应生成器用新语言重写；观察到的条目照常显示。
- **只增不减：**日志只增不减；新的简报会追加，而不会替换上一份。
- **跟随 tree：**日志跟随 tree：tree 隐藏的 agent（已收起、被筛掉或在折叠的父级下）不显示，折叠的父级会显示一行说明下面收起了几份日志；让 agent 重新显示，它的完整日志也随之出现。
- **紧凑布局：**紧凑布局中每块以 agent 的状态、类型图形和 Codex 原名开头，下一行是模型起的短名或任务；每个 agent 显示最近两条，选中的显示六条并排在最前，详情区域显示全部，只是不再重复上方已显示的最新汇报，日志里只有开始和完成时也不显示。每条的时间单独占一列，正文挂在它旁边，去掉聊天用的 markdown。点击日志行会打开该 agent 的详情。
- **存储与开关：**日志按会话保存在 `$HUD_HOME/display/agent-log/`（权限 0600，30 天后删除）。已存的模型说明、摘要和原因在关闭后端或暂停模型后仍按当前面板语言保留可见。紧凑布局和详情里的观察条目在有后端时始终可用，后端关闭时独立受 Agent →「Agent 日志」控制；这不会把日志变成卡片历史。

### 详情与改动

Inspector 按以下顺序显示：

1. 名字、模型和推理强度（先是图形，再用文字写出完整型号：`☀◆ gpt-6-astra · max`；卡片徽标是短写，文字模式为 `6astra·max`）
2. 不止一段的任务路径
3. 状态
4. 上下文用量和有输出时的输出速度（`输出 ~42 tok/s`）
5. rollout 报告过之后，它累计用了多少（`用量 1.2M 输入 (缓存 84%) · 32.1K 输出`，取最新一次报告中的累计 `total_token_usage`；宽度不够时先去掉缓存比例，再去掉输出）
6. 父会话在创建它之前留下明文时，这段文字写在「创建前原文」下
7. rollout 不公开任务文本时，它开始最新阶段时自己说要做的事（`本阶段自述`，完整）
8. 最新汇报、任务（总是显示）和日志、本轮经过时间和最近活动

按 `v` 展开完整时间与会话 ID。会话切换提示显示在底部。点击空白行，或区域左侧的空白，接下来的按键留在面板里，直到 Esc 或点击控制栏上的 `⌨ 按键在侧栏` 把按键交回 Codex。较长的内容各成一节，标题是一条暗色分隔线（`── 创建前原文 ──`），正文缩进两列。点击卡片只选中它；点在名字上，400 毫秒内再点一次才切换会话。Enter、空格、`v` 或 `◫` 按当前选中项打开详情。`o` 和 `⌂` 立刻切换。Codex 窗格较窄时，按[会话切换](#会话切换)所述用唯一名字匹配，否则提示加宽。

详情的 **~ 模型总结** 单独显示面板语言下最新保存的模型说明，与 agent 自己的「最新汇报」分开。**证据快照**（`coverageAt`）表示覆盖到哪个公开材料快照，**生成时间**（`generatedAt`）表示结果何时产出，各自只在明确存有对应元数据时显示。旧说明或定期简报没有覆盖元数据时，只写**记录时间**（日志时间），不伪造覆盖边界，也不推算生成时间。这里还解释进度上下文：模型后端关闭、模型暂停、实时进度关闭、总结隐藏、agent 不活跃、没有公开进度证据、刷新冷却、等待重试（已知时写剩余等待）、进度并发上限或每小时模型调用上限；排队和正在生成是不同状态。这些诊断只读取现有状态，不扩大进度请求目标；渲染过程不调用模型。

有不止一个工作树时，改动区域先列出工作树，再列出文件：每个工作树一行，列出其文件的那个标 `●` 并加粗，右侧写它的分支领先或落后上游多少（`↑2`、`↓1`）和状态（`4 改动`、`干净`、`锁定`）；然后是一条再次写出它的名字和计数的分隔线（`─ main · 2 未暂存 ───`），下面是它的文件。工作树和文件共用一个光标：移到某个工作树的行就列出它的文件，按 Enter 在详情区域显示它的信息（HEAD 提交的标题、分支、状态和计数，完整路径在「更多」里；不显示哈希）。旧设置文件里保存为打开的工作树区域，现在打开的是改动区域。文件属于列出的那个工作树，不推断某个文件由哪个 agent 修改。每个文件前是一个表示改动类型的彩色字母：`M` 修改（黄）、`A` 新增（绿）、`D` 删除（红）、`R` 或 `C` 重命名或复制（蓝）、`!` 冲突（红）；放得下时右端写增删的行数（`+12 −3`），暂存和未暂存各有多少见列表上方的计数。未跟踪的文件收成最后一行 `▸ 12 未跟踪`：按 Enter 或点击它，在它下面列出，再按一次收起。窄屏摘要中 `Δ` 是修改文件数，`S` 是暂存、`U` 是未暂存数量。
选中文件后按 Enter 打开暂存和未暂存 diff（只显示各段改动；git 头部重复路径并用哈希标出文件版本，不显示），自动放大 Inspector；Esc 还原。标题写文件名和增删的行数（`+12 −3`），下方暗色写所在目录；各段以面板语言标出已暂存、未暂存或未跟踪。新增行绿色、删除行红色、hunk 标记青色，保留 `+` / `-` 符号；长行在词与词之间折行，续行缩进两列，`+` / `-` 只出现在第一行；制表符按 4 列展开。未跟踪文件提供有大小限制的内容预览，未跟踪的目录列出其中有多少个文件和它们的路径。
这些操作只读取 Git 数据；禁用外部 diff、内容过滤器和部分克隆的自动下载，不提供暂存、提交或切换分支操作。

### 设置

设置 → 面板 →「宽度」适用于所有客户端：Claude、pi 和 Codex。预设为 40、48、56（默认）、64、80、100 列，←/→ 循环切换。其它已保存宽度仍可读取（16–200，包括旧值 32）；0 表示默认的 56 列。保存修改后的宽度立即调整当前面板，空间允许时智能体窗格至少保留 41 列；窄窗口中面板会更窄。所在分割区域或 tmux 窗口尺寸改变时重新应用宽度，手动拖动边框则保持不变，保存其它设置也不会干扰。没有保存过设置时，仍支持 `CODEX_HUD_TREE_WIDTH` 指定 tmux 初始宽度。

`hud panel [--width N]` 在 herdr 中于调用者旁打开面板，默认采用已保存的「宽度」（未设置时 56 列）；显式 `--width N` 仅覆盖这次打开，直到保存修改后的宽度。`--here` 在当前终端显示，不创建分割窗格。

设置页上方保留主导航，当前「设置」Tab 高亮；返回、保存、重置本组在下一行，宽度足够时另有「重置偏好」（Reset all）。点击当前设置 Tab 保留草稿和选中项。返回、Esc、其他导航 Tab 或会离开设置的前缀命令，都会检查未保存修改。有修改时先询问：**保存并离开**、**放弃修改**、**继续编辑**（默认；Esc 也继续编辑）。成功保存才应用草稿并前往原来请求的目标；保存失败则保留草稿和确认页，显示错误，供重试或继续编辑。没有修改时立即离开。导航只打开/选中目标视图，不会把已打开的视图反而关掉。这项保护针对面板内导航，不拦截 F12 替换窗格、进程终止或 tmux 会话被杀。

**重置本组**（设置页内直接按 `r` 也可）只修改当前选中行所在组的草稿；**重置偏好**只重置设置页明确管理的已知偏好，不是清空整个设置文件。两者都需保存后应用。两种重置都保留模型后端、API 密钥/地址、模型档位与统一型号覆盖、推理选项、每小时调用上限，以及背景图资源路径/文件。重置模型增强组或全部偏好时，保守地关闭每个生成功能并开启「暂停模型」，不会恢复默认开启的生成许可。重置其它组不改模型权限。

独立设置页按连续的七组排列，依次为：

| 组 | 设置项 |
|----|--------|
| 显示 | 主题、外观、图标、模型标签、动效 |
| 面板 | 语言、布局、面板排布、状态卡、时间线的样式和范围、宽度、背景图 |
| Agent | Agent 日志 |
| 卡片 | 任务标签、Agent 总结、本轮时钟、停滞阈值和边角（见[卡片设置](#卡片设置)） |
| 模型增强 | 所有会把内容发给模型的功能（见[模型增强](#模型增强)） |
| 状态栏 | 启动时显示状态栏、密度、上下文、通知 |
| 输入 | 鼠标、前缀键、刷新 |

每个主题都有自己的面板配色：首页、项目和检查页的卡片标题、卡片底、选中行、失败卡片和提问各用该主题的底色与墨色，切换主题每一页都看得出来。颜色仍只表示需要你处理的事（待回答用提问色和 `attention`、危险、成功）；`none` 和 `NO_COLOR` 不输出任何转义。深色主题把自己的文字色铺在每一行之下，`terminal` 沿用终端自己的文字色；`latte` 和 `paper` 是给浅色终端用的。

只能一起用的设置合成一行：简报节奏（两个间隔成对选择）、Agent 名称（替换名字、写在名字下或关闭）和通知（关闭、tmux，或 tmux 加桌面）。2–4 号区域没有设置行：它们由控制栏打开和关闭，并记住状态。

**移动**

- 设置页以手风琴方式展开：只有选中项所在的组展开，显示在组标题下（`── ▾ 卡片 ──`）；其他组各折叠成一行，写出组名和最能概括它的几个值（`▸ 显示  终端 · 标签行 · Unicode`），组内有未保存的项时前面标 `*`，因此七个组能在 24 行高的页面中同时显示。
- ↑/↓ 按顺序逐项移动，进入哪一组就展开哪一组；PgUp/PgDn 跳到下一组或上一组的第一项；点击折叠行会在该组第一项处展开，不改变任何值。
- 设置页是一个模态页：打开期间按键归它（方向键、Enter、`s` 保存、`r` 重置本组、`Esc` 请求离开），底部只写按钮没有覆盖的移动操作。窄屏保留完整 Back/Save 按钮，使用短标签。

**设置行与取值**

- 标签留在左侧，取值随实际面板宽度在右侧对齐，非默认值为强调色；宽度达到 70 列时，右侧再预留固定比例的简短说明列。
- 保存列宽后，设置行会按新的实际宽度重新排布，不再挤在左侧；选中项显示为 `‹ 取值 ›`，←/→、Enter 或点击即可修改（点击 `‹` 向回切换）。
- 列表下方一行说明选中设置的作用；当前不生效时，另有一条选中行提示说明原因。
- 选中主题、面板排布、外观或图标时，这一行上方的「预览」按未保存的取值画出面板的控制栏和一个区域的标题，保存之前就能看到效果。

**保存**

- 未保存字段带 `*`，Save 按钮随之高亮；Bar on launch 在下次启动时生效。
- Save 写入 `$HUD_HOME/hud-settings.json`（可用 `HUD_SETTINGS_PATH` 改路径），紧凑 HUD 下次刷新时同步显示偏好。已保存设置优先于环境默认值，`NO_COLOR` 始终优先。

**依赖其他设置的行**

- 依赖条件不可用的行会变暗，但仍可选中修改，方便提前设好偏好。
- 选中行提示会区分后端关闭、模型生成暂停，以及未开启 Agent 名称时的任务标签。
- 卡片进度还需要开启 agent 摘要，或同时开启子 agent和子 agent 总结；简报节奏需要定期 Agent 简报、主会话回顾或改动摘要之一。
- 后端一行下方还注明「有后端时生效」。
- 「暂停模型」保留已存文字，不会关闭显示开关。
- Agent 日志只控制后端关闭时紧凑布局和详情里的观察日志，从不在卡片上列出历史；有后端时观察条目始终可用。
- 已存模型说明在关闭后端或暂停后仍按面板语言显示，不受 Agent 日志开关影响。

**上次读取会话的时间。** 说明行上方有一行显示侧栏上次读取会话的时间（`HUD 读取会话 2s前`）；如果读取失败过，还会写出失败的环节、时间和原因，失败比上次成功读取更新时以警告色显示。读取失败时屏幕上保留的是上次的好数据，有了这一行，“会话很安静”和“HUD 读不到”才不会看起来一样。

### 卡片设置

设置 → 卡片控制显示，不是发送材料的许可。紧凑工作卡片只有五个控件：

| 设置 | JSON 键 | 默认值 | 控制内容 |
|---|---|---|---|
| 任务标签 | `cardLabel` | `true` | 卡片上的模型任务标签，不请求生成标签 |
| Agent 总结 | `cardSummary` | `true` | 最新保存的模型说明，只在已有原生许可时显示；不新增模型调用或来源许可 |
| 本轮时钟 | `cardClock` | `true` | 卡片上按分钟计的用时 |
| 停滞阈值 | `cardStallMinutes` | `10` | 无实质进展多少分钟后显示为停滞；整数 1–120，界面提供 5、10、15、30、60 |
| 卡片边角 | `cardCorners` | `square` | `square`（直角）或 `round`（圆角） |

旧卡片预设和十个已停用的富卡片布尔项不再有控件，也不会恢复旧卡片正文；任务标签、Agent 总结和本轮时钟仍有效。旧设置文件仍可安全加载，保存的原生摘要资格偏好继续约束原有采集及隐私范围，不新增材料或模型调用许可。关闭 Agent 总结只去掉该卡片的句子，不改变定期简报、结果摘要、失败原因、名称生成或其它生成器的许可。

### 模型增强

面板请模型写的所有内容都在设置的「模型增强」（LLM）组里，每一项都有自己的开关；内容使用面板语言，按模型撰写的文字显示，不冒充观察到的事实（卡片的摘要文字由模型撰写；紧凑布局和详情用 `~` 标出模型文字）。

- **后端：**「后端」选择由谁来写：`agy` 或任意 OpenAI 兼容的 chat completions 接口（`api`）；选关闭则不调用模型、不发送任何材料。生成/隐私设置与卡片的显示开关分开。OMP 后端已移除，旧配置中的 `omp` 自动迁移为 `api`。
- **共用队列、缓存和上限：**所有项共用一个队列（同一时间只有一个调用）、一个缓存和一个每小时上限（「调用上限」，默认每小时 60 次，同一 `$HUD_HOME` 下的多个侧栏合计）；超过上限的请求会被拒绝，原因显示在本该出现文字的位置。设置页列表下方显示今天已调用的次数。
- **简报节奏**控制定期 Agent 简报、主会话回顾和改动摘要，不控制按需卡片进度。它用两个数控制频率，可选 1m · 5m、2m · 10m、5m · 15m 和 10m · 30m：

  | 数值 | 默认 | 最多多久触发一次 |
  |------|------|------------------|
  | **间隔** | 5 分钟 | 重要变化：阶段、状态或失败的变化，你的提问，最终回复 |
  | **下限** | 15 分钟 | 常规变化：agent 的新说明或命令、运行很久的一轮、变化了的 diff |

- **语言：**「语言」（设置 → 面板）也是模型所写一切内容的语言：切换后立即重新请求，另一种语言写的内容既不显示，也不作为上一份简报或回顾发回；下一次保留下来的内容会被翻译。模型如果明显用了别的语言回复（要中文却交回日文或英文，要英文却交回中文或日文），这条回复按「回复格式无效」处理，不写入缓存，并在本该显示文字的位置显示失败；夹带的名字或简短引文不受影响。
- **存储：**缓存和调用记录（只有时间戳）保存在 `$HUD_HOME/display/model-cache/`，权限 0600。

各项发送的内容：

- **主会话回顾**（`briefMain` 默认 `false`）：主会话的滚动回顾，显示在状态卡（卡片布局）或简报区域顶部（紧凑布局）：目标、已完成的事（最多四条）、当前进展，以及以警告色标出的需要你做的事。它会发送你的提问和助手的公开回复与说明（每条约 600 字符，总共约 4000 字符，绝不包含推理内容）、计划步骤、待批准请求的摘要、压缩次数、用 Codex 的 `/goal` 设定的目标及其状态（以只读方式读取 `$CODEX_HOME/goals_1.sqlite`，读不到就不发送），以及每个 subagent 的名称、状态和本轮时长；subagent 的任务和说明只有在同时开启 Agent 简报时才发送。以方括号标签开头的提问（`[watcher] …`），或以同伴消息的抬头（谁发给谁、注明是同伴消息，如 `Docs lead → Root (peer, no reply owed).`）开头的提问，会标为「可能是自动消息」发送，因为往会话里写消息的工具常这样开头；它也不算你发出了提问。每次只带上一次的回顾和之后的新内容，所以开销稳定，Codex 压缩对话后也不会丢。你发出提问、出现最终回复、一轮结束、计划步骤完成或出现待批准请求时，在间隔允许的范围内立即更新；一轮运行很久时（例如在等 subagent），只要有任何变化（包括说明或 subagent 的进展），最多每个下限（默认 15 分钟，且不短于间隔）更新一次。什么都没变就不发送。回顾按会话保存在 `$HUD_HOME/display/recaps/`（权限 0600，30 天后删除），重新打开侧栏或 `codex resume` 时会立即显示上一次的回顾和它的时间；语言不同的回顾会重新生成。卡片布局中显示在「完整」档的状态卡里；紧凑布局中显示在简报区域顶部。
- **卡片进度总结**（`agentProgress` 默认 `true`，独立于 `briefAgents`）：沿用不变的**原生摘要资格策略**按需生成说明，且必须正在显示 Agents、没有模态页打开；纯任务或门面文字不会成为新对象。关闭 Agent 总结会排除该 L1；关闭子 agent或子 agent 总结会排除相应后代。保存的子 agent 范围、筛选和收起规则继续约束原生请求资格，不会因为父级存在就请求所有后代。有许可的原生说明可提供紧凑卡片的可选句子；完整说明与排队、生成、失败、调用上限诊断保留在详情里，不进入紧凑正文。旧子任务显示偏好为兼容性继续约束原生采集资格，但不会恢复卡片上的助手文字；原始汇报和日志历史留在详情里。只发送当前轮的公开证据：最多四条汇报（每条 600 字符）、阶段意图（300）、当前工具/动作（200）、明文任务和创建前原文（各 300）、名字/角色（各 80）、阶段元数据及后代状态计数。不读取推理，不发送加密任务。没有公开汇报、阶段意图或当前操作时，不编造进度，也不调用模型。输出是面板语言的**一句话，最多 120 字符**。首次请求不等简报节奏；相同输入去重并缓存，输入变化后最多每分钟刷新一次，失败后十分钟重试。隐藏相应摘要或 Agents 区域、打开模态页、关闭后端、暂停模型或切换会话/语言/轮次，会取消过期请求。它共用队列和调用上限，但独立于定期 Agent 简报和主会话回顾。
- **结果摘要**（默认关闭）：subagent 完成时，它完整的最终答复（仅公开的最终回复；超过约 8000 字符时取开头和结尾）只发送一次，返回三行：结论、依据，以及 agent 自己说明的存疑之处。主会话启动的 agent 每个阶段结束时，超过 1500 字符的返回也会生成摘要。摘要写入该 agent 的日志，在检查器的「~ 结果摘要」下显示，并在 Agent 简报的材料中代替原文。侧栏看到之前一小时以上就已完成的 agent，只有在你检查它时才生成摘要。
- **Agent 名称**（默认为替换名字；设置后端之前不发送任何内容）：为每个 agent 当前在做的事起一个约 10 个汉字或 4 个英文单词的短名，并给出一种工作类型（research、experiment、fix、review、writing、summary 或 other）。它由 Agent 简报在写说明时一并写出，同一次回复，不额外调用，用的也是已经发送的材料；工作没变时沿用原名，工作换了就换新名，显示的是面板语言下最新的一个。Codex 0.162 起派给 subagent 的任务是加密的。名称任务会发送一次父会话在创建该 subagent 之前写下的明文（400 字符，附带任务路径和角色）；没有这段文字时，才发送明文任务，多个合并为一次请求。Fernet 密文不发送。卡片用的是这个名字。简报根据说明和阶段起的名字只在它到达之前临时顶上，到达之后不再替换它。紧凑工作卡片之外，类型由 HUD 画成固定的图形，暗色显示在 agent 名字旁：⌕ 调研、⚗ 实验、⚒ 修复、◈ 评审、✎ 撰写、∑ 总结，other 不画（图例见 `?`）。替换名字时，面板用短名显示 agent；写在名字下时，紧凑卡片保留原生名字，短名仍在日志块中原名的下一行；关闭则用 Codex 的名字，两种请求都不发。卡片 →「任务标签」可以单独隐藏卡片上的标签，不影响其它视图；Codex 原名保留在 Inspector 中，不再有第二个卡片名字行或「原始名字」控件。Inspector 始终保留 Codex 的原名，即 `/subagents` 显示的名字，切换也按它进行。名字到达之前、功能关闭或请求失败时，卡片显示 Codex 的名字，不画图形。简报起的名字随说明存在 agent 日志里；按任务文本起的名字按文本的哈希保存在 `$HUD_HOME/display/model-cache/labels.json`（0600），每个任务只起一次；还没有类型时写下的旧条目照样可读，类型按 other 处理。会话也会得到一个标题：主会话回顾写过时取回顾的目标（不调用模型），否则用你的**第一条提问**（1500 字符）调用一次。标题保存为回顾旁的 `<session>.title.json`，在状态栏会话字段最宽的显示中出现，会话 id 仍在旁边。
- **失败原因**（默认关闭）：主会话的工具调用失败时，发送命令和输出的最后 2000 字符；subagent 以错误结束时，发送它 rollout 末尾的错误事件（或最后一个失败命令的输出）。返回一行原因，显示在时间线的事件下方；对 agent 还写入它的日志并在检查器中显示。rollout 没有记录错误输出的失败不发送任何内容。
- **改动摘要**（默认关闭）：改动面板打开时，当 diff 的文件或行数变化，最多每个下限一次，发送按文件的统计（最多 40 个文件）和最多 6000 字符的已暂存与未暂存内容；未跟踪的文件只发送文件名。返回一到两行，说明这次改动做了什么，以 `~` 标记显示在面板顶部；diff 之后又变了，旧摘要会注明，直到下一次更新。
- **批准说明**（默认关闭）：有命令等待批准时，发送完整命令（最多 2000 字符），并在简报区域顶部以「~ 待批准（模型描述）：」显示一句话，说明它会做什么。只做描述：判断命令是否安全的回复会被丢弃而不显示。它不能代替阅读命令本身；仍然在 Codex 的批准提示中作答。

这些模型功能从不读取推理或其它私有频道。卡片显示开关只影响呈现和自动进度请求目标：定期简报以及独立开启的摘要、名称、原因、改动和批准生成器保留各自的范围。预设、重置和总结诊断不新增模型材料、网络目的地或密钥存储方式；生成仍由现有模型许可和连接设置控制。

后台任务的结果按输入、后端、接口地址和实际模型缓存，跨侧栏也可复用；整体简报和滚动回顾不缓存。后台任务失败后等待 10 分钟再重试。

`codex-hud brief --dry-run` 打印面板此刻会为当前目录的会话发送的简报：说明和材料，以及它们的大小；按保存的设置、agent 日志和上一次回顾生成，不调用模型，不写任何文件，后端关闭时也能用。它只预览简报/回顾材料，不包含卡片进度或其它后台任务。`codex-hud brief --dry-run FILE` 改为写入 FILE（权限 0600）。

按 `Ctrl+\` `b` 或点击控制栏上的暂停按钮（暂停模型） 可以暂停和继续以上所有项（`briefingPaused` 默认 `false`，配置模型后端时可用）。模型增强 →「暂停模型」是同一个开关；保留已存模型文字，即使两个定期简报开关都关闭也适用。连接信息不在面板里输入：选中 模型增强 →「后端」时，设置页会写出设置文件的位置（`$HUD_HOME/hud-settings.json`，默认 `~/.hud/hud-settings.json`，或 `HUD_SETTINGS_PATH`）和其中的连接键名，并说明 base 和 key 是否已设置（两者的值都不显示）；选 `agy` 时提示 `CODEX_HUD_BRIEF_MODEL`。使用 `api` 时在 `hud-settings.json` 里设置：

```json
{ "briefing": "api",
  "briefingApiBase": "https://api.mistral.ai/v1",
  "briefingApiModel": "",
  "briefingApiLiteModel": "deepseek-v4-1-flash-1017",
  "briefingApiLowModel": "deepseek-v4-1-flash-1017",
  "briefingApiMediumModel": "deepseek-v4-1-flash-1017" }
```

base 留空即 `https://api.mistral.ai/v1`。key 只来自进程环境变量或 `$HUD_HOME/credentials.env`，按**精确的接口源**选择：`https://api.mistral.ai` 用 `MISTRAL_API_KEY`，`https://api.openai.com` 用 `OPENAI_API_KEY`；环境变量覆盖同名文件项。自定义/本地接口、仿冒主机、HTTP 变体和非默认端口都收不到这两个 key，带用户信息的 URL 会被拒绝；没有匹配的 key 时该功能关闭，不发请求。HTTP 重定向会被拒绝，不向重定向地址转发密钥或会话材料。设置文件里不存 key，key 放在环境变量或凭证文件（设置文件以 0600 权限写入）。API 按任务类型路由：命名、会话标题和审批说明用 lite；活跃进度总结、agent 简报、结果摘要和变更摘要用 low；主会话回顾和失败原因用 medium。非空的 `briefingApiModel` 覆盖全部 API 档位，`CODEX_HUD_BRIEF_MODEL` 覆盖任意后端的模型名。产品默认是 Mistral 源和三个档位都用 `deepseek-v4-1-flash-1017`；`agy` 保留默认模型 `gemini-3.8-flash-low`。设置 → 模型增强提供 **Lite effort**、**Low effort**、**Medium effort**（`briefingApiLiteEffort`、`briefingApiLowEffort`、`briefingApiMediumEffort`），默认分别为 `none`、`low`、`high`，可选 `off | none | low | high | xhigh | max`；`off` 不发送 `reasoning_effort`，`none` 明确关闭推理，其它值原样发送。`minimal` 和 `medium` 只在设置文件里为支持的接口显式填写时才接受，面板从不推断或提供。DeepSeek V4.1 Flash on Mistral 拒绝这两个值。不会悄悄换模型或换强度重试。已移除的旧键（`briefingApiKey`、`briefingApiReasoning`）在读取旧设置文件时被忽略，下次保存时丢弃，文件中的其它键保留。

### HUD 凭证与 Jev 配置

HUD 读取 `$HUD_HOME/credentials.env`（`HUD_HOME` 默认 `~/.hud`）。它必须是权限 **0600** 的普通文件；符号链接和 FIFO 会被拒绝，不跟随也不阻塞。格式为 `NAME=VALUE`，可加 `export ` 前缀和/或引号；**不做插值**。已知名称有 `GEMINI_API_KEY`、`TYPESAFE_API_KEY`、`TYPESAFE_MODEL`、`OPENAI_API_KEY`、`OPENAI_BASE_URL`、`MISTRAL_API_KEY`、`MISTRAL_BASE_URL` 和 `TEXT_MODEL_*`。

```dotenv
GEMINI_API_KEY=synthetic-gemini-key
TYPESAFE_API_KEY=synthetic-typesafe-key
OPENAI_API_KEY=synthetic-openai-key
MISTRAL_API_KEY=synthetic-mistral-key
```

凭证每次重新读取，不缓存。每个名称先取进程环境变量，再取 `credentials.env`。文件缺失就没有 key。不会从 pi、Codex、jev-ask 或其它文件隐式读取 key，`jev.env` 也不再是回退来源。

**决策提供方。**`config.json` 使用 `decisions.primary` 和 `decisions.fallback`，取值 `gemini`、`openai` 或 `typesafe`。默认 primary 为 **OpenAI**；自动 fallback 按 Gemini → OpenAI → TypeSafe 顺序选择第一个有 key 的其他提供方。显式 fallback 保留；若与 primary 相同，则自动选择。顶层 `decisions.primary` 缺失时，依次把 `decisions.provider`、旧的 `jev.decisions.provider` 当作 primary。设置 → 模型 → **决策 API** 在 Gemini / OpenAI / TypeSafe 间切换，按 `s` 只保存 `decisions.primary`；`（无 key）` 标记缺少凭证，但仍可选择。下个任务或决策 CLI 调用生效，运行中任务保留原提供方，显式任务配置仍固定。面板不显示或编辑 key。只有 fallback 的 key 存在时才会使用 fallback：它在单次调用中接管配额（429）、认证（401/403）、5xx 或超时失败；格式错误或被拒绝的回复仍归原提供方。primary 的 key 缺失而 fallback 的 key 存在时，用 fallback 并记录原因 `credentials_missing`；两者都没有时调用以 `jev_credentials_missing` 失败，并指出 primary 的变量名。Gemini（`gemini-decision-1`）使用 `x-goog-api-key`，无上下文缓存，输出 token 恒为 0；免费额度为 200 RPM、50,000 TPM、10,000 RPD。Gemini 配额/限流回复（429 或 `RESOURCE_EXHAUSTED`）触发进程内存冷却期：取 `Retry-After` / `retryDelay`，否则 60 秒；期间跳过 Gemini，到期再尝试。安全过滤 400 作为拒绝，不触发回退。若 Gemini 是任务的 fallback 且处于冷却期，则跳过并返回 primary 的错误，不尝试第三个提供方。TypeSafe 仍可显式选择。最多只有一次 fallback 调用，也不会重复浏览器动作：任务记录的 `decisionCalls` 写明实际作答的提供方和回退原因。

**导入旧配置。**旧位置只能通过一次性的显式 `hud import preview|apply [--from <文件>]...` 访问；不会自动发现，也不猜任何 Codex home。用 `--from` 逐个指定旧的 `hud-settings.json` 或 jev-ask TOML；也可以显式指定 `.env`。存在 `$HUD_HOME/jev.env` 时会自动合并进 `credentials.env`。`preview` 打印来源、目标以及将新增或跳过的名称/键，不写任何文件；`apply` 从不覆盖已有的 HUD 值（已有值优先，每个跳过都会报告），为每个被改动的目标做带时间戳的 0600 备份，并且可重复执行。输出从不包含值。TOML 的 `[jev]` 段映射为 `config.json` 的 `jev`（`cdp_url` → `cdpUrl`、`chrome`、`profile`、`state_dir` → `stateDir` 以及其它 camelCase 字段），`[aistudio]` 映射为 `aistudio`（`cdp_url` → `cdpUrl`、`state_dir` → `stateDir`、`models`、`default_model` → `model`、`default_thinking` → `thinking`）。运行时的 TOML 和 `JEV_ASK_CONFIG` 会被忽略。

```bash
# 预览：只列出来源、目标和名称，不写文件。
hud import preview --from /tmp/old-codex/hud-settings.json --from /tmp/old-jev/config.toml
# 应用一次：已有 HUD 值优先；被改动的文件获得带时间戳的 0600 备份。
hud import apply --from /tmp/old-codex/hud-settings.json --from /tmp/old-jev/config.toml
```

**Jev 位置。**HUD 不接触浏览器。浏览器任务运行外部 `jev-*` CLI，由这些工具管理 Chrome、profile、CDP 和操作状态；请直接配置对应工具。`hud import` 写入的旧 `jev` 位置与 `aistudio` 段不再用于 HUD 的浏览器设置。上面的决策 API 配置仍由 HUD 管理。

**按来源的 key。**委派摘要来源可在其私有 `model.json`（`connection.keyEnv`）中指定自己的 key 变量名。该名称先取捕获的环境变量，再取 `$HUD_HOME/credentials.env`，不读其它文件；`keyEnv: null` 表示无账户，不发送 key。它与面板路径互不相通：按主机匹配的面板 key 绝不会发给来源的自定义 base，来源的 key 也绝不进入面板；面板路径使用自定义 base 且没有主机匹配的 key 时关闭，不发请求。

### 背景图

面板 → 背景图会在侧栏空白处画一张字符画：盲文点阵、按原图上色的点阵，或 ASCII。它只占用没有内容的行，agent 和简报需要空间时会自动让出。`bin/codex-hud-art <图片> [dots|color|ascii]` 会把图片复制到设置旁边并打开装饰；`bin/codex-hud-art off` 关闭。图片由 ffmpeg 读取，它支持的格式都可以。

## 输出速度

底部状态栏用整数显示主会话输出速度，如 `42 tok/s`：本轮已有自己的采样时为亮色，否则保留上一轮的值、变暗且不再变化。面板状态带写作 `~42 tok/s`，选中代理的详情也会展示其可用读数。
它按 **wallclock** 口径，用**本轮可测的输出 token 增量 /（日志时间差 − 可识别工具等待区间的并集）**估算吞吐，包含首 token 等待（TTFT）和生成停顿；并行工具的重叠等待只扣一次。只扣起止配对完整的等待并集；缺失工具结果时保守地保留该段耗时，避免分母冻结而虚增速度。
不再使用约 30 秒的滚动窗口，不做平滑、速度封顶或一秒最小窗口限制。展开详情后注明实际估算时长。
Codex rollout 没有逐次请求的精确开始/流结束遥测，因此 `~` 表示本轮级近似，不等于 pi 的精确请求 wall TPS，也不是纯模型解码速度；无法识别的等待和落盘延迟仍可能计入分母。
缺少前次累计计数时，等待两个累计报告，仅计算实际可测区间；首个报告的最近调用用量可能重复上轮，因此不会拿它反推本轮起点。重复且累计输出不变的报告不稀释或刷新读数。新一轮开始时排除跨轮空闲时间。
没有足够样本时不显示；10 秒没有新样本后面板显示 `last ~42.1 tok/s`，保留上次读数。
上下文用量仍在状态栏里，开发面板不绘制 Ctx 趋势。

## 机器可读的状态

状态栏会按窗格宽度自我裁剪：能缩就缩，放不下就藏。这对读者是对的，对脚本是错的。
所以状态栏或侧栏里正在运行的那一个，每一次采集也会把已知状态写到 `$HUD_HOME/display/state/<tmux 会话名>.json`，
`codex-hud --json` 则打印当前目录会话对应的那一份。侧栏写出的 `bar.segments` 是空的。

```bash
codex-hud --json | jq '.context.percent, .agents.active, .attention[].label'
```

其中包含会话、项目、活动、上下文、额度、token、代理与需要关注的事项，
有待批准请求时的 `approvalSince`，推算成立时的 `quotaForecast`（是估计，不是读数），
另有 `bar.segments`：真正画出的那一行里，每个字段落在哪几列。
点击某一列能对应到某个字段，靠的就是它。

`agents` 的计数与面板一致（见[布局](#布局)）：`active`、`completed`、`failed`、`unknown`
统计主会话启动的 agent，子任务还在运行的也算 active；`agents.subtasks` 和 `agents.reviews`
按同样四项统计子任务和守护评审；`agents.nodes` 列出每个线程及其 `kind`（`agent`、`subtask` 或 `review`）。
这是 `version` 2；version 1 把所有线程合在一起计数。

规则与显示一致：每个值都是观测到的事实，没有数据的字段整个缺席而不是写 0，
这样“没有额度快照”和“额度为 0%”不会长得一样。文件以 `0600` 权限原子写入，
只在时钟之外确有变化时才写，且每秒至多一次；写下它的进程退出时才删除——
一个已经停止的 HUD 留下的状态文件，看起来会像还活着。属主是旁边 `<文件>.owner` 里的 pid。不属于自己的文件会留下，这样正在退出的侧栏不会删掉状态栏刚接手的快照。

`health` 说明状态栏自己的读取是否顺利：`lastReadAt` 是会话查找和 rollout 读取上次成功的时间，
`lastError`（`source`、`message`、`at`）是最近一次失败的采集。两者在发生之前都不出现。
单纯又一次成功读取不会触发重写，所以 `lastReadAt` 和 `updatedAt` 一样，是“截至上次写入”的值。

### pi 任务目录与会话历史

任务记录和报告位于 `$HUD_HOME/jobs/<job>/`；pi 会话历史保存在 pi 默认的
`~/.pi/agent/sessions/<cwd-dir>/`，任务的 `sessions/` 仅链接到主代理／助手的真实文件。
删除任务目录不会删除历史；用 `pi --session <session_id>` 从 pi 默认目录恢复会话。

底部状态栏从左往右连续排开，中间不留空。先是会话依托的环境：模型和推理强度（`gpt-5.6-astra xhigh`）；进度条和最近一次请求占用的上下文对比模型完整窗口，都是 Codex 上报的原值（`━━━━╸───── 149.1K/380K`，不扣基线；70% 以下为普通色，过 70% 变黄，过 85% 变红）；仓库和分支（`codex-hud main*↑2`）；账户额度只显示一个读数，即最紧的窗口（`7d 38%`），窗口用完但还有 credits 时只显示余额（`credits 6.8K`）。然后是主会话此刻的状态：会话状态和本轮计时（`▸ 12:58`；空闲时 `✓ idle`），输出速度，agent（`Agents 1▸ 1✓`）和计划（`Tasks 2/5`）。接着是通知区，占用剩下的列：最前面是需要你处理的告警（等待审批，或工具、agent、子任务、评审失败，危险色底）；然后一分钟内彩色显示刚发生的事（`✓ explorer finished · 12s ago`、`✗ explorer failed`、`✓ turn done in 12:48`、`◆ window spent, on credits now`）；之后，Codex 工作时显示正在运行的工具和它的对象（`exec_command npm test`，或脚本执行的命令），空闲时淡色显示最近一条通知和距今多久。最右边是 Codex 加载了什么：MCP 服务器、skills 和 hooks（`MCP 2  skills 10  hooks 1`）。计时和速度无论长短都占固定列宽，通知区无论写什么都占同样的份额，会话运行时它前面的字段不会被挤动。变窄时先去掉右段，再去掉推理强度和上下文进度条；然后通知区让出份额，只用剩下的列，接着去掉 Agents 字样、分支和计时。不再显示提示缓存提醒：Codex 会保留缓存。

面板的上下文比例对齐 [Codex 0.154 的计算](https://github.com/openai/codex/blob/rust-v0.154.0/codex-rs/protocol/src/protocol.rs#L2258)：使用最近一次 token 报告，从已用量和窗口大小两侧扣除 12K 固定基线，因此面板的 `20%` 对应原生的 `80% context left`。自定义窗口不超过 12K 时按原始窗口计算。总会话 token 不用于计算上下文占用。

```bash

CODEX_HUD_GLYPHS=glyph CODEX_HUD_THEME=mocha codex
```

### 提醒

默认关闭：Codex 自己有通知机制，同一件事弹两次比不弹更糟。在设置 → 状态栏 →「通知」打开，或用 `CODEX_HUD_NOTIFY=1` 开启：`tmux` 只发 tmux 消息，`tmux + 桌面` 同时发桌面通知（`CODEX_HUD_NOTIFY_DESKTOP`）。设置了的环境变量优先于设置。打开的侧栏也按同样的规则，在自己的采集节拍上发出提醒。

```bash
CODEX_HUD_NOTIFY=1 codex
```

它只提醒观测到的失败、Codex 正在等待的审批，以及已结束的代理，每次发生只发一条，并带冷却时间，避免状态反复时刷屏。
它不会对会话做任何操作：不自动确认、不发送按键、不自动重试。

`CODEX_HUD_NOTIFY_DESKTOP=1` 会额外发出终端之外的桌面通知。这是第二道开关：走出终端比发一条 tmux 消息要冒昧得多。

```bash
CODEX_HUD_NOTIFY=1 CODEX_HUD_NOTIFY_DESKTOP=1 codex
```

两条通道都是尽力而为，不支持时静默：一条是终端自己可能响应的 OSC 9 与 OSC 777 序列（包在 tmux passthrough 里，由启动脚本负责开启），另一条是 Linux 的 `notify-send` 或 macOS 的 `osascript`。
通知文本来自 rollout，写出前会剥掉全部控制字符：消息无法提前结束序列、把剩下的内容当成终端命令执行。

### config.toml

HUD 从 `CODEX_HOME/config.toml` 读取配置：

```toml
model = "gpt-5.2-codex"
approval_policy = "on-request"
sandbox_mode = "workspace-write"

[mcp_servers.my-server]
command = ["node", "server.js"]
enabled = true
```

用 `codexH` 启动后，按 `F12` 打开面板，启动时不会自动打开。常用侧栏宽度下，主会话速度优先于可选的模型和时长字段保留；超过十秒、属于上一轮或空闲时显示的采样标成“上次”，不会消失或冒充实时速度。

### 诊断与连接测试

按 HUD 前缀键（默认 `Ctrl+\`），再按 `d`，打开详情区的 HUD 诊断。
这里显示主会话 TPS 的采样时间、样本时长和估算口径；agent 详情中按 Enter
展开同类信息。本轮近期采样、旧采样/上一轮采样、暂无数据会分别标明。
JSON 快照新增可选 `outputRate` 证据及 `health.sessionBound`。

常驻面板直接提示当前故障：未绑定会话、读取失败、Herdr 探针/连接故障、
重连后离线通知未确认、分类后的模型错误和排队等待。底部缩小栏显示采集和
桥接故障；诊断详情保留上次成功读取/确认时间。正常时不额外显示诊断横幅。

设置 → 模型增强提供「测试连接」，该组内按 `t` 也可启动，再按一次取消。
测试使用当前草稿中的 lite/low/medium 三档路由，只发送固定测试消息，每次
最多 256 个输出 token，网络请求超时 15 秒。三次调用计入正常每小时预算；
不保存草稿，不发送会话文字。后端关闭或选 AGY 时不会发起 API 测试。
关闭设置或改变连接配置会取消检查，并防止旧结果重新出现。结果区分鉴权、
模型不存在、限流、超时、连接/服务故障、输出截断与无效回复。普通生成暂停时仍可显式
点击测试，因为测试是用户主动触发的操作。

同一台机器、同一 HUD_HOME 下的模型调用现在先原子预留预算再发送；缓存
写入合并，跨窗口相同的可缓存请求共享结果。发送进程崩溃或取消时，已预留的
额度可能保守保留；协调失败则拒绝发送，不绕过计数。排队时审批和显式测试
优先，其次可见进度，最后后台摘要，同时防止后台任务一直饿死；已发出的请求
不会被抢占。跨窗口协调依赖本地文件系统的原子重命名和一致目录读取。
