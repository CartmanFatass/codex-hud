## 安装

需要 **Node ≥24.0.0**（Node 24 为经过测试的支持版本线；见[运行时依据](./ARCHITECTURE.md#3-launch-and-installation)）。在检出目录运行：

```sh
./install --with claude,pi,codex,browser,herdr
```

可任选 **claude**、**pi**、**codex**、**agy**、**browser**、**herdr**；核心始终安装。
安装器先检查 Node，再运行扩展检查、构建或修改文件，构建 HUD 与 MCP，将命令链接到 `~/.local/bin`。
`--skip-build` 使用已有构建。保留检出／解压目录：已安装命令和客户端绑定均指向它。不修改 shell rc。

外部工具只检查，不安装、不鉴权。工作者另需 herdr、pi-roles 和 pi。herdr 扩展报告 PATH 中的位置，
仅缺少 herdr 时失败。browser 扩展要求 `google-chrome` 与 `jev-ask`，另报告可选的 `jev-aistudio`、
`jev-flow`；不写浏览器配置、不启动任何工具。Chrome、登录与密钥由这些外部 CLI 自行配置。
面板和决策 API 不需要 browser 扩展。

直接启动 `claude` 即使用全局 HUD 状态行，已有非 HUD 自定义状态行则保留；直接启动 `pi` 加载 HUD 页脚。
Codex 的 tmux 状态行使用安装器打印的函数：

```sh
codexH() { hud codex "$@"; }
codexH
```

只有面板按需打开：Claude、Codex 和 pi 都用 `/hud`，启动时不展开。用 `hud uninstall` 或
`./install --uninstall` 卸载；`--with names` 限定扩展。保留 HUD 数据和无关设置。
Claude 设置跟随符号链接并保留一次性普通备份；Codex 在官方 MCP 命令前备份解析后的 `config.toml`，
丢失注释时警告。pi 注册委派与显示两个包，并排除旧 p10k-footer。

安装 Antigravity 集成前，确保 `PATH` 上有 `agy`，再运行 `./install --with agy`。
安装器注册 HUD MCP、权限规则和钩子，保留已有的非 HUD 状态行。
用 `./install --uninstall --with agy` 移除该集成。

备份和多个 Codex home 的操作见[安装器扩展](../install.d/README.md)。

## 通用 CLI 与 MCP

```sh
hud --help
hud panel --help
hud panel                 # 在 herdr 中于调用者旁打开，否则在当前终端显示
hud panel --here          # 不分割窗格
hud panel --width 64      # 本次覆盖，直到保存修改后的宽度
hud statusline --help
hud import --help
hud trust <dir>           # 把该目录加入 grok、agy 和 claude 的信任列表
hud watch                 # 本窗格 HUD 任务每次状态变化一行（--all：所有任务）
hud doctor <jobId>        # 只读查看单个任务的本地记录
hud setup --detect        # 打印本项目的工作者配置 JSON
hud setup --apply PLAN    # 按计划写入 .hud/
hud setup --remove        # 去掉项目注册，留下 .hud/
hud tickets sync [--cwd DIR]  # 单向将 GitHub 父子议题镜像到 .scratch/
hud board [--cwd DIR] [--out FILE] [--open]  # 写出项目的 HTML 审阅看板，打印其路径
hud codex --model gpt-5    # Codex 参数原样交给 tmux 启动器
```

`hud codex-hud` 是 `hud codex` 的别名。面板可用 `--root <namespace/session-id>` 或
`--harness claude|pi|codex --session ID --source ABS` 选择观测，不建立执行身份。
没有显式选择时，`HERDR_PANE_ID` 允许用一秒预算向 `herdr pane current` 查询调用者的 Claude 转写或 Codex 会话（herdr 窗格内回退读取 `CODEX_THREAD_ID`）；
不猜聚焦窗格、不读取状态行写下的绑定。证据不可用时，仅保留未绑定原生会话的任务视图。

`hud doctor <jobId>` 读取 `$HUD_HOME/jobs` 下的单个任务目录。它显示任务身份、共享读取器给出的状态、原始
`STATUS.json`、未答问题、检查结果、最新进度，以及适用的停止／关闭标记和记录中的进程是否存活。
对 CLI 工作者，它会比较当前轮次、完成回执和当前报告签名，但不打印报告正文。缺失或无法读取的记录会标明。
该命令不修改任何文件，也不连接 herdr 或网络。

MCP 提供 **hud_roster**、**hud_create**、**hud_read**、**hud_wait**、**hud_peek**、**hud_send**、**hud_respond**、**hud_close**、**hud_land**、**hud_lease** 与 **hud_tickets**。
首次分派或项目上下文失效时，调用 `hud_roster` 获取角色可用性、能否继续、生效的 `runs_on` 和约定；上下文仍有效时直接调用 `hud_create`。
同一 MCP 会话再次调用时，若约定未变则省略正文，角色信息仍会刷新。
`hud_roster` 和该会话的首个 `hud_create` 结果会按调用者的运行环境给出通知提示；无法识别时给出通用提示。
传入 `detail: true` 可查看预设、后备位置、来源及可用选项。
`$HUD_HOME/roles/*.json` 按角色名覆盖内置 JSON，已注册项目的 `.hud/roles` 再覆盖。
已注册项目的 `.hud/`、cwd、HUD 主目录、包目录中第一个 `hud-convention.md` 整体替换默认约定。
见[项目工作者](#项目工作者)。

`hud_create` 接收 `role`、`task`（或 `brief_file`：位于 `cwd` 内的可读 UTF-8 文本路径，上限 256 KiB，与 `task` 互斥），可选 `cwd` 和仅用于显示的 `package`；还可用 `ticket`（`feature/NN`）和 `slice`（STATE 条目 ID）关联进度。不支持 MCP tasks 的会话可传入 `jobs: [...]`，在一次调用中批量派发多个任务：每项接受与单次创建相同的字段，按输入顺序返回逐项结果，单项失败不阻塞其余项，每个创建成功的任务仍保留自己的通知。
省略 `request_key` 时，根据调用窗格、角色、cwd 和任务正文生成去重键。默认在角色的首个可用位置（`runs_on`）启动。
`hud_create({retry_of: job})` 使用失败或停止任务的简报和选项开启新任务，显式传入的字段优先，但仍须遵守新建任务的规则。
未提供新的运行位置选项时，重试沿用原任务的相关选项，从角色或预设的执行链选择可用位置，而不锁定原执行环境。
各角色在哪里运行由角色文件和「控制」决定。只有 `general` 接受 `preset`、`on`、`model` 或 `thinking`，且只在用户要求时对单次任务生效。
对 `general`，`preset` 选取指定预设中首个可用且未耗尽的位置，不保存设置；也可用 `on` 覆盖执行环境或浏览器服务商
（默认值见内置 `harnesses.json` 与 `$HUD_HOME/harnesses.json`）。`preset` 和 `on` 互斥。
`model` 和 `thinking` 覆盖所选 `pi` 或 `cli` 位置的模型和推理强度。其他角色在启动前拒绝这四个字段，批量派发和重试也一样。
带 `detail: true` 的任务读取或查看会显示所选 `preset`。重复使用显式键会返回原任务；派生键仅复用最近 10 分钟内创建的任务。
`kind` 为 `flow` 选择 `image`（默认）或 `video`。
仅 `pi` 可覆盖布尔项 `lens`、`mcp`、`tps`、`ui_ext`、`skills`、`split`，以及 `pi_args`
（最多 128 项，每项 4096 字符，原样传递，不经 shell）。省略的开关沿用 pi-role 默认值；
split 默认取位置设置。`ui_ext: false` 禁用 UI 扩展；`skills: true` 加载个人技能；
split 为 true 时预留右侧助手窗格。拒绝覆盖 `--orchestrator`／`--notify`。调用方只有在使用 `general` 时才能传入模型、提供方和推理强度参数。重试时若更换角色，不沿用原先的位置覆盖项。
浏览器（`bro`）位置拒绝这些 pi 选项。

传入 `scout: "<问题>"` 时，HUD 先按 sonic 角色的常规设置，在目标任务的工作目录（包括托管工作树）中用相同的
`context_files` 运行 sonic。`hud_create` 立即返回目标任务 ID，支持 MCP tasks 的客户端则获得一个覆盖两阶段的任务；
收集结束后，HUD 自动启动目标任务，并把资料报告加入 `from_jobs`（16 个名额中须预留一个）。不会单独发送 sonic 通知。
若 sonic 失败或需要人工处理，HUD 仍会启动目标任务，在简报中注明原因，并关闭仍在运行的 sonic。
`role: "sonic"` 不接受 `scout`。问题就是 sonic 的任务正文；若启用了 Sonic 自动选档，也会将它用于选档。
浏览器目标接收的资料报告仍受通常的上下文字节限制。

可传入 `checks`，指定原本要亲自复跑的检查命令，最多五条。Pi 或 CLI 工作者声明本轮完成后，HUD 在任务的 `cwd` 中
用 `bash -lc` 依次运行命令，每条限时十分钟。重试和关闭后新建的修复任务会继承这些命令。`hud_read({job})` 显示
每项是否通过；`mode: "full"` 同时显示失败输出的末尾；开始新一轮或重写报告会让旧结果过期。`hud watch` 在结算行或检查完成后的通知中附上
`checks 2/3`。任务卡片和检查器也显示通过数／总数（`✓` 通过、`✗` 失败、`↻` 运行中、`~` 过期）。检查不会结算任务，也不决定是否验收。

可用 `context_files`（最多 32 个路径，以任务的 `cwd` 为基准解析）和 `from_jobs`（最多 16 个任务 ID，
各自指向 `$HUD_HOME/jobs` 中该任务的 `report.md`）传递上下文。文件须为可读的 UTF-8 文本，解析后的路径须分别位于
`cwd` 或 `$HUD_HOME/jobs` 内；无效引用会在启动前返回 `invalid_arguments`。Pi 和 CLI 工作者按简报中任务之后列出的路径读取文件；
浏览器（`bro`）会把标明来源的文件内容随简报发给浏览器服务（单个文件最多 64 KiB，合计最多 256 KiB，超限返回 `context_too_large`）。
通过 `from_jobs` 附带的 `sonic` 报告（包括 scout 资料报告）前会加上一行与简报语言一致的提示，说明 sonic 事实只是带 `file:line` 的未核实起点，据此做决定的代码须亲自阅读。
只有已注册的项目才会自动纳入根目录下可选的 `.hud/brief.md`：本地任务在正文后附上引用，浏览器任务按同样的大小限制内联其内容。
请确保该文件内容可发送给所选浏览器服务。引用上游报告不会将其标为已读，也不会关闭其工作者。

`isolation: "worktree"` 让任务在仓库旁自己的 Git 链接检出中运行（`<repo>-wt/<slug>-<id6>`，分支 `wt/<slug>-<id6>` 取自 HEAD，
链接 `node_modules`，并复制该 CLI 对主检出的信任）。浏览器角色和非 Git 目录会被拒绝。在完整模式下，`hud_read` 会附带 `worktree`（含检出路径）及 `git_summary`。
其中 `overlaps` 列出同一检出下也改动了这些文件的其他托管任务及重叠文件，排除其他工作树中已提交且文件版本与主检出 HEAD 一致的改动。
空列表表示未发现重叠，`null` 表示当前任务的 Git 摘要读取失败，`overlaps_incomplete` 表示结果不完整。
任务关闭后，只有工作树干净且分支未改动、已合并或每个切片提交在基分支上都有等价补丁时，watcher 才会移除检出和分支。
若工作树不干净，或仍有未摘取的补丁（包括集成时被修改的补丁），则保留并在 `job.json` 记录 `worktree_kept_reason`。
基分支 HEAD 变化后，后续扫描可重新检查因补丁未摘取而保留的分支；不会重试脏工作树。Project 把这些检出视为任务自己的，不算未登记的 worktree。

已注册项目可在主检出的 `.hud/project.json` 中设置 `worktree.disposable`（例如 `["dist/**"]`，默认为 `[]`）。清理时豁免匹配的已忽略文件；当 `node_modules/` 下存在已跟踪文件时，建树会链接主检出中其余未跟踪项，清理也会把 `node_modules/` 下的已忽略项视为可移除的依赖状态。其他忽略文件、未跟踪文件及已跟踪的改动仍会保留。

`hud_land({job})` 集成成功结算（`idle_grace`、`done` 或 `closed`）的托管工作树。主检出的项目配置示例：

```json
{"land":{"base":"main","gate":["npm test"],"after":["npm run build"],"push":true,"wrapper":"tools/env.sh","timeout_s":900}}
```

HUD 排队取得 `main-checkout` 租约，在新的分离工作树中运行 `gate` 命令。如果任务分支已经基于当前基分支顶端，直接测试任务的原始提交；否则只摘取从基分支不可达的提交。可选 `wrapper` 是相对主检出的可执行文件，在目标工作树中接收 `sh -c <命令>`。每条 `gate` 和 `after` 命令（包括立即重跑）都有独立的 `timeout_s` 时限，默认 900 秒。达到时限后，HUD 终止该命令的进程组，记录 `timeout` 和最后 40 行输出，释放租约，不派发修复。某条 gate 命令失败（包括 Node.js 报告单项测试超时）时，HUD 立即在同一工作树重跑一次。如果输出包含 Node.js 的 `test at <文件>:…` 失败位置，HUD 通过同一个 wrapper 用 `node --test` 只重跑这些文件；否则重跑整条命令。重跑通过则继续，并在通知中列出能识别的偶发失败测试名称。若仍失败，或摘取提交时发生冲突，HUD 把失败步骤和最后 40 行输出发给源任务，要求它变基到当前基分支、修复并提交。修复与 `hud_send` 使用相同的原生会话恢复窗口；若无法继续源任务，则在源工作树创建同角色的本地任务，并记录 `retry_of`。修复期间释放主检出租约；收到新的结算结果后，重新创建集成工作树并从头运行 gate。最多修复两次；工人一旦提问，问题照常送达主会话，本流程停止。

每次门禁运行失败（首次运行或立即重跑）都会在流程记录旁保存最多 8 KiB 的私有输出摘录：能识别时保留 Node.js 测试的断言或错误段，否则保留输出末尾数行。`hud_read` 在 `reruns` 中显示摘录路径，终结通知也在列出偶发失败测试的同一行给出路径。通过的运行不会写入摘录；流程记录移除后，摘录也会被清理。

通过后，若任务的 `ticket`（`feature/NN`）对应本地工单，HUD 在集成工作树中将工单更新并入最后一个已测试的提交。若工单写明 `**Owner try:** no`，则标为 `done`；若为 `yes` 或省略此字段，则标为 `ready-for-human`。HUD 勾选验收项，并在评论里记录已测试的 SHA 和通过命令数/总数。此操作不更新 `STATE.md`，也不使用主检出的暂存区。仅当涉及路径干净且主检出仍位于原基分支顶端，或基分支新增提交均未触及本次集成的路径时才快进；后一种情况下，HUD 会在新的分离工作树中把已测试的提交摘取到新的基分支顶端，并重新应用工单更新（若存在路径重叠或任何冲突则拒绝），在通知中说明此次重放，并不重跑 gate 直接快进。然后在主检出运行 `after`（若某条 `after` 主构建命令与集成工作树已测试的构建输入、编译器及配置完全一致，HUD 通过 `scripts/build.mjs` 的分段发布器发布已测试的 `dist`，跳过重复编译），按配置把当前基分支 HEAD 推送到 `origin`。快进后基分支可以继续前进，但 HEAD 必须仍包含已落地的提交（包括并入的工单更新），且落地所涉及的路径必须干净。最后移除集成工作树；若任务工作树干净且仍位于本次流程实际集成的源提交（即使摘取后的补丁与源提交不同），也一并移除任务工作树和任务分支。集成完成后若清理失败，流程仍以完成结束并附带 `cleanup_note`，不会标为失败。快进之后失败仍会报告已落地的 SHA。

主检出的 `after` 构建在发布 `dist/native/` 前校验原生状态栏的源码及二进制哈希。优先使用通过校验的已测试产物，否则保留匹配的本地产物或用 Cargo 构建。在受支持的平台上，如果没有匹配的产物且 Cargo 不可用，构建仍会成功，落地结果会通过 `after_note` 提示一次仍使用 TypeScript 状态栏。

调用返回流程 ID（MCP-task 客户端获得一个覆盖全程的任务），无需等待门禁。执行进程在开始任何步骤前加载同一版本的构建产物；若加载失败，流程会失败并显示 `HUD was rebuilt; retry the land`（HUD 已重新构建，请重试落地）。再次调用 `hud_land` 时，若流程仍在进行或基分支已快进，则返回原流程；若在快进前失败或取消，则启动新流程，保留原 ID 下的记录，并在取得租约后清理旧的集成工作树。`hud_read({job: "<流程 ID>"})` 可查询任一次尝试的状态、当前步骤以及各步骤墙钟耗时 `timings`（含重跑与跳过的 `after` 重建）。若另一个落地流程持有租约，`hud_read` 与面板卡片会显示该流程；若它正在运行门禁，还会显示步骤编号和已耗用的分钟数。每次尝试结束时只发一条通知，给出 SHA 或失败步骤和最后 40 行输出，并逐行列出每次修复。流程记录在 `$HUD_HOME/flows/`，watcher 重启不会重复集成，执行进程意外退出时报告中断。

对于 pi、Claude Code 或 Antigravity（`agy`）上可继续的角色，`hud_create({role, task, mode: "headless"})` 不打开标签页，仍可在面板查看进度或停止任务。每轮都启动新进程并沿用同一原生会话，输出追加到 `stdout.jsonl` 和 `stderr.log`。pi 的会话保存在任务的 `sessions/` 下；Claude Code 和 Antigravity 使用各自的原生会话存储。无界面 CLI 与标签页模式使用相同的提示词和工作者 MCP 配置：Claude Code 接收任务的 `--mcp-config`，Antigravity 使用已安装的 `hud` 服务并继承任务环境。它没有标签页可切换：在其任务卡上按 `g` 会打开详情，其中「输出」块显示 `stdout.jsonl` 的最新几行（工具调用、助手文字和错误，最多 12 行；任务运行时标注「运行中」），并按面板的采集节奏跟随日志；停止（`X`）与其他任务一样可用。提问即结束本轮；通过 `hud_respond` 或面板作答后，用答案恢复同一会话。提交报告后工作者关闭。无界面任务运行期间收到的后续消息按发送顺序排入下一轮；若本轮以提问结束，则与答案一起送达。关闭后，后续消息和落地修复在 `resume_s` 内恢复同一会话，超时则创建修复任务。

Sonic 以非交互方式运行一次 pi 查询，不打开工作标签页或窗格。主会话通过 `hud_create` 发起，工作任务通过 `hud_sonic` 发起并收取结果。两者都保留普通任务目录：`stdout.jsonl` 和 `stderr.log` 记录 pi 的输出，`report.md` 是已声明的报告。Sonic 可以发布进度和获取租约，但不能提问或接收后续消息，也没有空闲宽限期。sonic 角色文件可设置 `check_s`（默认 600）、`stall_s`（180）和 `max_s`（1800），均为正整数秒；`hud_roster({detail:true})` 显示生效值。HUD 在每个检查点停止陷入循环的查询（`looping`），否则发布一条进度并让同一个 pi 进程继续运行。若 `stall_s` 内标准输出未增长且没有工作任务进度，则以 `stalled` 停止；达到硬上限则以 `timeout` 停止。这些失败会保留已有的标准输出和最新进度。用 `hud_create({role:"sonic", retry_of:job})` 重试已停止的查询。新任务以一条说明停止原因的简短消息，从原任务 `sonic-session.jsonl` 的私有副本继续。如果会话不可用或 pi 在接收输入前拒绝打开它，pi 将收到原简报，以及未完成报告末尾最多 8 KiB 的内容（没有报告时取标准输出）。

Sonic 默认使用角色的思考级别（内置为 `high`），`hud_sonic` 不接受思考级别参数。设置中的 **Sonic 自动选档**（`sonicAutoThinking`，默认关闭，独立于「模型文字」）将任务文本的前 4000 字符作为数据连同角色职责与 `thinking_choices` 中的用途发送给决策 API，由其在 `none`、`low`、`high`、`max` 中选择；不读取引用的上下文、项目常驻简报或报告。按原样执行给定命令并报告输出、逐字复制或列出文件用 `none`；在指定文件中查找具体事实用 `low`。Pi 将 `none` 称为 `off`。缺少密钥、达到调用上限、约五秒后超时或结果无效时，仍用角色默认级别。用 `hud_create` 派发 sonic 或用 `hud_sonic` 启动子任务时，都不能覆盖思考级别。分发记录并返回映射到模型支持范围后的级别和来源 `thinking_source`。

**Imp 自动分流**（`impRouting`，设置 → 模型，默认关闭）独立于「模型文字」，使用一次决策 API 判断。生效的 `imp` 角色文件必须定义 `routing`，不会从低优先级角色文件继承该块。例如：

```json
"routing": {
  "light": { "preset": "hydrogen", "use": "按现有模式进行小改动" },
  "standard": { "use": "普通的端到端切片" },
  "hard": { "preset": "astra", "use": "跨模块或进程生命周期工作" },
  "modes": { "headless": "预计一次完成", "tab": "预计会提问、耗时较长或主人想观察" }
}
```

只提供文件中声明的档位。`light` 和 `hard` 指定角色预设；`standard` 不带 `preset`，沿用「控制」中当前选择的预设。分流会发送任务简报的前 4000 字符、指定本地工单（`feature/NN`，最多 4 KiB/4000 字符）、最多 32 个 `context_files` 的相对文件名（每个最多 512 字符）和字节数，以及档位和运行方式的用途说明。不发送上下文正文、常驻简报、既有报告、预设或模型 ID。所选的用途说明组成一行理由。

所选档位无可用位置时回退到 `standard`；决策失败、超时或设置关闭时，使用当前预设并打开标签页。自动选择标准档的无界面任务若在输入提交前启动失败，会尝试用标签页运行当前预设。显式指定 `mode: "tab"` 或 `mode: "headless"` 优先，此时只选择档位。自动无标签页运行仅用于支持该模式的可继续位置（pi、Claude Code 或 Antigravity），否则打开标签页。溢出到 `general` 时保留 `imp` 的运行链。`retry_of` 保留档位，不再请求决策；轻量任务的落地修复改用标准档。任务回执、创建结果和单任务 `hud_read` 返回 `route`，包括 `tier`、`mode`、`reason`、`source` 以及适用时的 `fallback` 或 `mode_reason`；任务卡也显示分流及原因：首页行（及分栏列表行、详情标题）上有档位和无界面标记，详情里有一行 `分流：轻量 · 无界面 — <原因>`。

按角色的软并发上限（`roleCaps`，默认 `imp: 3`、`general: 3`，其他角色不限；`0` 表示无上限）在整机范围内统计处于工作状态的任务（不计 `queued`、`idle_grace`、`done`、`closed`、`failed`、`stopped`、sonic 子任务和无界面 sonic）。开启 **imp→general 溢出**（`impOverflow`，默认开启）时，若 `imp` 达到上限而 `general` 尚有空位，则计入 `general` 的名额，但保留 `imp` 的执行链（适用时按分流选择，否则使用当前预设），并返回 `overflowed: true`、`overflow_from: "imp"`。无空位时，`hud_create`（以及批量创建中超出上限的条目）将任务创建为 `queued` 状态并保留完整简报与选项，在结果、通知与面板中显示排队位置 `queue_position`。有空位释放或在设置中调高上限时，watcher 立即按启动时的首个可用位置启动最早排队的任务；对排队任务执行 `hud_close`（或面板 `X`）会将其移除。

`hud_read({})`（或 `view: "compact"`）按从新到旧列出当前项目的活动任务和本会话报告未读的已结算任务。
每行包含 `job`、`role`、`state`，并在适用时带上 `report_unread: true`、`blocked: true`、待答问题编号 `question_ids`、受阻、等待或失败的原因 `reason`。

`view: "recent"` 返回最新 20 个任务的完整行，包括子任务和已处理的历史任务。两种列表都可显示已结算任务的有效 `summary`（最多 120 字符，不列文件），且都不会标记已读；未出现在列表中的任务仍可通过 `changes` 报告变化。`view` 不能与 `job` 或 `jobs` 同用。

`hud_wait({ jobs?, mode?, wait_ms? })` 一次监听多个任务。省略 `jobs` 时，监听调用开始时本会话尚未结算的任务。
`mode: "any"`（默认）在任一任务结算或需要关注时返回；`"all"` 等到所有任务结算，但遇到提问、受阻、等待主会话或失败时会提前返回。
`wait_ms` 为 0–120000 毫秒的整数（默认 60000；`0` 只检查一次）。返回 `ready`、`timed_out`、触发返回的任务编号 `triggered`
和精简任务列表 `jobs`。没有目标任务时立即返回 `ready: true` 和空列表。等待不会读取报告或问题正文、标记已读或已查看，也不会关闭工作者；
请用带任务编号的 `hud_read` 收取报告。

`hud_peek({ job })` 返回精简的 `status` 和里程碑，不读取窗格。显式传入 `lines`（1–120）才会读取窗格末尾的 `pane_lines`；

`hud_read` 的完整模式与 `hud_peek` 的 `progress` 返回最新 10 条；默认读取只返回最后一条 `latest_progress`；普通读取省略空进度；
列表和等待结果不含这些字段。里程碑不会触发 `changes` 或 `hud watch` 事件。

`hud_read({ job })` 返回任务状态和未读报告的 `digest`。`result` 优先采用已结算任务与报告签名匹配的工作者摘要，否则与任务通知一样，跳过标题和空行，取报告前 2 KiB 中的首行正文；若没有正文则显示 `Report ready`。
摘要给出 `hud_read` 调用提示、报告字节数、托管工作树的改动文件数；仅当报告前 64 KiB 明确写出 `Verdict:`、`Blockers:` 时才附上相应内容。
默认响应保留待答问题、已完成检查的单行结果及最新里程碑。工作树列出最多 20 个改动路径，有余项时显示 `+N more`，并提示重叠改动。
已读报告不再打开正文，而是返回 `report_unchanged: true`。`mode: "full"`（或 `full: true`）返回报告正文（最多 64 KiB）和 `report_path`，即使已读也会返回，同时保留原有的元数据、进度、检查和工作树诊断。
用 `jobs: [id, …]` 代替 `job` 可按输入顺序收取 `jobs` 结果数组，所有任务使用同一模式；找不到编号只影响对应条目。
`detail: true` 可在读取时附带启动诊断；只想检查时用 `hud_peek`。`wait_ms` 最多等 120000 毫秒，结算、问题或超时即返回。
返回报告摘要或正文时都会记录 `read_at`，不代表验收。当前回合有效声明报告且回合结束后，即使报告未读也关闭工作进程和窗格。
CLI 声明后 120 秒仍未结束时，交由主会话处理，不强制中断。未回答的问题、未结束或未收取结果的 Sonic 子任务会阻止关闭。

在原连接上取消当前回合的任务与 `hud_close` 一样会停止工作者；重复取消、取消旧任务或从新连接取消都不会产生影响。启用 MCP tasks 的会话要派发多个任务时，应并行发起多个 `hud_create` 调用，每次创建一个任务。`hud_create({jobs})` 会报错，不创建任何任务。
派发失败、重复调用和群发会立即返回。批量 `hud_send({messages})` 和 `hud_respond({answers})` 仍按输入顺序返回逐项结果。对这些批量调用开启的新回合，当前 MCP 连接会向调用窗格逐条推送一次同样的精简通知（报告等待检查，提问、失败或停止即时送达）。推送失败则转入 `changes`，连接提前结束时回退到常规的 `hud-notify`／`changes` 通道。
没有后台任务或后台任务已过期的工作，仍可用 `hud_read` 查询。这类会话不提供 `hud_wait`、`changes`（面板意图和未送达的批量通知除外）、
`watcher_alive` 或 `hud watch` 提示。

`hud_tickets` 在各客户端提供本地工单方法与操作（仅主会话可写，拒绝改写 GitHub 镜像）：默认 `guide` 返回方法模板；`ready` 返回无阻塞且无活动任务的 `ready-for-agent` 工单，格式为 `tickets: [{ticket, path, title, what}]`。将 `ticket`（`feature/NN`）及 `path`（作为 `brief_file`）传给 `hud_create`；活动任务在项目面板和首页进度中即算认领，无需提交认领记录，`hud_land` 将工单更新并入落地提交（`**Owner try:** no` 记为 `done`，`yes` 或省略记为 `ready-for-human`），不再追加 `STATE.md`。
`add` 按 `feature` 和 `tickets` 批量建单（可选 `owner_try` 布尔值，在状态行下写入 `**Owner try:** yes` 或 `no`）；`update` 可单条更新（`feature`、`ticket` 及 `status`／`owner_try`／`tick`／`blocked_by`），也可传 `updates: [{feature?, ticket, status?, owner_try?, tick?, blocked_by?}]` 按输入顺序批量更新并返回逐项结果（每项可覆盖 `feature`，单项错误不阻塞其余项）；`sync` 执行 `hud tickets sync`。

其他客户端的 MCP 工具响应还带 `changes`：自上次响应以来本窗格派出的任务每次状态变化一行（没有则省略）。面板、状态栏、pi 页脚、MCP
与 `hud watch` 用同一个 `jobRow` 推导任务状态，所以结论一致。`hud watch` 默认只打印需要关注的事件，如提问、结算、受阻或新的静置原因；
`--verbose` 才打印所有变化。`hud watch` 和 `changes` 都附上有效的工作者摘要（最多 140 字符）。未读报告通知给出 `hud_read job=<id>`（用 `mode: "full"` 读取全文），而不是文件路径。范围是调用者窗格（`HERDR_PANE_ID`），`--all` 为所有任务；空闲时只每 30 秒重扫一次。监听会把三秒内到达的结算合并成一条通知；提问仍立即送达。未协商 MCP tasks 的 Claude Code 可用 Monitor 运行它。
Codex 通过 `codex queue` 自动静默接收；pi 的 HUD 扩展用原生消息唤醒空闲的主会话，或在当前批工具调用完成后、下次模型请求前送达通知，不改编辑器草稿，也不需要打开面板或 Monitor。
Antigravity 也会自动启动后台监听：主会话工作时通过 `PreInvocation` 钩子接收任务事件，空闲时则将事件输入提示框。
pi 工作者不会启动此监听。调用者有窗格时，`hud_roster` 和 `hud_create` 返回 `watcher_alive`；监听有效时不会直接向其他客户端的窗格输入，也不会显示 Monitor 提示。
未启用监听时，问题仍可通过 Codex 队列发送；若无法排队或没有队列，则回退为直接输入。

任务是 `$HUD_HOME/jobs/<job>/` 中的普通文件。pi 历史保存在
`${PI_CODING_AGENT_DIR:-~/.pi/agent}/sessions/<cwd-dir>/`，任务的 `sessions/` 链接到主代理／助手文件。
CLI 任务的监督进程只观察；只有事实能结束任务：记录的进程号消失（或被替换）、标签页关闭、输入前派发被拒（`failed`；
磁盘上有新报告则 `closed`）。CLI 每次派发和 `hud_send` 都开始一个回合（`turn.json`）。`hud_report` 或备用的
`hud-progress --done` 将报告签名绑定到当前回合。未声明的报告按静默规则处理，本回合仍存活的子进程会推迟该规则。
续写会使旧回执失效；改写已声明的报告必须提交新回执，否则安静达到角色宽限期后转为 `waiting_orchestrator`，不结算也不调用决策 API。
终端输出不会影响回执。回执匹配且 CLI 回合已结束（或 pi 已原生结算并写出新报告）后，残留进程不阻止关闭；
未回答的问题和未收取的 Sonic 结果仍会阻止关闭。herdr 状态本身不会让仍在运行的任务判为失败。
回合安静超过空闲宽限且无报告时，做一次决策 API 选择，只在固定动作中选（继续等、一次固定的写报告提示、屏幕上有配额行才 `failed`、
交给主会话）；置信度低于 0.8 或出错则交给主会话。不确定的一律 `waiting_orchestrator` 并写明原因。监督进程由 herdr 推送、
文件变化和自身截止时间唤醒，另有每 30 秒一次重读状态；STATUS 只在行变化时写。`hud_create`、`hud_read`、`hud_send`、`hud_respond` 或 `hud_land` 会按需启动 watcher，后者经 `pi-role-reap` 回收已结束任务，
失败标签页保留两小时；没有未结束任务或待到期失败任务时退出。watcher 通过套接字关闭事件发现 HUD 启动的运行进程退出，无需定期扫描。原生 pi-roles 工作者没有这样的套接字，等待停止或已读关闭时仍可按 `HUD_WATCH_CLI_CHECK_MS`（默认 30000 毫秒）复查。监督进程已死而工作者仍在时任务为 `waiting_orchestrator`（“supervisor exited; worker still running”），watcher 按指数退避复查该工作者，对它 `hud_send` 会启动新的监督进程。已结算目录在**关闭一天后**的
后续扫描时清理，不设专门到期定时器；包括报告及 `hud_read` 访问。删除旧 pi 任务前先将真实 JSONL
会话移至 pi 存储；CLI 和浏览器会话留在各自存储。cwd 无效、目标冲突或移动失败则保留任务。删除会话链接不删除目标。
任务正常结算（`done` 或已有报告且已关闭）后，watcher 在 `resume_s` 到期后的扫描中删除 `stdout.jsonl` 和 `stderr.log`。
Sonic 和未设置 `resume_s` 的旧任务使用默认的 1620 秒。失败或已停止任务的原始日志保留到任务目录被删除为止。
删除任务目录前，watcher 向 `$HUD_HOME/archive/YYYY-MM.jsonl` 追加一行任务事实，不含任务说明或报告正文；写入失败不影响删除，HUD 暂不读取或清理归档。

## 项目工作者

已注册的项目可在 `.hud/project.json` 中启用临时文件清理，例如 `"scratch": {"paths": ["tmp/tasks"], "keep_days": 7}`。
请仅指定存放可丢弃数据的目录。watcher 在按需扫描中最多每小时清理一次：若指定目录下某个顶层条目中最新的文件也早于
`keep_days`（默认 7 天），则删除该条目。不接受含 `..` 的路径段、项目根目录本身或根目录之外的路径；不跟随符号链接，
并在 `$HUD_HOME/watch.log` 中记录删除的条目数。

```sh
hud setup --detect [--cwd DIR]
hud setup --apply PLAN.json [--cwd DIR]
hud setup --remove [--cwd DIR]
```

命令本身不提问。`hud-setup` 技能与 `hud-delegate` 一样，为 Claude、Codex 和 pi 安装；
它负责询问，这些命令只读或只写。

`--detect` 打印一份 JSON，不写任何文件。它给出 `--cwd` 的 git 顶层（否则就是 `--cwd`）、
该根是否已注册、参考角色（内置与 `$HUD_HOME/roles`）、项目角色及其有序的 `run` 链、启用集合、无效角色文件、
技能，以及工作者技能链接。清单中的可选角色带有 `enabled` 标记；是否启用由控制标签中的全局开关决定，不属于项目设置。
技能根目录来自 `$HUD_HOME/setup.json` 的 `skill_roots`
（默认 `~/.pi/agent/skills`、`~/.claude/skills` 和 `~/.agents/skills`），其后总是包含本仓库自带的
`integrations/skills`。技能是含 `SKILL.md`
的目录，名字取 frontmatter 的 `name`。每项带 `model_invocable`：frontmatter 有
`disable-model-invocation: true` 时为 false。pi 仍加载该技能，但不放进模型的技能列表，
所以工作者不会自己选用它。

`--apply` 按计划写入项目的 `.hud/`（应提交）：

```
.hud/project.json          启用的角色，以及 apply 自己创建的链接、角色文件和提示
.hud/roles/<name>.json     项目指定的运行链，或与参考角色不同的 pi 角色
.hud/skills/<name>         指向技能目录的符号链接（仅工作者）
.hud/agents/<role>.md      可选的仅工作者提示
.hud/hud-convention.md     可选，内置约定的副本
.hud/brief.md              可选，手动添加的常设简报（setup 不管理）
```

计划为 version 1：`roles`（启用的名字）、`pi_roles`（只调 pi：`from`、`pi_role`、`model`、
`thinking`、`split`、`can_continue`、`skills`）、可选的 `runs`（角色名到非空的有序运行位置列表）、
`skills`（名字到技能目录的绝对路径）、`agents`（角色到 markdown）和 `convention`（`keep` 或
`copy-default`）。`runs` 可指定参考角色或 `pi_roles` 中复制的角色。若两处都指定同一角色，`runs`
决定顺序，`pi_roles` 为其中每个 pi 位置补充默认设置。打印 `removed`、
`wrote`、`linked`、`skipped (exists)`、`registered`，或 `no changes`。同一计划再跑一次不会改任何东西。
不是本命令创建的文件或链接会留下，并报 `skipped (exists)`。

apply 把项目根记入 `$HUD_HOME/projects.json`。项目配置只有注册之后才加载。
`--remove` 去掉注册，留下 `.hud/`。常设简报不依赖注册，仍会使用。

已注册项目的角色文件可在 `run` 和 `presets[].run` 中列出 pi 与 CLI 位置。CLI 位置只接受
`harness: "cli"`、`agent`、`model` 和 `thinking`，不接受额外参数；不允许浏览器（`bro`）位置。
设置、技能和提示等工作者定制仍只适用于 pi。setup 不修改任何 CLI 自己的文件，也不运行 `hud trust`。
若 CLI 位置需要信任该项目目录，请自行运行 `hud trust <dir>`。

## 首页

首页依次显示需要你回答的问题、包泳道中的任务卡片和子代理泳道。
卡片的实时数据只有两个来源：`$HUD_HOME/jobs/` 中归属于调用窗格的 HUD 任务，以及选定的 Claude 或 Codex 主会话的原生子代理树。
首页不扫描 `tmp/tasks/`，也不读取已停用的观测记录；`CODEX_HUD_PANEL_ALL_DELEGATIONS` 不再改变任务范围。
首页不派发或串联工作；对任务只有主人的三个微操作（见「按键」）。运行中任务有待答问题才需要你；已结束任务遗留的问题不算。
报告不证明成功，显示标签不代表验收或合并。缺少证据保持未知。

首页**每个任务一行**：固定两格宽的状态图标、工单 ID、简短标题，右侧依次是角色图标（`⚒ ✎ ✦ ◈ ⚖ ⚡ •`，文本图标 `I F G O R * .`，与状态栏同一张表）、提供方／短模型／思考档位标记（先按 `◎ sol-fast◕` → `◎◕` → `◎` 收窄，标题短于 16 格才截断）、分流或无界面任务的分流标记（档位 `▂` 轻量、`▄` 标准、`▆` 复杂，文本图标 `- = #`，无界面运行时再加 `∅`，文本图标 `h`，例如 `◎ sol-fast◕ ▂∅ ⚡2 6分`；两者都没有的任务不显示，标签页任务没有运行方式标记）、活跃的 `⚡N`、状态词（`失败`、`停滞`）和用时。标题取任务所属工单文件（该任务 `ticket` 对应的 `.scratch/<feature>/issues/NN-*.md`，去掉 `NN:` 前缀）的标题，其次是 brief 标题，再其次是模型生成的短名；只有都没有时才显示任务原文。泳道只有包含多个任务时才有标题行（工单 ID、标题，右侧为阶段），其任务缩进显示在其下。待答提问以琥珀色提问条置顶（标题右侧带模型／思考档位标记及活跃的 `⚡N`，下方泳道不再重复）。失败的任务保留卡片（红色原因行），直到失败被查看或被取代；有活跃落地或侦察流程的任务多一行子行（`落地 · gate[3] test:mjs · 1分`、`侦察中 · 1分`；等待其他落地时保留其等待行）；未读报告（`✓●`，文本图标 `+*`）保持单独一行；失败的流程保留其步骤链行。排队任务折成一行 `◷ 排队 N · cache-v2/04 · …`，隐藏时限内已读的已结束任务折成一行 `✓ 完成 N · …`（放得下就写完整 ID，否则 `+N`）；在折叠行上按 Enter 展开为每个任务一行。在任务行上按 Enter 就地展开卡片（句子、里程碑、活动），展开期间该任务不并入折叠行；报告句子也在详情中。
没有工单文件时，标题优先取与面板语言一致的 brief 标题；语言不同时，生成句子的同一次请求可提供短名来替换它（工单标题语言不符时同样替换）。关闭模型文字时保留工单或 brief 标题；窄泳道仍保留数字后缀。经典布局的任务行不会自动展开；原生子代理卡片和分栏预览仍会展开最新且仍属当前的已结束卡片，到折叠时限为止，显式选择在本次面板生命周期内优先。泳道标题的 Enter 折叠泳道。
提问条展开后在选项旁显示答复按键；`o` 仍可打开提问文件。

**sonic 子任务。** HUD 任务派出的 `sonic` 任务（`parent_job`）在首页（经典与分栏）不再占独立行或卡片，只作为 `⚡N`（文本图标 `*N`）显示在其父工作者行（及父提问条标题或分栏泳道行）上，且只统计正在运行的 sonic 数量，从不累加已结束的 sonic。sonic 子任务不计入泳道状态条、分栏任务数或「今日完成」，也不会抢占分栏泳道行。`/` 过滤命中 sonic 任务时，其父任务仍一并保留。

**流程。** 带有落地流程（`$HUD_HOME/flows/<flow>.json`）或带侦察派发的任务，在经典首页的任务行下方，流程运行或等待期间多一行子行（见上）；分栏预览、失败的流程和详情在卡片上显示一行流程步骤（`门禁 ▸ 合并 ▸ 推送`
或 `侦察 ▸ 运行`）及当前步骤或最终结果（已落地 SHA、完成、失败或已取消），分栏列表行亦显示活跃步骤链。落地运行期间该任务保持可见、不折叠，直到流程结束；「折叠时限」现在只作用于原生子代理卡片和分栏预览。

**面板生命周期。** 打开前已结束的任务不加载，包括决定和模型输入；`a` 不能显示它们。
活跃／未知任务不论年龄均可显示。构建重载保留最初打开时间。原生代理和项目 STATE 切片查询保持各自范围。

**卡片时限。** 已结束原生卡片默认五分钟折叠、五分钟隐藏（两者默认重合；可在设置 → 面板分别调整）。已读的已结束 HUD 任务一开始就在「完成」折叠行里，到隐藏时限才离开。隐藏时限小于折叠时限则按折叠时限算。
失败／停止的任务一旦被重试、修复、同角色同目标的后续任务或已落地的切片／工单替代，就会离开首页；按 `a` 可看到暗色的「已替代」卡片。
已查看的失败按普通时限折叠和隐藏。未处理的失败保持展开显示原因行，在两种模式下均于三十分钟后离开首页；仍可用任务编号通过 `hud_read({job})` 查看。运行／提问卡片不隐藏。
`a` 在原位显示较早卡片为暗色单行，Enter 展开。任务扫描考虑最新 200 个目录。

已答问答仍照常收集，但不再有首页区块或专门的面板视图。详情的文件列表仍显示答复文件及其默认／偏离标记。
评审结论需要记录的 accept／changes-required 行及已结算输出，助手退出本身不是结论。

**首页原生代理。** Claude/Codex 主会话各有泳道，分栏布局中标为 `子代理`。子项缩进一级，更深写 `↳ parent`；
隐藏父项不隐藏活跃后代。pi 助手已是 HUD 任务。Claude 子代理的长转写会先显示最新的公开步骤，再分批向前重放，补齐 Agent/Task 嵌套。
重放保留已知完成时间，追平前不请求模型。完成后转写增长才重新运行；新 finished 元数据或已追平的公开
`end_turn` 且无未结束工具调用才再次结算。不完整读取不能证明空闲。`o` 打开转写，不切换客户端对话。

**模型推荐。** 默认保持事实顺序；推荐模式将最多 200 卡片的有限显示事实交给所选决策 API 打 0–4 分，
变化的看板最多两分钟一次。问题、失败和需要人工处理的卡片受保护，原生子树保持完整。
低分已结束卡片进入较早项，可用 `a` 显示。另一次聊天调用按总结间隔生成短简报。
无 key／失败沿用默认顺序；简报依据的内容一变，旧简报就不再显示，即使新简报尚未生成或生成失败。关闭模型同时隐藏两者。

**首行。** 经典与分栏首页顶部均为一行摘要条（`/` 筛选时隐藏）。左侧突出需要处理的状态：`? N 项等你处理`（STATE「Waiting for the owner」条目与任务提问合并计数，若有未处理失败附 `· ✗N`）、`✗ N 失败`、`✓● N 未读报告`，或全无待办时的 `✓ 没有需要你处理的事`。右侧以与状态栏一致的 Variant A 分组格式列出活跃与近期工作者（`◎ sol-fast◕ 3 ?  ▲ neon◕ 1 ✗  ✻ sonnet● 1 ✓●  ⚡4`），窄屏依次省去模型名与思考档位图标，空闲时显示 `0 运行中`。经典首页有 STATE 待处理条目时，在首行按 Enter 或单击打开项目总览的「等你处理」块。底栏在 56 列起显示 `✓ N 今日完成`（不计 sonic 子任务），更窄时显示 `✓ N`，为零时不显示。

**空余行。** 先给卡片留空间，再自上而下显示：STATE 的待处理条目（每项一行，最多五项，其余 `还有 N 项`）、
最近落地的工作（38–55 列三行，更宽五行；按切片时，首页按台账顺序显示，靠后的在前），最后在底部显示进度块：
STATE Now 摘要（最多折三行）、里程碑堆叠进度条与计数图例（已验收、待试用、工作中、受阻、已规划；不含已放弃的切片）。
没有匹配的里程碑时统计整个台账，标题为 `全部切片`。项目工单总表包括已完结的功能。已开始的功能各占一行；未开工功能合并为一行，显示就绪和待前序的数量。
按切片显示时，已开始的功能另列最多六张未完工单，待前序只计数。分栏首页的进度行显示里程碑、待试用项数及工作中的切片数；空闲时显示已验收比例。「等你处理」分别统计待决定和待试用项。进度块先取它的行，两个列表只用剩下的。
变矮时依次减少最近完成、待处理、工单、摘要多余行、图例、摘要、条，最后整个块消失。
Enter 或单击待处理条目打开它的全文页（Esc 回到总览上该条目那一行），在「等你处理」标题上打开总览的「等你处理」，在最近完成或进度块上打开项目的进度页，在工单行上打开工单页。

## 项目

项目是一个总览，每节一页，按时间线排布：什么在等你、正在发生什么、刚落地了什么，最后是各页的现状。总览自上而下：

- 项目名行（面板所在目录名，见下面的切换项目），带当前里程碑；
- **等你处理**：STATE 的待办，Enter 折叠（以 `(waits on ID, feature/NN)` 结尾的条目，在这些切片验收或放弃、工单完成后自动消失）；标题写明总数和还有多少待试用（`4 · 5 待试用`：第二个数字使用「验收」设置的单位，统计所有里程碑）。
  一条放不进一行的文字，在总览有空行时从第一个词下面起完整折行，自上而下（你要试的东西不会被截成一个名字）；面板太矮就收成一行，先于最近完成和各页行让位，光标所在的那条除外，它保留完整文字。在条目上 Enter 或单击，用一个页面（`‹ 项目 › 等你处理`）显示它的全文：
  STATE 里怎么写就怎么显示，含续行，用词和顺序不变（接着上一句的行并入同一段，编号行或 `-` 行另起一段）。页面可用移动键和滚轮滚动；
  Esc 或单击顶部面包屑返回，光标仍在该条目上；`o` 打开 STATE.md。不调用模型；
- **现在**：每个工作中或受阻的切片一行（`◐ ID  文字`，右侧是任务的角色和分钟数、`提问中 ?`、`受阻`或哪里不一致），
  再是本项目未结束且没有切片显示的 HUD 任务（`◉ 角色  标题  年龄`）。切片的文字只在整句放得下时才写在同一行。
  清单里没有的工作树不是在进行的工作：它们计在工作区一行上。没有进行中的工作时写 `没有进行中的工作`；
- **最近完成**：最新落地的工作（待试用、已验收），按已知的提交日期由新到旧；
  40 列时三行，更宽五行；
- 每页一行带一句摘要：**进度**（待试用、受阻、工作中；里程碑已在项目名行显示，下方是当前里程碑的条）、**工单**（完成／总数、工作中、受阻；
  项目没有工单时不显示）、**工作区**（未登记工作树、分支、改动、工作树、领先／落后、编辑中的任务；它的页面列出未登记的）、**文档**（spec 里程碑、最新评审）。一行放不下就从末尾整项丢弃，不截断某一项。

面板比总览矮时，先收起**最近完成**（先收到最新的几行，再整节），然后是条和各块之间的空行；等你处理、现在和各页行保留
（连这些都放不下时页面随光标滚动）。Enter 或单击打开一页，面包屑行 `‹ 项目 › 页名` 取代标签行；
Esc 或点击面包屑回到总览，光标停在刚离开的那一页。每页各自记住光标和滚动，面板自我重载后也保留。

事实来自 `docs/handoff/STATE.md`（根 `STATE.md` 回退）、`docs/spec.md`、评审、角色／约定／指令及 Git 工作树。
不猜里程碑或完成。密钥只显示名称及是否存在；浏览器 ✓ 仅指 Chrome 和 `jev-ask` 在 PATH，非运行或登录证明。

**进度页**：STATE 的 Now 摘要（最多两行），再是当前里程碑（`Milestone:`；没有当前里程碑时按整个账本算）：
名称、一条条和 `已验收/总数`、有切片的状态（`1 工作中  1 受阻  2 待试用  3 待办`，数量为零的不写）、以及一行此前各里程碑
已验收的总数（`✓ 此前 5 个里程碑已验收 24 项`）。然后三节：

- **现在**：账目里 `working`／`blocked` 的切片，各带其任务在首页卡片上的那句；漂移标记表示缺失工作树或非活跃账目状态，
  不回写 STATE（清单里没有的工作树在工作区页）。再是本项目还没结束、也没有切片显示的 HUD 任务（角色、标题、年龄）。任务标题取工作板的描述，
  否则取 `job.json` 的标题，再否则取 `brief.md` 的首个标题（或首行）：仅在完整采集时，经采集器按文件签名缓存、限定大小的读取得到。
  这样的每一行都是独立的停靠点：Enter 或 `o` 打开其报告，没有则打开 brief；任务很多时可用键盘翻页。
- **下一步**：STATE 的 `## Next`，显示前两条，每条最多两行（被截断的 `…` 条目按 Enter 展开全文，再按折回；放得下的条目
  按 Enter 打开 STATE.md），再加一行 `还有 2 项`，按 Enter 显示其余（`收起` 折回）。
- **历史**：最近七天完整列出，最新在前，是带日期的动态：每个已落地的切片一行（`◇`／`✓`、ID、文字和年龄，`待试用 1天` 或 `3天`），
  Enter 显示它的里程碑、提交和日期。更早的工作每个里程碑一行（`▸ M4  ✓ 7 已验收  ◇ 1 待试用  15–24天`，带天数范围），
  Enter 展开其切片；没有提交日期的切片不猜日期，归在其里程碑下。日期取账目行最后一个哈希（7-40 位十六进制），
  经安全 Git 策略读取，来自采集器本来就跑的那一次批量 `git log`。

**粒度。** 设置 → 面板 → **粒度**（`hud-settings.json` 中的 `acceptance`）默认为 `task`（任务）。
进度页每个里程碑一行，先显示最需关注的状态标记，再列出各状态的切片数。里程碑为 `—` 或空的切片各自独立。
工单页每个 `.scratch` 功能一行，显示已解决数／总数（含已放弃的工单）和最早未结工单的状态。
经典布局按 Enter 或查看分栏预览，即可查看成员的原有详情。项目总览按功能和任务计数，等你处理的待试用数按有待试用切片的任务计数。

首页和 HTML 看板的待试用行仍使用此设置；watch/MCP 通知及简报生成不变。选 `slice`（切片）可恢复逐个切片和工单的视图。

**只看待试用（经典）。** 在待试用数量（`2 待试用`，自成一个停靠点）上按 Enter 或单击，或按 `t`，页面只留还没试用的：
标题 `仅待试用 ── n` 取代面包屑下的全部内容，其下是待验收的行。按切片时，账目里状态为 `try` 的切片按里程碑分组、最新在前：最新的里程碑展开（`◇ DATA-ONE  文字  1天`），
更早的每个一行折起（`▸ M3b  ◇ 1  19天`），按 Enter 展开。切片显示账目里的完整文字，折行排在 ID 下面；面板太矮放不下时，光标所在以外的切片各留两行。
在切片上按 Enter 显示里程碑、提交和日期；模型开启时，在原文之上还有**简报**（改了什么，白话，至多两句）和编号的**验收步骤**（怎么试，至多四步）；
调用未完成或失败、或模型关闭时，只显示原文。在标题上按 `t`、Enter 或单击，或按 Esc，

窄屏（40 列）时一行放不下就折到第二行，不截断唯一的一行。在行上 Enter 或 `o` 打开 STATE.md；
在折叠行上 Enter 折叠／展开，`o` 只在该行没有文件时折叠。

已验收的关联切片（含主人按 `y` 的记录）、done/closed/complete/resolved 状态或非空且全勾的清单，即完成。已放弃的工单也计入已解决数。关联切片落地或最近 64 个提交标题提及工单，则显示待试用，后续工单可开始。依赖可写本功能编号／标题或 `feature/NN`；仅等普通前序标为待前序，未知或受阻前序才标为受阻。工作中的任务和托管工作树在读取时关联，不改写工单。最新 64 目录的任务查询与切片共享。
**工单页**：先是全部工单的完成／总数细条和每个功能的短码（`hp hub-pages 4/7`），再按状态分栏列出各功能的工单，

**等你处理**在最前：在等人回答的工单（`needs-triage`、`needs-info`、`ready-for-human`），行下附最新评论，不论还有什么拦着它；

**已完成**初始折叠（Enter 展开）。在工单上 Enter 就地显示检查项（✓／○）和最新评论（`## Comments` 下最后一条），再按一次折回；
`o` 打开工单文件。

**控制标签。** 控制是项目之后的主标签，顶部显示当前项目。`[`／`]` 与项目标签共用同一个项目选择，不改变首页所属项目。打开控制时只采集当前项目的角色等控制信息，不采集 Git 状态、工作树或工单。角色视图从上到下是：

- **需要处理**：有已启用的位置耗尽、无可用位置或找不到所选预设的角色，以及无效角色文件。角色行如 `imp [daily] → agy`；需要处理的原因显示在下方。在无效文件行上按 Enter 或 `o` 打开文件。
- **正常**：默认折叠为角色名。Enter 展开后每个角色一行，显示下次运行的位置；项目自己的角色行末标有 `项目`。只有 `default` 以外的命名预设才显示标签，未选择预设的文件链也不显示标签。
- **用量**和**文件**：默认折叠。用量展开后显示额度窗口、pi 花费和今日按角色的派发情况（角色今日用过 2 个以上位置，或有启动失败、配额标记时，在角色行下按运行位置拆分子行，仅展示记录的完成／失败、启动失败、转交主会话与配额标记，不影响路由）；文件展开后显示约定、指令、pi 角色定义、忽略的配置、原生代理，以及密钥、浏览器和宿主的存在情况。

角色行在宽度足够时显示下次使用的完整模型名，否则只显示宿主（pi 的提供方已知时一并显示）。已知的继承模型以灰字显示。分栏在下方预览选中角色的编号备选链和来源；Enter 进入位置，Esc 返回列表。经典布局按 Enter 在该角色下方展开编号的备选链及其来源。在角色或位置上按 `o` 打开来源文件。链中 `◉` 表示下次使用、`○` 备选、`⊘` 已停用、`✗` 已耗尽、`−` 未安装。`x` 只清除真实的额度耗尽标记，已停用的位置也可清除，但不会因此启用。

**宿主**（按 `h` 或点击「角色／宿主」标题）列出 pi 运行器、内置 CLI 适配器、浏览器工具和 pi 提供方，适用于**本机的所有项目**。
空格或 Enter 开关当前项；Del 移除已启用项，即停用，不会卸载。在「已停用」组上按 Enter 展开或折叠。`i` 打开「添加回」：输入开关 ID 的一部分进行筛选，↑↓ 选择，Enter 恢复，Esc 取消。经典和分栏布局都可操作。开关与安装状态分开：已安装表示找到了可执行文件，提供方已列出不代表已登录或有额度。关闭 pi 运行器后，各提供方保留自己的开关，并显示「pi 已停用」。`jev-ask` 同时控制 ChatGPT 和 Gemini；`jev-aistudio` 控制 Argon。`r` 刷新本地模型列表。

只有显式操作开关才会写入 `$HUD_HOME/harnesses.json` 的 `disabled` 属性（原子写入，0600），保留其他键，所有角色文件内容不变。ID 为 `pi`、`pi:<提供方>`、`cli:<代理>` 和 `bro:<工具>`；不在列表中就启用，新发现或未列出的项也一样。`cli:grok` 与 `pi:xai` 独立。开关配置无效或无法读取时会报错，不会按全部启用处理。

角色视图、`hud_roster` 与 `hud_create` 共用同一套选择规则：按顺序跳过停用、额度未恢复或缺少可执行文件的位置。例如停用 `pi:xai` 后，`imp [daily]` 可转到 `agy`，预设和原来的 pi 位置都不变。恢复 xai 后，它按原顺序参与选择，但真实的额度标记仍须清除或过期。pi 提供方来自显式模型或 pi 角色中的完整模型 ID；若只有模型名，则在未经筛选的缓存中精确匹配唯一提供方；未设置模型才看 pi 的设置。无法确定时显示「提供方未知」，不阻止派发，也不解析 `pi_args` 来判断提供方。`general` 的单次 `preset`、`on` 和 `model` 覆盖值也遵循这套规则；显式指定的停用目标会被拒绝，而不是改派。没有可用位置时，`hud_create` 在创建任务之前返回 `no_available_place`。

角色文件可为 Claude 和 Codex CLI 工作者指定额外的 MCP 服务器，例如 `"mcp_servers": ["chrome-devtools"]`。省略此字段或设为 `[]` 时，只加载 HUD 工作者 MCP。Claude 从用户 `.claude.json`（设置了 `CLAUDE_CONFIG_DIR` 时为 `$CLAUDE_CONFIG_DIR/.claude.json`）的 `mcpServers` 中按名称读取条目，以该任务的私有配置严格启动。若 Claude 配置中没有所指定的名称，本次启动尝试会失败。Codex 仅在本次启动时禁用未列出的服务器；列出的服务器保持其配置状态。如果 HUD 无法读取某层 Codex 配置，就保留原有 MCP 设置，并在启动诊断中记录 `mcp scope not applied`。HUD 不会为限制 MCP 而修改宿主配置。

Claude 将角色指令文件追加到系统提示，Codex 使用开发者指令。角色文本不含控制字符时，Grok 将其追加为规则；否则在首条消息前附上指令，无法内联时则指向角色文件。Claude 的角色文件路径含控制字符时也使用这一回退方式。Herdr 无法在 CLI 启动参数中编码控制字符（包括换行和制表符）；其他启动参数含控制字符时，HUD 会跳过该运行位置，而不是修改参数。Agy 的交互模式没有对应的系统提示参数，也不能按次严格选择 MCP 服务器，因此沿用原有 MCP 配置，并在首条消息前附上角色指令以及已注册项目的 `.hud/brief.md`。首条消息只内联小于 16 KiB 且不含 NUL 的文本，否则指向对应文件；四种 CLI 的组装简报 `brief.md` 也遵循这条规则。

角色文件可带 `presets`：`[{ "name": "short-token", "run": [...] }]`，每项是完整有序位置列表，按 `run` 的规则校验。名称在同一文件内唯一，1–32 个 `[A-Za-z0-9._-]` 字符。预设按内置 → 用户 → 已登记项目合并，每一层先用 `hidden_presets` 隐藏继承的名称，再以本层定义替换同名项或追加新名称。由生效角色文件的 `active_preset` 选择名称，`null` 选择文件自身的 `run`。没有此字段时仍运行文件链，以首个规范化后完全匹配的名称作为预设名。指定的名称不存在时使用文件链，控制标签和名册会显示缺失的名称。`hud_roster` 的详情返回生效的 `run`、`preset` 和合并后的 `presets`。只有 `general` 能用 `hud_create(preset: …)` 为单次任务选取预设，不保存。

在**控制 → 角色**中，停用的可选角色列在**可选角色**下。选中 `pro` 或 `flow` 后按空格（或点击页脚的 **Space 开关**），即可为所有项目切换该角色。此操作原子写入 `$HUD_HOME/role-switches.json`（权限 0600），不改动角色文件。手动设置可使用 `{ "pro": true, "flow": false }` 这样的 JSON 对象；移除某个键后，是否启用取决于是否有用户角色文件定义该角色。项目角色白名单仍然生效，不能启用已全局停用的角色。

在**角色行**上按 `c`/`C` 立即循环切换下一个／上一个命名预设（从文件链开始时选择首个／末个）。`p` 打开列表，文件链和名为 `default` 的预设都可选择。输入筛选，↑↓ 选择，Enter 应用，Esc 或 Ctrl+C 取消。列表显示每条链的下次位置；全部停用的预设仍可选，下次位置显示「无」。`N` 从当前链复制草稿，`I` 从空白新建草稿。输入唯一的名称并按 Enter 打开草稿。`R` 重命名当前命名预设，Enter 提交。`D` 预览删除当前命名预设以及之后使用的文件链，Enter 确认，Esc 取消。选择、复制、重命名和删除操作不会启动任务，也不会覆盖 `run`。耗尽标记仍按位置保留。

## 审阅看板

`hud board [--html] [--cwd DIR] [--out FILE] [--open]` 写出项目的审阅看板：一个静态 HTML 文件，用浏览器打开；页面没有脚本、
字体、图片、链接，也不发任何网络请求（Content-Security-Policy 只允许内联样式），所有项目文字都经过转义。内容：页头（项目、
分支及改动／领先／落后、里程碑、写出时间，以及进行中／受阻／待试用／已验收／待办的堆叠进度条）；**需要你处理**（STATE 的等你事项和
未答复的任务问题，含选项与默认；没有则不显示）；**待试用**（每个切片一张卡：里程碑、时间、提交、已存的模型简述与编号步骤，没有则为台账原文，
台账行提到的 `.scratch/` 工单，以及逐文件 `--numstat` 条）；**进行中**（进行中与受阻的切片，运行中的任务及角色、模型、用时、当前一句话）；
**工单**（各功能的进度条、未完成工单及其清单）；以及**最新里程碑评审**。没有内容的部分不显示。页面跟随系统的浅色／深色，也可用页首的
自动／深色／浅色开关（纯 CSS）切换，从手机宽度到宽屏都能阅读。

它只采集一次，方式与项目页相同：不启动 HTTP 服务，不调用模型。待试用简述只在面板已存过时出现（与面板同一缓存和模型文字总开关）；
本窗格的任务只在 herdr 内（`HERDR_PANE_ID`）出现。文件默认为 `$HUD_HOME/display/board-<项目>.html`，`--out` 可指定；以 0600 先写临时文件再重命名，
目标处已有的链接会被替换而不会被跟随。命令打印该路径。`--open` 随后分离地运行 `wslview`，否则 `xdg-open`；两者都不在 `PATH` 时只在 stderr 提示（退出码 0）。

在面板中，`w`（首页或项目页；选择器和设置中无效）对当前显示的项目做同样的事并打开，顶部显示 `已导出看板: <文件>`，直到下一次按键。

首页、项目和控制是默认的主标签。设置 → 面板 → **实验功能**（`hud-settings.json` 的 `experiments`，默认关闭）会加入实验性 **EXP** 标签。

`openai` OAuth 路线的底栏显示已用百分比。用量最高的窗口在前，显示用量条和重置倒计时（`7d ████░░░░░░ ≈43% (2d4h)`）；空间足够时才显示另一个窗口。
当前请求的直报优先，且不带 `≈`（`5h 11%`）。过时估值用暗色显示，末尾加 `?`；超过重置点的窗口显示 `↻`。`oapi` 等其他路线不展示订阅额度。
打开**代理读数**可查看两个窗口及其重置时间、来源、最近成功和错误、下次尝试。
若提示需登录，请登录绑定的 Codex 配置，然后关闭再开启自动刷新。关闭实验功能即停止刷新。

**API 赠额**并列显示两本账。pi 的底栏只显示当前 API 路线已启用的账本，以用量条表示已花比例，并显示估算剩余美元和距续期天数（例如 `API ████████░░ ≈$12.34 (12d)`）；不显示订阅额度。
`openai-api` 计入 `oapi` 请求；`anthropic-api` 只计入已安装的 pi HUD 能确认使用 API 密钥直连 Anthropic 的请求。
Claude OAuth、第三方网关和无法归属的请求不计入。Claude Code 状态栏不变。关闭实验功能后，两本账保留，停止采集。

底栏提示整条显示：先列当前行的动作，再列 Enter 的具体动作、适用时的 `Esc 返回`，最后是页面动作。
空间不足时从右侧丢弃提示，但 `? 帮助` 固定在最后。移动、切换标签和打开设置的快捷键仍然可用，不占底栏空间。
编辑器或选择器接管按键时使用自己的提示，不显示 `? 帮助`；帮助页本身只显示 `Esc 返回`。
例如，运行中的 HUD 任务有 `g 任务页`（无界面任务为 `g 输出`）和 `X 停止`，待试用行有 `Space 勾选  y 验收  n 标记`，
控制的角色行在两种布局都显示 `⏎ 备选链`。`o 文件` 打开当前行的文件。
没有 Agents 区、叠放／紧凑布局、时间线、活动中心、代理日志、Summary 或诊断页。各页保留选中／滚动。
图标为 `unicode` 或 `text`，旧 nerd/emoji 值按 unicode 加载。

安装目录入口变化稳定两秒后，限时子进程先验证导入，成功才在原窗格重启。
选中、滚动、折叠、显示全部、覆盖页、设置光标、打开时间与宽度覆盖保留。旧版保存的技能标签在重载时回到首页；原「项目／控制面」位置会在控制标签打开。
未保存设置延迟重载；坏构建保留旧面板并暗显提示。状态行独立，新代码需重启。
明确空闲且不变的观测可放缓至五秒采集，输入／绘制独立。

### 分栏布局

已保存的设置 `panelLayout`（默认 `classic`；设置 → 面板 → 布局）可选 `split`：首页、项目和控制变为
**上方一个列表，下方是光标所在行的预览**（`docs/design/panel-v8/` 方案 2）。预览沿用经典布局的卡片和句子；提问条不重复预览标题上的泳道名。

- **首页。** 每个包泳道、每个区块（等你处理、进度）各占一行，行数不随任务变化：标记、名称、阶段，
  然后是角色图标和该泳道最重要任务的状态。排队的泳道与已读的已结束泳道各折成一行（`◷ 排队 N · ids`、`✓ 完成 N · ids`），预览列出它们的卡片。提问或失败另有一行原因，所以需要你的事始终在屏幕上；光标起始于第一个这样的行。
  列表下方预览该行：提问条和泳道的卡片、等你处理的条目与最近待试用的工作，或里程碑与工单汇总。
  面板很矮时先去掉空行，再从底部缩短预览；列表不会让位（极矮时列表随光标滚动）。光标不在的工作中泳道，
  会在该行的空余格子里显示模型句子里标出的关键词（没有则显示原因或已走过的阶段）；宽度余下不足六格时不显示。
- **项目页。** 列表是“等你处理”和各页面；光标行的预览是该页的要点（进度：摘要、进度条、待试用切片、现在、最近验收）。
  待试用和最近验收两组的行保留状态标记和年龄，不重复状态词。在页面行上按 Enter 打开页面。等待项和没有简报的待试用切片显示完整文字并折行（太长时预览用 PgUp/PgDn 滚动）。
- **进度页。** 一个清单列表（工作中、受阻、待试用、待办；已验收、下一步、历史各占一行）。切片行以标记表示状态，台账文字在词边界截断；有简报的待试用切片仍显示简报首句。光标所在切片的预览标题显示状态词，下方显示完整台账文字；有简报时，简报和验收步骤在上方，原文折叠在其下。
  在总览的进度预览中，Space 勾选高亮的待试用行，并将按键焦点切入预览。未勾选时，在总览的预览中按 `y` / `n` 仍会处理下一个待试用行。
- **控制。** 上方是角色（需要处理的在前），下方是选中角色的详情和备选链。Enter 进入位置：↑↓ 选择，
  再按 Enter 打开位置表单；草稿与放弃确认留在预览内。在角色行按 `c` / `C` 切换预设，`p` 打开预设列表。
- **工单、工作区、文档。** 每项一行，下方是工单的检查项和最近评论，或该项的完整文字；Enter 打开文件。

| 按键 | 分栏布局里 |
|---|---|
| 上/下 | 在列表中移动（按 Enter 把按键带进预览后，在预览中移动） |
| PgUp/PgDn、预览上的滚轮 | 滚动预览；列表上的滚轮移动光标 |
| Enter | 预览里有可操作内容（卡片、等你处理的条目、位置）的行，会把按键带到预览里，在那里 Enter 与经典布局一致；其他行同经典布局 |
| `=` `+` / `-` | 列表／预览增高一行（列表占比保持在总行数的五分之一到五分之四之间，面板重载后保留）。控制标签的位置添加／删除用 `i` 和 `Del`，不与这些键冲突 |
| 拖动分隔线 | 在分隔线行（预览上方的标题行）按下并拖动，列表到指针所在行为止。需要终端在按住按键时上报移动 |
| Esc | 先从预览回到列表，然后同经典布局 |
| 点击 | 选中一行（或预览中的一行）；再点一次等于 Enter |

按键在预览里时，列表缩成光标周围的三行，其余都给预览；Esc 恢复所选占比。
预览行数超过可见行数时，其最后一格显示滚动条：滑块（`┃`，文本图标为 `#`）在暗色轨道（`│`，`|`）上；这时预览各行少排一格，所以不会被截断。

单个等你处理条目的页面和项目列表，在两种布局下都是经典布局的画面。

卡片／问题展开，下列角色／客户端、模型／强度、包、状态／阶段与观测到的本地时间。
若工作者记录了里程碑，详情和两种布局下展开的运行中任务卡会以一行暗色文字显示最新一条，其下是活动行：

原生卡片列转写和已有上下文百分比、估算 tokens/s、累计 tokens；缺失省略，不额外调用模型。

### 改动摘要

`3` 显示分支／HEAD、领先／落后（无上游证据则未知）、改动计数及每工作树路径／分支／脏状态一行。

## 模型文字

一个总开关控制任务／原生名称与句子、检查器里的决定标题、决策标签、推荐首页排序／简报。
从不写工作流事实或指挥工作者。关闭则隐藏并不请求；无保存偏好时，存在 Mistral/OpenAI/Gemini key 默认开启。
聊天仍需匹配端点 key，决策另需 Gemini/OpenAI/TypeSafe key。

| 设置 | 键／默认值 |
|---|---|
| 模型文字 | `modelEnabled`，依 key |
| 模型 | `model`，`deepseek-v4-1-flash-1017` |
| LLM 上限 | `modelCallsPerHour`，60；30/60/120/240/无限 |
| 决策上限 | `decisionCallsPerHour`，0；600/2000/无限 |
| 总结间隔 | `summaryIntervalMinutes`，5；2/5/10/15/30 分钟（验证 1–120） |

两上限以 0 表示无限，仍计数 `n/∞`。同一 HUD 主目录的面板合计。
文字用 `display/model-cache/calls.json`，标签／排序用 `display/model-cache/decision-api/calls.json`，包括回退尝试。
各计数下一行按次数列功能。变化的运行文字按总结间隔请求；HUD 任务结算即清除运行句子。
有效的工作者摘要立即显示，即使关闭模型文字也一样。与面板语言一致时不调用句子模型；语言不符时，若已启用则只翻译摘要。
摘要缺失或过期时，模型从报告提取结果。待试用任务标题下方显示最新待试用切片的简报首句（如有）。首次请求最终句子无需等待运行间隔；失败后的重试、原生子代理的最终句子和排序仍保留两分钟下限。
结果标签仍由决策 API 独立判断。

## 底部状态行

Claude 与 Antigravity 状态行、pi 页脚、Codex tmux 状态行使用相同的事实和布局：

```text
model effort │ context %/window │ repo branch(dirty) │ quota │ ~N t/s │ notices ··· MCP n  skills n
```

上下文十格，70% 前绿、70% 起黄、85% 起红，有数据时对齐客户端压缩窗口。
Claude/Codex 只显示各自最紧额度窗口，蓝、75% 起品红、90% 起红；pi 用会话费用，位于编辑器右上条带，不在底部重复。
缺失事实省略。通知区依次是：需要你处理的事、HUD 的工作者、客户端自己报告的事件（Claude 或 Codex 子代理的开始／完成／失败，以及 Claude 技能加载，各保留三分钟）。

工作者只显示计数，不显示标题，也只显示此刻正在运行的：每个角色一个图标加人数，顺序为 imp `⚒`、frontend-imp `✎`、general `✦`、oracle `◈`、
reviewer `⚖`、其它角色 `•`、sonic `⚡`（`⚒3  ✦2  ◈1  ⚡4`），组间两个空格；没有运行中工作者的角色不显示。文字图标用 `I`、`F`、`G`、`O`、`R`、`.`、`*`
（`I3  G2  O1  *4`）。不显示提供方、模型和思考强度。该区读取本窗格任务的实时名单，因此运行数小时的工作者仍被计入；已结束的不计（该区不读取已结束的任务），
排队中的也不计；没有运行中的工作者时该区不显示。最后一组之后，一个 `!N`（状态行的告警徽标）统计各角色中等你回答的工作者总数，答复前一直保留；
工作中没有标记，已结束或失败的工作者也没有标记。`⚡` 按 `visualLength` 占两列，状态行按此宽度排版。
待批准的审批固定在最前，点名第一项，其余写 `+2`，放不下时写 `! 3 needs`；没有待处理就不固定。没有时钟、任务数、hooks 数、当前工具或空闲回退文字。

- Claude 状态行：`~N t/s` 根据转录中的输出词元数和从提示或工具结果到回复的耗时估算最新回复的速率。
  在 Linux x64/WSL 上，安装后的 `hud-statusline` 启动器可用原生程序渲染紧凑的 `line` 和 `p10k` 样式，每次都读取标准输入的新数据。
  工作摘要或缓存缺失、过期，原生程序不可用，有实时转录通知，或使用其它样式、转发、管理命令、`--details`、`--source` 时，回退到 TypeScript。
  Claude 额度数据仍发布到本地；标准输入不落盘。源码安装可用 Cargo 构建原生程序；用 Cargo 打包的 Linux x64 发布归档已包含它，安装机器不需要 Cargo。
- Codex 状态行：`~N t/s` 显示从会话日志得出的现有输出速率估值。
- Antigravity 状态行：同一个 `hud-statusline` 命令显示模型、上下文、可识别的额度（如 `5h 80% left`，按当前模型选 Gemini 或第三方模型那组）以及同样的工作者区（读取本窗格的任务，方式与 Claude 相同），不读取其转录，也不转发其输入。`--details --lang en|zh` 另显示输入／输出词元总数。有 Linux x64 原生二进制时，启动器对同一 agy 进程和工作目录复用上一次结果，重绘时约每秒刷新一次，变化可能在下次刷新时才出现。没有该二进制时，每次都由 TypeScript 渲染。

设置样式：`line`、`p10k`、`gauge`、`tide`、`micro`、`stacked`、`headline`、`triptych`。
Stacked 在 Claude/pi 为两行，Codex 回退 line；Tide 底色需 truecolor。文字图标／无色仍保留含义。
`barFields` 从 `model,context,project,quota,tps,notice,loaded` 选择，不改变顺序。
如果指定了字段列表，请加入 `tps` 来显示速率。窄栏（184 列终端打开面板后主窗格为 144 列）按代价由小到大省略：
已加载计数；两个仪表格子（一起）；额度重置时间和分支的 `↑n`；子代理标题（先留几个词，再全部去掉）；
速率；两条子代理通知中较旧的一条；推理强度；上下文窗口（`41%`）；分支；额度；项目；上下文。模型永不丢弃。
工作者区只有一种形式，不会缩短；工作者启动时数字保持原样，让出空间的是额外项。
pi 顶条跟随样式，其它扩展状态保留。状态行仅英文（子代理自己的描述除外）。

### pi 控制

以下控制只影响当前 pi 会话，不保存为面板偏好：

| 命令 | 作用 |
|---|---|
| `/hud`、`/hud toggle` | 切换面板（不会自动打开） |
| `/hud on`、`/hud off` | 打开／关闭面板，与页脚独立 |
| `/hud status` | 报告面板状态 |
| `/hud reconnect` | 取消会话切换后重新绑定，保留本会话的页脚开关选择 |
| `/hud help` | 显示面板／页脚命令帮助 |
| `/hud footer on`、`/hud footer off` | 恢复／隐藏整个 HUD 页脚及编辑器顶条，仅本会话有效 |

以下字段／分组修改保存到 `$HUD_HOME/config.json` → `piFooter`；保存失败时只在本会话生效并警告。
`/hud footer` 或 `/hud footer list` 按组列出已启用字段及配置路径。
`/hud footer reset` 将全部字段恢复为开启。`/hud footer band on|off` 切换顶条组，
`/hud footer footer on|off` 切换底部组。
`/hud footer on|off|toggle <segment...>` 修改指定字段，或用 `all` 代表全部
（例如 `/hud footer off lens viz`、`/hud footer on all`）。不带字段的
`/hud footer on|off` 是会话内整个框架的开关，不是持久化的分组修改。

底部组 id：`model thinking path git mcp skill lens viz statuses context`。
顶条组 id：`session cache tokens tps ttft cost time`。这些开关只控制字段可见性，不会产生缺失事实。
context 属于底部组，但存为 `piFooter.band.context`；其它 id 按分组存到
`piFooter.footer` 或 `piFooter.band`。

## 机器可读状态

活跃 Codex 状态行／面板在事实变化时每秒最多一次，私有原子写入
`$HUD_HOME/display/state/<tmux-session>.json`。`hud codex --json` 读取当前目录会话快照：

```sh
hud codex --json | jq '.context.percent, .agents.active, .attention[].label'
```

Version 2 含会话、项目、上下文、额度、tokens、代理、注意事项，可选健康／速率证据及状态行字段列位置
（面板 `bar.segments` 为空）。主会话代理、子任务、守护评审分别计数。无事实省略，不填零。
