## 安装

需要 **Node ≥24.0.0**（Node 24 为经过测试的支持版本线；见[运行时依据](./ARCHITECTURE.md#3-launch-and-installation)）。在检出目录运行：

```sh
./install --with claude,pi,codex,browser,herdr
```

可任选 **claude**、**pi**、**codex**、**browser**、**herdr**；核心始终安装。
安装器先检查 Node，再运行扩展检查、构建或修改文件，构建 HUD 与 MCP，将命令链接到 `~/.local/bin`。
`--skip-build` 使用已有构建。保留检出／解压目录：已安装命令和客户端绑定均指向它。不修改 shell rc。

外部工具只检查，不安装、不鉴权。工作者另需 herdr、pi-roles 和 pi。herdr 扩展报告 PATH 中的位置，
仅缺少 herdr 时失败。browser 扩展要求 `google-chrome` 与 `jev-ask`，另报告可选的 `jev-aistudio`、
`jev-flow`；不写浏览器配置、不启动任何工具。Chrome、登录与密钥由这些外部 CLI 自行配置。
面板和决策 API 不需要 browser 扩展。

直接启动 `claude` 即使用全局 HUD 状态行，已有非 HUD 自定义状态行则保留；直接启动 `pi` 加载 HUD 页脚。
Codex 的 tmux 状态行使用安装器打印的函数：

```sh
codexH() { hud codex "$@"; }
codexH
```

只有面板按需打开：Claude、Codex 和 pi 都用 `/hud`，启动时不展开。用 `hud uninstall` 或
`./install --uninstall` 卸载；`--with names` 限定扩展。保留 HUD 数据和无关设置。
Claude 设置跟随符号链接并保留一次性普通备份；Codex 在官方 MCP 命令前备份解析后的 `config.toml`，
丢失注释时警告。pi 注册委派与显示两个包，并排除旧 p10k-footer。
备份和多个 Codex home 的操作见[安装器扩展](../install.d/README.md)。

## 通用 CLI 与 MCP

```sh
hud --help
hud panel --help
hud panel                 # 在 herdr 中于调用者旁打开，否则在当前终端显示
hud panel --here          # 不分割窗格
hud panel --width 64      # 本次覆盖，直到保存修改后的宽度
hud statusline --help
hud import --help
hud trust <dir>           # 把该目录加入 grok、agy 和 claude 的信任列表
hud watch                 # 本窗格 HUD 任务每次状态变化一行（--all：所有任务）
hud setup --detect        # 打印本项目的工作者配置 JSON
hud setup --apply PLAN    # 按计划写入 .hud/
hud setup --remove        # 去掉项目注册，留下 .hud/
hud tickets sync [--cwd DIR]  # 单向将 GitHub 父子议题镜像到 .scratch/
hud board [--cwd DIR] [--out FILE] [--open]  # 写出项目的 HTML 审阅看板，打印其路径
hud codex --model gpt-5    # Codex 参数原样交给 tmux 启动器
```

`hud codex-hud` 是 `hud codex` 的别名。面板可用 `--root <namespace/session-id>` 或
`--harness claude|pi|codex --session ID --source ABS` 选择观测，不建立执行身份。
没有显式选择时，`HERDR_PANE_ID` 允许用一秒预算向 `herdr pane current` 查询调用者的 Claude 转写或 Codex 会话（herdr 窗格内回退读取 `CODEX_THREAD_ID`）；
不猜聚焦窗格、不读取状态行写下的绑定。证据不可用时，仅保留未绑定原生会话的任务视图。

MCP 提供 **hud_roster**、**hud_create**、**hud_read**、**hud_wait**、**hud_peek**、**hud_send**、**hud_respond**、**hud_close**。
先调用 `hud_roster` 获取生效的角色、模型／推理强度来源、可接受选项和约定。
`$HUD_HOME/roles/*.json` 按角色名覆盖内置 JSON，已注册项目的 `.hud/roles` 再覆盖。
已注册项目的 `.hud/`、cwd、HUD 主目录、包目录中第一个 `hud-convention.md` 整体替换默认约定。
见[项目工作者](#项目工作者)。

`hud_create` 接收 `role`、`request_key`、`task`，可选 `cwd` 和仅用于显示的 `package`。
默认在角色的首个可用位置（`runs_on`）启动。传入 `preset` 可使用指定预设中首个可用且未耗尽的位置，
仅对本次任务生效，不修改角色文件。也可用 `on` 覆盖执行环境或浏览器服务商（默认值见内置
`harnesses.json` 与 `$HUD_HOME/harnesses.json`）。`preset` 和 `on` 不能同时传入。
重复键返回原任务，不再次启动。指定过的 `preset` 会随 `hud_read` 的任务详情返回。
`model` 和 `thinking` 可覆盖所选 `pi` 或 `cli` 位置的模型和推理强度；`kind` 为 `flow` 选择 `image`（默认）或 `video`。
仅 `pi` 可覆盖布尔项 `lens`、`mcp`、`tps`、`ui_ext`、`skills`、`split`，以及 `pi_args`
（最多 128 项，每项 4096 字符，原样传递，不经 shell）。省略的开关沿用 pi-role 默认值；
split 默认取位置设置。`ui_ext: false` 禁用 UI 扩展；`skills: true` 加载个人技能；
split 为 true 时预留右侧助手窗格。拒绝覆盖 `--orchestrator`／`--notify`。
浏览器（`bro`）位置拒绝这些 pi 选项。

可用 `context_files`（最多 32 个路径，以任务的 `cwd` 为基准解析）和 `from_jobs`（最多 16 个任务 ID，
各自指向 `$HUD_HOME/jobs` 中该任务的 `report.md`）传递上下文。文件须为可读的 UTF-8 文本，解析后的路径须分别位于
`cwd` 或 `$HUD_HOME/jobs` 内；无效引用会在启动前返回 `invalid_arguments`。Pi 和 CLI 工作者按简报中任务之后列出的路径读取文件；
浏览器（`bro`）会把标明来源的文件内容随简报发给浏览器服务（单个文件最多 64 KiB，合计最多 256 KiB，超限返回 `context_too_large`）。
引用上游报告不会将其标为已读，也不会关闭其工作者。

`isolation: "worktree"` 让任务在仓库旁自己的 Git 链接检出中运行（`<repo>-wt/<slug>-<id6>`，分支 `wt/<slug>-<id6>` 取自 HEAD，
链接 `node_modules`，并复制该 CLI 对主检出的信任）。浏览器角色和非 Git 目录会被拒绝。对该任务的 `hud_read` 会附带 `git_summary`。
任务关闭后，只有检出中毫无改动、或其提交已合入主检出时，watcher 才会移除检出和分支，且从不强制；否则保留并在 `job.json` 记录
`worktree_kept_reason`。Project 把这些检出视为任务自己的，不算未登记的 worktree。

角色文件定义 `role`、`instructions`、`can_continue`、可选 `idle_grace_s`（默认 600）及有序的 `run` 位置列表，支持 `pi`、`cli`（`grok`、`agy`、`claude` 或 `codex`）与 `bro`（`jev-ask`、`jev-aistudio`、`jev-flow`）；旧版单位置文件自动加载为 `run[0]`，`"harness": "jev"` 自动加载为 `"bro"`。内置角色：`imp`（`pi` implementer → `pi` Grok 4.7）、`reviewer`（`pi` reviewer → `agy` Hydrogen high）、`sonic`、`oracle`（`cli` `claude` `fable` high → `pi` `architect`；没有角色文件定义 `architect` 时，`hud_create` 也接受 `architect` 作为它的别名）、`pro`（依次为 `chatgpt`、`gemini`、`argon`）和 `flow`（`jev-flow`）。在 `cli` 位置启动需要 `instructions/<instructions>.md`（内置 `implementer.md` 与只读 `reviewer.md`、`oracle.md`），缺失时返回 `unsupported_harness`。遇到配额或限流失败会把该位置在 `$HUD_HOME/exhausted.json` 标记耗尽 1 小时并在失败原因写明下次将使用的位置，但不自动重试。另写 `$HUD_HOME/roles/<name>.json` 注册自定义角色，
例如前端设计角色用 `"agent": "claude"` 和 Claude 模型别名。列模型：`grok models`、
`agy models`、`claude --help` 或 `codex -m`。HUD 只传模型标志、强度标志、该 CLI 的权限绕过标志
和 `args`。不传 home、会话或配置标志，也不设这些环境变量，分发时也不替 CLI 信任目录：
出现信任对话框则拒绝，失败原因写明 `hud trust <cwd>`。会话留在各 CLI 自己的存储里。
herdr 经交互 shell 启动 CLI，所以该 shell 的函数仍生效。

`hud trust <dir>` 把该目录加入 grok、agy 和 claude 的信任文件（先在 `$HUD_HOME` 下备份）。
文件不存在则不创建。codex 跳过。

`hud_read({})`（或 `view: "compact"`）按从新到旧列出运行中或仍需处理的任务。每行包含 `job`、`role`、`state`，
并在适用时带上 `report_unread: true`、`blocked: true`、待答问题编号 `question_ids`、受阻、等待或失败的原因 `reason`。
任务已关闭但报告未读时仍会列出。`view: "recent"` 保留最新 20 个任务的完整列表，包括已处理的历史任务。
两种列表都不会标记已读；未出现在列表中的任务仍可通过 `changes` 报告变化。`view` 不能与 `job` 同用。

`hud_wait({ jobs?, mode?, wait_ms? })` 一次监听多个任务。省略 `jobs` 时，监听调用开始时本会话尚未结算的任务。
`mode: "any"`（默认）在任一任务结算或需要关注时返回；`"all"` 等到所有任务结算，但遇到提问、受阻、等待主会话或失败时会提前返回。
`wait_ms` 为 0–120000 毫秒的整数（默认 60000；`0` 只检查一次）。返回 `ready`、`timed_out`、触发返回的任务编号 `triggered`
和精简任务列表 `jobs`。没有目标任务时立即返回 `ready: true` 和空列表。等待不会读取报告或问题正文、标记已读或已查看，也不会关闭工作者；
完整结果请用带任务编号的 `hud_read` 读取。

`hud_peek({ job, lines? })` 返回精简的 `status` 行和工作窗格末尾的 `pane_lines`（1–120 行，默认 40）。
窗格缺失或不可用时，`pane_lines` 为 `null`，并返回 `pane_reason`。该工具不读取报告、不标记已读或已查看，也不关闭工作者。
pi 和 CLI 工作者可用简报里的可选命令 `hud-progress.mjs` 记录里程碑（每条一行，最多 240 字符，保留最新 50 条）。
`hud_read({ job })` 与 `hud_peek` 的 `progress` 返回最新 10 条，`latest_progress` 返回最后一条（没有则为 `null`）；
列表和等待结果不含这些字段。里程碑不会触发 `changes` 或 `hud watch` 事件。

带 `job` 时读取 STATUS、未读报告（最多 64 KiB）与待答问题。报告比 `read_at` 新，或尚无 `read_at`，即为未读。
已读报告只返回 `report_unchanged: true`，`full: true` 可再次读取正文。`wait_ms` 最多等 120000 毫秒，结算、问题或超时即返回。
返回报告正文时记录 `read_at`（包括工作中和空闲宽限期），不代表验收。已结算的 pi 或 CLI 工作者在当前回合的报告被读取后关闭
（`closed after report read`）；续写后读取上一回合的报告不会关闭工作者，未读报告仍保留原有的空闲期限。读取失败或受阻状态会单独标记为已查看。
工作者写完报告后只回复 `report written: <path>`，不在对话中重复正文。
`hud_send` 给工作中的 pi 或 CLI 任务排队消息；角色允许继续且报告未读时，也可在空闲宽限期内续写。读取已结算的报告后，修正须另开任务；`message_key` 去重。
CLI 工作者用同一条 `QUESTION` 和 `hud_respond` 流程提问（`hud-ask`，20 分钟后用默认）。
CLI 受阻时任务显示为需要你；会话经 `changes` 或 `hud watch` 得知。
`hud_respond` 只写一次 `qN.answer.md`。`hud_close` 提前回收，正常清理由 watcher 负责。主人也可在面板里回答未答的问题
（`r`，再按数字或 `d`）；主会话通过一行 `changes` / `hud watch` 得知：`[role@job] ANSWERED qN from panel: <答案>`，
取自 `$HUD_HOME/panel-actions.jsonl`（读取方运行期间作出的回答；更早回答的问题只是不再出现）。
主会话决定所有下一步，MCP 不知道工作流。工具参数见 [MCP README](../packages/hud-mcp/README.md)。

每个 MCP 响应还带 `changes`：自上次响应以来本窗格派出的任务每次状态变化一行（没有则省略）。面板、状态栏、pi 页脚、MCP
与 `hud watch` 用同一个 `jobRow` 推导任务状态，所以结论一致。`hud watch` 默认只打印需要关注的事件，如提问、结算、受阻或新的静置原因；
`--verbose` 才打印所有变化。范围是调用者窗格（`HERDR_PANE_ID`），`--all` 为所有任务；空闲时只每 30 秒重扫一次。Claude Code 用 Monitor 运行它。
Codex 通过 `codex queue` 自动静默接收；pi 的 HUD 扩展自动把事件作为原生后续消息送给主会话，不改编辑器草稿，也不需要打开面板或 Monitor。
pi 工作者不会启动此监听。调用者有窗格时，`hud_roster` 和 `hud_create` 返回 `watcher_alive`；监听有效时不会直接向窗格输入，也不会显示 Monitor 提示。
未启用监听时，问题仍可通过 Codex 队列发送；若无法排队或没有队列，则回退为直接输入。

任务是 `$HUD_HOME/jobs/<job>/` 中的普通文件。pi 历史保存在
`${PI_CODING_AGENT_DIR:-~/.pi/agent}/sessions/<cwd-dir>/`，任务的 `sessions/` 链接到主代理／助手文件。
CLI 任务的监督进程只观察；只有事实能结束任务：记录的进程号消失（或被替换）、标签页关闭、输入前派发被拒（`failed`；
磁盘上有新报告则 `closed`）。每次派发和 `hud_send` 开始一个回合（`turn.json`）。对于从未提交完成回执的回合，在 `advisory` 模式下，
herdr 不在 `working`、新报告稳定 10 秒且本回合启动的后代进程均已退出时，回合才结算。仍存活的本回合后代进程也会推迟安静任务决策和自动关闭。
匹配的 `hud-progress --done` 回执可以直接结算；改写报告后必须提交新的匹配回执。如果回合安静达到角色的宽限期仍没有新回执，
任务转为 `waiting_orchestrator`，不结算也不调用决策 API；主会话可用 `hud_send` 继续或用 `hud_close` 停止。
pi 的读后自动关闭也按最近一次派发或发送判断。
可继续的 CLI 工作者在报告被读取或期限届满时结束空闲宽限；两种情况都通过 `/quit` 和 watcher 回收，因到期关闭时原因为 `settled`。herdr 状态本身不会让仍在运行的任务判为失败。
回合安静超过空闲宽限且无报告时，做一次决策 API 选择，只在固定动作中选（继续等、一次固定的写报告提示、屏幕上有配额行才 `failed`、
交给主会话）；置信度低于 0.8 或出错则交给主会话。不确定的一律 `waiting_orchestrator` 并写明原因。监督进程由 herdr 推送、
文件变化和自身截止时间唤醒，另有每 30 秒一次重读状态；STATUS 只在行变化时写。按需 watcher 在创建时启动，经 `pi-role-reap` 回收已结束任务，
失败标签页保留两小时；没有未结束任务或待到期失败任务时退出。CLI 任务开着时还会检查监督进程是否还活着；
`HUD_WATCH_CLI_CHECK_MS`（默认 30000）是该间隔。监督进程已死而工作者仍在时任务为 `waiting_orchestrator`（“supervisor exited; worker still running”），对它 `hud_send` 会启动新的监督进程。已结算目录在**关闭一天后**的
后续扫描或下次创建时清理，不设专门到期定时器；包括报告及 `hud_read` 访问。删除旧 pi 任务前先将真实 JSONL
会话移至 pi 存储；CLI 和浏览器会话留在各自存储。cwd 无效、目标冲突或移动失败则保留任务。删除会话链接不删除目标。

## 项目工作者

```sh
hud setup --detect [--cwd DIR]
hud setup --apply PLAN.json [--cwd DIR]
hud setup --remove [--cwd DIR]
```

命令本身不提问。`hud-setup` 技能与 `hud-delegate` 一样，为 Claude、Codex 和 pi 安装；
它负责询问，这些命令只读或只写。

`--detect` 打印一份 JSON，不写任何文件。它给出 `--cwd` 的 git 顶层（否则就是 `--cwd`）、
该根是否已注册、参考角色（内置与 `$HUD_HOME/roles`）、项目角色、启用集合、无效角色文件、
技能，以及工作者技能链接。技能根目录来自 `$HUD_HOME/setup.json` 的 `skill_roots`
（默认 `~/.pi/agent/skills`、`~/.claude/skills` 和 `~/.agents/skills`），其后总是包含本仓库自带的
`integrations/skills`。技能是含 `SKILL.md`
的目录，名字取 frontmatter 的 `name`。每项带 `model_invocable`：frontmatter 有
`disable-model-invocation: true` 时为 false。pi 仍加载该技能，但不放进模型的技能列表，
所以工作者不会自己选用它。

`--apply` 按计划写入项目的 `.hud/`（应提交）：

```
.hud/project.json          启用的角色，以及 apply 自己创建的链接、角色文件和提示
.hud/roles/<name>.json     仅当 pi 角色与参考角色不同
.hud/skills/<name>         指向技能目录的符号链接（仅工作者）
.hud/agents/<role>.md      可选的仅工作者提示
.hud/hud-convention.md     可选，内置约定的副本
```

计划为 version 1：`roles`（启用的名字）、`pi_roles`（只调 pi：`from`、`pi_role`、`model`、
`thinking`、`split`、`can_continue`、`skills`）、`skills`（名字到技能目录的绝对路径）、
`agents`（角色到 markdown）和 `convention`（`keep` 或 `copy-default`）。打印 `removed`、
`wrote`、`linked`、`skipped (exists)`、`registered`，或 `no changes`。同一计划再跑一次不会改任何东西。
不是本命令创建的文件或链接会留下，并报 `skipped (exists)`。

apply 把项目根记入 `$HUD_HOME/projects.json`。项目配置只有注册之后才加载。
`--remove` 去掉注册，留下 `.hud/`。克隆来的 `.hud/` 在该克隆里跑过 setup 之前不起作用。

只调 pi。其他 harness 的角色只能显示或隐藏，不改它们的文件。本命令不运行 `hud trust`。
若所选 CLI 角色的目录未被信任，请自行运行 `hud trust <dir>`。

## 首页

首页依次显示需要你回答的问题、包泳道中的任务卡片、原生会话泳道及「替你决定」。
观测文件，不派发或串联工作；对任务只有主人的三个微操作（见「按键」）。运行中任务有待答问题才需要你；已结束任务遗留的问题不算。
报告不证明成功，显示标签不代表验收或合并。缺少证据保持未知。

卡片是标题加固定两行句子；未有文字用 `┃ …` 占位。Enter 原地展开完整句子和事实。
任务标题优先取 brief 标题，否则模型短名或任务首行按宽度显示。只有最新且仍属当前的已结束卡片
初始展开，到折叠时限为止；显式选择在本次面板生命周期内优先。泳道标题的 Enter 折叠泳道。

**sonic 子任务。** HUD 任务派出的 `sonic` 任务（`parent_job`）不再是卡片，而是父卡片下的一行：
`├─ ⚡ sonic · 短标题  3m ◉`（最后一个用 `└─`，ascii 为 `|-` 和 `` `- ``），带用时和状态符号，经典和分栏预览都一样。
父卡片折成标题行时隐藏这些行，右侧写 `⚡ N sonic`（仍在运行的个数）。`/` 过滤命中 sonic 任务时，其父任务一并保留。

**面板生命周期。** 打开前已结束的任务不加载，包括决定和模型输入；`a` 不能显示它们。
活跃／未知任务不论年龄均可显示。构建重载保留最初打开时间。原生代理和项目 STATE 切片查询保持各自范围。

**卡片时限。** 已结束 HUD／原生卡片默认五分钟折为一行、十五分钟隐藏；失败／停止至少保留三十分钟。
设置 → 面板可调整。隐藏时限小于折叠时限则按折叠时限算。运行／提问卡片不隐藏。
`a` 在原位显示较早卡片／决定为暗色单行，Enter 展开。任务扫描考虑最新 200 个目录。

**决定。** 已答问答显示问题、回答、替代选项和原因；只有明确偏离写明的默认选项才显示 `≠`，
含糊自由文本不算。只有明确 `One-way: true` 才固定标出单向决定。普通决定三十分钟隐藏，偏离两小时。
评审结论需要记录的 accept／changes-required 行及已结算输出，助手退出本身不是结论。

**首页原生代理。** Claude/Codex 主会话各有泳道。子项缩进一级，更深写 `↳ parent`；
隐藏父项不隐藏活跃后代。pi 助手已是 HUD 任务。Claude 读取元数据并分批向前读取转写，记住公开 Agent/Task 嵌套。
重放保留已知完成时间，追平前不请求模型。完成后转写增长才重新运行；新 finished 元数据或已追平的公开
`end_turn` 且无未结束工具调用才再次结算。不完整读取不能证明空闲。`o` 打开转写，不切换客户端对话。

**模型推荐。** 默认保持事实顺序；推荐模式将最多 200 卡片的有限显示事实交给所选决策 API 打 0–4 分，
变化的看板最多两分钟一次。问题、失败和需要人工处理的卡片受保护，原生子树保持完整。
低分已结束卡片进入较早项，可用 `a` 显示。另一次聊天调用按总结间隔生成短简报。
无 key／失败沿用默认顺序；简报等待或失败保留上次好文字和有效排序。关闭模型同时隐藏两者。

**首行。** `? 5 项等你处理 · 0 运行中` 把 STATE「Waiting for the owner」的条目和任务问题一起计数
（与项目页签的数字相同）；只有两者都为零才显示 `✓ 没有需要你处理的事`。有待处理条目时，Enter 或单击打开项目总览的「等你处理」块。
底栏的 `✓ n 今日完成` 为 0 时不显示。

**空余行。** 先给卡片和决定留空间，再自上而下显示：STATE 的待处理条目（每项一行，最多五项，其余 `还有 N 项`）、
最近落地的切片（38–55 列三行，更宽五行；首页不读提交日期，故台账靠后的在前），最后在底部显示进度块：
STATE Now 摘要（最多折三行）、六状态进度条／图例、每功能最多六个未完工单。进度块按当前里程碑统计，与项目总览一致；
没有当前里程碑时统计整个台账，标题为 `全部切片`。进度块先取它的行，两个列表只用剩下的。
变矮时依次减少最近完成、待处理、工单、摘要多余行、图例、摘要、条，最后整个块消失。
Enter 或单击待处理条目打开它的全文页（Esc 回到总览上该条目那一行），在「等你处理」标题上打开总览的「等你处理」，在最近完成或进度块上打开项目的进度页，在工单行上打开工单页。

## 项目

项目是一个总览，每节一页，按时间线排布：什么在等你、正在发生什么、刚落地了什么，最后是各页的现状。总览自上而下：

- 项目名行（面板所在目录名，见下面的切换项目），带当前里程碑；
- **等你处理**：STATE 的待办，Enter 折叠（以 `(waits on ID, feature/NN)` 结尾的条目，在这些切片验收或放弃、工单完成后自动消失）；标题写明总数和还有多少切片待试用（`4 · 5 待试用`：台账里状态为 `try` 的切片，不分里程碑；进度行和项目列表是同一个数）。
  一条放不进一行的文字，在总览有空行时从第一个词下面起完整折行，自上而下（你要试的东西不会被截成一个名字）；面板太矮就收成一行，先于最近完成和各页行让位，光标所在的那条除外，它保留完整文字。在条目上 Enter 或单击，用一个页面（`‹ 项目 › 等你处理`）显示它的全文：
  STATE 里怎么写就怎么显示，含续行，用词和顺序不变（接着上一句的行并入同一段，编号行或 `-` 行另起一段）。页面可用移动键和滚轮滚动；
  Esc 或单击顶部面包屑返回，光标仍在该条目上；`o` 打开 STATE.md。不调用模型；
- **现在**：每个工作中或受阻的切片一行（`◐ ID  文字`，右侧是任务的角色和分钟数、`提问中 ?`、`受阻`或哪里不一致），
  再是本项目未结束且没有切片显示的 HUD 任务（`◉ 角色  标题  年龄`）。切片的文字只在整句放得下时才写在同一行。
  清单里没有的工作树不是在进行的工作：它们计在工作区一行上。没有进行中的工作时写 `没有进行中的工作`；
- **最近完成**：最新落地的切片（待试用、已验收），按账本读取时已有的提交日期由新到旧（`◇ ID  文字  待试用 10小时`）；
  40 列时三行，更宽五行；
- 每页一行带一句摘要：**进度**（里程碑、工作中、待试用、受阻，下方是当前里程碑的条）、**工单**（完成／总数、工作中、受阻；
  项目没有工单时不显示）、**工作区**（未登记工作树、分支、改动、工作树、领先／落后、编辑中的任务；它的页面列出未登记的）、**文档**（spec 里程碑、最新评审）。一行放不下就从末尾整项丢弃，不截断某一项。

面板比总览矮时，先收起**最近完成**（先收到最新的几行，再整节），然后是条和各块之间的空行；等你处理、现在和各页行保留
（连这些都放不下时页面随光标滚动）。Enter 或单击打开一页，面包屑行 `‹ 项目 › 页名` 取代标签行；
Esc 或点击面包屑回到总览，光标停在刚离开的那一页。每页各自记住光标和滚动，面板自我重载后也保留。

事实来自 `docs/handoff/STATE.md`（根 `STATE.md` 回退）、`docs/spec.md`、评审、角色／约定／指令及 Git 工作树。
不猜里程碑或完成。密钥只显示名称及是否存在；浏览器 ✓ 仅指 Chrome 和 `jev-ask` 在 PATH，非运行或登录证明。

**进度页**：STATE 的 Now 摘要（最多两行），再是当前里程碑（`Milestone:`；没有当前里程碑时按整个账本算）：
名称、一条条和 `已验收/总数`、有切片的状态（`1 工作中  1 受阻  2 待试用  3 待办`，数量为零的不写）、以及一行此前各里程碑
已验收的总数（`✓ 此前 5 个里程碑已验收 24 项`）。然后三节：

- **现在**：账目里 `working`／`blocked` 的切片，各带其任务在首页卡片上的那句；漂移标记表示缺失工作树或非活跃账目状态，
  不回写 STATE（清单里没有的工作树在工作区页）。再是本项目还没结束、也没有切片显示的 HUD 任务（角色、标题、年龄）。任务标题取工作板的描述，
  否则取 `job.json` 的标题，再否则取 `brief.md` 的首个标题（或首行）：仅在完整采集时，经采集器按文件签名缓存、限定大小的读取得到。
  这样的每一行都是独立的停靠点：Enter 或 `o` 打开其报告，没有则打开 brief；任务很多时可用键盘翻页。
- **下一步**：STATE 的 `## Next`，显示前两条，每条最多两行（被截断的 `…` 条目按 Enter 展开全文，再按折回；放得下的条目
  按 Enter 打开 STATE.md），再加一行 `还有 2 项`，按 Enter 显示其余（`收起` 折回）。
- **历史**：最近七天完整列出，最新在前，是带日期的动态：每个已落地的切片一行（`◇`／`✓`、ID、文字和年龄，`待试用 1天` 或 `3天`），
  Enter 显示它的里程碑、提交和日期。更早的工作每个里程碑一行（`▸ M4  ✓ 7 已验收  ◇ 1 待试用  15–24天`，带天数范围），
  Enter 展开其切片；没有提交日期的切片不猜日期，归在其里程碑下。日期取账目行最后一个哈希（7-40 位十六进制），
  经安全 Git 策略读取，来自采集器本来就跑的那一次批量 `git log`。

**只看待试用。** 在待试用数量（`2 待试用`，自成一个停靠点）上按 Enter 或单击，或按 `t`，页面只留还没试用的：
标题 `仅待试用 ── n` 取代面包屑下的全部内容，其下是账目里状态为 `try` 的切片（只认状态，从不匹配文字，不论哪个里程碑），
按里程碑分组、最新在前：最新的里程碑展开（`◇ DATA-ONE  文字  1天`），
更早的每个一行折起（`▸ M3b  ◇ 1 待试用  19天`），按 Enter 展开。切片显示账目里的完整文字，折行排在 ID 下面；面板太矮放不下时，光标所在以外的切片各留两行。
在切片上按 Enter 显示里程碑、提交和日期；模型开启时，在原文之上还有**简报**（改了什么，白话，至多两句）和编号的**验收步骤**（怎么试，至多四步）；
调用未完成或失败、或模型关闭时，只显示原文。在标题上按 `t`、Enter 或单击，或按 Esc，
回到完整动态，光标和滚动位置不变；离开该页或切换项目会清除筛选。不增加任何读取：用的就是已解析的账目。

窄屏（40 列）时一行放不下就折到第二行，不截断唯一的一行。在行上 Enter 或 `o` 打开 STATE.md；
在折叠行上 Enter 折叠／展开，`o` 只在该行没有文件时折叠。

工单读取 `.scratch/<feature>/issues/<NN>-<slug>.md`，最多 16 功能 ×64 文件，每份 64 KiB。

状态 done/closed/complete，或至少一个复选框且全部勾选，即完成；否则未完／未解析依赖为受阻，无依赖为就绪。

**工单页**：先是全部工单的完成／总数细条和每个功能的短码（`hp hub-pages 4/7`），再按状态分栏列出各功能的工单，

**控制标签。** 控制是项目之后的主标签，顶部显示当前项目。`[`／`]` 与项目标签共用同一个项目选择，不改变首页所属项目。打开控制时只采集当前项目的角色等控制信息，不采集 Git 状态、工作树或工单。角色视图从上到下是：

chatgpt、gemini、aistudio），模型取 `harnesses.json` 中该宿主的默认值；`e`/`E` 思考档位（Flow 位置用 `m` 在 image/video 间切换）。

在供应商一级则要输入完整的 `供应商/模型`）；Tab 显示全部供应商和模型而不是精选的；筛选为空时按 ← 或退格回到供应商；
Esc、Ctrl+C 或单击离开选择器，不写任何东西。选择器打开时所有按键都归它（`q` 输入字母 q）。

精选列表是主人真正用的，而不是 `pi` 的约 170 个模型：每个供应商只列其匹配规则选中的模型，其中每个系列只留最新的
（系列即去掉版本号和日期戳的 id：`claude-opus-4-5`、`4-6`、`5`、`5-5` 是同一系列，最新是 `5-5`；带日期的快照让位于同版本的无日期 id）。
角色当前用的模型始终列出，即使精选会把它藏起来。规则是 `catalog.pi.include`，随 `catalog.json` 内置
（`arena` `*`、`mistral` `deepseek*`、`anthropic` `*opus*`、`openai` `gpt-6*`），可在 `$HUD_HOME/harnesses.json` 里按供应商覆盖：
`{"catalog":{"pi":{"include":{"arena":["*"],"openai":["gpt-6*"]}}}}`（`*`、`?` 通配 `供应商/` 之后的名字，不分大小写）。

对 `pi`、`agy` 和 `grok`，模型列表优先取自宿主自己的命令
（`pi --list-models`、`agy models`、`grok models`），仅在打开控制标签或在其内按 `r` 时运行（不在首页或定时刷新时运行），在
`$HUD_HOME/display` 下缓存一天（命令缺失或失败时静默回退）；随后是内置 `catalog.json` 与
`$HUD_HOME/harnesses.json` 的 `catalog` 键（`claude` 与 `codex` 始终使用此目录），最后是 `$HUD_HOME/roles/*.json`
里写过的模型；选择器只在这份合并后的列表上精选，不改它。改动写入
`$HUD_HOME/roles/<role>.json`（原子写入、0600、以内置角色为底、保留其他字段和位置里的其他键）或
`$HUD_HOME/exhausted.json`；下一次 `hud_roster` 和 `hud_create` 即读取，所以页面显示的就是下一个任务用的。
来自项目文件的角色在此不可改；若位置的文件里设了启动选项（`split`、`skills`、`args`……），切换宿主会拒绝，
因为那会重建它们：两种情况都在顶部一行说明，下一个按键后消失，`o` 可打开文件。

**切换项目。** 有多个项目时，总览的项目名行写作 `名称 ▾ 项目 i/n`，`[`、`]` 依次切换面板自己的项目和
`$HUD_HOME/projects.json` 里仍存在的根（去重，最多 16 个）。在项目名行按 Enter 或单击，打开**项目列表**
（`‹ 项目列表` 取代标签行；Esc 或单击面包屑回到总览）。
在某一页内 `[`／`]` 同样有效，面包屑改显项目名，该页的光标、滚动、折叠重新开始。选择归面板所有，重载后保留，不在设置里。
首页始终是面板自己的项目，从首页的进度块打开也回到它。面板为每个访问过的项目保留一个采集器（最多四个，面板自己的不丢，
其余丢最旧的），只采集正在显示的那个。只有一个项目时没有 `▾ 项目 i/n`，也没有列表。

**项目列表。** 每个项目两行：名称、当前里程碑、`?` 等你处理的项数（STATE 的等待项）、`◉` 该根下未结束的 HUD 任务数；
下一行是它现在在做什么（`◐ A-ONE, A-TWO 工作中`：工作中的切片，没有则受阻的，再没有则最新落地待试用的 `◇ B-TWO 待试用`，
再没有则最新已验收的 `✓ D-ONE 已验收`，按账本顺序）和距上次改动的时间（STATE.md 或工单文件，取较新者；
账本里的提交日期要读 Git，列表不读）。80 列及以上，该项目的堆叠条排在行首。没有 STATE.md 的项目显示 `无 STATE.md` 和未完成的工单数。顺序：面板自己的项目，
然后有等待项的，然后有任务在跑的，其余按最近改动，各组内最新在前。Enter 或单击打开该项目的总览（在这个总览上按 Esc
回到列表；不是从列表进入的总览，Esc 回到主页面或退出独立面板）。光标同时标出一项的两行。列表只在可见时读取：
对每个列出的项目按文件签名读 STATE 和工单（与首页相同），并用一次遍历最新 64 个任务目录统计各根下未结束的任务。
不读 Git、角色，也不做完整采集；列表打开期间至多每五秒读一次（重新打开则立即读），当前项目自己的完整采集暂停。
距上次改动的时间写作 `12分钟`、`3小时`、`4天`。
没有 STATE.md 的项目在进度页显示 `无 STATE.md`，其他页照常。

在页内 Enter 折叠标题、显示工单详情或打开行的文件，`o` 在 `$EDITOR`（默认 vim）的 herdr 标签页打开文件，编辑器退出即关闭；
工作区查询失败则退为旁侧分割。首页、项目和控制保留各自的光标与滚动位置。完整项目采集只在总览或某一页可见且无遮挡时运行；
首页只复用 STATE／工单缓存。Git 最多每五秒一次。不启动浏览器或 MCP。

## 审阅看板

`hud board [--html] [--cwd DIR] [--out FILE] [--open]` 写出项目的审阅看板：一个静态 HTML 文件，用浏览器打开；页面没有脚本、
字体、图片、链接，也不发任何网络请求（Content-Security-Policy 只允许内联样式），所有项目文字都经过转义。内容：页头（项目、
分支及改动／领先／落后、里程碑、写出时间，以及进行中／受阻／待试用／已验收／待办的堆叠进度条）；**需要你处理**（STATE 的等你事项和
未答复的任务问题，含选项与默认；没有则不显示）；**待试用**（每个切片一张卡：里程碑、时间、提交、已存的模型简述与编号步骤，没有则为台账原文，
台账行提到的 `.scratch/` 工单，以及逐文件 `--numstat` 条）；**进行中**（进行中与受阻的切片，运行中的任务及角色、模型、用时、当前一句话）；
**工单**（各功能的进度条、未完成工单及其清单）；以及**最新里程碑评审**。没有内容的部分不显示。页面跟随系统的浅色／深色，也可用页首的
自动／深色／浅色开关（纯 CSS）切换，从手机宽度到宽屏都能阅读。

它只采集一次，方式与项目页相同：不启动 HTTP 服务，不调用模型。待试用简述只在面板已存过时出现（与面板同一缓存和模型文字总开关）；
本窗格的任务只在 herdr 内（`HERDR_PANE_ID`）出现。文件默认为 `$HUD_HOME/display/board-<项目>.html`，`--out` 可指定；以 0600 先写临时文件再重命名，
目标处已有的链接会被替换而不会被跟随。命令打印该路径。`--open` 随后分离地运行 `wslview`，否则 `xdg-open`；两者都不在 `PATH` 时只在 stderr 提示（退出码 0）。

在面板中，`w`（首页或项目页；选择器和设置中无效）对当前显示的项目做同样的事并打开，顶部显示 `已导出看板: <文件>`，直到下一次按键。

两种布局下调整项目标签页的排布，不改变首页、控制、工单、计数或按键；保存后立即生效。**时间线**为默认。**看板**在总览显示

（阶段、进度、`?`、`◉`、时间）。**收件箱**在总览顶部按优先级列出「需要你处理」（提问与 STATE 等待项、最新在前的待试用切片、等待答复的工单、受阻切片、达到上限的角色，右侧给出原因词，标题计数与时间线一致），其下是运行中、`最近验收` 行和子页行；进度页依次为待试用（跨里程碑最新在前）、受阻、工作中、下一步和折叠为一行的已完成；项目列表分为需要你处理、运行中和安静（每个安静项目占一行）；工单与时间线相同。在收件箱的角色提醒上按 Enter，跳到控制标签中的该角色；按 `o` 仍可打开文件。

在经典的待试用视图和分栏的待试用行上，Space 勾选或取消勾选当前行（`▣`，文本图标为 `*`）。`y` 验收、`n` 标记已勾选的行；
未勾选时仅处理当前行。所有涉及的切片合写到 `$HUD_HOME/tries.jsonl` 的一条记录，`hud watch` 和 MCP `changes` 各显示一行。
记录结果或离开视图后，勾选会清除。

### 布局与重载

首页、项目和控制是默认的主标签。设置 → 面板 → **实验功能**（`hud-settings.json` 的 `experiments`，默认关闭）会加入实验性 **EXP** 标签。
用 ↑/↓ 选择，Enter 编辑或打开赠额账；Enter 保存，Esc 取消。校准时先按 Enter 预览，再按 Enter 保存新基准。
经典和分栏共用同一表单。设置保存在 `$HUD_HOME/exp/`，应用于本机所有项目。Codex 配置只能从本机已知项中选择，EXP 不会改动 CLI 配置。
在 **pi 订阅代理**中选择 Codex 配置并开启自动刷新。pi 绘制 HUD 底栏时，若读数到期，HUD 用该配置的现有登录查询 Codex 额度，不发送提示词；不用 pi 时不刷新。
`openai` OAuth 路线的底栏显示近似剩余额度（`5h ≈72%`），当前请求有直报时优先显示直报（`5h left 72%`）。`oapi` 等其他路线不展示订阅值。
旧读数标为过时，超过重置点的窗口显示待刷新。打开**代理读数**可查看两个窗口及其重置时间、来源、最近成功和错误、下次尝试。
若提示需登录，请登录绑定的 Codex 配置，然后关闭再开启自动刷新。关闭实验功能即停止刷新。

**API 赠额**并列显示两本账。pi 在 API 路线上只显示当前路线已启用的账本（例如 `API ≈$12.75`），不显示订阅额度。
`openai-api` 计入 `oapi` 请求；`anthropic-api` 只计入已安装的 pi HUD 能确认使用 API 密钥直连 Anthropic 的请求。
Claude OAuth、第三方网关和无法归属的请求不计入。Claude Code 状态栏不变。关闭实验功能后，两本账保留，停止采集。

详情、改动、设置和帮助共用标题带、精确列宽的行和完整页脚提示（窄时从右丢弃）。
没有 Agents 区、叠放／紧凑布局、时间线、活动中心、代理日志、Summary 或诊断页。各页保留选中／滚动。
图标为 `unicode` 或 `text`，旧 nerd/emoji 值按 unicode 加载。

安装目录入口变化稳定两秒后，限时子进程先验证导入，成功才在原窗格重启。
选中、滚动、折叠、显示全部、覆盖页、设置光标、打开时间与宽度覆盖保留。旧版保存的技能标签在重载时回到首页；原「项目／控制面」位置会在控制标签打开。
未保存设置延迟重载；坏构建保留旧面板并暗显提示。状态行独立，新代码需重启。
明确空闲且不变的观测可放缓至五秒采集，输入／绘制独立。

### 分栏布局

已保存的设置 `panelLayout`（默认 `classic`；设置 → 面板 → 布局）可选 `split`：首页、项目和控制变为
**上方一个列表，下方是光标所在行的预览**（`docs/design/panel-v8/` 方案 2）。预览里的卡片、提问条和句子与经典布局完全一致。

- **首页。** 每个包泳道、每个区块（等你处理、已替你决定、进度）各占一行，行数不随任务变化：标记、名称、阶段，
  然后是该泳道最重要任务的状态。提问或失败另有一行原因，所以需要你的事始终在屏幕上；光标起始于第一个这样的行。
  列表下方预览该行：提问条和泳道的卡片、等你处理的条目与最近落地的切片、决定，或进度区块。
  面板很矮时先去掉空行，再从底部缩短预览；列表不会让位（极矮时列表随光标滚动）。光标不在的工作中泳道，
  会在该行的空余格子里显示模型句子里标出的关键词（没有则显示原因或已走过的阶段）；宽度余下不足六格时不显示。
- **项目页。** 列表是“等你处理”和各页面；光标行的预览是该页的要点（进度：摘要、进度条、待试用切片、现在、最近验收）。
  在页面行上按 Enter 打开页面，与以前一致。等待项和待试用切片显示完整文字并折行（太长时预览用 PgUp/PgDn 滚动）。
- **进度页。** 一个清单列表（工作中、受阻、待试用、待办；已验收、下一步、历史各占一行），光标所在切片在下方说明：它的完整账目文字；模型开启时，待试用切片的简报和验收步骤在其上方。

- **控制。** 上方是角色（需要处理的在前），下方是选中角色的详情和备选链。Enter 进入位置：↑↓ 选择，
  `p m e i Del K J x` 作用于它，Esc 返回；在列表里 `c` / `C` 给角色应用预设。
- **工单、工作区、文档。** 每项一行，下方是工单的检查项和最近评论，或该项的完整文字；Enter 打开文件。

| 按键 | 分栏布局里 |
|---|---|
| 上/下 | 在列表中移动（按 Enter 把按键带进预览后，在预览中移动） |

## 底部状态行

Claude 状态行、pi 页脚、Codex tmux 状态行共用事实渲染器：

```text
model effort │ context %/window │ repo branch(dirty) │ quota │ ~N t/s │ notices ··· MCP n  skills n
```

上下文十格，70% 前绿、70% 起黄、85% 起红，有数据时对齐客户端压缩窗口。
Claude/Codex 只显示各自最紧额度窗口，蓝、75% 起品红、90% 起红；pi 用会话费用，位于编辑器右上条带，不在底部重复。
缺失事实省略。代理／任务开始、完成、失败及 Claude 技能加载事件保留三分钟。
待批准／待答问题固定显示。没有时钟、任务数、hooks 数、当前工具或空闲回退文字。

- Claude 状态行：`~N t/s` 根据转录中的输出词元数和从提示或工具结果到回复的耗时估算最新回复的速率。
- Codex 状态行：`~N t/s` 显示从会话日志得出的现有输出速率估值。

设置样式：`line`、`p10k`、`gauge`、`tide`、`micro`、`stacked`、`headline`、`triptych`。
Stacked 在 Claude/pi 为两行，Codex 回退 line；Tide 底色需 truecolor。文字图标／无色仍保留含义。
`barFields` 从 `model,context,project,quota,tps,notice,loaded` 选择，不改变顺序。
如果指定了字段列表，请加入 `tps` 来显示速率。窄栏（184 列终端打开面板后主窗格为 144 列）按代价由小到大省略：
已加载计数；两个仪表格子（一起）；额度重置时间和分支的 `↑n`；通知标题（先留几个词，再全部去掉）；速率；
两条通知中较旧的一条；推理强度；上下文窗口（`41%`）；分支；额度；项目；上下文。模型永不丢弃，任务角色名保持完整；
任务启动时数字保持原样，让出空间的是标题，余下的空间再还给标题。
pi 顶条跟随样式，其它扩展状态保留。状态行仅英文。
