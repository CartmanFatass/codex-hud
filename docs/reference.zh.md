## 面板

### 区域

面板有四个区域：**1 卡片**（卡片布局中是卡片，紧凑布局中是树）、**2 时间线**、**3 改动**（工作树列在改动的文件上方）和 **4 详情**；默认只打开卡片，其余从控制栏或用 `Ctrl+]` `2`–`4` 打开。各区域纵向排列。每个区域有一行**标题**，按面板的外观来画（见下），写着它的名字；右端在需要滚动时写当前显示的行（`7–14/46`），否则写有多少项（`4 个文件`、`9 条`）；下面是内容，只在左边有一条竖线 `│`（聚焦的区域用强调色，其它为暗色），没有右边框，也没有底线。面板在 30 行及以上时，各部分之间空一行：控制栏下、两个区域之间、状态卡上方；空行从不挤占区域的行，圆角框外观也不空行，它的边框已经把各部分隔开。区域只有**打开和关闭**两种状态，关闭的区域不占任何行。点击区域的标题把它放大到控制栏和状态卡之间的全部空间，再点一次还原，和 `Ctrl+]` `z` 一样。区域只占它要显示的行数；剩余空间给卡片，详情区域有焦点时给详情。卡片区域也一样：它的标题行写着各状态的数量，点击它放大卡片；它也可以从控制栏关闭，其它区域随即分掉它的空间。
每个区域保留自己的滚动位置。选中代理按 ID 保持，选中文件按路径保持。

### 布局

**两种布局**（设置 → Panel →「布局」，保存后立即生效）：

- **卡片**（rich，默认）：agent 以卡片显示。顶部一行按状态统计主会话启动的 agent（`!1 失败  ✓3 完成  ▸3 运行`，每个数字都带文字；子任务还在运行的也算运行中），会话中的守护评审以 `◈N` 显示在这一行（有评审失败时为错误色），放得下时还写出这些 agent 之下（各层级）一共有多少子任务、其中几个失败（`· 17 子任务，1 失败`），面板窄时计数先去掉文字，视图的 `4–19/46` 也让位，这一项留到最后（`!1 ✓3 ▸3  · 17 子任务，1 失败`）；其下是一个可滚动的视图：主会话启动的每个 agent（**L1**）一项，顺序、筛选和收起规则与列表相同。L1 再启动的 agent（**L2**：implementer、reviewer、scout 之类）不单独成项，而是在它们的 L1 的卡片里。运行中、失败、刚完成不到 1 分钟以及需要留意的 L1 是一张**卡片**，右侧不封口。顶边是状态图标、任务类型图形（“短标签和标题”给出时）、agent 的名字（用它所在方向的颜色，和时间线里同一批 agent 的颜色一致；过长时从中间截断；带下划线，点击它即切换到该 agent）、它的守护评审 `◈N` 和模型/推理徽标；底边是运行中的本轮时钟（`◷4m07s`，按秒走，静默时为警告色）或完成/失败多久了（`12d`），然后是填满剩余底边的上下文用量细线，百分比写在填充的末端（`────57%──────`），以及 `▾`。卡片里每项一行，没有内容的不写：它要做什么（任务，加粗；rollout 不公开任务文本时，是它自己说要做的事）；它和谁协作（负责人的卡片写 `⇄` 和与它互发三条以上消息、自己没有子任务的 agent；后者的卡片写 `→` 和它服务的负责人，用负责人的颜色）；它此刻在做什么（`▸ npm run bench`，它尚未返回的工具调用）；最新的模型说明（`~`）和最新的汇报；要紧的子任务，最多三个，失败的在前，每个写状态、名字、它返回了什么，失败时写原因（以 `~` 标出，来自「失败原因」），右端是时钟或距今时间；其余子任务按角色计数（`3 implementer · 2 reviewer · 1 critic +1`，所有角色共有的前缀不写）。失败的、被说明标为需要留意的，或角色列在 `importantRoles` 里的子任务算要紧（见[设置](#设置)）；设置 → Agents →「角色统计」可以隐藏计数那一行。卡片按状态着色：运行中为信息色、静默为警告色、失败为错误色、刚完成为成功色；选中卡片的顶边落在一条较亮的色带上。设置 → Agents →「卡片边角」选直角（`┌`，默认）或圆角（`╭`）。其余已完成的 L1 各占**两行**：`✓ audit_deps   ☽◐ ───57%──── 12d`，用量条和时间在各行对齐；下一行缩进、暗色，写它做到了哪一步：最新的模型说明，没有时是最新的汇报，再没有时是任务。名字优先：用量条会截断多数名字时，整个列表都不画用量条；连续几行时间相同时，只在第一行写出时间。`j`/`k` 在卡片和两行的条目之间移动，两行的条目只是被标记（第一行落在较亮的色带上），`e`、空格或点击才把它展开成卡片。展开卡片（`e`、空格，或点击顶边或 `▾`）时，标签替换了名字的会写出 Codex 的原名，并列出所有要紧的子任务，然后是该 agent 的完整日志（新的在前，约 20 行，其余见详情区域；没有日志时显示它最后的汇报），最后是完整的任务文本。点击某个子任务那一行会选中它，供详情区域查看。卡片和详情区域里 agent 的文字去掉聊天用的 markdown：链接只留文字，粗体、代码和标题标记去掉，完整的提交哈希只显示前 7 位。守护评审线程没有自己的卡片，只是 `◈N` 标记；失败的仍会显示为卡片。主会话的简报不在这个视图里，而在底部的状态卡中（见下）。
- **紧凑**（compact）：Agents 区域（树，每个 agent 和子任务一行，用 Codex 的原名，标题行与卡片布局相同），下面是简报、回顾和 agent 日志，与之前相同。

所有视图的计数口径一致：**agent** 指主会话启动的 agent，**子任务**指它们之下任意层级的 agent，**评审**指守护批准评审（不论挂在哪一层）。Agents 区域的标题行和卡片、状态卡的警报和通知（各种失败合成一句：`! 1 个 agent · 1 个子任务 · 1 个评审 失败`）、状态栏的 Agents 字段和警报、Agent 简报以及 `codex-hud --json` 都把三者分开计数；子任务还在运行的 agent 也算运行中。卡片上的子任务包括各层级，评审显示为卡片的 `◈N`，有评审失败时为红色。

### 控制栏

**控制栏**是面板的第一行（圆角框外观是两行），面板所有的控件都在上面；卡片、状态卡和各区域的标题上都不画按钮。每个控件都是一个**按钮**：图标，放得下时加上文字。栏上不写任何按键；按键只在帮助里。

```
120 列   ⌂ 主会话   ▦ 卡片   ≣ 时间线  ± 改动  ◫ 详情                                     ǁ 暂停简报  ⊕1 已收起  ⚙ 设置  ? 帮助
 56 列   ⌂  ▦ 卡片    ≣ 时间线   ± 改动   ◫ 详情       ǁ ⊕1 ⚙ ?
 40 列   ⌂  ▦ 卡片   ≣ 时间线  ±  ◫    ǁ ⊕1 ⚙ ?
 32 列   ⌂  ▦ 卡片   ≣  ±  ◫   ǁ ⊕1 ⚙ ?
```

- `⌂` 把 Codex 切回主会话。所有按钮都放得下文字时它才带上文字（主会话）；圆角框外观的标题里只要放得下就带着。
- 标签就是各个区域，按区域的顺序：`▦` 卡片、`≣` 时间线、`±` 改动、`◫` 详情，图标和区域标题上的一致。聚焦的标签按外观来画（标签行外观里是一块填色的标签），打开的用正文色，关闭的为暗色。叠放时，点一下打开关闭的区域并聚焦它，再点一下关闭打开的区域，卡片也一样；标签页排布下，点一下就切换到那个区域，区域标题不再重复标签上的名字，只写计数和行范围（`✓38 完成  · 101 子任务    23–44/103`），框线外观里没有可写的就只剩框线。
- `ǁ` / `▶`（暂停简报 / 继续简报）暂停或继续简报，只在配置了简报时显示；`⊕1`（已收起）显示被收起的已完成 agent，`⊖1`（收起）再把它们收起，只在有这样的 agent 时显示（卡片布局只计 agent，即列表的行：子任务无论如何都在卡片里；紧凑布局计树收起的每一行）；`⚙` 打开设置；`?` 打开帮助。
- 控制栏随宽度变化。先去掉文字，再去掉按钮：文字先去掉操作按钮的（只有所有按钮都放得下文字时才有），然后是关闭区域的标签的，再是打开区域的标签的（聚焦的除外），最后是聚焦标签的，其间标签之间的间距从三列逐步收窄到一列。然后去掉按钮：关闭区域的标签、“已收起”按钮、简报按钮、其它标签、聚焦的标签。主会话、设置和帮助始终保留。按钮两侧间隙的中点之间，任何位置都算点这个按钮。没有颜色时（`theme: none`），聚焦的标签加方括号，关闭的区域没有标签。

### 外观与图标

**外观**（设置 → 面板 →「外观」，或 `CODEX_HUD_LOOK`）有五种画控制栏和区域标题的方式。在设置里选一种外观会换上它配套的图标（只设 `CODEX_HUD_LOOK` 不会换图标）；之后仍可在「图标」里改。

```
tab     ⌂  ▦ 卡片   ≣ 时间线  ±  ◫    ǁ ⊕1 ⚙ ?
band    ⌂ ▦ 卡片  ≣ 时间线  ±  ◫ ──── ǁ ⊕1 ⚙ ?
tile    ⌂  🤖 卡片  🕘 📝 🔍          ǁ ⊕1 ⚙ ?
frame  ╭─ ⌂ 主会话 ──────────────── ǁ ⊕1 ⚙ ? ─╮
       │  ▦ 卡片   ≣ 时间线  ± 改动  ◫ 详情   │
pill    ⌂ ▦ 卡片  ≣ 时间线  ±  ◫    ǁ ⊕1 ⚙ ?
```

- **tab**（标签行，默认；Unicode 图标）：聚焦的标签填色，两边各留一列底色。区域标题是图标和名字，聚焦时用强调色，没有自己的底色。
- **band**（状态带；Unicode 图标）：控制栏是一条有底色的色带，和状态卡的色带一样，标签和操作按钮之间的空白是一条强调色的线；聚焦的标签用强调色。区域标题也是色带，放大的区域的标题像聚焦的标签一样填色。
- **tile**（Emoji 色块；Emoji 图标）：每个打开的标签各有一块底色，聚焦的填色；区域标题后面接一条横线，聚焦时为强调色。
- **frame**（圆角框；Unicode 图标）：整个面板外围一个圆角框。主会话是顶边上的标题，操作按钮在顶边右端；标签在它下面一行；每个区域的标题是横穿框的一条边（`├─ ± 改动 ────────── 4 个文件 ─┤`），内容在框的两边之间（聚焦区域旁的左边框为强调色），底部由状态卡的转角收口（`╰─ … ─╯`）。不足 20 列时按 tab 画。
- **pill**（胶囊；Nerd Font 图标）：聚焦的标签是两端圆角的胶囊；区域标题也是胶囊，聚焦区域的用标签色，其它的落在底色块上。

**图标**（设置 → 面板 →「图标」，或 `CODEX_HUD_ICONS`）选择图标集：`unicode`（上面的字符）、`nerd`（[Nerd Font](https://www.nerdfonts.com/) 图标：主页 `U+F015`、机器人 `U+F06A9`、历史 `U+F1DA`、差异 `U+F440`、信息 `U+F05A`、暂停 / 播放 `U+F04C` / `U+F04B`、眼睛 / 划掉的眼睛 `U+F06E` / `U+F070`、齿轮 `U+F013`、问号 `U+F059`）、`emoji`（各区域为 🤖 🕘 📝 🔍，各占两列，操作按钮仍用 Unicode 字符）或 `text`：按钮只有文字（`← 主会话`、`卡片 时间线 改动 详情`、`暂停简报`、`+1 已收起`、`设置 帮助`），窄时缩短（`← 主`、`暂停`）。`glyphs: text` 效果相同。Unicode 和 Nerd Font 图标以及胶囊的圆角都由 MesloLGS NF 绘制（见[字体](../README.zh.md#字体)）。

### 状态卡

**状态卡**位于底部，由一条色带和一个转角组成，就像 omp 画它的状态行；用量条是细线，读数写在填充的末端：

```
 ✓ 空闲 ★◆ 5d ──────────────────────56%──────────────────272K ~3m
│ ◎ 把分词器提速一倍，同时不破坏中日韩文本
│ ▸ 等待中日韩修复和缓存审查
│ ✓ 流式接口已合并
│   基准测试已在 50 MB 语料上搭好
│   依赖审计无问题
│   新增流式分词接口
╰─ parser-kit · main * ↑2 7d ───────────────────────────99% ↺4d18h
```

- **色带**有自己的底色，横跨整个宽度：会话状态（工作中时是正在运行的工具和目标、本轮时长和 `~N tok/s`）、模型徽标和会话时长；上下文用量条，百分比在填充末端，结尾是窗口大小（`config.toml` 设了 `model_auto_compact_token_limit` 时用 `┃` 标出自动压缩点）；配置了简报时，再加简报的状态（`~3m` 为回顾的时间，其余用文字：生成中…、失败、已暂停）。点击色带任意位置切换档位，同 `r`。
- **正文**挂在左侧一条竖线（`│`）下，竖线的颜色就是主会话的状态：空闲为暗色、工作中为信息色、失败为错误色、同步延迟或需要你（待批准、工具、agent、子任务或评审失败、回顾说需要你）为警告色。
- **转角**（`╰─`）：会话所在位置（项目名加粗，仓库不同时为 `› 仓库`，`· 分支`）；最紧的额度窗口的用量条，标为 `7d`、读数 `99%`；重置倒计时；提示缓存的提醒只在缓存过期前 5 分钟出现，为警告色。
- 用量条以信息色填充，超过 70 % 为警告色，超过 85 % 为错误色，底轨为暗色。
- 空间不够时，色带依次去掉输出速率、任务数、会话时长、窗口大小、模型和简报状态，然后用量条缩成百分比；转角依次去掉其它窗口、分支、窗口名、仓库和预计，然后是用量条和重置时间。状态和百分比最后才去掉。不足 24 列时不画状态卡。

它有三档（设置 → Panel → 状态卡，与其它面板偏好一样保存）；按 `Ctrl+]` `r` 或点击它的色带依次切换：

- **一行**（min）：只有色带，右端是简报状态和额度读数；有工具、agent、子任务或评审失败，或回顾说需要你时带 `!` 标记。
- **状态**（status）：色带、有警示时的警示行，以及转角。
- **完整**（full，默认）：上述内容，再加主会话的简报：先是模型对待批准请求的说明（`⚑ ~ …`），然后是回顾，标签在同一列行内：需要你（`!`，警告色）在前，然后是目标（`◎`）、现在（`▸`）和最近两条已完成（`✓`，其余以暗色 `+N` 计数），每项最多两行；只有没有回顾时，全局一句话才放在「现在」的位置；最后是调用失败或格式不符的回复。暂停时简报变暗。图形设为 text 时标签是文字（需要你、目标、现在、已完成），按显示宽度对齐成一列。状态卡最多占面板的三分之一，面板够高时至少给 agent 留 10 行；上方各区域用不完的行也归它，只要简报填得满：这时显示全部已完成事项，每项最多四行。简报放不下时保留需要你、现在和目标，其余滚动可见（在状态卡上滚动鼠标滚轮），并有一行说明还有多少不在视野里。

紧凑布局不变：简报和回顾仍在树下方的区域里，用同样的行内标签，所以它的状态卡只有「一行」和「状态」两档（「完整」即「状态」），`Ctrl+]` `r` 在两者之间切换。

### 滚动与选中

卡片区域标题行以下的视图放不下时可以滚动：鼠标滚轮、`PgUp`/`PgDn`，以及移动选中项（视图会跟着把选中的 agent 滚进来）。标题行右端写着当前显示的是哪几行（`6–17/40`）。滚动位置在重绘和新内容到来时保持不变，内容变少时自动收回。视图不足 12 行时先去掉空行，而不是藏起内容。底部状态卡和打开的 2–4 号区域位置不动。

### 按键

下表每个按键都要先按前缀：`Ctrl+]`，再按该键（或设置里选的前缀）。不带前缀时按键交给 Codex。

| `Ctrl+]` 之后 | 作用 |
|------|------|
| `,` / `?` | 打开设置 / 帮助（也可点 `⚙`、`?` 按钮）；方向键、Enter 或点击修改，Save 保存 |
| `Tab` / `Shift+Tab` | 切换区域（标签页排布下切到下一个 / 上一个区域） |
| `1`–`4` | 打开并聚焦对应区域，已打开的则关闭：`1` 卡片（紧凑布局中是树）、`2` 时间线、`3` 改动、`4` 详情；标签页排布下切换到该区域；点击它的标签也一样 |

### 会话切换

会话切换借助 Codex 自带的 `/subagents` 选择器（已对照 Codex 0.154 和 0.157 验证），选中显示该代理完整 UUID 的那一行，不会提交猜测的 `/agent <id>` 命令。需要空输入框（包括查看子代理时的只读输入框）或已识别的选择器；有草稿、处于复制模式或无法识别界面时，会提示原因。键盘移动选中项只预览，按 `o` 才切换。目标已在可见范围内时合并移动操作，长列表按页翻找，Enter 前再次核对该行。切换后不再重复打开选择器，避免二次弹窗和对话重绘；请求已发送不等于独立确认了最终显示的会话。

Codex 窗格窄于约 63 列时，选择器不再显示 UUID。此时按选择器显示的名字（任务路径，或 `Main [default]`）匹配，且仅当本会话没有其他代理显示同一名字时才切换；否则拒绝切换并提示加宽 Codex 窗格。有代理正在运行时，Codex 每次打开选择器都会在对话里插入一条 “Sub-agents running” 提示，这是 Codex 自身的行为。

### 列表中的 agent

活跃排序只调整同级节点：有运行中子孙的分支优先，按最新一轮启动时间排序，普通 token 或日志更新不会改变顺序。
父子关系支持两种日志元数据格式。没有状态证据的代理显示为未知，不会凭最近写入时间判定为运行或完成。

每个 agent 的 rollout 只读一次，每次从上次停下的地方接着读。读到哪里、读到了什么（状态、阶段、未返回的调用）保存在 `$CODEX_HOME/hud/scan/`，超过 256 KB 的 rollout 各一个文件（权限 0600，一周既没用到也没更新即删除），侧栏或状态栏重新启动时只读之后新写入的部分。只有文件仍与保存的记录相符（同一个文件和线程，记录结束处的字节没变）时才使用它，否则从头重新读取。

代理以任务路径的最后一段命名，与 Codex `/subagents` 选择器显示的名字一致：`/root/essays_2020_2021` 显示为 `essays_2020_2021`。标签到达之前，这个名字是树的行、卡片和日志块的标题。开启“短标签和标题”（默认开启，设置了后端后生效）后，模型起的短名会在卡片、行、紧凑树、时间线和 Inspector 标题里替换它（设置 → Agents → 标签替换名字；关闭时短名写在名字下一行）；展开的卡片和 Inspector 仍会写出 Codex 的原名，切换 agent 也始终按原名进行。Codex 随机分配的昵称（Copernicus、Meitner 等）和角色移到 Inspector 中。守护评审线程（Codex 0.155+ 会在会话旁开一个，用来评审批准请求）没有自己的行或卡片：由父级显示 `◈N`，有正在运行的评审时为信息色；失败的仍会显示。

已完成的代理在完成 3 分钟后从列表中收起（Settings → Hide finished：1m、3m、10m、30m 或 never）。运行中和失败的代理不会被收起；子代理仍在显示的已完成父代理保留为淡化行。每个已完成的行都显示完成了多久；控制栏统计被收起的数量（`⊕12`），点击它或按 `Ctrl+]` `a` 即可全部显示。

### 时间线

第 2 个区域默认关闭，以主会话为主轴按时间倒序排列整个会话，每条写距今时间（连续几条时间相同时只在第一条写出）。主会话自己的事件在最左边：完成的一轮及其回复的开头（`⏎`）、请求批准与答复、上下文压缩、额度窗口越过 80 % 和 95 %、一轮中断或失败、工具调用失败（写出它运行的命令，`exec` 脚本写它的第一条命令，如 `✗ rg -n …`，没有命令时写工具名）；连续相同的合并为一行并标 `×N`。主会话启动的 agent 缩进一级，每个阶段一行：结束的阶段放在结束的时刻，写用了多久、这段时间里结束的各层级子任务（`✓2 ✗1`），它最新的阶段还写返回内容的前几行；仍在进行的阶段放在开始的时刻，写它的时钟和它说要做的事。为别人工作的 agent，其阶段写出是为哪个负责人做的（`性能顾问 → 分词器提速`）。子任务只有要紧的（与卡片相同）才有一行，再缩进一级，放在它结束的时刻。每个 agent 用它所在方向的颜色，与卡片上的名字一致：一个 L1 和它下面的 agent 同色，为别人工作的 agent 用负责人的颜色，同时进行的方向颜色互相错开。「失败原因」写过的原因显示在失败下方，以 `~` 标出。只写 rollout 记录下的事实：一段安静不算一条。守护评审的开始和完成不显示，失败仍保留。待批准的请求还会显示已经等了多久，在状态栏警示（最宽形式）和侧栏的状态卡片里都有。

设置 → 面板 →「时间线样式」有三种画法：

```
主轴      28m ⏎ 中日韩第一阶段已合入；竖排标点作为第…
          30m ├─▸ 性能顾问 → 分词器提速              ◵
              │    核对查表是否一直留在 L1 缓存里
          40m │ ╰✗ b03_review_harness              15m
          50m ├─▸ 中日韩正确性                       ◴

缩进      28m ⏎ 中日韩第一阶段已合入；竖排标点作为第…
          30m   ▸ 性能顾问 → 分词器提速              ◵
                  核对查表是否一直留在 L1 缓存里
          40m     ✗ b03_review_harness             15m
          50m   ▸ 中日韩正确性                       ◴

分道      28m ⏎ │ │ 中日韩第一阶段已合入；竖排标点作…
          30m │ ▸ │ 性能顾问 → 分词器提速            ◵
              │ │ │   核对查表是否一直留在 L1 缓存里
          40m │ ✗ │   b03_review_harness           15m
          50m │ │ ▸ 中日韩正确性                     ◴
```

- **主轴**（rail，默认）：主会话的条目在左边一条竖线上，agent 的条目从竖线分出，子任务再往里一级。
- **缩进**（indent）：同样的层级，只用缩进表示。
- **分道**（lanes）：主会话一道，每个有子任务或仍在工作的方向各一道，最多三道，48 列起四道；方向的条目落在它那一道上，方向仍在工作时它那一道从顶部画起。

设置 → 面板 →「时间线范围」是时间窗口：最近 1、3（默认）、6、12 或 24 小时，并且无论多久都至少显示最新的 8 条；仍在进行的阶段不论从何时开始都会显示。更早的条目在最后一行计数（`▸ 更早 40 条`）：点击它，或在时间线有焦点时按 Enter，每次再加载 20 条。

### Agent 日志

tree 下方（卡片布局中在各自的卡片里）每个 subagent 都有一份日志，按时间倒序：观察到的开始、完成、失败和最新说明（与刷新 tree 的同一次读取写入），以及简报对它的说明（以 `~` 标出，表示由模型撰写）。日志只增不减；新的简报会追加，而不会替换上一份。日志跟随 tree：tree 隐藏的 agent（已收起、被筛掉或在折叠的父级下）不显示，折叠的父级会显示一行说明下面收起了几份日志；让 agent 重新显示，它的完整日志也随之出现。紧凑布局中每块以 agent 的状态、类型图形和 Codex 原名开头，下一行是模型起的短名或任务；每个 agent 显示最近两条，选中的显示六条并排在最前，详情区域显示全部，只是不再重复上方已显示的最新汇报，日志里只有开始和完成时也不显示。每条的时间单独占一列，正文挂在它旁边，去掉聊天用的 markdown。点击日志行会选中对应 agent。日志按会话保存在 `$CODEX_HOME/hud/agent-log/`（权限 0600，30 天后删除）。选了模型后端时显示；后端关闭时，打开 Agents →「Agent 日志」也会显示（只有观察到的条目）。

### 详情与改动

Inspector 默认显示名字、模型和推理强度（先是图形，再用文字写出两者：`☀◆ gpt-6-astra · max`）、状态、本轮经过时间和最近活动。按 `v` 展开完整时间与会话 ID。会话切换提示显示在底部；点击 Agents 摘要或空白行不会切换会话，只有具体条目会触发切换。

有不止一个工作树时，改动区域先列出工作树，再列出文件：每个工作树一行，列出其文件的那个标 `●` 并加粗，右侧写它的分支领先或落后上游多少（`↑2`、`↓1`）和状态（`4 改动`、`干净`、`锁定`）；然后是一条再次写出它的名字和计数的分隔线（`─ main · 2 未暂存 ───`），下面是它的文件。工作树和文件共用一个光标：移到某个工作树的行就列出它的文件，按 Enter 在详情区域显示它的信息（HEAD 提交的标题、分支、状态和计数，完整路径在「更多」里；不显示哈希）。旧设置文件里保存为打开的工作树区域，现在打开的是改动区域。文件属于列出的那个工作树，不推断某个文件由哪个 agent 修改。每个文件前是一个表示改动类型的彩色字母：`M` 修改（黄）、`A` 新增（绿）、`D` 删除（红）、`R` 或 `C` 重命名或复制（蓝）、`!` 冲突（红）；放得下时右端写增删的行数（`+12 −3`），暂存和未暂存各有多少见列表上方的计数。未跟踪的文件收成最后一行 `▸ 12 未跟踪`：按 Enter 或点击它，在它下面列出，再按一次收起。窄屏摘要中 `Δ` 是修改文件数，`S` 是暂存、`U` 是未暂存数量。
选中文件后按 Enter 打开暂存和未暂存 diff（只显示各段改动；git 头部重复路径并用哈希标出文件版本，不显示），自动放大 Inspector；Esc 还原。标题写文件名和增删的行数（`+12 −3`），下方暗色写所在目录；各段以面板语言标出已暂存、未暂存或未跟踪。新增行绿色、删除行红色、hunk 标记青色，保留 `+` / `-` 符号；长行在词与词之间折行，续行缩进两列，`+` / `-` 只出现在第一行；制表符按 4 列展开。未跟踪文件提供有大小限制的内容预览，未跟踪的目录列出其中有多少个文件和它们的路径。
这些操作只读取 Git 数据；禁用外部 diff、内容过滤器和部分克隆的自动下载，不提供暂存、提交或切换分支操作。

### 设置

设置 → 面板 →「宽度」只提供面板排过版的宽度：32 列（默认）、40、48 和 56，每一档能放下的东西不同（列表行的用量条、模型徽标的文字、时间线的第四条泳道）；←/→ 在其间切换，越过两端会回到另一端。设置文件里写的或拖动边框得到的其它宽度照样能显示，←/→ 从它所在的位置接着切换。保存后立即调整，Codex 保留至少 41 列，所以窗口较窄时面板会比设定的窄。旧设置文件里的 0 显示为 auto，即默认宽度。tmux 窗口尺寸变化时（例如在后台创建的会话从更宽的终端接入）会重新套用宽度；手动拖动边框则保持不变。没有保存过设置时，仍支持 `CODEX_HUD_TREE_WIDTH` 指定初始宽度。

独立设置页分为 Status bar（密度、主题、模型标签、动画、上下文口径、启动时的底栏、通知）、Agents（排序、收起已完成、Agent 日志、标签替换名字、角色统计、卡片边角、重点角色）、LLM（模型增强：所有会把内容发给模型的功能，见下文）和 Panel（布局、面板排布、外观、图标、状态卡、语言、2–4 号区域以及时间线的样式和范围、宽度、图片、鼠标、前缀键、刷新间隔）四组。取值在标签旁对齐成一列，不是默认值的取值为强调色，宽度达到 70 列时每行后面还有一句暗色的简短说明（窄面板上取值仍在右侧对齐）；选中项显示为 `‹ 取值 ›`，←/→、Enter 或点击即可修改（点击 `‹` 向回切换）。列表下方一行说明选中设置的作用。选中主题、模型标签、面板排布、外观或图标时，这一行上方的「预览」按未保存的取值画出面板的控制栏和一个区域的标题，保存之前就能看到效果。未保存字段带 `*`，Save 按钮随之高亮；Bar on launch 在下次启动时生效。Save 写入 `$CODEX_HOME/hud-settings.json`（可用 `CODEX_HUD_SETTINGS_PATH` 改路径），紧凑 HUD 下次刷新时同步显示偏好。已保存设置优先于环境默认值，`NO_COLOR` 始终优先。Back 放弃未保存修改；Reset 恢复默认草稿，需 Save 才应用。设置页是一个模态页：打开期间按键归它（方向键、Enter、`s` 保存、`r` 重置、`Esc` 返回），底部只写按钮没有覆盖的移动操作。依赖其它设置的行（所有模型功能依赖后端，桌面通知依赖通知，常规更新间隔依赖它控制的 Agent 简报、主会话回顾或改动摘要）在其所依赖的设置关闭时变暗，后端一行下方注明「有后端时生效」；这些行仍可选中，可以提前设好。窄屏保留完整 Back/Save 按钮，使用短标签。说明行上方有一行显示侧栏上次读取会话的时间（`HUD 读取会话 2s前`）；如果读取失败过，还会写出失败的环节、时间和原因，失败比上次成功读取更新时以警告色显示。读取失败时屏幕上保留的是上次的好数据，有了这一行，“会话很安静”和“HUD 读不到”才不会看起来一样。

Agents →「重点角色」（设置文件里的 `importantRoles`）指定哪些角色的子任务算要紧。设置页提供：无（默认）、本会话子任务出现过的每个角色（写法和卡片上一样），以及当前设定的值；同时指定几个角色要在设置文件里用逗号分隔（`"importantRoles": "critic, oracle"`），设置页会把它保留为一个可选值。这些角色的子任务和失败的、被说明标为需要留意的子任务一样：在负责人的卡片上写出名字，在时间线上有一行，并在 Agent 简报的报告里写出。名字与角色相同，或是角色在某个短横线之后的结尾部分，都算匹配，所以 `critic` 也匹配 `team-platform-critic`。选「无」时，只有失败的和被标为需要留意的子任务算要紧。

### 模型增强

面板请模型写的所有内容都在设置的「模型增强」（LLM）组里，每一项都有自己的开关；内容使用面板语言，显示在简报标题下方，标明是模型写的，而不是观察到的事实。「后端」选择由谁来写：`omp`、`agy` 或任意 OpenAI 兼容的 chat completions 接口（`api`）；选关闭则所有项都停用。所有项共用一个队列（同一时间只有一个调用）、一个缓存和一个每小时上限（「调用上限」，默认每小时 60 次，同一 `CODEX_HOME` 下的多个侧栏合计）；超过上限的请求会被拒绝，原因显示在本该出现文字的位置。两项设置控制频率：「简报间隔」是重要变化（阶段、状态或失败的变化，你的提问，最终回复）最多多久触发一次，「常规更新间隔」（默认 15 分钟）是常规变化（agent 的新说明或命令、运行很久的一轮、变化了的 diff）最多多久触发一次。设置页列表下方显示今天已调用的次数。缓存和调用记录（只有时间戳）保存在 `$CODEX_HOME/hud/model-cache/`，权限 0600。各项发送的内容：

- **Agent 简报**（选了后端后默认开启）：区域顶部一句话概括所有 subagent，并为每个 agent 写一条说明，记入它的日志。它发送一份报告，主会话启动的每个 agent 一条（不含 guardian 审查），为别的 agent 工作的紧跟在那个 agent 之后：名称和角色；处于第几阶段、已运行多久，或何时完成、何时失败；由谁派发，任务（300 字符），没有任务文本时改用它接手时自己的话，即本阶段的第一条说明；最新公开说明（600 字符）和正在执行的命令（200 字符）；上一阶段的返回，以及更短的（300 字符）再往前两个阶段的返回；按角色计数的子任务，以及最多四个要紧的子任务（失败的、说明要求留意的，或角色列在 `importantRoles` 里的），附状态和返回或失败原因；失败的批准审查；本阶段给它发过消息的有谁。不超过 1500 字符的返回按原文发送，更长的在开启结果摘要时发送摘要，否则取开头和结尾。报告先列需要留意的 agent（它或它的子任务在一小时内失败过，或说明要求留意），再列运行中的，再列半小时内完成的；更早完成的只给最后一次返回。随报告一起发送的还有上一次简报以来发生的事（阶段开始和结束、失败，最多 20 条）和上一次简报本身（概括句和最新的说明），因此模型只为新情况涉及的 agent 写说明，最多八条，其余 agent 保留原来的说明。整个请求控制在 16 KB 以内：超出时按固定顺序删行，每一步都从报告底部删起，删到够为止（更早阶段的返回；没有子任务的 agent 除第一行外的内容；半小时以前完成的 agent；最新说明；要紧的子任务；半小时内完成的 agent 的返回，然后是这些 agent 本身；每个 agent 除第一行外的内容；最后是整条 agent），需要留意的 agent 从不删减。最多每个「简报间隔」一次，在某个 agent 的阶段、状态或失败情况变化时调用；新的说明、正在执行的命令或常规子任务的进展，最多每个「常规更新间隔」发送一次。回复不是要求的 JSON 时会退回一次请模型改正；仍然不对就保留上一份简报，并在区域里说明。
- **主会话回顾**（默认关闭）：主会话的滚动回顾，显示在状态卡（卡片布局）或简报区域顶部（紧凑布局）：目标、已完成的事（最多四条）、当前进展，以及以警告色标出的需要你做的事。它会发送你的提问和助手的公开回复与说明（每条约 600 字符，总共约 4000 字符，绝不包含推理内容）、计划步骤、待批准请求的摘要、压缩次数、用 Codex 的 `/goal` 设定的目标及其状态（以只读方式读取 `$CODEX_HOME/goals_1.sqlite`，读不到就不发送），以及每个 subagent 的名称、状态和本轮时长；subagent 的任务和说明只有在同时开启 Agent 简报时才发送。以方括号标签开头的提问（`[watcher] …`），或以同伴消息的抬头（谁发给谁、注明是同伴消息，如 `Docs lead → Root (peer, no reply owed).`）开头的提问，会标为「可能是自动消息」发送，因为往会话里写消息的工具常这样开头；它也不算你发出了提问。每次只带上一次的回顾和之后的新内容，所以开销稳定，Codex 压缩对话后也不会丢。你发出提问、出现最终回复、一轮结束、计划步骤完成或出现待批准请求时，在「简报间隔」允许的范围内立即更新；一轮运行很久时（例如在等 subagent），只要有任何变化（包括说明或 subagent 的进展），最多每个「常规更新间隔」（默认 15 分钟，且不短于简报间隔）更新一次。什么都没变就不发送。回顾按会话保存在 `$CODEX_HOME/hud/recaps/`（权限 0600，30 天后删除），重新打开侧栏或 `codex resume` 时会立即显示上一次的回顾和它的时间；语言不同的回顾会重新生成。卡片布局中显示在「完整」档的状态卡里；紧凑布局中显示在简报区域顶部。
- **结果摘要**（默认关闭）：subagent 完成时，它完整的最终答复（仅公开的最终回复；超过约 8000 字符时取开头和结尾）只发送一次，返回三行：结论、依据，以及 agent 自己说明的存疑之处。主会话启动的 agent 每个阶段结束时，超过 1500 字符的返回也会生成摘要。摘要写入该 agent 的日志，在检查器的「~ 结果摘要」下显示，并在 Agent 简报的材料中代替原文。侧栏看到之前一小时以上就已完成的 agent，只有在你检查它时才生成摘要。
- **短标签和标题**（默认开启；设置后端之前不发送任何内容）：每个 subagent 的任务文本（400 字符）只发送一次，多个合并为一次请求，不发送别的内容；回复为每个任务给出一种工作类型（research、experiment、fix、review、writing、summary 或 other）和一个约 10 个汉字或 4 个英文单词的短名。类型由 HUD 画成固定的图形，暗色显示在 agent 名字旁：⌕ 调研、⚗ 实验、⚒ 修复、◈ 评审、✎ 撰写、∑ 总结，other 不画（图例见 `?`）。面板显示 agent 名字的地方都改用短名（标签替换名字，默认开启；关闭时短名写在卡片和日志块中原名的下一行）；展开的卡片和 Inspector 保留 Codex 的原名，即 `/subagents` 显示的名字，切换也按它进行。回复到达之前、功能关闭或请求失败时，卡片显示任务文本，不画图形。标签按任务文本的哈希保存在 `$CODEX_HOME/hud/model-cache/labels.json`（0600），每个 agent 只生成一次；还没有类型时写下的旧条目照样可读，类型按 other 处理。会话也会得到一个标题：主会话回顾写过时取回顾的目标（不调用模型），否则用你的**第一条提问**（1500 字符）调用一次。标题保存为回顾旁的 `<session>.title.json`，在状态栏会话字段最宽的显示中出现，会话 id 仍在旁边。
- **失败原因**（默认关闭）：主会话的工具调用失败时，发送命令和输出的最后 2000 字符；subagent 以错误结束时，发送它 rollout 末尾的错误事件（或最后一个失败命令的输出）。返回一行原因，显示在时间线的事件下方；对 agent 还写入它的日志并在检查器中显示。rollout 没有记录错误输出的失败不发送任何内容。
- **改动摘要**（默认关闭）：改动面板打开时，当 diff 的文件或行数变化，最多每个「常规更新间隔」一次，发送按文件的统计（最多 40 个文件）和最多 6000 字符的已暂存与未暂存内容；未跟踪的文件只发送文件名。返回一到两行，说明这次改动做了什么，以 `~` 标记显示在面板顶部；diff 之后又变了，旧摘要会注明，直到下一次更新。
- **批准说明**（默认关闭）：有命令等待批准时，发送完整命令（最多 2000 字符），并在简报区域顶部以「~ 待批准（模型描述）：」显示一句话，说明它会做什么。只做描述：判断命令是否安全的回复会被丢弃而不显示。它不能代替阅读命令本身；仍然在 Codex 的批准提示中作答。

每一项的结果都按输入缓存，同样的答复、摘要或 diff 不会发送第二次，跨侧栏也一样。失败的请求 10 分钟内不再重试。

`codex-hud brief --dry-run` 打印面板此刻会为当前目录的会话发送的简报：说明和材料，以及它们的大小；按保存的设置、agent 日志和上一次回顾生成，不调用模型，不写任何文件，后端关闭时也能用。`codex-hud brief --dry-run FILE` 改为写入 FILE（权限 0600）。

按 `Ctrl+]` `b` 或点击控制栏上的暂停按钮（暂停简报） 可以暂停和继续以上所有项（Agent 简报或主会话回顾开启时可用）。使用 `api` 时在 `hud-settings.json` 里设置：

```json
{ "briefing": "api",
  "briefingApiBase": "http://localhost:11434/v1",
  "briefingApiModel": "qwen3:8b",
  "briefingApiKey": "" }
```

base 留空即 OpenAI。key 留空时依次读取 `CODEX_HUD_BRIEF_API_KEY`、`OPENAI_API_KEY`；都没有就不带 key，适合本地服务。设置文件以 0600 权限写入。`CODEX_HUD_BRIEF_MODEL` 对所有简报方式覆盖模型名。请求使用较低的思考强度：`omp --thinking low`，以及 `agy` 的默认模型 `gemini-3.8-flash-low`。发给 `api` 接口的只有所有兼容服务都接受的字段；如果你的接口接受 `reasoning_effort`，设置 `"briefingApiReasoning": true` 后也会发送它。

### 背景图

面板 → 背景图会在侧栏空白处画一张字符画：盲文点阵、按原图上色的点阵，或 ASCII。它只占用没有内容的行，agent 和简报需要空间时会自动让出。`bin/codex-hud-art <图片> [dots|color|ascii]` 会把图片复制到设置旁边并打开装饰；`bin/codex-hud-art off` 关闭。图片由 ffmpeg 读取，它支持的格式都可以。

## 输出速度

默认状态栏新增 `Out ~42.1 tok/s`，选中代理的详情也会展示其可用读数。
它用日志里的**累计输出 token 增量 / 日志时间差**估算最近约 30 秒的吞吐，展开详情后注明实际采样窗口。
这不是纯模型解码测速，窗口可能包含工具或服务等待时间；新一轮开始时排除跨轮空闲时间。
没有足够样本时不显示；10 秒没有新样本后显示 `last ~42.1 tok/s`，保留上次读数。
Ctx 仍保留当前占用与压缩次数，开发面板不绘制 Ctx 趋势。

## 机器可读的状态

状态栏会按窗格宽度自我裁剪：能缩就缩，放不下就藏。这对读者是对的，对脚本是错的。
所以每一次采集也会把已知状态写到 `$CODEX_HOME/hud/state/<tmux 会话名>.json`，
`codex-hud --json` 则打印当前目录会话对应的那一份。

```bash
codex-hud --json | jq '.context.percent, .agents.active, .attention[].label'
```

其中包含会话、项目、活动、上下文、额度、token、代理与需要关注的事项，
有待批准请求时的 `approvalSince`，推算成立时的 `quotaForecast`（是估计，不是读数），
另有 `bar.segments`：真正画出的那一行里，每个字段落在哪几列。
点击某一列能对应到某个字段，靠的就是它。

`agents` 的计数与面板一致（见[布局](#布局)）：`active`、`completed`、`failed`、`unknown`
统计主会话启动的 agent，子任务还在运行的也算 active；`agents.subtasks` 和 `agents.reviews`
按同样四项统计子任务和守护评审；`agents.nodes` 列出每个线程及其 `kind`（`agent`、`subtask` 或 `review`）。
这是 `version` 2；version 1 把所有线程合在一起计数。

规则与显示一致：每个值都是观测到的事实，没有数据的字段整个缺席而不是写 0，
这样“没有额度快照”和“额度为 0%”不会长得一样。文件以 `0600` 权限原子写入，
只在时钟之外确有变化时才写，且每秒至多一次；HUD 退出时删除——
一个已经停止的 HUD 留下的状态文件，看起来会像还活着。

`health` 说明状态栏自己的读取是否顺利：`lastReadAt` 是会话查找和 rollout 读取上次成功的时间，
`lastError`（`source`、`message`、`at`）是最近一次失败的采集。两者在发生之前都不出现。
单纯又一次成功读取不会触发重写，所以 `lastReadAt` 和 `updatedAt` 一样，是“截至上次写入”的值。

缓存提醒也在同一行：`◷~08m` 表示距最近一次模型用量报告约 8 分钟，每满一分钟更新；25 分钟变黄，30 分钟后显示红色 `◷~30m+`，新用量报告到达时重新计时。采用 30 分钟提醒窗口，`~` 表示估算，不代表服务端确认缓存仍有效或已经过期。读取异常时改用 `?`；没有采样时不显示。提醒在所有密度中启用，25 分钟后优先保留在窄窗口中；纯文字模式显示 `Cache ~25m`。

上下文比例已对齐 [Codex 0.154 的计算](https://github.com/openai/codex/blob/rust-v0.154.0/codex-rs/protocol/src/protocol.rs#L2258)：使用最近一次 token 报告，从已用量和窗口大小两侧扣除 12K 固定基线。`Ctx 20%` 对应原生的 `80% context left`；括号中显示扣除基线后的已用量/可用窗口。自定义窗口不超过 12K 时按原始窗口计算。总会话 token 不用于计算上下文占用。

```bash
CODEX_HUD_STATUSLINE=0 codex               # 关闭底部状态栏，仍可使用侧栏
CODEX_HUD_CONTEXT=remaining codex         # 与原生状态栏同方向显示剩余比例
CODEX_HUD_GLYPHS=glyph CODEX_HUD_THEME=mocha codex
```

### 提醒

默认关闭：Codex 自己有通知机制，同一件事弹两次比不弹更糟。在设置 → Status bar →「通知」打开，或用 `CODEX_HUD_NOTIFY=1` 开启；「桌面通知」是 `CODEX_HUD_NOTIFY_DESKTOP` 对应的第二道开关。设置了的环境变量优先于设置。

```bash
CODEX_HUD_NOTIFY=1 codex
```

它只提醒观测到的失败、Codex 正在等待的审批，以及已结束的代理，每次发生只发一条，并带冷却时间，避免状态反复时刷屏。
它不会对会话做任何操作：不自动确认、不发送按键、不自动重试。

`CODEX_HUD_NOTIFY_DESKTOP=1` 会额外发出终端之外的桌面通知。这是第二道开关：走出终端比发一条 tmux 消息要冒昧得多。

```bash
CODEX_HUD_NOTIFY=1 CODEX_HUD_NOTIFY_DESKTOP=1 codex
```

两条通道都是尽力而为，不支持时静默：一条是终端自己可能响应的 OSC 9 与 OSC 777 序列（包在 tmux passthrough 里，由启动脚本负责开启），另一条是 Linux 的 `notify-send` 或 macOS 的 `osascript`。
通知文本来自 rollout，写出前会剥掉全部控制字符：消息无法提前结束序列、把剩下的内容当成终端命令执行。
