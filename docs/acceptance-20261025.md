## 测试基线

默认环境中的 `NO_COLOR=1` 会改变主题、焦点标记和仪表字符。旧测试继承这个环境，却断言彩色布局，导致 16 项失败。
相关九个测试文件现在通过 `useDisplayFixture()` 为每项测试选择明确的显示配置，并在结束后恢复。原有无色仪表、标签等断言保留；新增检查覆盖无色环境对已保存主题的覆盖行为。

| 当前验证 | 结果 |
| --- | --- |
| `NO_COLOR=1 npm test`（在隔离副本中） | 编译通过；TS 单元测试 953/953；MJS 47/47 |
| `env -u NO_COLOR npm run test:unit`（同一构建） | 953/953 |
| 窄屏语义矩阵 | 两种主题 × 中英文 × 五种外观 × 四种宽度 × 两种高度，共 160 组；TPS、历史标记、上下文及导航点击区域通过 |
| 完整集成测试初次执行 | runner 报告 23 通过、1 失败、1 跳过；其中 Windows 脚本自行报告跳过但返回 0，计入了通过数 |
| 失败项修复后定向复验 | `test-bar-click.sh` 29/29 断言通过；其余集成项沿用本次完整运行证据 |
| 独立启用真实 Herdr 回归 | 紧凑/展开两布局通过，包括快速重开、等待处理、探针故障、连接恢复和观察器退出 |

点击测试的失败原因是快照写入竞态：固定坐标快照与真实面板写入同一个 `bar.json`，后者把 `bar.segments` 改为空数组。
测试现在复制实际切换脚本及点击解析模块到临时目录，使用不写快照的占位面板，并使用唯一 tmux socket。
它验证实际 tmux 布局和焦点变化；实际面板的渲染及鼠标输入另由窄屏测试验证。

本机运行环境为 Node 24.22.1、tmux 3.4、WSL Linux。CI 已增加空 `NO_COLOR` / `NO_COLOR=1` 矩阵；本轮没有声称远端 Node 18/20/22 CI 已运行。
